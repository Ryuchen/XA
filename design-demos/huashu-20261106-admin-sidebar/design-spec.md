# 管理后台侧边菜单栏 · 共同设计规格

## 任务本质
为电竞运营管理平台重新探索侧边菜单，服务门店店长、客服、财务、售后和平台超级管理员。菜单首先帮助人定位当前业务、找到下一步操作，并明确当前数据属于哪家门店。

## 已确认内容
- 沿用“业务分类折叠”，不重新发明业务分类，不减少现有菜单入口。
- 平台与工作区：门店管理、运营工作台。
- 门店经营：订单中心、陪玩中心、老板中心、资金与核算、客服与消息。
- 门店配置：店铺运营、团队与系统。
- 当前示例展开订单中心，包含订单处理、履约与售后、派单配置，以及订单与派单、预约管理、报单审核、订单评价、群派单配置。
- 超级管理员可在声浪电竞与兴安电竞之间切换；普通门店角色只读所属门店。切换门店不要求重新认证。
- 保留菜单搜索、折叠侧栏、锁定展开及当前页面反馈的语义。

## 输出与比较条件
- 六张候选缩略图：同页六格，每格约 480 × 300 px。
- 三个完整可交互 HTML：统一使用 1440 × 900 px 首屏截图，并保存整页截图。
- 原型需支持业务分组展开／收起、当前菜单切换、门店切换、侧栏收起与展开。
- 原型不请求业务接口、不修改真实门店、不伪造订单与资金数据。内容区只用于对照菜单宽度和当前位置。
- 原型选择页适配窄屏方便查看；正式后台仍以桌面及 1366 × 1024 CSS 逻辑视口为最小适配目标，不借此增加手机端要求。

## 视觉与交互约束
- 使用项目真实 SVG Logo 和 MiSans 字体栈。
- 使用 Blue Planet 海洋蓝和奶白中性色，保留深浅主题可读性。
- 以 4pt 为间距基准，常规菜单操作行高 40–44px，原型触控目标至少 44px。
- 正文不小于 14px，辅助标签不小于 12px；隐藏滚动条但保留滚动能力。
- 状态不能只依赖颜色：当前项同时有文字字重、位置标记或图形反馈。
- 原型不复制后台业务代码，选定方向后再改正式组件。

## 共同 form 五问
- 叙事角色：门店业务的导航员，不是数据看板主角。
- 观众距离：长时间工作的桌面操作者，需要快速扫读与肌肉记忆。
- 视觉温度：克制、可信、清楚，避免营销页式炫技。
- 容量：九组业务域及各自子菜单，允许纵向滚动和权限裁剪。
- 视觉母题：门店边界与订单履约路径，而非电竞装饰或游戏插画。

## 假设
- 本轮比较的是导航结构、密度和门店上下文，不决定新的业务权限或路由。
- 用户尚未选定任何新方向；必须展示后等待选择。
