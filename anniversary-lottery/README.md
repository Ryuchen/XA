# 兴安电竞店庆抽奖（独立项目）

独立 Django 项目、独立登录、独立 MySQL 数据库 `xa_anniversary`、独立容器服务。不读取原陪玩平台账号、订单、积分或钱包。

## 当前阶段：历史剩余次数补抽

自 2026-10-26 起启用 `LOTTERY_REMAINING_ONLY = True`，该开关由代码发布控制，后台不提供修改入口。

- 此前已发放的剩余次数可在原房间、原参与码下继续使用，不再受原房间结束时间限制；未到开始时间、已暂停房间、停用账号或暂停奖池仍不能抽取。
- 管理后台停止新建房间、添加老板（包括零次数账号）和追加次数；服务器拒绝这些提交，旧表单或直接请求也不能添加。原生 Django 管理页仍为只读审计。
- 历史次数、累计保底、已有结果及发放记录不重置。单抽、十连抽、“再来一次”返还及30/50次额外保底继续执行原规则。
- 允许查询个人历史、核对兑奖、重置遗失参与码，以及暂停或恢复已有房间/账号。次数用完后不能再发起新抽奖，已完成请求仍可查询原结果。
- 不修改历史房间日期、不批量恢复此前停用的资格，也不新增任何次数。

下方开设房间及发放步骤为原活动阶段说明，补抽期间相关后台入口已关闭。

## 使用

活动域名：`https://ann.xaesports.club/`。管理员入口：`https://ann.xaesports.club/control/`。初始超级管理员账号由部署程序生成，交付文件保存在本地 `.tools/anniversary-20261016/admin-credentials.json`（不属于项目源码）。登录后可在导航栏修改密码。域名需在 DNSPod 配置 `ann` 的 A 记录为 `43.167.213.74`，HTTPS 证书由网关自动签发。

1. 开设房间，填写名称与开始、结束时间（北京时间）。
2. 添加老板昵称，分别填写小红、大红、大大红奖池的初始次数。
3. 将房间链接和该老板的专属参与码私下交给本人。
4. 老板进入房间、输入参与码，选择奖池进行单抽或十连抽；十连抽要求该奖池至少有 10 次机会。
5. 可随时追加次数、暂停房间、停用老板或重置参与码。重置会使旧参与码及旧登录失效。
6. 老板可在自己的房间分页查看全部个人记录，每页 10 条，可前后翻页或跳转页码。后台按房间核对记录；奖品由管理员实际交付后填写说明，标记已发放。

参与码仅用于对应房间的一位老板，抽奖接口同时校验登录身份与当前房间。每位老板只在自己的房间查看本人的抽奖及兑奖记录；切换房间或账号时清空旧记录，不能访问其他老板记录或管理后台。参与码仅生成时显示，数据库仅保存其摘要；遗失后由管理员重置。老板的房内登录最多持续 12 小时。

## 奖池与概率

完整录入原海报的三个 6×6 奖池，共 108 格，包括积分、店铺余额、冠名、TAG、优惠券、感谢参与和再来一次。

小红奖池沿用两颗独立公平骰子，每面 1/6、每格 1/36，算法为 `independent-fair-v4`。大红和大大红使用 `targeted-quarter-v6`：先生成两个安全随机点数；仅当落入指定奖项时，再以 1/4 概率保留，另外 3/4 均匀转入本池的感谢参与奖格。其他格不重新抽取，确保其他奖项的自然概率严格不变。最终点数与实际奖格一致，但这两个奖池的最终骰子不再独立等概率。

| 奖池 | 定向调整奖项 | 原自然中奖概率 | 新自然中奖概率 |
| --- | --- | ---: | ---: |
| 大红 | 9折优惠券（两格合计） | 1/18 | 1/72 |
| 大红 | 20元店铺余额 | 1/36 | 1/144 |
| 大大红 | 85折优惠券（两格合计） | 1/18 | 1/72 |
| 大大红 | 40元店铺余额 | 1/36 | 1/144 |

这两个奖池分别将 1/16（6.25个百分点）的概率转入感谢参与；各目标格均精确降低75%，不对其他奖品权重重新归一化。积分、冠名、TAG、其他余额和再来一次维持原概率。调整只影响自然抽取，不影响30/50次额外余额保底。抽取概率不随历史中奖或累计进度变化。旧记录与旧请求重放保持原结果及审计快照。

概率和随机票仅保存在服务端审计快照中，老板页面及公开接口不展示。网页点击奖格仅查看奖项与骰子坐标。每个奖池的余额保底对应本池最高价值的两个余额档位。

| 奖池 | 每 30 次额外保底 | 每 50 次额外保底 |
| --- | ---: | ---: |
| 小红 | 5 元店铺预存 | 10 元店铺预存 |
| 大红 | 10 元店铺预存 | 20 元店铺预存 |
| 大大红 | 20 元店铺预存 | 40 元店铺预存 |

第 150、300… 次同时发放本池两档余额保底。

三个奖池分别累计；计数包含“感谢参与”和“再来一次”，失败请求、重放请求不增加计数。普通中奖不会重置累计进度。保底在骰子结果之外额外记录，因此即使骰子显示“感谢参与”，达到保底次数仍会获得对应奖励。每项保底有独立发放记录，管理员可分别核对交付。

每次抽奖消耗对应奖池一次机会，“再来一次”返还本次次数。不收费、不自动扣余额或积分。所有中奖奖品都记录为待发放，由本项目管理员兑奖；不会自动修改其他系统账户。

十连抽在一个数据库事务内完成当前奖池的 10 次独立投掷；任一步失败，整批不扣次数、不写结果、不发奖。开始前至少需要 10 次机会；每次“再来一次”仍返还机会，所以实际消耗可能少于 10 次。10 次结果分别计入本池累计抽数，跨过 30/50 次节点时照常额外生成保底奖励。结果弹窗展示整批奖项、骰子点数、实际消耗与额外保底，每一抽也会单独出现在历史中。整批使用永久去重的请求凭证，弱网重试只查询同一批结果。

全部个人历史通过独立分页接口读取，不再受最近 30 条限制。翻页固定首屏的记录编号上界，期间的新抽奖不会把既有记录挤到下一页；刷新或完成新抽奖后回到最新第一页。每个分页请求仍校验老板身份和当前房间，其他老板、其他房间的记录不返回。

所有抽奖都由服务器使用系统安全随机源生成，数据库事务同时完成次数变化、结果和奖品记录。请求凭证永久去重；弱网重试使用原凭证，不重复扣次数。MySQL 行锁防止并发超扣。每次抽取保存当时奖池版本、算法版本、初始点数随机票、定向保留及转入感谢参与的随机票（如适用）、精确的最终联合概率和结果快照；发放次数保留管理员、原因及凭证。

原海报活动为 2026-10-16 至 2026-10-25，房间起止时间由管理员设定，结束时刻不含该时刻。已有抽奖记录后，导入命令拒绝覆盖原奖项。抽奖算法升级会增加已有奖池版本，过期页面需刷新后才能发起新的抽奖。

## 本地运行

Python 3.12 或以上：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py seed_lottery
.venv\Scripts\python manage.py createsuperuser
.venv\Scripts\python manage.py runserver 127.0.0.1:18086
```

本地默认 SQLite；活动入口 `/`，后台 `/control/`，原生用户与审计后台 `/admin/`。生产环境使用 MySQL，配置变量见 `.env.example`。

```powershell
python manage.py test lottery --noinput
python manage.py makemigrations --check --dry-run
```

行锁测试在 SQLite 上跳过，部署前在隔离 MySQL 上运行全部测试。

## 部署

当前发布目录 `/opt/xa-anniversary-20261026-v7/project`，Compose 项目 `xa-anniversary`，服务名 `lottery-web`（网络别名 `anniversary-web`），使用独立 `xa_anniversary` 数据库用户，权限仅限该库。配置位于 `/etc/xa-anniversary/release.env`，权限 600，不进入源码。

复用服务器现有 HTTPS 网关，新增独立域名配置，把活动转发到独立容器：

```caddy
ann.xaesports.club {
    encode gzip
    reverse_proxy anniversary-web:8000
}
```

Django 设置 `LOTTERY_SCRIPT_NAME` 为空，静态文件由独立服务 WhiteNoise 提供。网关实际配置源是 `/opt/xa-redeploy-20261006/deploy/Caddyfile`，挂载为 `/etc/caddy/Caddyfile.core`。以后重新部署主项目网关时需保留上述独立域名转发规则。

首次部署新增独立服务、数据库及域名路由。后续增量更新只替换本活动容器，并在迁移前备份、迁移后核对原有业务记录；不更新原应用镜像，不迁移 `xa_db`，不重设管理员密码。MySQL 数据沿用服务器持久卷。当前发布验收及回滚信息保存于 `/opt/xa-anniversary-20261026-v7/verification.json`，网关安装前备份位于 `/var/backups/xa-anniversary/`。

活动下线时可暂停全部房间；需彻底停止服务时，在生产目录使用独立 Compose 配置停止 `xa-anniversary`，并恢复或移除这条网关路由。保留 MySQL 库用于记录查询，避免删除抽奖和兑奖数据。
