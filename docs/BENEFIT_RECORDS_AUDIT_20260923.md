# 收益明细与统计口径验收 · 2026-09-23

本轮核对陪玩钱包的奖惩、礼物明细，以及后台陪玩看板的统计口径。不改变抽成比例、礼物定价、退款条件或已确认的分账规则。

## 修正

- 原接口一次读取并返回全部奖惩和礼物记录。现在两类记录分别分页，默认每页 20 条、最多 100 条，返回页码与总数；数据库汇总始终覆盖全部记录。
- 礼物“实得”原先直接累加订单预计分账，可能把未入账金额计入。现在仅汇总本人钱包中关联该礼物订单的成功收益流水，排除失败、处理中及其他类型流水。
- 明细保留应得分账快照，并增加实际入账金额及状态：已入账、待入账、需联系客服核对。结算标记已存在但金额不一致时不会显示结算成功。
- 只纳入已支付且已完成的礼物。存在成员明细时，以本人分账为准；退出且零收益的成员不算作本人礼物，无成员的历史订单才回退订单头。
- 业务账号优先于旧用户关联。读取收益不创建钱包；没有旧账号映射的业务账号也能查看记录，不会把旧主体的钱包流水转计到本人。
- H5 两类明细可独立继续加载，追加时去重，刷新后的过期响应不能覆盖新数据。金额列保留独立宽度，长订单号在剩余空间内截断。

## 验证

- 新增 7 项后端场景测试，覆盖跨页汇总、全部记录可达、流水状态、退款与未支付排除、成员分账、退出成员、零收益结算、参数边界及业务账号隔离。
- SQLite 全量 925 项：914 项通过、11 项行锁测试跳过，日志 `.tools/benefits-full-tests.log`。
- 独立 MySQL 8 测试库专项 25 项全部通过，覆盖收益明细、真实打赏接口及后台看板合约；日志 `.tools/benefits-mysql-tests.log`。测试库已销毁，本地临时 MySQL 实例已停止。本轮未重跑 MySQL 全量。
- 陪玩 H5 TypeScript 检查与构建通过；构建保留 2 项既有资源体积提示。
- 浏览器专用本地账号验证：23 条礼物、23 条奖励分别从 20 条追加到全部记录；礼物实得始终为 8400 币、奖励始终为 230 币，待入账及缺流水记录不增加实得。测试分类、商品停用，不修改现有用户余额。
- 375 × 812 手机视口下复查深色模式，长订单号不再挤到金额/状态列，待入账、已入账、需核对三种状态显示完整。
- 后台看板原有口径已明确为已支付订单的预计分账，成员分账/转单归属测试通过；本轮未改变其业务口径。

## 限制与待办

- 礼物归类仍依据服务的当前分类；修改历史服务分类会影响统计归类，现有模型尚无礼物类别快照。
- 提现账户绑定的保存数量/方式仍等待用户确认；真实微信、KOOK、企微及生产部署联调仍需实际配置与环境。
