# XA 企业级数据库设计规范

最后更新：2026-07-30

适用数据库：MySQL 8.0+

ORM：Django 6

## 1. 设计目标

- 数据库负责保证不可被业务流程绕过的永久不变量。
- API、管理命令、异步任务和后台脚本共享同一套模型约束。
- 核心状态、金额、比例、评分和时间区间均有数据库级校验。
- 高频查询使用与筛选条件、排序方向一致的联合索引。
- 旧 `CustomUser` 与新 `ClubAccount` 并行迁移期间，两套关联都保持唯一性。
- 所有结构变更通过 Django migration 发布，不直接手工改生产表。

## 2. 字段与命名规范

| 类型 | 规范 |
| --- | --- |
| 主键 | 当前表沿用 Django `BigAutoField`；外部接口使用业务编号，不暴露其连续性语义 |
| 业务编号 | `order_no`、`tx_no`、`account_no`、`boss_no` 必须唯一 |
| 金额 | 一律使用整数内部账务单位；当前系统 `10` 个内部单位等于 `1` 兴安币，禁止使用浮点数 |
| 比率 | 使用整数百分比，数据库约束为 `0..100`；老板折扣率为 `1..100` |
| 时间 | Django 时区感知 `DateTimeField`，数据库统一存 UTC，展示时转换为业务时区 |
| 状态 | `TextChoices` + `CHECK` 约束，禁止写入未声明状态 |
| 快照 | 订单名称、价格、抽成、收款信息等需要审计还原的数据在业务发生时固化 |
| JSON | 仅用于弱结构展示数据；可筛选、关联、计费的数据必须拆成关系字段或子表 |
| 删除 | 交易主数据优先 `PROTECT`/`SET_NULL`；从属明细和临时关系才使用 `CASCADE` |

## 3. 核心约束

### 账户域

- `CustomUser.boss_no`、`ClubAccount.account_no` 全局唯一。
- 账户类型、用户角色、推荐分佣率由数据库校验。
- 新旧账户迁移期的业务关系同时保留：
  - 旧关联：`user` / `provider` / `customer`
  - 新关联：`account` / `provider_account` / `customer_account`
- 收藏、游戏档案、签到、月进度、优惠券、排班和订单陪玩明细均增加新账户侧唯一约束。

### 订单域

- 服务价格必须大于零，商品抽成率为空或在 `0..100`。
- 订单局数至少为一，订单状态、支付状态、陪玩模式均为受控枚举。
- 陪玩结算抽成率为 `0..100`，实得不得超过结算基数。
- 评价的综合、技术、态度、沟通评分均限制为 `1..5`。
- 订单金额拆分守恒属于流程不变量：在事务结算完成时校验，不对创建中间态添加过强表约束。

### 钱包域

- 钱包余额、累计充值和累计赠送不得为负。
- 流水类型和状态为受控枚举；金额使用有符号整数表达增减。
- 提现金额必须大于零，税率为 `0..100`，税额不得超过申请额。
- `actual_amount = amount - tax_amount` 同时由模型自动计算和数据库约束保证。
- 报单金额必须大于零，实付不得超过报单金额。
- 资金变更必须在 `transaction.atomic()` 中锁定钱包行，并同步写入不可变流水。

### 营销与运营域

- 优惠券门槛非负、面额大于零；限量券的领取数不得超过总量。
- 签到序号和礼物天数限制为 `1..31`，月份限制为 `1..12`。
- 排班限制为周一至周日、`0..1440` 分钟，且开始时间必须早于结束时间。
- 通行证结束时间必须晚于开始时间，折扣和实付金额必须守恒。

## 4. 索引策略

联合索引按“等值过滤字段 → 范围字段 → 排序字段”排列，覆盖以下核心查询：

- 订单：老板/陪玩 + 状态 + 创建时间、状态 + 自动取消时间、服务 + 创建时间。
- 流水：钱包 + 状态 + 时间、钱包 + 类型 + 状态 + 时间、订单 + 类型 + 状态。
- 提现/报单：业务账户 + 状态 + 时间、后台状态队列 + 时间。
- 消息：接收账户 + 已读状态/类型 + 时间。
- 服务：启用状态 + 排序、游戏/服务分类 + 启用状态 + 排序。
- 签到、优惠券、排班和通行证：业务账户作为首列。

不要为每个字段机械建索引。上线后应结合慢查询日志和 `EXPLAIN ANALYZE` 调整；删除索引前先确认没有外键依赖和查询回退。

## 6. 发布流程

```bash
cd services/backend
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate --plan
python manage.py migrate
python manage.py verify_business_account_relations
python manage.py test --settings=config.test_settings
```

生产发布前应完成实例级备份并验证恢复流程。对于大表新增索引，应在影子库测量锁表时间；超过可接受窗口时改用 MySQL 在线 DDL 或专用在线变更工具。

## 7. 后续演进

当前保留旧用户外键是兼容策略，不是最终形态。待所有调用方切换到
`ClubAccount` 且完成持续数据对账后，再分阶段执行：

1. 将新账户外键补齐为非空；
2. 停止双写并移除旧账户查询回退；
3. 将交易历史中的旧账户外键改为 `SET_NULL` 或归档快照；
4. 删除旧账户侧重复唯一约束与字段；
5. 对订单、流水和审计日志按时间评估分区与冷热归档。
