# VIP 新等级及重启的重算边界（2026-11-13）

门店后台新增启用等级、重新启用等级以及停用后恢复 VIP，继续使用现有预览令牌、钱包/配置锁、会员重算、既有权益保护和升级权益补发或延期流程（须 `VIP_THRESHOLD_RECALC_ENABLED` 和权益保护实际可用）。停用期间的等级变更由该流程记录延期基线；没有足够依据时沿用既有人工核对规则。

该开关默认关闭且尚需联调，不能静默保存需要重算的上述变更。首版门店初始化中，持老板配额锁并以锁定读确认本店没有任何老板账号（含退店账号）时允许创建/启用等级或启用 VIP；其他情况返回明确错误等待重算能力可用。并发老板注册使用同一配额锁；配额控制关闭时不使用空店例外。未启用等级的草稿可继续保存，开关和已有权益均未自动改变。平台初始化入口沿用现有同类空店及重算规则。

未运行测试或迁移。最终需以隔离数据库联调并发新老板注册、初始化、启用 VIP、门槛变更、停用期间延期及恢复、License ALLOW/DENY/UNKNOWN、升级权益幂等及已有券保留；开关关闭时有老板的等级结构变更仍不可办理，并非功能已完整交付。

平台新店 VIP 开关处理模块原来在停用基线审计中重复指定 `status_code`，导致模块无法导入、平台开关入口报错；已移除重复参数，保留原操作者、请求、停用基线及状态审计字段。修正不改变开关默认状态或声明流程已完成联调。

## 停用基线补全

门店及平台初始化真实停用 VIP 时，同事务保存停用前的等级、门槛、启用状态等既有重算基线，并在审计中记录当时等级权益配置；重复停用不会覆盖基线。平台在有老板时仍按既有可用保护流程冻结已发券条款。停用前权益配置审计是核对证据，不能代替已发权益流水，也不会用于推测历史发放。

重算开关仍关闭时，有老板的恢复继续明确受限；启用该能力后通过已有预览、原周期流水和 License 判断重算。首店配置在持老板配额锁且确认无任何老板后可以恢复，仅关闭相应延期周期，不发券、不改已有流水。缺少对应数据库结构会使停用事务失败，不能视为基线已保存；首版结构迁移及最终联调仍未执行。

## 在籍业务周期

重算预览和执行只纳入 `license_membership_active=True` 的本店老板；停用或封禁但未退店者仍参与。真实退店已推进业务周期，不能因零门槛或新等级将权益发给尚未重新入店的新周期。等级变更与恢复时对变动账号加锁复核在籍状态和业务周期；重新入店后的新周期按正常确认实销及已有权益事实参与重算。既有已发权益不因本修正被删除。

当前仍未打开重算总开关。实际升级发券、延期恢复及不同授权状态的事务联调尚未完成；本次修复了未来启用真实重算时的可达退店错发问题，不表示已有老板门店在默认开关下已能办理重算。

## 结构重算的累计权益

新增等级、调整门槛和停用后恢复的事务，向新达等级发放专属权益后，按最终生效等级复用正常升级的累计权益规则，纳入较低等级配置和首版六级模板的目标配额；幂等键、原业务周期、License 校验及既有人工核对屏障继续生效。既有券仍按原流程先冻结条款；未经授权或不可核验时不能假称补发成功。

人工核对入口的累计补发已在后续“人工核对累计权益”中接入，按人工确认等级限制范围。总开关仍未打开；实际资金、等级、旧券、License、延期恢复及重复提交需要最终隔离联调。

## 人工核对累计权益

后台 `vip-upgrade-reviews/<id>/resolve` 选择补发时，在原钱包和门店配置锁后锁定老板账号及所有相关等级、奖励和 VIP 券，再核对审核记录、在籍状态、原业务周期和 License；以本次确认的等级为上限复用累计权益规则，其他待核对记录仍按原屏障处理。已有交付记录的规格和已发券条款保持不变，重复相同核对请求沿用原结果。确认已发只留审核事实，不补发。

默认重算开关仍未打开；未执行测试或迁移。需最终联调多条不同等级待核对、退款与跨周期、并发退店、授权到期/不可核验、旧券与已发交付规格、重复提交及锁顺序。
