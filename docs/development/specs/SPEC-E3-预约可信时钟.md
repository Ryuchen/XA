# SPEC-E3 预约可信时钟与决策恢复

2026-11-25 当前执行切片。依据功能排期第 15 项、开发 28 E3、D81/D89/D90/D91，以及根指南的租户、幂等和事实留痕规则。

## 完成定义

- 单人及双陪预约的确认、拒绝、补位、报价、付款前复核与到期扫描，生产环境均从本店 MySQL 获取带连接身份的 UTC 时间；SQLite 只在显式测试配置下作为可控替身。
- 锁等待、数据库断连、上界回执丢失、时钟倒退、连接变化和提交跨截止均不能猜成成功。PENDING 返回暂不可用，REVIEW 返回冲突并阻断后续报价、扣款、改派和确认。
- 每个决策保存原截止、动作、席位、操作者、前后状态、单调时钟与数据库时间证据。相同 `decision_key` 只能重放同一内容；异内容冲突。
- 跨截止或结果未知只补偿本次未确定动作，不改资金事实，不删除证据；到期扫描的单候选失败不阻断其他候选。
- 老板与陪玩页面在原意图未确定时保留原键，区分成功、到期、待核和未知。

## 非目标

不改变预约价格、确认时限、补位资格、转单次数、退款或结算规则；不开放新资金组合；不将 SQLite 结果写成 MySQL 或五入口验收。

## 验证

聚焦预约 API、单双陪、补位、到期、断连、重放、跨截止与双店隔离测试；Django 检查和迁移一致性；Boss/Provider 契约测试、类型检查与构建。真实 MySQL 锁等待、登记五入口和浏览器操作另留联调记录。

## 回退

按切片反向提交应用代码和前端接线；已提交回执及业务记录保留，不能删除或重写历史。
