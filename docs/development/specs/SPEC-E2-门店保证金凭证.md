# SPEC-E2 门店保证金收退凭证与保障公示

2026-11-25 当前执行切片。依据功能排期第 07 项、开发 28 E2、PRD 39 SA02 已批准项及 PRD 40 的信任保障要求。

## 完成定义

- 平台按门店合同配置保证金应收金额，人民币金额统一使用分；不得硬编码门店金额。
- 缴纳与退还只登记已核对的线下凭证，不发起真实付款，不把接口受理当作银行或支付渠道成功。
- 每笔事件保存门店、方向、金额、业务键、安全凭证引用或摘要、操作者和时间；相同 `client_request_id` 仅重放相同内容，异内容冲突。
- 已收净额不超过应收，退还不超过已收净额；凭证或金额事实不完整时保持待核，不能显示零额或已保障。
- 历史收退事件不可修改或删除，差错通过补偿事件处理；平台写入需独立授权和审计，审计失败不得留下半笔业务事实。
- 老板端只读本店保障状态，不暴露内部备注、操作者、完整银行资料、凭证细节或其他门店信息。

## 非目标

本切片不实现闭店 30 天公示、停止新增、逐户钱包或尊享卡余额返还、真实银行收付及资金监管账户；不得用保证金登记替代上述流程。

## 验证

聚焦权限、双店同数字 ID、金额上下限、收退守恒、重放与冲突、历史不可变、审计失败回滚、公开状态及脱敏；必要 stores 相邻回归、Django 检查和迁移一致性。真实线下收退、MySQL 并发和浏览器公示另行联调。

## 回退

应用代码可反向提交；已提交收退事件和审计保留，通过补偿事件纠错，禁止删除或改写历史。
