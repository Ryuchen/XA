# SPEC-E2 闭店公示与新增业务守卫

2026-11-25 当前执行切片。依据功能排期第 07 项、PRD 39 SA02、PRD 40 信任保障及 PRD 37 §3.4。

## 完成定义

- 独立授权平台角色可发起本店闭店公示，保存申请人、原因类别、可信控制库时点、30 天政策版本、最早结清时点、请求号和内容摘要。
- 同号同内容恢复原记录，异内容冲突；重复申请不得重置倒计时。历史启动和到期事件不可改删，审计失败不得留下半笔状态。
- 到期前不能确认结清资格，恰好 30 天进入 `SETTLEMENT_PENDING`；到期不自动停用门店，也不等于已退款或已完成最终结清。
- 公开公告按本店域名返回，未公示、公示中、待结清和待核状态明确区分；不得暴露内部原因、操作者、请求号、时钟身份或金额。
- 公示中与待结清阻止新服务单、礼物单和新预约；守卫不得放入通用状态机，已有预约成单、订单履约、售后、退款、提现与读取保持原流程。
- 老板端只读展示公告，平台端按权限发起和确认；未知结果沿原请求号恢复，门店切换清理旧快照。

## 非目标

本切片不实现逐户钱包或尊享卡余额返还、闭店手续费、真实线下退款、最终结清/停用，也不宣称充值、开卡、账号等全部新增入口已接守卫。未获明确批准的撤回与自动闭店不开放。

## 验证

覆盖权限、双店同数字 ID、30 天边界、时钟失败/回退、幂等与冲突、不可变、审计回滚、公开脱敏、每个新单入口和已有业务继续；前端契约、类型和构建。真实控制 MySQL、Worker、双店浏览器与全入口联调另留记录。

## 回退

反向提交应用及页面接线；已提交公示和事件保留，通过后续授权处置纠错，不删除或重写历史。
