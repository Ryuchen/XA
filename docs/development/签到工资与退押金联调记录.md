# 签到、工资与退押金：待最终联调

## 本轮规则和代码

- 签到消费按照店内实际付款日统计，预约创建日不影响归属；服务、礼物和加购的店币实付纳入，已退店币从原付款日消费扣减。加购以 `OrderAddonPayment.paid_at` 判断付款日，并继续校验对应成功扣款流水；跨午夜时不以稍后写入流水的时间改归属。查询显式排除加购付款流水，避免重复计入。
- 参考 [Saleor 支付模型](https://github.com/saleor/saleor/blob/main/saleor/payment/models.py) 区分支付事件及其成功状态；本项目的日期仍使用自己的加购付款快照和钱包流水，不引入外部支付实现。
- 签到发奖在获取当月进度锁后重新检查门店 License，按实际发奖时状态区分授权拒绝和无法核验；已有补签卡仍可使用。门店尚无授权时仍可先完成配置。
- 加购实销发积分在等待会员资料锁后重新读取业务周期、会员和积分开关，并按实销时的 License 状态记录发放决定；授权未知时保留待核对事实，不伪造发放结果。已确认实销的重放与既有权益不变。
- 已确认工资后发生的绩效退款调整，在下一期最多扣至工资为零，未扣部分记为放弃，不结转；提成欠扣仍按既有独立规则结转。退款工资核算目前受 `PAYROLL_REFUND_ACCOUNTING_ENABLED` 和事件屏障等配置限制，不能把代码存在视为已启用或验收完成。
- 陪玩退押金结清检查区分已经核对过的加购入账流水与主单收益，避免相同金额被误认为重复主单收入；主单、加购和平台补贴均将实际记账时间纳入结清时间，等待期从相关业务实际全部结清后计算。普通逐段订单优先读取本人已经核对的分段结算凭证，不再仅依赖旧陪玩分配行的结算时间。安全箱补贴继续走既有补贴凭证，不能为了查询资格倒序锁定订单。
- 如果陪玩已有业务先结清，之后才缴清现金押金，七天从押金缴清与业务结清中较晚的时点起算；后缴押金须能对应本人当前周期的实际缴纳记录和资金流水，无法核实时返回待核对。

## 最终联调重点

- 昨日创建预约、今日付款，以及今日加购：当日消费各计一次；核对跨日退款、积分抵扣、礼物、本店账号与跨店隔离，已发签到奖励不追回。
- 已确认工资后退款，下一期绩效应扣 150 元、工资 100 元时，实际扣 100 元并记录放弃 50 元；后续工资不再扣该绩效差额，提成不足仍单独结转。
- 主单与加购收益金额相同、交易晚于结算业务时间、平台补贴、分段转单、未结售后和收益冻结等情况，验证退押金等待期与实际流水。核对事务回滚、重试和 MySQL 并发。
- 已结清业务之后补缴押金、以及押金缴清之后又产生业务的两种时间顺序，均按较晚的实际结清时点起算七天；覆盖分次补缴、押金周期、流水不完整和门店隔离。

普通补资订单及积分订单的个人结算可能只写入独立结算凭证，不修改旧分配行的结算时间。无本人受影响的主单退款和服务中转单时，退押金检查读取该个人凭证、报单和实际流水，而不是一直显示待结算；积分订单分别按抵扣前成交基数与抵扣后付款基数核对收益快照。普通及积分订单均读取服务前改派后的实际席位。

积分订单退款后的陪玩保留收益可能与原分配行预计收益不同。无服务中转单且有一至两次主单积分协商退款时，退押金检查按本人受影响的已确认方案、退款资产、个人承担、报单和实际结算流水判断，不再以原预计收益匹配；第二次退款的店币与积分构成按前次实际退款重算，查询不倒序获取订单行锁。支持读取服务前改派席位；服务中转单及其他复杂组合仍待接入，不能视为完整支持。

积分协商退款只影响另一位陪玩时，系统读取双方确认与实际退回的店币和积分，按本人此前已结算的凭证和业务结清时间判断，不因另一人的退款重置本人等待期。当前支持无服务中转单的一次或两次主单退款；该读取路径尚待最终联调。

普通服务订单在无转单、仅有首次协商退款且没有加购退款扣减主单收益时，退押金检查也读取受影响陪玩的实际保留收益、个人承担、已审核报单和结算流水。对实际不受其他人协商退款影响的陪玩，独立结算凭证仍可使用，退款不会仅因另一人售后而使其旧收益失效；其他复杂退款及转单组合仍需继续接入。

普通订单协商退款的售后等待按实际终止时点区分：服务中双方确认终止，从确认时起算；服务已经完成后才协商退款，沿用订单完成时开始的等待期。报单冻结仍从本人最后一次有效提交开始，两段重叠，且收益须等适用售后处理完成及整单完成后才能结算。

本轮未执行测试、数据库迁移或部署，不能据此认为链路已验收。
