# VIP 等级和门槛的实际重算

本店后台等级新增、消费门槛修改、等级重新启用和停用分别使用既有预览令牌与保存接口；角色权限仍为 `engagement:edit`。可用的首版规则下，事务先锁老板配额、各老板钱包及本店会员配置，再复核等级、已确认净消费和权益事实。新增或修改在同一事务按全部在籍老板重算等级；新达等级的权益由原发放服务按本店配置、License 和幂等事实处理，旧权益条款不改写。等级停用也按全部在籍老板计算，预览返回影响、升级、降级数量；变更前固化并锁定降级者原有私有券。失败时配置、等级和发放一起回滚。

VIP 停用期间的结构变更仍仅写配置及延期事实，重新启用时按停用基线重算。平台首次开业配置中有老板时复用同一等级流程。不存在已登记月券切换时，首版直接按等级保存的月券数量、折扣和安全箱折扣执行；每月唯一发放决定保留已发数量，月中升级原券不变，锁定券不随新等级变动。已登记切换但规则不可用时仍要求核对。后台会员配置状态字段反映当前能力，不改环境总开关。

普通无切换月券路径现记录实际发放决定（包括零数量），不根据固定等级表重新生成。当前按首版空库开发，未对旧线上数据做迁移。未运行测试或迁移；最终须在隔离库联调新增/停用/门槛调整的并发付款、售后、账号入退店、License 变化和消息回滚。
