# 停售通行证时的无卡可见延迟

通行证停售只停止新购；无卡陪玩的订单可见延迟仍实际参与抢单。门店通过 `GET/PUT /api/admin/config/provider-pass/no-pass-delay` 读取或保存 0 至 86400 秒的整数，保存时复用通行证配置锁，要求无卡延迟不短于各档通行证当前延迟，并记录本店操作审计。未保存时读取仍会标明 `configured=false`，不能把默认值当成已确认配置。

首位本店管理员按 `escort:edit` 保存后，以 `GET/POST /api/admin/dictionaries/setup-confirmation/no_pass_delay` 核对实际快照；平台超级管理员也可在初始化配置快照读取并用已有确认接口提交 `no_pass_delay`。首次开业在通行证停售时仍要求已保存并确认无卡延迟，不要求开启通行证或填写四档价格；通行证销售开启时仍核对完整档位和延迟。业务继续从已有 `get_pass_delay_seconds` 读取同一门店配置，不改变已购通行证、派单计算或历史订单快照。

参考 [NestJS 队列延时和优先级](https://github.com/nestjs/docs.nestjs.com/blob/master/content/application/queues.md) 区分延时与优先级；本项目的无卡与通行证排序、单位和规则均依照本项目 PRD，未采用其队列模型。

本次未执行测试或迁移，仅解析 Python 语法。隔离环境需要验证两店配置隔离、修改与确认并发、停售下开业、无卡及已购通行证抢单的真实可见时间；此记录不是完整业务验收。
