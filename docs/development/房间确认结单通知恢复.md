# 房间确认结单通知恢复

房间结单经客服核实后，由老板确认或到期自动确认时，若同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `ROOM_CONFIRMATION_NOTICE_RECOVERY_ENABLED`，在原结单事务中按实际确认记录和参与人名单固定通知意图。实际确认名单中的陪玩与订单老板分别收到结单消息；自动确认及老板主动确认各使用对应文案。

提交后逐人创建站内消息，失败由逐店任务恢复；每个确认事实及收件账号最多创建一条。投递重新核对已核实的申请、实际确认方式、完成状态及订单日志，陪玩使用原履约席位／分段周期，老板使用原订单周期；来源无法证明、账号离店或重入时记录跳过。消息失败不回滚已提交的结单或资金处理；创建站内消息不等于客户端收到实时刷新。开关关闭沿用原周期保护的即时消息路径。

启用前须各店应用 `site_messages/0024_roomconfirmationnotice` 及依赖，并运行逐店 worker/beat。最终联调须覆盖老板主动确认和超时自动确认时双方通知、单双陪及转单、等待异议和状态变化、并发重复确认、资金结算与事务回滚、单人通知失败恢复、账号停用及重入、双店同号。其他结单审核和订单实时事件仍未覆盖；客服安排新单继续进入抢单池，正式注销保持关闭。本轮未运行检查、测试或迁移。
