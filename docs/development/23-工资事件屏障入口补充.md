# 工资事件屏障入口补充

启用 `PAYROLL_EVENT_BARRIER_INTEGRATION_ENABLED` 时，抢单待核对的后台取消动作在最外层事务先获取本店工资事件共享锁，再锁订单、资金和退款来源。普通店币与积分原路退款均沿用原有资金校验；恢复抢单动作不产生退款，不增加此锁。该变更使取消退款与工资确认按既有屏障串行化，退款发生月及已确认工资调整仍由原工资核算处理。

单笔赠礼和礼物篮的真实扣款也在外层业务锁之前获取同一屏障；礼物篮逐项调用单笔流程时在同一事务中复用该锁。现有工资绩效事件明确排除礼物，新增屏障不会将礼物计入工资业绩；礼物成本仍按现有 ROI 事实核算。

普通转单后追加协商的执行入口在订单和资金锁前取得共享屏障，再按原事务写入退款及结案；退款记账仍按原 `OrderRefund` 发生时间进入工资事件，重试沿用原请求凭据。普通协商、带加购追加协商及积分追加协商分别已有独立入口屏障，本次未修改其资金逻辑。

后续按实际写入调用栈复核：老板下单、预约付款、客服代单及充值、加购付款／退款分别在业务锁前接入屏障；后台直接退款、老板取消、抢单仲裁取消、超时任务以及普通／积分协商结案的现有写入口亦有对应屏障。预约及已指派积分取消复用后台退款事务，积分售后通过订单能力上下文或结案入口取得屏障。检查范围以当前源码为准，未执行并发验证。

微信直付付款及退款属于未对外开放的测试域，工资事件查询明确排除 `direct_payment` 订单，不能视为已完成正式工资记账；开放前须接入可信渠道证据、发生月事件和相同锁序。旧版协商退款和安全箱旧版终止接口的资金执行目前分别被预览的不可执行条件阻断；若将来重开，须先在最外层接屏障并核对现行确认规则。本轮未对这些不可达或测试域路径声称生产接通。

普通下单、预约、加购付款、协商退款、超时及自动抢单取消已有各自入口接线；其全部组合、其他写入口与相应锁序尚需最终联调逐项验证，不凭本次局部修改宣称覆盖所有资金事件。本轮未运行测试或迁移；最终联调需覆盖 MySQL 下工资确认与普通转单追加退款并发及重试、跨月退款、后台取消竞争、积分／店币来源、赠礼及礼物篮失败回滚、门店隔离与配置关闭场景。
