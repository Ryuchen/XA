# 工资普通退款流水直接关联

普通订单退款事务现在将实际退回老板钱包的流水直接关联到本笔 `OrderRefund`。工资核验优先读取该关联，并继续核对订单、原付款钱包、金额、余额、操作人、发生月份和与积分／协商退款凭证的一致性。这样，同一订单由同一操作人执行多笔同金额普通退款时，每笔都可独立进入退款发生月绩效以及已确认工资的下一期提成扣回；原工资快照不改写，提成不足继续结转，绩效不足按既有规则处理。

付款、退款和工资确认仍依赖门店工资事件屏障及相关核算开关，必须在正式启用前完成全入口锁序和并发联调。没有直接关联的其他退款来源仍使用原有积分／协商凭证或可唯一核验的流水；无法唯一证明的事实继续要求核对，不推测对应关系。本次创建 `orders/0263_orderrefund_customer_transaction` 结构迁移，未执行迁移或测试，也未回填既有数据库。

最终需在隔离环境验证同额多次普通退款跨月及发生月已确认两种时序、工资确认与退款并发、逐笔绩效和提成、工资不足及结转、重试回滚、积分与协商退款和双店隔离。
