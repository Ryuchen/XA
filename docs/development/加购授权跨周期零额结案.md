# 加购未知授权跨业务周期结案

老板的加购会员或积分授权在原实销时为 UNKNOWN，平台超级管理员后来依据原时点资料核对为 ALLOW 或 DENY 时，如果老板已进入更晚的本店业务周期，不能将旧周期权益发给新周期。服务端先按既有钱包、账号锁顺序复核当前周期，并要求存在该老板原周期的退店审计；再核验原加购付款流水、付款来源、会员开关、授权未知依据、实销前退款及积分基线。事实完整时记录原结论和核对依据，但零积分、零会员成长，结果标记 `CYCLE_CLOSED`；同一请求幂等并沿用平台跨库审计恢复。

本分支不推测退店后的退款净额；未发放时记录中的退款基线是原实销时基线，不表示审核时的退款余额。若周期倒退、缺少退店事实、原付款或实销来源无法证明，继续待核对。同一业务周期仍可能发放的 ALLOW 请求继续严格核对全部当前退款来源及净额，不借此分支跳过账务证明。已发权益、付款和退款流水不修改。

参考 [Ledger 账户生命周期实现](https://github.com/ledger/ledger/blob/main/src/account.cc) 将账户状态作为独立核对事实；本项目退店、周期和授权规则以自身数据与 PRD 为准。

按开发期要求未运行测试或迁移，仅完成 Python 语法解析。隔离环境仍须验证退店与核对并发、原周期审计缺失、跨店、后续退款来源异常及平台审计恢复；此变更不代表真实资金链或全部权益场景验收完成。
