# 员工今日派单原价口径

后台员工列表的 `today_dispatch_amount` 使用门店本地时间：主服务以可证明的客服派单工作日归属，加购以真实付款日归属于该单经确认的同一客服。金额使用系统内部钱包单位，与原接口单位相同；主单按优惠前原价、加购按付款价计算，不使用薪资的优惠后店币实付口径。部分退款按老板实际退款等值冲减，积分部分计算等值；主单全退时原价清零，加购各自独立计算退款。

实际工作来源仅接受现有客服代派单或客服指派日志；老板创建、陪玩抢单、系统分配等不能推测成客服派单。存在已人工核实的派单工资业绩时，其员工与实际工作时间须能对应一条客服工作日志；未核实业绩时，多个可证明工作日志须指向同一客服。归属冲突、未知原价、支付或退款凭证不足时，涉及员工的 `today_dispatch_amount` 为 `null`，`today_dispatch_review_count` 返回待核对订单数量，不把未知金额当零。无已付款有效来源且无待核对项时返回 0。

本轮按已付款订单统计，未付款的正常订单不作为已完成的派单金额；若未付款状态却存在付款流水则待核对。实际支付、积分返还及加购退款复用现有凭证核验；无法证明的历史截点或不支持的来源留待核对。加购和主单互不抵扣。接口保留原字段，同时新增待核对数量；未修改薪资实付计算或任何资金执行。

最终应在隔离门店验证客服代单、客服实际指派、老板自行下单及系统抢单、人工归属冲突、跨日派单与加购、活动优惠、积分部分／全部退款、同一单多加购、多笔退款和双店隔离。当前未运行测试或迁移，尚未完成三端联调。

加购日期取付款事实的 `OrderAddonPayment.paid_at`，并核验同事务成功扣款流水；付款记录与流水跨午夜时按付款日归属，不按流水创建日归属。当前加购仅支持原价付款，未来引入折扣时须先持久化并核验独立原价，再接入该统计。现有直付试运行和赠礼订单不纳入此指标；无可证明派单客服的订单不可推测归属。上线前仍须针对跨午夜与退款并发完成隔离联调。
