# 转单退款后的会员授权核对

正式资金模型中，转单主单已通过逐段实销结算且实销前有退款时，原处理会保存当时的 VIP 授权决定；UNKNOWN 由平台超级管理员通过现有 `license-vip-review` 接口核对，DENY 不作为 UNKNOWN 重试或因续期自动计成长。主单消费积分和加购使用各自原决定，核对会员后仍须按原积分入口及本金快照处理，避免重复发放。

此前若 UNKNOWN 决定后又发生合法退款，核对会要求当前累计退款等于实销时快照，无法办理。现在仅对已核实的正式资金转单：检查实销时前已提交退款的金额与原快照一致，当前累计退款不得小于原快照且不能超过原付款；继续核验逐段结算清单、每轮协商退款、钱包付款和资金来源，并以当前实际净额判断是否可恢复成长。原时点事实、已付款及已获权益不改；全额退款不恢复成长。非转单分支的原有核对范围不扩大。

这些规则只消费现有订单和资金证据，不新增退款或转单能力。默认付款 `funding_terms` 为空的转单仍缺少可复用的正式分段资金证明；证据不完整、后续轮次或结算凭证无法通过时继续待核对，不能猜测原授权或本金。参考 [Ledger Core 对退款和历史凭证的处理](https://github.com/PacemakerX/ledger-core) 保留原交易并累计核对退款，具体逐段凭证按本项目规则执行。

本次未运行测试或迁移，仅完成 Python 语法解析。需在隔离环境最终验证实销前后退款与实销并发、授权 UNKNOWN/DENY、控制库断连、双店隔离、全退、平台审计补记及积分不重复；不代表所有转单退款组合或正式资金链已验收。
