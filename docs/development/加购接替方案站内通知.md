# 加购接替方案站内通知

真实加购接替方案创建时，在同店事务中为老板、原陪玩与接替陪玩分别保存通知意图；老板周期来自订单，两位陪玩周期来自各自履约段。提交后立即尝试创建站内消息；异常保留 PENDING，逐店恢复由 `ADDON_HANDOVER_PROPOSAL_NOTICE_RECOVERY_ENABLED` 控制，默认关闭。

投递前核对真实付款、三方决定、当前加购责任和接替目标；原周期缺失或责任事实无法证明时进入 REVIEW，账号周期改变、订单已不在服务中、本人已决定或方案结束时不再发送过时提示。决定、替换及实际退款导致方案失效时，已发提示原位更新。若本人已经收到待确认消息，既有结果通知不重复创建；未收到的人仍沿用既有结果通知及其恢复开关。站内消息不代表短信、微信或 WebSocket 刷新已送达。

首次部署依赖 `site_messages/0048_addonhandoverproposalnotice` 及前置 0047。开发期未运行测试或迁移；真实支付、各方分时确认、退款失效、双店隔离、失败恢复及 MySQL 锁序须最终隔离联调。
