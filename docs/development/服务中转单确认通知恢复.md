# 服务中转单确认通知恢复

具有原价履约段和真实 `OrderOriginalShareTransfer` 的服务中转单，在接替陪玩本人通过转入入口确认入队时，若同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 与默认关闭的 `SERVICE_TRANSFER_NOTICE_RECOVERY_ENABLED`，在原入队事务中为老板、原陪玩和接替陪玩各保存通知意图。老板使用原订单周期，陪玩分别使用转出及转入履约段保存的原周期；分配或转单登记本身不会冒称接替人已确认入队。

提交后独立投递，失败由逐店任务重试；每次转单对每个收件账号最多创建一条。投递核对真实转单、前后履约段、同一席位及本人实际入队事实；账号离店重入、原周期缺失或来源不明时记录跳过。通知只描述该次入队事实，并引导查看订单当前安排，不表示收益到账。发送失败不回滚转单、入队或资金事实；站内消息创建不代表客户端已收到。关闭开关沿用原仅刷新订单的路径。

独立 work-stint 转入路径尚无可直接证明前后账号原周期的持久快照，本次未推断或覆盖；服务前改派、转单待确认提醒及其他转单结果不在本链范围。启用前须在各店应用 `site_messages/0035_servicetransfernotice` 及依赖，并运行逐店 worker/beat。最终联调覆盖单双陪、多次转单、转入确认及重放、历史参与人、状态后续变化、消息部分失败和并发恢复、账号停用/重入、双店同号、事务回滚及未覆盖路径。既有转单和资金门禁不变，正式注销保持关闭；本轮未运行检查、测试或迁移。
