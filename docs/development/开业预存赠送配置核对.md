# 开业前预存赠送配置核对

预存本金可以不设赠送档位。首次开业检查仅在本店存在启用中的预存赠送档位时，要求档位经现有金额校验并对当前配置快照完成确认；没有启用档位时明确显示未启用赠送，不阻断开业。新增、停用或修改档位会改变确认指纹，启用中的配置须重新核对。开业本身不发放赠送、不修改已产生的充值或权益。

平台超级管理员可通过现有 `PUT /api/admin/platform/store-management/{id}/setup/membership/recharge-package` 保存档位，读取 `GET /api/admin/platform/store-management/{id}/setup` 中会员配置和预存档位核对快照，再通过 `POST /api/admin/platform/store-management/{id}/setup/confirm/recharge_packages` 提交快照指纹。开业核验从本店业务库读取同一份配置及确认记录。首位门店超级管理员也可按已有业务权限使用本店档位和确认接口；营业后有权限的门店人员继续使用已有档位接口读取与维护。平台配置读取新增预存档位对应权限上下文，避免平台核对结果被错误显示为无权限。

参考 [Saleor 结账错误分类](https://github.com/saleor/saleor/blob/main/saleor/checkout/error_codes.py) 中对未发布及不可购买状态的区分；本店是否启用赠送以及金额、确认和保护规则依据本项目 PRD 与现有业务实现，不套用其商品模型。

按开发期约束未运行测试或迁移，仅解析修改文件的 Python 语法。后续需在隔离环境验证未启用／已启用／变更后未确认、平台及本店权限、并发保存与开业，以及营业后读取和实际充值快照。本项不代表完整开业流程或资金链路已验收。
