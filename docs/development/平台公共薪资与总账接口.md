# 平台公共薪资与总账接口

本切片仅处理平台财务作为平台公共人员的人民币薪资成本；它不向门店库写入工资，不表示已实际付款。只有获得全门店授权的平台财务或平台超级管理员可访问，单店授权财务和店内身份不可访问。工资对象必须具有全门店平台财务授权记录；停用账号不会自动清除既有工资。

平台薪资付款、调整和补发列表，以及门店薪资业绩来源，不再静默截断前 200／300 条；服务端按原稳定顺序分批读取并返回完整结果。现有接口仍一次返回完整数组，内存和响应体随记录量增长，最终联调须覆盖大量数据、权限及跨店隔离。

每月先由授权人员通过 `PUT /api/admin/platform/salaries/roster` 提交 `month`（`YYYY-MM`）、`account_ids`（平台账号 UUID 数组）和 `scope_confirmed: true`，明确确认本月全部应发名单。名单、确认人及时间写入平台审计；当月名单必须覆盖当前有效的全门店平台财务。历史月份不按今天的角色自动推断，由操作人确认该月范围；没有名单时不能视作无人。

`GET /api/admin/platform/salaries?month=YYYY-MM` 返回名单、尚未配置方案和尚未确认的人员；`PUT /api/admin/platform/salaries/{account_id}` 提交 `month`、`base_fen`、`performance_fen`，金额为非负整数人民币分。`POST /api/admin/platform/salaries/{account_id}/confirm` 确认该人员本月金额并保存不可回写快照；重复提交返回既有结果。`POST /api/admin/platform/salaries/close` 提交 `month`、相同的 `account_ids` 和 `roster_confirmed: true`，名单内所有人必须先配置并确认。关账后名单和工资快照不能修改。

`GET /api/admin/platform/ledger?month=YYYY-MM` 分别读取每店真实经营核算，并将平台公共工资只计入平台一次。任何已登记门店未初始化、不可用、该店 ROI 不完整，或本月公共薪资名单／确认／关账不完整时，`complete` 为 false，`profit_fen`、`total_cost_fen` 和 `roi` 为 null；各店状态及工资缺项单独返回，不把未知值当作零。结果是分库读取时点的聚合，不是跨库原子快照。

关账后核实须调整时，`POST /api/admin/platform/salary-adjustments` 提交唯一 `request_id`、`account_id`、已关账的 `original_month`、`kind`（`CREDIT` 补发／`DEBIT` 扣减）、正整数 `amount_fen`、`reason` 和 `deduction_source`。补发来源填空字符串；扣减须明确填写 `REFUND_COMMISSION`（退款提成）或 `OTHER`（其他），不能凭备注猜测来源。同请求重试返回原结果，参数不一致拒绝；调整进入下一个该人员尚未确认、尚未关账的适用月，关联原快照并记录审计。该月工资先计补发再扣减，最低为零；尚未扣完的余额继续结转，冲减应用记录可追溯。每月工资确认快照包含增项、扣项与 `net_fen`，平台总账按净工资计入一次。`GET /api/admin/platform/salary-adjustments` 查询调整与尚未应用余额。

`POST /api/admin/platform/salary-payments` 接收唯一 `request_id`、`account_id`、已确认关账的工资 `month`、正整数人民币分 `amount_fen`、线下付款凭证 `reference`、`paid_on` 和 `payment_confirmed: true`。可分次登记，不得超出应付净额，凭证不能重复登记；零元工资无需登记付款。该接口只由授权人员登记人工核实的线下付款事实，不连接支付渠道。`GET` 同路径查看记录。

`GET /api/admin/platform/salaries/{account_id}/separation` 预核对已记录的月份、未付款工资和剩余调整。`POST` 同路径提交唯一 `request_id`、`ended_on`、`reason` 和 `scope_confirmed: true`，须由操作人明确确认全部工资核对范围；账号需先由有权限的人员停用，所有已登记的应付工资已关账且已人工登记全额支付，所有补发及其他来源扣减已处理完。满足条件后才生成离职结清记录，并逐笔核销未扣完的退款提成。工资快照、已扣金额和核销明细均保留；重复相同请求返回原结果。

离职结清后发现应补发工资，`POST /api/admin/platform/salary-supplements` 接收唯一 `request_id`、离职人员 `account_id`、可为空的 `original_month`、唯一核对依据编号 `basis_reference`、`reason` 和正整数人民币分 `amount_fen`。填写原月份时须能关联该人员的原工资快照；没有原快照时须据独立依据编号登记。登记后补发先处于待支付状态，作为单独平台成本计入当前第一个未关账月份，不修改原工资、离职结清或已核销退款提成。重试同请求返回原记录；同一依据不能重复登记。`GET` 同路径查询。

`POST /api/admin/platform/salary-supplements/{supplement_id}/payments` 由授权人员登记人工核验的线下补发付款，字段为唯一 `request_id`、正整数 `amount_fen`、`reference`、`paid_on` 和 `payment_confirmed: true`；可分次，不得超付，付款凭证不得与普通工资付款重复。`GET` 同路径查询。接口不调用支付渠道，不因登记补发自动标记付款。

系统只能核对已录入的名单、工资、补发依据和人工登记的付款事实，无法自动发现未登记工资、外部漏付或用不同依据编号重复申报同一事项。账号停用本身不表示离职或已付款，也不因账号重新启用推断重新雇佣。平台角色跨库操作门店薪资以其独立接口和实现状态为准，不能以公共工资快照代替。
