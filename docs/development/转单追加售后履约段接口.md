# 转单追加售后履约段接口

普通服务订单发生转单且已有已确认的协商后，老板提交售后或客服登记协商售后时，可在原有 `affected_provider_account_ids` 之外传入 `affected_segment_ids`，值为本单受影响履约段 ID 数组。客户端应从订单的本人履约段信息取得 ID，不自行构造。

每位受影响陪玩仅有一个可处理履约段时，允许省略 `affected_segment_ids`，服务端自动确定；存在多个可处理段时必须显式选择。已在先前协商确认终止的段不能再次选择，同一陪玩后来转回形成的新段可独立选择。段和陪玩必须属于同一订单及本门店；不同请求不能复用同一操作凭证。

售后记录和每版协商方案均返回 `affected_segment_ids`。老板和授权客服可查看方案中的完整范围，陪玩只查看属于自己的段。双方确认与执行按该版段范围及收益、付款来源快照核验；历史方案及原已结算段保持不变。退款与收益金额沿用订单接口现有的最小记账单位。

老板读取已完成订单的售后记录时，`confirmed_termination_segment_ids` 给出已确认终止的具体段；`confirmed_termination_provider_ids` 仅包含全部已开始履约段均已关闭的陪玩，不能用账号标记替代段范围。

首版开发中：当前段级追加退款路径及多次转单、加购、零退款、到账释放和并发回滚尚需最终联调。新系统的加购退款若消耗主单未结算收益，按本人未关闭的履约段从最近接入段开始记录实际扣减；已确认终止的旧段不会被后续扣减覆盖。积分转单路径对段明细的接入以对应接口实现为准。
