# 普通混合付款二次协商的到账历史与补资

普通双陪混合付款订单在第一次部分协商退款后再次协商，正式补资写入现能识别已核验的追加退款资金版本，按最新整单缺口分配本店实际到账，不再误用无退款测算。整单补资足额、订单完成及各陪玩的报单和等待条件仍由原逐人结算器核验。

首次主单退款 RELEASE 的到账回读改按首次退款时点还原本金、赠送和赔付退回构成，同时核对当前累计退款来源及真实后续协商关联；第二次退款不能改写第一次资金快照。二次退款自身需要释放已启用共享用途账本的到账时，第二次 RELEASE 的到账本地无锁来源及用途事件尚未接通，退款事务明确拒绝，不能将该组合视为完成。未启用账本的既有隔离路径及无释放的受控路径不由该限制自动证明通过。

本轮未运行检查、测试或迁移。最终须接通二次 RELEASE 与用途事件的同事务写入、共享到账锁序和按事件时点回放，再联调多到账、重复请求、资金守恒、两店隔离与并发回滚。

普通双陪二次正额协商退款的共享到账释放已接入限定路径：无加购、第二次退款前无人结算，且所有实际补资分配已存在于首次退款资金版本中。第二次退款在同一门店事务内完成双方确认、实际退款、售后结案和审计后，按已锁到账逐笔写入 RELEASE 与用途事件；任一核验或写入失败时整笔事务回滚。到账本地回读只读取本单事实并持有当前到账锁，核验首次释放、两次退款、混合来源和分摊、实际到账使用与二次释放，不锁共享到账上的其他订单；相同请求重试核对原事件。

该限定路径之外尚未完成：首次退款后新增到账分配、此前已有陪玩结算、含加购或其他释放历史等情况仍须建立对应来源及时点回放，相关退款仍受门禁。不能将上述限制视为产品规则或整个普通订单资金链完成。未运行检查、测试或迁移；最终联调须覆盖两次退款释放及零释放、共享到账跨订单、跨库操作恢复、重复请求、并发回滚和双店隔离。

## 后续：首次退款后的新增分配

上述首次退款后新增分配的限制已在限定路径内继续处理。二次退款 RELEASE 的到账本地回读按首次退款资金记录时点重放原分配及释放，再按第二次退款时点核对新增分配、平台到账操作及本到账的用途事件；不通过此前会锁定其他到账的核实入口读取来源。如果首次退款时没有分配，原写入流程不会创建首次 RELEASE 记录；回读以首次终止完成时点重算首次资金事实，要求该时点之前没有分配，然后核对后续真实分配。退款、分配释放和用途事件仍由同一门店事务提交或回滚，平台到账操作按本店记录核验。

当前仍限定普通双陪、无加购、无转单或其他释放历史、第二次退款前无人结算；不代表这些正常业务组合已完成，也不代替最终验证。未执行测试、迁移或数据库操作；须在隔离环境联调首次零分配及首次有分配两种时序、多笔共享到账、重复请求、失败回滚、并发与双店隔离，以及退款后的补资和逐人结算。

## 后续：首次退款前已付款的加购

普通双陪二次退款的共享到账 RELEASE 已继续接入首次退款前付款、尚无加购退款和换人的加购。到账回读重算首次退款时的主单及加购实际付款来源、加购收益和整单补资，并核对首次结算预留中每笔加购的陪玩与履约段；二次退款后沿用结案事务内释放及用途事件写入，后续由既有整单补资核验和逐人主单、加购收益结算入口处理。该路径同样支持首次退款时无分配和首次退款后新增分配，不将其他订单作为来源加锁。

首次退款之后付款的加购、加购退款或换人、其他释放历史，以及第二次退款前已有陪玩结算的共享到账 RELEASE，仍未打通，相关来源继续阻断；需要按各自事件时点及实际账务接入，不能视为产品长期限制。未运行测试或迁移；最终须在隔离环境核对混合付款、多笔加购、两次退款和释放、二次补资、两人各自等待报单、共享到账并发、重试回滚及双店隔离。

## 后续：首次退款后付款的加购

增加一个受限的真实付款及二次退款路径：普通双陪首次部分退款后仍在履约，首次退款后新加购付款时没有任何门店补资分配，且加购由仍在履约的陪玩承担。付款仍经原有选择、权限、钱包扣款及原始资金来源记录；因为付款当时没有补资分配，不产生付款释放。随后可按现有入口补资、完成履约、再次协商退款；二次 RELEASE 在同一事务核对付款和用途事件。回读分别在首次释放与第二次退款前重放加购付款，核对第二次退款前的整单预留和逐人加购收益，不将后付款写回首次退款快照。

此接入目前只覆盖一笔加购、没有加购退款或换人的情况。首次退款后付款时已有补资分配仍被挡住：付款可能改变门店补资缺口，需要先实现付款事务内真实重平衡、共享到账用途事件及其历史回放。多笔加购、加购退款或换人、其他释放历史及二次退款前已结算等组合仍需继续接通。本轮未运行测试或迁移；须最终在隔离环境验证付款、退款、补资、逐人结算、共享到账并发、重试与回滚。

## 后续：付款时已有门店补资

对上述一笔加购场景，已接入首次退款后加购付款时已有门店补资的路径：付款事务按已验证的本单分配和首次退款后实际来源重算缺口，释放超额分配，并为每笔释放同事务写入到账用途事件；无释放也保存付款资金版本。二次退款回放先核对该付款版本和同一到账上的历史用途，再执行其自身的释放；整单补资足额及每位陪玩的完成、等待和报单规则仍由原结算入口处理。到账按本单已有锁序处理，来源回放不增加其他订单锁。

仍限定首次退款后的一笔加购、无加购退款和换人、无其他释放历史、第二次退款前无人结算；多笔加购等组合尚未因本次修改接通。付款可用状态是预览，实际付款仍在事务内重新核验资金并可拒绝。未执行测试或迁移，付款释放、后续二次释放、零释放、多笔共享到账、重试、并发回滚、逐人结算及双店隔离均须最终联调。

## 后续：该笔加购的独立退款

继续接入首次主单退款后付款的一笔加购，在第二次主单退款前发生一次独立加购退款的受限路径。加购退款仍经原有双方确认、原付款来源退款和陪玩承担记账；其资金版本按实际退款时点核对此前主单及加购付款释放并写到账用途事件。后续主单协商退款回放该加购退款版本，并将其实际主单收益扣减纳入逐人预留，再沿用整单补资和逐人结算入口。已按历史时点读取首次主单退款来源，避免第二次主单退款改变首次来源的重算结果。

此路径仍要求首次主单退款已有资金释放版本，且第二次主单退款见证到账已包含在加购退款时的分配版本；首次退款时无分配、加购退款后新增加的到账、多个加购退款、加购换人及第二次退款前已有陪玩结算仍未接通。未执行测试或迁移；退款确认、混合来源、付款与退款各次释放、追加补资、逐人报单等待、并发、幂等及失败回滚须最终隔离联调。

## 后续：零分配与退款后新到账

上述一笔加购独立退款路径继续接入两种时序：首次主单退款时没有到账分配和释放版本；以及独立加购退款之后才为本单分配新的到账。首次零分配以实际终止完成时点重算首笔退款，并核对当时没有分配；后续到账见证回放加购退款时，只按其退款时已存在的分配、实际退款及释放重建历史，同时核对该新到账确实在历史版本之后分配给本单。实际二次退款仍在同一门店事务内退款、释放并记录用途；不通过新到账锁定其他订单或其他到账。

仍限一笔加购及一次独立加购退款，且不包含加购换人、其他类型释放、二次退款前已有陪玩结算等组合。未运行测试或迁移；须最终隔离联调首次零分配、加购退款时零分配、新到账与共享到账、各次正额和零额释放、最终补资、逐人等待报单、两店隔离、重试和并发回滚。

## 后续：同一加购多次退款

首次主单退款后的一笔加购允许在第二次主单退款前多次独立退款。每次方案仍受未退款余额约束并经双方确认；执行按已扣减的加购及主单收益计算本次承担，核对原付款来源及实际钱包、押金流水，退款事务内更新补资版本与到账用途。第二次主单退款逐个回放此前退款版本、到账释放和累计收益扣减，再使用既有整单补资及逐人结算入口。首次退款无分配及中途新增到账沿用上一节的历史时点核验。

当前只开放同一笔加购、首次主单退款之后发生的独立退款；跨多个加购、加购换人、其他释放类型、二次退款前已有人结算及不受支持的取整或事件同一时刻仍保留门禁。未运行测试或迁移，最终须在隔离环境联调多笔部分退款及全额退款、原来源、补资各次释放与零释放、重复请求、跨到账并发、押金补差、两人逐次结算和双店隔离。

## 后续：首次退款后的多笔加购

普通双陪首次主单退款后仍在履约时，继续履约席位可依次付款多笔加购。每次付款复用真实钱包扣款、资金来源、同事务补资重算及到账 RELEASE；后付款版本按自己的时点回放此前付款、加购退款和释放。各笔加购可沿用独立协商退款入口，逐笔核对双方确认、原付款来源和已使用收益；历史退款回放只读取该退款前已发生的加购付款，不把未来付款计入承担。第二次主单退款沿用已接入的逐笔加购退款、补资版本和逐人结算路径。

当前仍限制未转单、无加购换人、真实双方确认及可核对的付款／退款版本，且第二次主单退款前无人结算；同一时刻无法排序、其他释放类型及超出既有退款承担核验的组合继续阻断。未执行测试或迁移，最终须隔离联调跨加购依次付款退款、混合来源、收益累计扣减、每次正额及零额释放、后续补资、重复请求、共享到账并发回滚、两人等待报单及双店隔离。

## 后续：首次退款后的双陪加购接替

增加限定的真实接替链：普通双陪首次部分退款终止原加购负责人后，在本单尚未分配门店补资时，客服可为其已付款加购安排仍在履约的另一席接替；老板、原负责人和接替人三方确认后，按双方各自抽成快照保存已完成和剩余份额。接替时没有补资分配，因此无需释放；之后可按实际缺口分配到账，第二次主单退款按真实三方确认、客服审计及逐段加购收益回放，并沿用同事务退款 RELEASE、整单补资和逐人结算。多笔加购可各自接替，前提是接替确认时本单仍无补资分配。

接替前已有任何补资分配时仍不开放：现有接替释放实现属于隔离测试，尚未接入共享到账用途事件和后续历史回放。接替与独立加购退款混合、同一加购多次接替或被拒后重新发起、履约转单、接替前已结算陪玩等也未由本节覆盖。已接受方案的相同决定可重试核对。未运行测试或迁移；须最终隔离联调三方拒绝与重试、逐段抽成、无补资确认后新增到账、二次退款释放、逐人报单等待、并发回滚及双店隔离。

## 后续：接替前已有补资

上述双陪加购接替现接入接替前已有本店补资分配的受限路径。三方最后确认、逐段收益快照、整单缺口重算、实际多余分配 RELEASE 和到账用途事件在同一门店事务内提交；即使无需释放也保存接替资金版本。按本单到账顺序加锁，到账本地回放逐笔核对此前真实付款、退款或接替版本及本到账用途，不锁定共享到账的其他订单。第二次主单退款回放各接替版本，并沿用整单补资和逐人结算入口；多笔加购各自接替按实际事件时点处理。

此路径仍不覆盖接替与独立加购退款混合、同一加购多次接替或被拒后重新发起、履约转单、接替前已有陪玩结算及其他未核验释放历史。未运行测试或迁移；最终须隔离联调三方确认与拒绝、接替前后新增分配、多个到账及多笔加购、各次正额与零额释放、后续退款、逐人等待报单、幂等、并发回滚和双店隔离。

## 后续：接替双方共同承担加购退款

接入有限的接替后加购退款：原负责人和接替人各自保留份额时，可由实际承担人确认退款，按各自的当前加购份额、逐段待结算收益、本人钱包和押金执行并核对原付款来源；历史到账回放逐人复原各笔承担，并核验此前接替、付款和退款 RELEASE。后续第二次主单退款继续使用补资和逐人结算链。已终止陪玩使用主单收益的范围不超过首次主单退款后的本人保留收益；多人的零余额押金证据仍受门禁。

本轮仍阻断该组合中各人向上取整产生门店差额的退款：现有加购退款只有差额数值，尚缺逐笔可核对的独立门店收入流水以及该差额在后续资金缺口和最终结算中的保留，不能把净收益数字当成实际入账。接替前已有加购退款、同一加购多次接替、转单和其他未核验释放历史继续限制。未运行测试或迁移；最终须隔离联调双方确认、份额累计消耗、混合来源、钱包押金、各次释放、退款后补资、逐人报单等待、并发回滚、幂等及双店隔离。

## 后续：逐人取整与差额实际入账

接替双方共同承担加购退款时，各人每笔按整数店币向上取整；历史到账回放按当时本人份额及此前累计取整重新核对承担。加购退款新增独立关联差额流水的字段和首版结构迁移文件，未执行迁移。整单资金计划将各笔加购退款差额列入本店最低应得并相应重算补资；待整单足额且完成最终结算时，从普通店铺收入中拆出各笔差额，分别记入真实本店钱包并关联对应退款。最终回放核对全部独立流水与金额，避免与主单退款差额重复入账。没有二次主单退款和有二次主单退款的最终结算入口都已接线。

当前仍限制接替前已有独立加购退款、同一加购多次接替或转单、其他未核验释放历史；已终止陪玩承担超过其加购剩余收益与主单保留收益之和，即使其钱包或押金足额也暂阻断，避免现有逐段扣减误用主单原始收益。多人承担时如需以零余额钱包直接扣押金，现有单笔零余额证据尚不能表达多人，继续阻断。未运行测试或迁移；须最终在隔离环境迁移空测试库并联调多人逐笔取整、多个独立差额流水、补资不足与足额、退款后追加退款、真实钱包和押金、逐人报单等待、幂等与并发回滚及双店隔离。

## 后续：已终止陪玩钱包与多人押金

接替后双方共同退款时，已终止陪玩的可扣主单收益改按首次协商后的本人保留金额，扣除此前实际加购退款占用；收益不足时继续扣本人可用钱包，再扣本人押金并创建各自缺口。原路退款、逐人扣款、押金扣减、缺口、资金释放和到账用途仍在同一门店事务内处理；新单补差许可及后续收益优先补缺口沿用现有真实链。多人各自钱包为零而直接扣押金时，分别记录退款当时的本人钱包、账号和业务周期，并纳入资金版本和到账历史回放。向上取整超过老板实退额的本人承担按已确认份额作为押金限额，不错误限制为老板实退额。

同一付款在同一履约段重复产生保留份额和当前份额仍不开放：现有退款扣减凭证只绑定付款、参与人及履约段，不能证明扣减应归哪次份额，而后续接替只可转出当前份额。虽然最终结算可按付款和履约段汇总收益，单靠汇总不能补足该归属，需要逐份额扣减凭证及对应回放后才能解除门禁。未运行测试或迁移；最终须隔离联调多参与人跨加购扣减与失效重提、原路退款、钱包押金和尾差、共享到账释放、后续主单退款、逐人结算及并发回滚。

## 后续：退款逐份额分配凭证

新增首版结构迁移 `0259_addon_refund_share_allocation`，不执行迁移。加购退款事务在记原路退款和逐人收益扣减之前，按当时已确认接替版本中的实际剩余份额顺序分配退款基数及待结算收益扣减；随后同事务保存付款、参与人、具体接替份额和两类金额，并基于退款发生前时点重新核对。普通主单退款前的逐人退款核验和主单退款后的到账本地核验也校验这些记录；跨加购扣减记录各自付款及其已确认份额。尚未发生接替的付款没有接替份额，仍按原始付款及履约段核验。

这一步不放开同付款同段重复份额：当前退款历史读取及部分逐人退款核验仍按段归集或顺序推导，尚未全面按新凭证逐份额回放，也未接通重复段的后续接替和逐人结算。不得把新凭证写入视为该业务闭环；未对已有数据推测或回填份额来源。未执行测试和迁移；最终须在隔离库应用首版结构并联调同一退款的原路资金、逐人及跨加购扣减、钱包押金、补资 RELEASE、后续接替与结算、并发和事务回滚。

## 后续：逐份额凭证回放

加购当前职责现按退款事件读取逐份额分配记录，核对记录所指确认版本、付款、参与人及履约段，并与真实退款基数和逐段收益扣减合计逐项核对后扣减对应份额。跨加购扣减也按被扣付款的实际份额回放。普通主单退款前后逐人核验先汇总同一陪玩同一履约段的多份额，避免字典覆盖；退款申请与最终收益仍按现有逐段口径计算。

同付款同段重复份额仍未开放。普通未转单双陪每人只有一个主单履约段，目标加购先扣本人该付款收益，且本人承担按比例向上取整；若本人承担不小于退回基数、按同段顺序扣减且原份额收益不超过基数，可保持每份额剩余收益不超过基数，该范围不能直接推断会出现零基数非零收益。多段或其他扣减顺序须另行证明并在写入时校验。另一个明确阻断是普通退款后的最终结算 `_parts` 当前遇同付款同段两份收益会拒绝；应保留逐份额事实并按实际同人同段收益合并成一笔钱包入账，核对退款和资金守恒后才能解除门禁。新回放严格要求相应逐份额凭证，不推测或回填历史归属。未运行测试或迁移；最终须在隔离库联调 0259 迁移、不同退款资金来源、跨加购扣减、重复段及零基数收益、接替确认、共享到账释放、逐人结算与事务回滚。

## 后续：普通双陪同段多份额结算

普通未转单双陪中，同一加购经多次真实确认接替后，可在同一陪玩的履约段留下多份收益。每次退款按 0259 的逐份额事实记录和回放，写入前对重复段逐份核验退款后的收益不超过剩余基数；不满足条件的退款继续阻断。已确认接替快照仍逐份保留原始基数、收益及确认事实。普通退款后最终结算保留这些明细，并将同一付款、同一陪玩和同一履约段的收益合计为一笔实际钱包收入；若同一付款和履约段的陪玩归属不一致则拒绝结算。无主单退款的普通加购结算沿用已有的同段收益合计。

本次仅开放已有普通双陪门禁核验通过的时序；主单转单、积分、未知退款资金版本，以及退款后存在收益超过剩余基数的重复份额继续受各自门禁约束。未执行测试或迁移；须在隔离库先执行 0259，最终联调多次接替、重复段各份额退款及跨加购扣减、三方重新确认、原路资金与钱包押金、尾差流水、共享到账 RELEASE、整单补资与逐人结算，以及并发重试和回滚。

## 后续：普通转单加购退款的份额与资金版本

普通主单转单后，既有加购退款入口继续在同一门店事务内退回原付款、记录逐人承担、保存逐份额分配，并通过转单退款资金版本重算和 RELEASE；该资金版本生成、回读及最终转单结算读取当前版本时，现核验实际加购退款的逐份额凭证。首次主单退款前的转单加购退款历史还核验老板及全部实际承担陪玩的确认和承担合计。既有转单逐人结算按付款、陪玩和履约段合计真实收益。

目前只接入无加购退款取整尾差的转单时序。转单资金版本尚未将加购退款尾差按每笔 0257 流水独立预留和入账；若本次或此前转单加购退款有尾差，退款入口和结算版本回读会阻断，避免把计算数字当作已入账。转单前尚无可核验补资释放来源及其他未支持的加购/接替时序仍受既有门禁。未运行测试或迁移；最终须隔离联调 0259、真实三方确认、原路退款、钱包押金、多份额及跨加购扣减、转单资金版本与共享到账 RELEASE、整单补资和本人报单等待期结算、并发幂等回滚。

## 后续：首次主单退款后的转单加购取整

普通转单订单仅有一次已完成主单退款、没有后续主单协商轮次，且首次主单退款前的加购退款无尾差时，其后的加购退款可包含各陪玩按责任比例向上取整形成的尾差。退款事务核验参与人确认、逐人计算及逐份额来源，将各笔退款与尾差写入转单资金版本，在重算门店最低资金需求后同事务计算共享到账 RELEASE。版本回读再次核验各笔退款及取整事实，资金不足时不能结算。

整单完成、补资足额并满足本人报单和等待期后，最终门店结算从普通门店收益中扣除这些尾差，按各笔加购退款分别创建并关联 0257 的真实门店钱包流水；回读核对退款、金额及钱包流水。首次主单退款前已有加购尾差、后续主单协商轮次、未核验的到账版本及其他转单时序仍受门禁。未运行测试或迁移；最终须在隔离库联调多名陪玩取整、原路退款与钱包押金、既有及新增共享到账、各次 RELEASE、整单补资、逐人结算、重复请求和事务回滚。

## 后续：首次主单退款前的转单加购尾差

普通订单转单后、首次主单退款前，加购退款发生时该订单尚无门店补资分配，可按实际多名陪玩确认和向上取整完成退款；由于当时无已分配到账，不产生虚构 RELEASE。此后可新增实际补资，首次主单退款的转单加购资金计划按退款发生时点将这些尾差纳入门店资金需求，再按真实分配及既有释放凭证计算可释放金额。整单最终结算逐笔写入并关联退款的 0257 门店尾差流水；首次主单退款后的加购尾差同样累计核验。

退款发生前已有本单补资分配的转单加购尾差仍阻断：该时序尚缺能核验转单前后逐事件需求的本单资金版本及共享到账 RELEASE。首次主单零退款协商、后续主单协商轮次及其他未核验资金版本也未在本次开放。未运行测试或迁移；最终须隔离联调退款时零分配、退款后新增共享到账、首次主单退款资金版本及 RELEASE、逐人钱包押金、每笔尾差流水、整单补资和逐人结算、并发重试与双店隔离。

## 后续：转单退款后到账用途账本纠正

核查发现此前普通退款后转单的 RELEASE 只创建了本单分配释放行，并未写共享到账用途事件；此前将该部分描述为已完整接入用途账本不准确。现在同一释放事务中，按已锁到账编号顺序写入用途 RELEASE 并复核到账用途；到账本地回读核验本店分配、转单资金版本、真实退款来源和释放快照。没有用途账本版本的到账仍按已有路径处理。

首次主单退款前已有补资分配的转单加购退款仍受门禁。其尚需实现不在共享到账锁下反向锁订单、能按真实事件时点回放转单逐段收益和历次退款的资金版本；不能直接把当前逐段计划冒充历史版本。本次未运行测试或迁移；最终须隔离联调共享到账用于多个订单、并发释放、重试、事务回滚、用途账本与实际分配守恒及最终逐人结算。

## 后续：首次转单主单退款 RELEASE 核查

首次普通转单主单退款的 RELEASE 也存在独立缺口：原实现写入分配释放行，但未写共享到账用途事件。其资金事实回放 `facts_locked` 重新进入订单资金计划并锁订单，不能从共享到账锁内调用；现有普通主单无锁回放明确排除转单。此时不能仅凭资金版本哈希或当前逐段状态证明历史资金。

在有用途账本版本的到账且本次确有资金释放时，首次转单主单退款现会在写 RELEASE 前阻断；零释放不生成虚假用途事件。后续必须实现按原协商、转单、支付、逐人扣款、加购退款及分配事件时点的到账本地无锁核验，并与 RELEASE 用途事件同事务写入，之后才能接通首次主单退款前已有补资分配的加购退款。未运行测试或迁移。

## 后续：首次转单退款的到账本地版本

限定一次普通转单、一次主单退款、退款资金事件之前无加购付款、无此前补资释放且所有分配均接入到账用途账本，首次主单退款事务保存原资金版本及分配释放，并在同一事务按到账编号写 RELEASE 用途事件。到账本地只读核验原支付和退款流水、确认方案、转单协商快照与逐段收益、本人收益及钱包押金承担、原分配平台凭证，并重新计算资金需求及逐到账释放；不在到账锁下重取订单锁。再次读取时核验原用途分配事实。

加购付款已存在、此前有释放、混合用途账本版本、再次主单退款或后续转单等组合仍受原门禁；这一步尚未接通首次主单退款前已有分配的加购退款。未运行测试或迁移，最终须隔离联调共享到账多订单并发、真实转单协商及退款、分配和释放守恒、幂等、回滚与最终逐人结算。

## 后续：首次转单退款前已有加购付款

首次普通转单主单退款 RELEASE 的到账本地回放进一步覆盖一笔已付款但尚未退款的加购；可核验一次已完成的初次加购接替，按事件时点重建实际原付款、逐段加购收益和整单资金需求。原事务内写入本单 RELEASE 与到账用途事件，最终继续使用既有分段结算。仍限定一次转单、一次主单退款、此前无释放且所有分配均有用途账本；不在持有到账锁时使用会锁订单的接替重试分支。

本次尚未开放首次主单退款前已有补资分配的加购退款：其需要加购退款本身在退款事务冻结可回放的转单分段版本及 RELEASE，并让首次主单到账本地回放逐笔核验这些前序释放与用途；当前不以未退款加购付款冒充此链路。未运行测试或迁移；最终须隔离联调真实付款、三方接替、共享到账、首次主单 RELEASE、逐人结算和并发回滚。

## 后续：已有分配的首次转单加购退款

普通订单一次转单、只有一笔加购及其第一笔退款时，退款前已有的本单补资分配可参与资金重算。退款事务在实际原路退款和逐人、逐份额承担后，按当时转单逐段收益、付款来源及本次尾差冻结资金版本；对多余分配写 RELEASE，并在同事务记录共享到账用途。首次主单退款的到账本地回放逐笔核验此前加购退款释放和用途事件，再按累计实际金额计算本次释放；整单完成并补资足额后沿用逐人结算和每笔门店尾差流水。

限定一次转单、一笔加购、最多一次初次三方接替、一笔加购退款，退款前没有更早的本单 RELEASE，相关分配均有用途账本，首次主单退款后不再发生转单或第二次主单退款。更多退款、付款、接替、历史释放及未核验到账时序仍受门禁。未运行测试或迁移；最终须隔离联调共享到账用于多单、真实转单接替、退款和钱包押金、尾差预留、两次 RELEASE、后续新增分配、逐人结算、幂等与并发回滚。

## 后续：转单后多笔加购及退款的事件回放

一次普通转单后，已有的多笔加购付款及各自多次退款可按事件时点重建。每次退款事务核验此前各付款、初次三方接替、退款决定及逐人逐份额承担，累计各笔取整尾差，冻结当时逐段资金需求；已有分配与前序加购退款 RELEASE 沿用同店到账用途账本核验，并在同一事务写本次 RELEASE 用途事件。首次主单退款的到账本地回放逐笔核验各退款资金版本及见证到账的历史用途，按实际剩余分配计算释放；最终仍逐人结算并逐笔关联尾差门店流水。

范围限一次主单转单、各加购最多一次初次接替且该加购接替之前没有退款、已有分配的到账均有用途账本，前序 RELEASE 均来自本版转单加购退款；本轮覆盖的多笔加购付款须已通过现有付款入口，付款时已有分配的转单加购资金重算尚未开放。先退款时完全无分配且无资金版本、之后再分配的混合历史，以及多次主单转单、第二次主单退款、其他释放类型继续受限。未运行测试或迁移；最终须隔离联调跨付款多次退款、累计尾差与本人钱包押金、共享到账跨订单并发、多次 RELEASE、首次主单退款、逐人结算、幂等和回滚。

## 后续：付款时已有分配与后续新增到账

一次普通转单、首次主单退款前，加购付款时已有本单到账分配的，付款事务按订单、资金互斥、到账顺序加锁，按真实付款与当时逐段收益冻结资金版本，并同事务记录多余分配 RELEASE 和到账用途。付款可在已核验的其他加购退款之后发生；后续退款继续累计各次付款、退款、尾差及 RELEASE。首次主单退款的到账本地回放逐笔核验付款与退款版本、该到账的原分配和释放用途，并包含之后新增的实际分配，最终沿用逐人结算和逐退款尾差流水。

仍限一次主单转单、每笔加购最多一次初次接替且该付款接替前无退款、已有分配均有用途账本、前序 RELEASE 均属于本版转单加购付款或退款。先退款时完全无分配而没有资金版本、随后再分配的历史仍受限；再次主单退款、后续转单及其他资金版本亦未开放。未运行测试或迁移；最终须隔离联调付款前已有分配、退款后新增及共享到账、先退款后再购、多次 RELEASE、尾差及钱包押金、首次主单退款、逐人结算与并发幂等回滚。

## 后续：首次主单退款后的多笔加购退款

一次普通转单且首次主单退款完成后，既有加购退款入口继续按原支付来源退款、逐人确认和逐份额承担；每次退款在同一事务刷新转单资金版本，累计主单及加购退款尾差后计算本次共享到账 RELEASE，并写入用途事件。完成整单、整单补资、本人报单审核及等待期后，逐人结算按实际剩余收益记账，并按每笔退款单独关联门店尾差流水。重复执行已完成退款时，现按原加购退款资金版本或原转单资金版本核验及回读到账用途，不把版本缺失误作成功。

首次主单协商影响的某陪玩只对应一个已核验履约段时，该段确认后的本人保留收益仍可用于后续加购退款：按协商前已扣加购收益、主单协商扣减及协商后的新扣减依次核算，不能重新消耗已扣金额。影响该陪玩的多个履约段如何分配协商扣减仍未证明，继续使用既有闭段边界。各加购接替次数、已发生的付款/退款资金版本及共享到账限制仍按前节；第二次主单退款和后续转单未在本次开放。未运行测试或迁移，最终须隔离联调主单前后多笔退款、原路资金、剩余收益与钱包押金、累计尾差、各次 RELEASE、幂等和逐人结算。

## 后续：转单第二次主单退款与既有加购尾差

普通转单追加协商的预览、确认、原路退款和逐段结算沿用既有逐轮事务。第二轮资金计划现按事件边界累计首次及第二次主单退款的尾差，以及此前实际加购退款的尾差，作为门店资金需求；完成整单和补资后，结算按原主单轮次及各笔加购退款分别创建和关联门店真实流水。首次主单 RELEASE 的到账回放允许第二次主单退款已发生，但仍按首次事件重建原付款退款来源，不能把第二次退回金额回填首次事件。

第二次主单退款若需释放已接入用途账本的共享到账，当前在写释放前阻断：既有第二轮资金核验会重取订单锁，尚未实现到账本地只读回放和同事务用途事件。无此 RELEASE 的时序继续走既有链；首次零退款后的加购尾差、第二次主单退款后的加购退款及其他未核验版本保持限制。未运行测试或迁移；最终须隔离联调两轮确认、原路退款、加购尾差逐笔入账、整单补资与逐人结算，并补全共享到账 RELEASE 后验证多订单并发及回滚。

## 后续：第二次转单退款的到账本地 RELEASE

一次普通转单、两次真实主单协商退款且分配均接入用途账本时，第二轮结案事务先按订单、资金互斥、到账顺序加锁，再按第二轮资金版本写入本单 RELEASE 和到账用途事件。到账本地只读回放两次双方确认、原付款与逐次原路退回、实际履约段和已占用收益、本人钱包押金、此前加购付款退款及各到账前序用途，再计算当前释放；不在到账锁下反向锁订单。重复结案会核验原资金版本及到账用途。第二轮资金计划和最终结算保留此前加购退款的逐笔尾差。

范围限首次和第二次均为实际主单退款、仅一次主单转单、已有分配均有用途账本，前序加购及释放须有各自已支持的真实资金版本。首次零退款协商、第二次主单退款之后的新加购退款、后续转单和其他未核验历史仍受门禁。未运行测试或迁移；最终须隔离联调两轮确认、加购退款和尾差、同一到账跨订单使用、多次释放及用途、钱包押金、整单补资与逐人结算、并发幂等回滚。

## 后续：第二次主单退款后的加购退款

一次普通转单、两次实际主单协商退款均已终止后，可继续按已有加购责任及真实支付来源协商退款。退款事务记录逐人逐份额承担，重新冻结当前转单资金版本，累计两轮主单和各笔加购退款尾差，再按已核验分配和前序 RELEASE 写本次到账用途；整单资金足额后按原等待期及本人审核逐人结算，并将两轮主单及各笔加购退款的尾差分别入账。第二轮 RELEASE 本地回放以其发生时点为界，不将后续加购退款回填旧版本。

第二轮影响本人仅一个履约段、且该段未被首次协商终止时，本人已确认保留收益可承担后续加购退款；协商前已占用主单收益及之后的新占用分别扣除。首次零退款、同一履约段跨两轮协商、多人多段承担如何归属、后续转单和其他未核验资金版本仍受限制。未运行测试或迁移；最终须隔离联调两次主单退款后多次加购退款、此前及新增共享到账、各次 RELEASE、真实钱包押金与尾差、整单补资和逐人结算、并发幂等及回滚。

## 后续：首次零退款协商后的加购退款

普通订单一次转单后的首次协商为真实零退款并已终止时，可继续对加购发起退款。原事务核对加购责任、双方确认和逐份额承担，按原付款来源退款，刷新转单资金版本并将各笔加购尾差计入门店资金需求，再按真实分配写 RELEASE 和共享到账用途。零退款的确认、原付款、实际分段收益及本人零承担使用不反向锁订单的到账本地事实核验；整单完成并补资足额后，沿用逐人结算和每笔加购尾差流水。

范围限一次普通转单、首次零退款已真实结案、之后没有追加主单协商轮次；每笔加购最多一次初次接替且本付款接替前未退款，前序释放须为已支持的转单资金版本，已有分配须有用途账本。零退款之前已有加购退款、后续主单协商、再次转单及其他未知来源仍受限制。未运行测试或迁移；最终须隔离联调零退款前后付款、双方确认、实际钱包押金、取整、共享到账多订单释放、整单补资、逐人报单等待期及并发回滚。

## 后续：加购付款或退款后的第二次转单

普通服务订单每个席位最多两次真实转单；已发生加购付款或退款、已有本单到账分配时，主单退款前的转单事务现保存当时逐段资金版本，按原订单、资金互斥、到账顺序锁定并在同一事务释放多余分配、写到账用途事件。转入陪玩尚未入队时资金版本按真实已确认转入基数及抽成保存，不将预计收益当成已结算收入。到账本地回放逐事件重建转单前后基数、抽成、加购来源及累计尾差，不把后来的转单回填早期版本。

转单前已有一次已确认加购接替、其后发生退款时，第二次转单后可按退款后的原负责人实际剩余份额发起第二次加购三方接替；确认事务重算整单并写入对应资金版本与到账 RELEASE。首次及第二次主单退款的到账本地核验按各自事件时点回放此前转单，最终沿用整单补资和逐人结算。

仍限普通钱包资金、每席最多两次转单、每笔加购最多两次已确认接替且第二次接替直接对应真实后续转单；加购初次接替前已退款、更多接替、未接入用途账本的分配及其他未核验历史继续受限。退款时无分配且没有资金版本、之后才补资的部分旧时序仍未接通。未运行测试或迁移；最终须隔离联调付款/退款后第二次转单、转入未入队与开始履约、两次加购接替、每笔尾差、共享到账跨订单、多次 RELEASE、两轮主单协商、整单补资及逐人结算、并发幂等回滚。

## 后续：加购多次接替与首次接替前退款

普通转单订单的加购资金回放不再把两次作为加购负责人接替上限，也不要求每次加购接替都对应一次新的主单转单。连续已确认接替按真实版本链逐次核验老板、原负责人和接替人的决定、客服审计、实际剩余份额及抽成；每次仍沿用原确认事务重算资金、到账 RELEASE 和逐人结算。主单每席最多两次转单的规则不变。

首次加购接替前已有本付款退款时，首次接替按实际原路退款、逐笔收益扣减后的剩余基数和收益重新计算；之后的接替继续读取逐份额凭证。尚限已确认接替版本连续可核验；拒绝或退款失效后跨版本重提、未接入用途账本的分配及其他缺少真实历史凭证的时序继续受门禁。未运行测试或迁移；最终须隔离联调首次接替前退款、三次及以上三方接替、接替之间跨付款扣减与尾差、多次 RELEASE、两轮主单协商、整单补资、逐人结算、并发幂等和回滚。

## 后续：转单加购接替拒绝或退款失效后的重提

普通转单订单的加购接替被任一方拒绝，或尚待确认时因同一加购退款、另一笔退款实际扣用方案份额而失效后，客服可按当前已生效责任、实际退款与剩余收益重提。版本回放核对原方案的三方决定、客服审计，以及退款失效时绑定的真实退款与逐人逐段扣减；已同意的旧决定不带入新方案。新方案仍要求老板、原负责人和接替人各自确认，并沿用真实资金版本、到账 RELEASE 及逐人结算。

本次覆盖普通转单主单退款前、或已有一次已完成主单退款的受限时序；第二次主单退款后的待确认方案失效、未知历史事件和不在已有资金版本内的组合仍受门禁。开启到账用途账本时，尚未建立用途版本的共享到账仍不能安全参与该释放：现有资金核验明确拒绝该来源，不能推测其他订单占用或伪造账本；首次部署须完成真实到账初始化。未运行测试或迁移；最终须隔离联调拒绝重提、退款与最后确认并发、跨付款扣减、原路退款和钱包押金、多个 RELEASE、共享到账、尾差及逐人结算、幂等回滚。

## 后续：第二轮主单退款后的待确认接替

普通转单订单的两轮实际主单退款均已完成且具有对应协商轮次凭证时，待确认加购接替受到真实退款影响，可在退款事务内失效并保留当时方案、决定和逐人扣减；后续重提按事件顺序核验已生效及已失效的版本。退款执行入口和可执行状态现允许存在待确认方案，实际受影响方案仍由事务内锁定、核验并失效；未受影响方案不因另一笔退款自动失效。后续资金版本、到账 RELEASE 和逐人结算仍使用既有转单链及其门禁，本次未验证全部组合可达。

到账用途账本已在平台到账核验实际入口、同一门店事务中对无任何既有分配的新到账初始化；有既有分配而无用途版本的到账不能按空账初始化，也未做历史迁移。最终须在隔离环境联调两轮退款后方案失效和重新三方确认、共享到账多订单、退款与最终确认并发、逐份额承担、尾差、RELEASE、整单补资和逐人结算及失败回滚。本轮未运行测试或迁移。

## 后续：首次补资前的转单加购退款

普通转单订单在首次主单退款前完成加购退款、当时尚无门店到账分配时，加购退款事务仍按真实付款、退款、确认和分段收益写入空分配的零 RELEASE 版本。后续首次到账分配发生在该版本之后，首次主单退款及到账回放可按实际时间核对该退款，而不会把后来到账当成退款时已有的资金。该变更沿用原路退款和逐人承担，不提前发放收益，也不改变其他场景的门禁。

本次未运行测试或迁移。须最终在隔离环境联调混合本金、赠送及赔付付款，加购部分退款、首次补资、首次主单退款、后续 RELEASE 与逐段结算，并核对并发回滚；其他付款与退款交错组合仍受既有能力范围限制。
