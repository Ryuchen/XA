# 消费积分授权未知的拒绝结案

订单已实销且原消费积分授权决定为 UNKNOWN 时，平台超级管理员可依据真实原时点授权资料在既有积分核对接口提交 DENY。服务端核对原订单、老板账号、业务周期、实销及原付款事实和原授权未知依据，并记录付款时的退款基线；本次不发积分、不重算当前退款、不修改已获权益。后续退款或退款来源暂时不完整不会让这个零额拒绝结论永久卡在待核对；同一请求重试仍返回原结果并沿用平台审计恢复。

ALLOW 不使用该简化路径：仍需核对原付款、本金来源、当前实际退款及钱包流水；关联会员授权须先核实允许，账号换周期或本金全退不补发。缺少原订单、实销时间、付款流水或原决定基线时，DENY 也继续待核对，不能将缺失事实当作零。

参考 [NZ Ledger 的业务事实与授权证据关联](https://github.com/nz-ledger/nz-ledger/blob/main/docs/rfc/0001-canonical-accounting-domain.md)，本项目依旧使用现有门店决定与平台核对审计，不引入外部账本模型。

按开发期要求未运行测试或迁移，仅完成 Python 语法解析；控制库故障、后续多次退款、跨周期、平台审计失败重试及积分抵扣/转单真实路径仍须隔离环境联调。来源无法证明的 ALLOW 继续待核对，不代表资金全链路验收完成。
