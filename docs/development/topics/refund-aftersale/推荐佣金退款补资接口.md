# 已发推荐佣金退款的到账补资接口

本接口供平台财务核对并分配已核实的线下到账。已发推荐佣金保留在原收款人账户；门店通过本店到账承担退款相应金额。到账与通行证、订单积分补资共用用途账本，已占用金额不可重复使用，也不能把代管押金当作本次补资。

接口位于后台域名 `/api/admin/`，使用独立平台认证和 `pass_refund_repayment:register` 的平台授权，并校验 URL 门店与到账所属门店。金额均为店币内部整数单位，10 内部单位为 1 店币；不接收小数。

## 试算

`GET /api/admin/platform/referral-funding/{slug}/orders/{order_id}/quote?refund_amount={integer}`

返回 `data.order_id`、`refund_amount`、本次应由门店承担的 `amount`、`requires_funding`。试算是查询时的提示，到账预留及退款提交均在锁内重新核验；当 `amount` 为 0 时无需本次佣金补资。

## 预留

`POST /api/admin/platform/pass-refund-repayments/{slug}/{claim_id}/referral-refund-allocation`

请求体：

```json
{"request_id":"UUID", "order_id":123, "refund_amount":1000, "amount":100}
```

`claim_id` 为平台已核实的到账编号，`request_id` 为本次操作 UUID，`refund_amount` 为本次实际退款店币金额，`amount` 为该笔已发佣金的门店承担额。成功返回 `operation_id`、`status`、`receipt_id`、`allocation_id`、`order_id`、`amount` 和 `refund_amount`。平台先保存操作意图，本店再同事务保存到账分配、操作结果及用途事件。已经预留的到账占用不可重复用于其他用途。

若响应中断或提示结果不明，使用完全相同的 URL 和请求体重试；不同请求内容不能复用原 UUID。尚未取得本店分配事实的待处理意图，可由有权平台财务调用 `POST /api/admin/platform/referral-funding/{slug}/{operation_id}/void`，请求体为 `{"reason":"核实原因"}`。系统核对本店不存在 allocation、action 和用途事件后才解除 pending；已有本店分配时须用原请求恢复，不允许作废。

若响应中断后没有取得操作编号，可调用 `GET /api/admin/platform/referral-funding/{slug}/request-status?request_id={UUID}` 查询本店的 `operation_id`、操作 `kind` 和 `PENDING`／`COMPLETED`／`REJECTED` 状态；已完成预留并随后释放时，预留状态为 `RELEASED`。该查询不替代本店账本凭据核验。

已完成但尚未绑定退款的预留，可调用 `POST /api/admin/platform/referral-funding/{slug}/{operation_id}/release`，请求体为 `{"request_id":"UUID", "reason":"释放原因"}`。系统在同一订单与到账事务中核验原凭据、写入释放记录及共享账本反向事件，将整笔未使用金额恢复为本店到账可分配余额；已绑定实际退款的预留不能释放。响应中断时以完全相同的请求重试。若释放意图尚未产生本店释放凭据且确认不再执行，可调用 `POST /api/admin/platform/referral-funding-release/{slug}/{release_operation_id}/void`，请求体为 `{"reason":"核实原因"}`；已有本店释放事实须用原请求恢复。

## 目前范围与联调

当前实现仅针对已结算、无积分、无加购、无转单的普通店币订单，支持全额、部分和多笔退款；逐笔绑定实际退款金额，历史部分逐笔重算并核对。协商、积分、加购、转单及涉及其他资金构成的组合仍受门禁限制，不因接口可访问而开放。`REFERRAL_REFUND_FUNDING_ENABLED` 与共享到账账本依赖的开关保持默认关闭；已有本系统已预留的操作仍须核验原付款、原到账和平台完成事实。

普通已结算订单沿原退款分摊的最小记账单位和累计比例，计算本笔原本会分配到已发推荐佣金的份额，由门店承担该份额；多笔累计、全退时补齐。该计算不冲回推荐人的已发佣金；最终联调须核对逐笔及累计资金守恒。

有权限查看详细退款核算的后台响应中，单笔 `records[].referral_store_funding` 是实际绑定的 `{amount, allocation_id, receipt_id}`，无绑定记录时为 `null`；`recovered_amount` 仍仅表示实际追回的资金，不把门店到账补资算作追回推荐人收益。

以上代码与迁移尚未执行开发期测试或迁移。最终联调须覆盖同店及跨店权限、老板和陪玩收款人、同人多身份、全额及多笔部分退款、舍入为零、到账不足、通行证／订单共用到账、重复请求、跨库结果不明、取消 pending、并发和事务回滚；协商、积分、加购与转单须待真实来源接线后单独覆盖。
