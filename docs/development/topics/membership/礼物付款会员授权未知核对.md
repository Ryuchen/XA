# 礼物付款的会员授权未知核对

礼物新购仍由原 `GIFTS` 授权判断：无可验证许可时不能借此入口创建赠礼。已通过该判断并进入同一付款事务后，如 VIP_GROWTH 核验变成 UNKNOWN，系统与礼物付款一起持久保存原订单、老板、业务周期、金额和当时授权故障证据，继续原本金扣款、礼物收益及权益；不把未知视为允许升级，也不回滚合法付款。已确定 DENY 保持不增加会员成长。

平台超级管理员可通过 `GET /api/admin/platform/store-management/{id}/license-gift-vip-review?kind=PENDING|REVIEWED` 查询，再向 `POST /api/admin/platform/store-management/{id}/license-gift-vip-review/{decision_id}/resolve` 提交 UUID `request_id`、`ALLOW|DENY` 和真实原时点核对依据 `reason`。相同请求重试返回原决定并可恢复平台审计，保留原操作人；不同请求不能重复处理同一决定。

允许前核对原礼物付款成功流水、付款时 VIP 开关、本金来源、退款记录及退回老板钱包的流水。部分退款按当前实际净本金建立原周期的会员消费确认；后续退款仍沿用现有退款冲减。全额退款或老板退店进入新周期时不恢复成长。若核对后现有 License 或本店 VIP 暂不允许重算，则保留待重算标记，使用现有按门店周期任务恢复；不因当前授权状态推断历史事实，不重做付款或发券。

参考 [Transactional Outbox 与幂等处理](https://github.com/shirinjamshidiyan/eventflow-commerce-outbox-saga/) 的付款事实与后续处理分离；本项目以同店事务记录付款与待核对事实、平台审计另库恢复，不照搬其消息模型。
