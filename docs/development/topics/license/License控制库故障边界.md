# License 控制库故障边界

门店已有可验证的本地路由快照时，控制库故障不会因为缺少 License 快照就停掉已有老板、陪玩的核心业务。有效的本店 License 快照按其授权起止和宽限期随时间变化；没有可验证快照时，新增账号及新增增值权益无法核验，应暂停并提示联系平台。已获得的权益按其自身规则使用。

三库隔离测试中，控制库所有 SQL 均被模拟拒绝、门店路由快照有效且 License 快照缺失时，已验证老板查询钱包、使用已领取优惠券下单并真实扣减店币、已绑定陪玩开始服务；新活动不参与报价，新老板注册返回 503 且没有创建账号。测试中的微信绑定和已有券是预置业务事实，短信发送使用测试替身，未调用真实微信、短信或支付渠道。此结果不代表所有订单、售后、提现或后台入口均已验证。

Mac 独立三库通过专用 TCP 中继断开控制库的既有会话和新连接。两店使用可信路由和 License 快照，证照仍保留为未知。已验证原优惠券领取回执、钱包查询、用旧券实际付款、履约、拒绝新领券和开户，以及复连后从原时段核对 KOOK 积分。连接完成握手后断开时，驱动层既可能返回 MySQL 2013，也可能在复用已关闭的连接时抛出 `InterfaceError`。两种异常均沿用既有故障边界。该演练覆盖控制连接，整台数据库停机及真实 KOOK 接入仍待联调。[MySQL 验收记录](../../16-开发进度.md#2026-11-21-证照准入的-mysql-行锁和控制连接演练)

控制连接断开时，已验证实际 Celery worker 从两家静态登记门店的签名路由派发定时实销任务。两店同号订单分别完成本店资金结算。证照缺少在线依据时，VIP 和积分保留原决定待核。断连和复连后的重复扫描均未重复入账，已有停用凭证的门店不再派发。此用例使用独立内存队列和实际 MySQL。[周期结算验收记录](../../16-开发进度.md#2026-11-21-控制连接断开时定时任务继续本店结算)

两家店库保持在线、独立控制 MySQL 实际停止时，用 Beat 和专用 Redis 复跑了双店普通服务结算。两店分别保留本店的账本和权益待核记录。在线停用一店再停止控制实例时只派发另一店。独立 Beat 进程使用原调度文件重启，下一次发布接续原 60 秒间隔。控制恢复后，后续周期恢复在线枚举，重复派发保持原记录。其他周期任务仍待验证。[实例停机验收](../../16-开发进度.md#2026-11-21-独立控制-mysql-停机后的-redis-定时结算) · [Beat 重启验收](../../16-开发进度.md#2026-11-21-独立-beat-进程重启续用原调度)

平台财务身份和门店授权位于控制库，即使持有此前签发的有效令牌，每次访问仍需重新核验账号、权限及安全版本。现有本地签名快照只证明门店路由与 License，不证明平台财务身份、权限或撤权，因此不能拿它们授予离线终审和打款权限。控制库不可用期间，平台提现终审和线下付款登记不可用。已验证故障发生在令牌认证、初始门店授权或门店事务内权限重验时，接口返回 503 且提现状态、钱包冻结及平台操作流水不变；控制库恢复后可重试。

若门店提现事件和钱包变更已提交，但随后平台审计写入失败，响应的 `audit_status` 为 `PENDING`；这不改变门店事件或推定外部付款结果。控制库恢复后，原操作人可使用相同请求编号重试；授权平台人员也可通过 `GET /api/admin/platform/withdrawals/{slug}/{withdrawal_id}/audit-recover` 查看已提交事件的 `MISSING`、`RECORDED` 或 `REVIEW` 审计状态，再向同一路径 `POST` 提交 `event_id` 与原 `client_request_id` 补记。补记校验本店事件、原请求编号和当前人员权限，只补平台审计，不再次修改钱包；保存原操作人并记录补记人。控制库仍不可用时返回 503，以相同事件重试即可。SQLite 真实控制库审计 INSERT 故障注入验证了重试及付款事件不重复；隔离 MySQL 验证了同事件并发补记唯一，故障在该 MySQL 测试中通过替代发布函数模拟。外部实际付款结果不明时仍须单独核对，不能由审计补记推断成功。

后台提现审计扫描受 `WITHDRAW_AUDIT_AUTO_RECOVERY_ENABLED` 控制，默认关闭。启用后每次最多派发 25 个已初始化门店（含已停用门店），每店最多检查 100 条已提交事件，游标循环回绕以覆盖晚提交事件。任务只补审计。提交前控制库、门店库断线分别报告并回滚该批，保留原游标。事件和已有审计不一致时报告待核对。隔离 MySQL、独立 Beat、Redis 及实际 worker 已验证终审与付款待核对的审计补记、经 Redis 重派、控制库断线恢复及钱包和流水核对。队列失联、控制库提交结果未知及发布环境待联调。[定时补记验收](../../16-开发进度.md#2026-11-23-提现审计定时补记与断线续扫)

如果门店没有可信路由快照，系统无法在控制库故障时安全确认门店，相关请求会返回不可用。动态店及静态店混合部署已验证真实控制实例停机时的冷启动和定时实销扫描。平台统一身份服务和控制库位于同一故障域，独立身份服务断连、营业店库单独故障、全部平台财务资金流程及其他动态门店任务仍待联调。[冷启动验收](../../16-开发进度.md#2026-11-21-动态门店从签名索引冷启动)
