# 普通退款转单后加购接替

普通订单主单协商退款后发生真实服务转单、原履约归属进入退款 REVIEW 时，客服可按现有接替入口选择当前正在履约的转入陪玩。创建与每次确认会先校验本店普通转单能力域、最新真实资金版本、原钱包资金覆盖和目标履约段；目标抽成沿用本人分段快照。老板、原负责人和接替人仍各自确认，历史已完成份额保持原归属。

最后确认仍在原订单资金事务中调用 `refresh_for_event`，按实际接替更新资金版本并调用原到账 RELEASE 写入；后续退款与逐段结算仍走已有资金版本和责任份额路径，不重造原付款或已付收益。此接线依赖现有能力开关和资金事实，转单能力域不支持的时序、缺少版本或未结本人售后仍不能办理。

此外修复首次正数主单退款后、独立加购退款先于接替方案创建的场景，无需伪造尚不存在方案的失效凭证。未运行测试或迁移；最终联调需覆盖原付款来源、三方确认、共享到账正数与零 RELEASE、后续退款、整单补资及逐段结算和重复请求。
