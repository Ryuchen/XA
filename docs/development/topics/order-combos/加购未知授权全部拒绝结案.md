# 加购未知授权的全部拒绝结案

平台超级管理员核对加购会员成长和积分的原时点 UNKNOWN 决定时，如果所有未知项都确认 DENY，可通过原加购授权核对接口直接作零权益结案，不因后续退款状态或老板业务周期关闭而被卡住。服务端仍核对同店原账号与周期、付款流水和付款时会员开关、实销时间、原授权未知依据、实销前每笔已执行退款的钱包流水及来源方案，并复算原本金退款和积分基线；原证据缺失或矛盾时继续待核对。

只有全部未知项都拒绝才走此分支，不写积分、不恢复会员成长，不改变原付款、退款或已获权益；同一请求和平台审计沿用现有幂等及恢复流程。只要任一未知项选择 ALLOW，仍须通过原有全部当前付款/退款来源、净额和账号周期校验；控制库当前状态不会替代原时点事实。

参考 [Formance Ledger 的拒绝结果与幂等重放](https://github.com/formancehq/ledger/blob/main/docs/technical/architecture/subsystems/admission/idempotency.md)，本项目继续使用既有门店审计与平台授权，不引入外部账本。

按开发期要求未运行测试或迁移，仅完成 Python 语法解析。实际多次退款的原来源快照、同额退款、跨店和跨周期、并发核对及控制库审计失败恢复仍须隔离环境联调；缺少原时点凭证的旧事实不推断为零或可补发。
