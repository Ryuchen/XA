# 门店动态建库配置

平台按门店独立业务数据库创建和初始化门店。部署设置 `XA_DYNAMIC_STORE_DATABASE_TEMPLATE_ALIAS` 指向 `XA_STORE_DATABASES` 中已配置的非 `default` MySQL 连接模板后，动态建库能力默认启用；也可显式设置 `XA_DYNAMIC_STORE_DATABASE_ENABLED=false` 关闭。未配置模板时默认关闭，接口不接受用户提供的数据库账号、密码或任意库名。

门店数据库逻辑别名按 `tenant_<slug>` 生成，将标识中的连字符转为下划线。物理库名默认与别名相同。部署方可用 `XA_DYNAMIC_STORE_DATABASE_NAME_PREFIX` 指定物理库前缀，用于新环境登记独立库。前缀以小写字母开头、下划线结尾，最多 16 位，可含小写字母、数字和下划线。Web、worker 及迁移命令须使用同一前缀。已登记门店的归属指纹包含实际库名，变更前缀会拒绝访问原登记目标，不能用来迁移或接管已有库。

首次建库、结构迁移、门店初始化和首位管理员均按既有平台权限及初始化流程执行。仅注册连接不会创建数据库，部署方须为模板准备目标库的建库及业务访问权限，并在空库环境完成初始化。

恢复连接时使用平台控制库的原归属凭证，核对部署模板 `HOST`、`PORT` 和生成的库名。已有归属凭证的门店如果目标变化，先由平台运维检查配置，再重试。已初始化门店缺少凭证时须先核对归属。模板通过顶层连接字段设置目标，可继续配置 TLS、超时及隔离级别。会改变目标或在建连时执行命令的 MySQL `OPTIONS` 会被拒绝，包括库名和地址覆盖、socket 参数、客户端默认配置文件及 `init_command`。

控制库暂时无法读取时，允许降级的入口仍需核对已签名的本店路由快照。Mac 独立 MySQL 已通过网页接口创建一间动态店和一间静态店，并核对迁移、归属、首管及混合入口。独立控制实例停机时，新进程使用签名索引路由两店，实际 worker 在专用 Redis 完成同店扫描。缺失或篡改索引会拒绝相应动态店请求，在线配置前缀漂移在注册连接前拒绝。另有新动态店完成首次开业 API 验收，正式提交产生的索引已在控制库停机时通过新进程核验。两个动态门店并发建库及新域名浏览器入口仍待验收。[冷启动验收](../../16-开发进度.md#2026-11-21-动态门店从签名索引冷启动) · [首开验收](../../16-开发进度.md#2026-11-21-动态门店首次开业实库验收)
