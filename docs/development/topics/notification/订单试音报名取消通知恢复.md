# 订单试音报名取消通知恢复

真实订单从 PENDING 进入 CANCELLED 时，在同一状态迁移事务中，为该订单仍待处理的每位报名者保存取消通知意图；收件账号与周期取自原报名，按账号和原周期去重。提交后独立投递，失败由既有逐店报名通知任务恢复；投递时核对原报名、账号周期及真实取消状态日志。来源不明、离店或重入则记录跳过，不改变已完成的订单取消、退款及其他业务事实。

取消事务还把已有逐事件记录直接关联的邀请和组队确认消息更新为报名已结束；尚未投递的邀请或确认在获取同一订单锁后核验订单状态，取消后不会作为待处理邀请发送。无法与原报名意图直接关联的历史消息不靠文案猜测或批量改写；读报名详情仍以订单取消状态为准。已创建的站内消息不等于客户端收到实时刷新。

复用 `orders/0256_application_business_cycles`、`site_messages/0019_orderapplicationnotice` 和默认关闭的 `ORDER_APPLICATION_NOTICE_RECOVERY_ENABLED`，没有新增迁移；须应用依赖迁移并运行本店 worker/beat。最终联调覆盖老板与超时取消、单陪和双陪、多次报名去重、并发邀请投递与取消、消息更新和恢复失败、账号重入、两店同号、取消事务回滚及实际资金退款。客服新单仍走抢单池；其他通知和实时事件仍有缺口，正式注销保持关闭。本轮未运行检查、测试或迁移。
