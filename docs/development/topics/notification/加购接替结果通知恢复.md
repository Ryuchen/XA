# 加购负责人接替结果通知恢复

加购负责人接替方案在真实确认事务中达到最终结果后，若同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 与默认关闭的 `ADDON_HANDOVER_NOTICE_RECOVERY_ENABLED`，为付款老板、原负责人及接替人各保存一条通知意图。三方全部同意且原资金释放处理成功后提示接替生效；有人拒绝则提示未生效，单人确认但方案仍待其他人时不冒称最终结果。

老板使用原付款订单周期，两个陪玩分别使用对应持久履约段的原周期。提交后独立投递，失败由逐店任务重试；每个方案对每个账号最多创建一条消息。投递核对原订单、两段履约归属、三方决定和最终结果；方案已替换、来源不明或账号离店重入时记录跳过。消息不透露其他陪玩的个人分账金额，创建消息不代表客户端已收到；消息故障不回滚已提交的确认及资金事实。关闭开关沿用原仅刷新订单的路径。

本次不改变接替资格、确认、退款、分账及原有功能开放门禁。启用前须在各店应用 `site_messages/0034_addonhandoverresultnotice` 及依赖并运行逐店 worker/beat。最终联调覆盖三方逐次确认、任一方拒绝、重复请求、单双陪和多次转单、方案替换、资金释放失败回滚、消息部分失败及并发恢复、账号停用/重入和双店同号。其他转单通知仍未全覆盖，正式注销保持关闭；本轮未运行检查、测试或迁移。
