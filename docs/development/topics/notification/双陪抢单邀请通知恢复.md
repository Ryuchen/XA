# 双陪抢单邀请通知恢复

双陪组队 INVITE 回执本身保存真实受邀账号周期。开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `GRAB_INVITE_NOTICE_RECOVERY_ENABLED` 后，逐店任务扫描已证明按时且通行证事实已核验、尚无通知结果的回执，复用唯一回执投递记录补发；提交后的即时发送沿用原路径。投递前按账号、订单、轮次、队伍与回执的锁序重新核验来源和收件账号周期，消息失败不会改变队伍或抢单事实。

邀请在订单仍待分配、队伍仍等待队友且轮次为 OPEN 或 PARKED 时有效；首轮窗口结束本身不使邀请过期。总期限按生产开池证据的 PARKED 截止区间判断，时间有歧义则保留待重试；已结束、离店或重入记录跳过，无法证明的回执不发送，留待核对。邀请文案不披露订单内容。站内消息已创建并不代表客户端已收到。

无新增结构迁移，但启用前须完成既有 `orders/0248_grab_invitee_business_cycle` 和 `site_messages/0010_grabinvitenoticedelivery` 及依赖，在各店运行 worker 和 beat。最终联调须覆盖首次发送失败、重复与并发恢复、OPEN 转 PARKED 后确认、总期限、队伍退出或订单分配竞争、回执证据不明、双店同号和账号重入；正式注销仍关闭。本轮未运行检查、测试或迁移。
