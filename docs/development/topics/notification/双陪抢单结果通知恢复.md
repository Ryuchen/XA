# 双陪抢单结果通知恢复

双陪抢单池完成实际分配或重开时，同时启用 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和 `GRAB_RESULT_NOTICE_RECOVERY_ENABLED` 后，在分配或重开事务内保存每位实际参与人的通知意图。陪玩来源分别为本人 INVITE 或 CONFIRM 回执及所属队伍，老板来源为原付款订单周期；分配后赢家双方有派单提醒，未中队伍及重开参与者各有结果消息。客服安排新单仍走抢单池。

提交后逐人尝试创建站内消息，逐店定时任务恢复失败项；每个轮次意图位置至多产生一条消息。投递时在账号锁后复核所属轮次、队伍成员、原回执、中奖结果及收件账号周期；来源不明、离店或重入时记录跳过。消息发送故障不改变已经提交的抢单结果；消息创建不代表客户端实际收到。开关关闭时保持原有通知路径。

空库结构迁移依赖 `orders/0254_team_grab_notice_intents` 和 `site_messages/0017_grabteamresultnotices`，上线前须应用依赖迁移、开启两个开关并运行带门店上下文的 Celery worker 和 beat。须在隔离环境联调双店同号、双陪赢家与其他队伍、重开、事务回滚、单人失败后恢复、并发扫描和账号重入。留池资格失效即时通知不在此恢复范围；其他通知和实时事件仍有缺口，正式注销保持关闭。本轮未运行测试、检查或迁移。
