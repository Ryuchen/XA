# 特殊玩法加购协商退款通知恢复

真实加购协商退款完成入账和分担记录后，若同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 与默认关闭的 `ADDON_REFUND_NOTICE_RECOVERY_ENABLED`，在原退款事务中为付款老板及该方案实际承担退款的陪玩分别保存通知意图。老板消息描述实际退回余额的数量；陪玩消息提示查看本人订单与收益流水，不把未结算收益当成已到账。其他陪玩和推荐人不因本次通知额外获得信息。

提交后独立投递，失败由逐店任务重试；每笔加购退款对每个实际收件账号最多创建一条消息。投递复用已有只读加购付款及退款收据核验，核对双方确认、实际老板退款流水和陪玩分担记录，并核对老板原订单周期或陪玩原履约周期；缺失、冲正、来源不明或账号重入时记录跳过。消息故障不回滚已提交退款；创建站内消息不代表客户端已收到。开关关闭沿用原仅刷新业务数据的路径。

此功能不改变加购退款计算、售后范围或原有开放门禁；尚未接通的积分、转单、重复退款等组合不会因通知而开放。启用前须在各店应用 `site_messages/0032_addonrefundnotice` 及依赖，并运行逐店 worker/beat。最终联调覆盖实际可用的单双陪、加购接替与退款、余额/押金及未结算收益承担、付款/退款流水缺失或冲正、重复调用、并发恢复、账号停用或重入、双店同号及事务回滚。正式注销保持关闭，本轮未运行检查、测试或迁移。
