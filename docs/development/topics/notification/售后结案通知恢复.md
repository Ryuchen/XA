# 售后结案通知恢复

客服处理完成或实际协商终止调用统一售后通知入口时，若同时启用 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `AFTERSALE_CLOSURE_NOTICE_RECOVERY_ENABLED`，在结案业务事务中为原订单老板及适用的陪玩分别保存通知意图。每条意图固定原订单收件周期和本次结案历史事件的位置及摘要；同一售后单重开再结案会形成不同事件，通知记录不复制售后私密说明。

提交后独立投递，失败由逐店任务重试；每个结案事件和收件账号最多创建一条消息。投递时核对历史事件、订单来源周期、账号类型、在店状态和当前周期，来源不明、案件已重开或账号重入时记录跳过，避免把旧结案说成当前状态。消息故障不回滚已提交的结案及退款；站内消息创建不代表客户端已收到。开关关闭时沿用原按周期保护的即时通知。

须在各店应用 `site_messages/0020_aftersaleclosurenotice` 及依赖并运行逐店 worker/beat。最终联调覆盖普通结案、退款及协商终止、双陪与转单、重复结案/重开、部分通知失败与并发恢复、双店同号、账号停用与重入、业务事务回滚及真实资金一致性。售后处理中通知和其他实时事件仍未纳入此恢复链；客服安排新单仍走抢单池，正式注销保持关闭。本轮未运行检查、测试或迁移。
