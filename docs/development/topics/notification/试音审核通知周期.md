# 试音审核通知周期与恢复

试音报名记录保存报名陪玩的原业务周期；生命周期集成开启时，先持本店陪玩共享锁并核验原请求身份，再写报名。后台通过或驳回时，将原报名账号、周期和当次审核内容与审核结果同事务保存；消息只在审核提交后独立投递。

`AUDITION_NOTICE_RECOVERY_ENABLED` 默认关闭。它与生命周期集成同时开启时，本店任务按报名唯一恢复审核通知，创建消息或明确记录原账号离店、重入及来源不可核验而跳过；通知失败不回滚审核。仅开启生命周期集成时使用原周期保护的即时通知；生命周期集成关闭时沿用原通知路径。停用但仍在店且同周期的陪玩可收到已有结果。

首版空库新增 `audition/0005_signup_notice_cycle`，随后应用 `site_messages/0015_auditionnoticedelivery`（同时依赖 site_messages/0014）；启用恢复前须运行本店 Celery worker 和 beat。最终联调须覆盖通过与驳回、双店同号、通知写入失败恢复、并发扫描与重复调用、报名与注销竞争、重入跳过及审核回滚。其他通知仍未全覆盖，正式注销继续关闭。本轮未运行检查、测试或迁移。
