# 老板指定订单通知

老板在钱包付款时直接指定单陪或双陪的实际入口，在付款、ASSIGN 状态日志和陪玩席位同一事务内，为原老板及每位被指定陪玩保存通知意图。意图固定真实付款流水、安排日志、席位及对应原业务周期，不包括客服安排新单进入抢单池的流程。

提交后尝试投递；本店任务重试 PENDING 意图，每个安排事件及收件席位最多投递一次。投递前核对付款流水、老板实际操作、原席位和账号周期；付款或来源无法核验列 REVIEW，账号重入、订单取消、改派或席位已结束列 SKIPPED，陪玩开始服务后不再补发旧派单提醒。通知失败不改变已经提交的付款和安排。

`ORDER_ASSIGNMENT_NOTICE_RECOVERY_ENABLED` 和 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 均开启时保存可恢复意图；前者默认关闭。关闭时使用原周期即时通知并记录投递失败，但没有持久重试。启用前须应用首版结构迁移 `site_messages/0044_orderassignmentnotice` 及其依赖，并运行本店 worker/beat。未修改前端，未运行测试或迁移。最终须联调单／双陪、积分或零金额支付、付款回滚、并发扫描、改派取消、两店同号和账号重入；其他创建与履约通知未因此全覆盖。
