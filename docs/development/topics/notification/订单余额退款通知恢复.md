# 订单余额退款通知恢复

普通非积分订单的实际余额退款在原退款事务中，为原通知范围内的老板、相关陪玩及符合既有条件的推荐人保存各自通知意图。仅在同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `ORDER_REFUND_NOTICE_RECOVERY_ENABLED` 时启用；提交后独立投递，失败由逐店任务重试，每笔退款对每个账号最多创建一条消息。

退款记录未直接关联老板余额退款流水，因此仅在本订单对应金额的退款记录和成功余额退款流水各可唯一确认时绑定；投递再次核对实际流水、金额、账号和无冲正状态，无法证明则记录跳过，不猜测退款到账。收件周期取原订单老板、陪玩席位／履约段或推荐来源，重入、来源不明或身份无法对应时跳过。推荐人非订单参与者的既有钱包入口与可见范围保持不变；消息发送失败不改变已提交退款，站内消息创建不代表客户端已收到。退款记录本身缺失或与本次金额不一致时不生成通知，也不虚构来源。

此恢复链不覆盖积分及混合支付退款、直付退款、加购退款或其他未开放的资金场景，原门禁和原通知路径不变；同金额多次退款等无法唯一对应流水的情况保留跳过待核对。启用前须各店应用 `site_messages/0030_orderrefundnotice` 及依赖并运行逐店 worker/beat。最终联调覆盖售后全额/部分余额退款、双陪/转单及推荐人、同额多次退款、流水缺失与冲正、账号重入、双店同号、失败恢复、幂等并发及退款事务回滚。正式注销保持关闭，本轮未运行检查、测试或迁移。
