# 客服开始服务通知周期恢复

客服将已接单订单推进服务中时，沿用原有通知对象与文案：只通知原来会收到消息的在席陪玩，不增加老板或其他人员的提醒。真实 START 状态日志、在席陪玩原账号和业务周期及发送意图在同一本店事务内保存；提交后创建消息，失败由逐店任务恢复，按状态日志和席位幂等。

恢复时核验客服实际 START 日志、席位来源和账号周期；来源缺失或冲突保留 `REVIEW` 待核对，订单已结束、席位释放或账号注销重入时跳过过时待发送消息。旧即时通知在新恢复路径启用后停用，防止重复。已发送消息保留在原周期，列表沿用历史周期标识。

`STAFF_START_NOTICE_RECOVERY_ENABLED` 默认关闭，依赖 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED`；开启生命周期而关闭恢复时旧通知在事务提交后按原席位周期核验，缺来源记录告警，不能自动恢复。生命周期集成关闭时沿用旧规则。启用恢复前须执行 `site_messages/0042_staffstartnotice` 及依赖结构迁移并配置逐店任务。`REVIEW` 暂无专门后台核对页；其他尚未接入周期和恢复的发送路径仍需逐项处理。本轮未运行测试或迁移，需隔离联调单陪、双陪、状态变化、注销重入、失败重试及门店隔离。
