# 咨询关联协商售后

客服在原 `POST /api/admin/aftersales/open-negotiation/` 请求中可附加整数 `chat_message_id`，其余订单、原因、受影响陪玩、可选履约段／加购和操作编号沿用原接口。该消息必须是咨询人本人发送、正式关联当前订单的消息；客服须有原售后权限及该会话的接待或主管查看权限。后台在同一事务按生命周期、咨询账号、会话、订单顺序锁定并复核：老板必须是该订单原周期购买人；陪玩必须有实际订单关联、属于本次受影响范围，且咨询消息和订单来源周期一致。不可用的账号、来源或权限返回错误，不代造。

成功登记后，售后历史随原事务保存咨询消息、会话、账号和原周期。同一操作编号重放时连同消息来源核对；不同来源或内容返回冲突。方案仍由原协商接口发起，老板和受影响陪玩各自确认，客服沿既有执行入口核验并处理；没有新增退款记账。原有协商方案与退款执行开关及各资金场景门禁继续生效，不代表所有场景已开放或款项已退回。

本轮不修改前端，不新增或执行迁移，不运行测试。最终须在隔离门店环境联调双陪本人范围、客服转交／主管权限并发、订单卡片来源、双方同意／拒绝、重放冲突、账号重入及各退款资金构成。

售后历史中的咨询来源仅向当前有该会话读取权限的后台接待客服或主管返回；老板、陪玩及无会话权限的其他后台账号仍可查看其原有售后信息，但不取得私有咨询消息或会话编号。
