# 加购退款方案站内通知

客服创建真实加购退款方案时，在同店事务中为老板和每位承担人分别保存通知意图。老板周期取订单，陪玩周期取本次实际退款和承担涉及的原履约段；多个相关段周期不一致或无法核实时进入 REVIEW，不按当前账号猜测。提交后尝试创建站内消息，异常保持 PENDING；逐店重试开关 `ADDON_REFUND_PROPOSAL_NOTICE_RECOVERY_ENABLED` 默认关闭。

重试核对仍开放的售后和待确认方案、付款流水、实际份额与已冻结跨付款计划；本人已决定、方案结束或账号重入后不再发送旧待确认提示。已发提示在本人决定、方案通过、拒绝或替换时原位更新，不额外创建消息；方案通过仅表示已确认，不宣称退款已完成。当前只覆盖本次方案流程，外部短信／微信及 WebSocket 实际送达不在此恢复范围。

首次部署依赖 `site_messages/0047_addonrefundproposalnotice` 和前置 0046。开发期未执行测试或迁移，需最终隔离联调双店、多责任人、原周期和多段、方案变动、失败重试及数据库锁序。
