# 积分普通单退款后的平台补资

正式受控 MySQL 积分服务链中，平台财务对无服务中转单的订单登记已核实到账并分配补资时，平台入口及门店写入入口均使用同店同单 `funding` 资金上下文。此前退款后资金计划、协商终止事实和资金释放凭证回读没有接受这一阶段，导致已合法退款的普通订单无法继续补足资金。

现将该阶段接入上述只读核验及到账预锁，仍须逐项核实原积分和店币支付、退款及退回来源、参与人承担、已保存的协商确认、到账分配与释放凭证。平台财务身份、到账核实、跨库操作记录、请求幂等和原锁顺序沿用既有入口；这不授权在补资阶段执行退款，也不改变退款金额或分配规则。足额后既有平台提交后通知和定期任务继续按报单与等待期进行逐人结算。

对于原受控范围内双陪两次协商退款，补资阶段也可回读追加退款的终止、资金版本及释放凭证并预锁到账；原有退款次数、人员、时序及资金版本限制继续生效。首笔退款后的报单和结算回读也可核验已有到账用途账本。

适用范围仍受既有正式功能开关、同单业务作用域和各类退款资金证据门禁限制；不据此开放全部转单、加购、多次退款或其他尚未接通组合。未运行测试或迁移，正式积分与到账用途账本开关维持原值。最终须使用隔离 MySQL 联调本金／赠送／赔付混合支付、原路退款、双陪两次退款、补资不足及分次补足、多到账共享、双陪等待期、平台跨库失败恢复、重复请求、并发及资金守恒。
