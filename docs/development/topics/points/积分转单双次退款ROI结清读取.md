# 积分转单双次退款 ROI 结清读取

本轮修正双陪积分转单、两笔主单退款的经营 ROI 读取：只有实际付款的加购才进入资金版本核验；尚未付款的加购意向不再使这类订单误报待核对。存在已付款加购时仍按原资金版本、逐笔退款、实际份额及结算凭证核验，不把未付款意向当收入。

通过既有最终结算验证的订单，实际主单和加购收益钱包流水按各自入账时间列入已核实的结算证据；付款收入、实际退币、积分返还及推荐佣金仍分别沿用原有期间口径。平台多店聚合调用各门店同一 ROI 入口，未增加跨门店读取或资金写入。

ROI 的第二次退款读取按各人承担和钱包、押金流水核对，按实际各人承担总额校验退款回收额。不能核验的其他时序继续显示待核对。按开发约定本轮未运行测试或迁移；最终须在隔离环境联调多门店、跨月付款和各次退币／积分入账、未付款意向、已付及部分结算、佣金先后发放，以及实际加购退款版本。

继续开发：转单追加退款预览按实际履约份额逐人分摊、输出确认条款并按账号排序锁定；执行在原事务内逐人写入钱包、押金及承担凭证，累计回收额。资金版本和共享到账本地回放按全体参与人核对确认、分段收益、取整、钱包和押金流水。多人的单人数量门禁已移除，已结算人员、同一履约段重复售后及实际资金不足等原有条件仍有效；完整业务尚待隔离联调。

原积分 `funding_after_refund` 将差额并入门店净收益或抵减补资缺口；直接增加收入会重复或缺少资金。本轮改为先预留各笔已确认差额，再计算补资缺口与释放，最终结算从店铺总应付拆出差额流水，老板退款金额不变。

共享资金函数增加差额预留参数，首次和后续积分退款的主要预览、释放、资金版本、加购重建与到账回放已传入真实确认的累计差额；加购合并保留该预留。转单逐段及无转单退款结算在原结算事务逐笔写入并回读店铺流水。此为代码接线，尚未在隔离环境联调。

新增首版结构迁移 `orders/0269_points_refund_rounding_transaction.py`，为每笔积分协商记账关联独立差额流水；本轮未执行迁移，也未发生任何实际订单记账。

同一陪玩多段：`orders/0270_points_negotiation_segment_deduction.py` 新增逐段扣减事实与方案计划字段。预览按本人真实剩余段收益顺序生成分配计划，计划纳入积分资产摘要并向相关协商参与人返回；退款事务写入逐段记录，普通凭证核验及共享到账回放核对计划与记录，加购重建使用实际扣减。已移除本人选中多个履约段的数量门禁，已终止、已结算及余额不足限制保留。上述链路未运行测试或实际记账，两项迁移均未执行；多次转入转出、跨加购占用与共同承担的组合仍须隔离联调。

后续入口修复：转单二次退款和服务前改派的访问范围、加购资金选择按真实已付款加购判断；额外未付款意向不会制造收入或资金事件，也不会单独阻断主单退款。已有付款、退款和接替仍需真实凭证和事件版本；本次未扩展其他尚无凭证的跨加购时序。未运行测试或迁移。

跨加购回放修复：第二次主单退款后，未接替的目标加购退款可以同时消耗同一陪玩来自已接替和未接替的其他加购收益。原回放在出现一个接替来源后错误地要求所有来源均有接替；现在分别核对未接替来源的原付款、本人履约段、历史扣减和未结算状态，接替来源仍核对其真实接替与资金事件。退款执行、资金版本及后续结算沿用原事务与凭证。此路径未做隔离联调。
