# 积分非转单后续退款与加购

非转单积分订单在首次主单退款后，可按现有受控资金能力准备后续主单退款；后续退款版本记录退款发生前各笔加购的付款、退款、净来源和收益。售后按具体加购或整单绑定资金阶段，并核验每笔付款凭据；结算读取后续退款版本，不用事后最新加购数据替代历史事实。

到账释放见证按各笔已付款加购核对已付陪玩的收益流水，并保留未支付但已有预留的资金记录。主单退款后的新加购或退款如未纳入后续版本，仍须另建资金版本，现有核验会拒绝混用；不得将受限代码当作完整资金能力。

本次未执行测试或迁移。最终联调须覆盖双店、真实充值及积分支付、多笔加购先后付款和独立退款、两次主单退款、已结算与未结算陪玩、共享到账、收益与押金、失败回滚、重试及 MySQL 锁竞争。具体能否执行仍以现有业务门禁及到账账本能力为准。

## 同单双陪加购接替后首次主单退款（开发中）

非转单积分订单已有一次 `SAME_TEAM_V1` 加购接替、此前没有加购退款时，首次主单协商退款预览及后续报单、结算按已存接替资金版本和本人履约份额接线；到账用途重建核对此前接替释放，支持实际无到账释放的版本。退款结算读取本单兑换和服务订单两类真实到账归属。已有加购退款后再退主单、追加主单退款及其他未完成组合仍受限，不改变既有主单退款或陪玩收入事实。

以上为代码接线范围，尚未运行测试或迁移；最终联调须覆盖双店隔离、有／无到账、不同责任人分配、真实退款及结算、并发、失败回滚和重试，并核对用户确认的双方确认及完整资金凭据。

## 同单接替后先加购退款、再首次主单退款（开发中）

受控范围扩展至同单双陪无主单转单、一次 `SAME_TEAM_V1` 接替后，对该加购先发生一笔独立退款，再发生首次主单协商退款。到账重建按付款、接替、加购退款、主单退款顺序读取真实凭据，并核对接替及加购退款资金版本（包括没有释放金额的版本）；后续报单与结算继续读取本人净责任份额。多个加购退款、退款晚于主单或其他尚未接通的组合保持原有限制。

本次未运行测试或迁移；完整流程、双店、有无到账、不同受影响人、跨段扣减、并发与失败回滚和重试均须最终联调。

## 同单接替后主单退款、再退加购（尚未开放）

后续组合仍需在同一订单及资金锁内接通：使用首次主单退款及其终止凭据重建各本人仍可承担的履约段，按退款时点读取原加购付款、三方接替和实际主单退款；在加购退款事务内写入新的资金版本及到账 RELEASE，并支持无到账的真实空版本。`points_addon_handover_refund_facts.funding_facts` 当前的同单分支明确拒绝已有主单退款，后续 posting 的现有读取又要求转单结构；不能把该结构伪造成同单接替。`points_business_access.service_order` 的退款阶段尚未授予该组合，`addon_funding_release._record_after_main_refund` 及相应到账核验和按人结算仍须接入该非转单事实。入口继续关闭；未测试或迁移。
