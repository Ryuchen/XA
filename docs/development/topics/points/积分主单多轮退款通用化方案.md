# 积分主单多轮退款通用化

用户没有设置退款次数上限。同一主单每次售后仍须在对应有效期内立案，由老板及本次受影响陪玩分别确认，按照真实剩余付款来源、本人各段待结收益、钱包和押金处理；每席转单最多两次不等于退款最多三次。

当前 `PointsNegotiationPosting` 已按实际方案一对一保存退款及逐人承担；`PointsRefundRoundEvidence` 以 posting 唯一、`previous` 链和包含历次事实的 `snapshot.rounds` 保存后续版本，`points_refund_round_evidence.record_locked` 不以三轮为上限。这些结构可作为通用化的起点，但它们本身不授权退款，也不完成到账释放或结算。

当前正式路径仍有具体阻断：`points_third_refund_settlement_plan.build_locked` 限定三笔退款和唯一版本；第三轮专属付款、加购退款、接替、后续转单及到账回放以 third 版本定位，部分通过 `.first()` 或数量等于 3 读取；第三轮终止与历史复核也按固定前两次及第三次关系核验。直接放开申请或改用最新一行会丢失事件边界，不能保证同一到账不重复释放、旧段不重开或已结算人员不重复付款。

## 需要接入的通用事务

1. **预览和确认**：按同店已锁订单及资金锁读取全部已执行 posting，按实际事件时序核对前一笔退款、各方确认、每段实际待结收益、已付款加购及各次转单；按原本金、赠送、赔付和积分构成计算本次上限与本人承担，分别冻结方案哈希。无历史事实或事件顺序不可证实时返回待核对，不以当前席位反推旧段。
2. **执行和版本**：同一事务验证最新方案及当事人确认、逐人逐段扣款与押金可用额，写入真实退款、posting 和各来源流水；按该次真实资金计划逐笔写入所需 RELEASE。随后以对应 posting 写 `PointsRefundRoundEvidence`，`previous` 指向上一后续版本，核验原付款、前序轮次及本次版本；重试对同一业务请求回读原结果，不重复扣款或释放。首两轮既有凭证与后续版本须按实际来源衔接，不创建虚构退款或零释放流水。
3. **到账回放**：在持有到账锁的范围内，仅按事件中保存的本单分配、此前真实 RELEASE、轮次及后续加购或转单版本重放，逐笔区分各订单及各次事件。不得在到账锁后反向获取订单或资金锁；历史没有分配时保留真实空分配，后来到账不得倒灌到旧时间。
4. **最终结算与权益**：以最后已验证版本及其之后真实事件生成整单计划，合并已支付人员的原流水和未支付段，核对整单补资、各自报单、售后等待与冻结时间后结算。已确认关闭的旧段不重新开启，同一人合法转回按新段处理；本人此前已付流水不改写。实销、VIP、积分和成就仅在最终结算及逐笔原付款退款凭证可核实时确认。

各调用应复用资金代理现有的 `points_third_target_invalidation.record_termination_locked(order, posting)` 等事务能力，按实际受影响段失效待确认接替，不因轮数改变无关方案。需要把现有第三轮专属版本、后续事件和结算调用逐步改为显式传入对应轮次并核对前链，再从公开方案创建、确认、执行、到账恢复和结算全部接线；不得只创建读取助手或打开开关。

本记录仅为接线方案，未放开第四次及以后退款，未新增结构或迁移，也未运行测试。最终联调须覆盖多次退款、每席两次转单、同人新段转回、多笔加购交错、共享到账、零实际释放、钱包及押金不足回滚、已结算人不重复支付、跨店与幂等竞争。

逐轮历史前缀接线：现有 `points_refund_round_evidence.record_locked` 在第四轮及以后，除复用原 `_facts` 按真实 posting 和 RELEASE 回放外，还在同一事务读取并核对自第三轮起的每个已保存版本：posting 顺序、previous 前链、原订单、转单版本、快照摘要与对应历史前缀必须一致，且本次 previous 须是上一轮。第三轮的现有快照格式、摘要及调用不变。此改动只加强现有版本捕获与真实回放，不开放第四轮退款事务、到账释放或最终结算；这些真实入口仍需完成。未运行测试或迁移。

本轮新增受控 N 轮接线：`0287` 为轮次版本绑定真实后续 0285 转单，并在方案中固化已确认的前轮、资金事件、分配与资金快照。公开售后建案、预览、方案/双方确认和执行接入一个明确本人在服段的路径；执行复用原付款来源、收益→钱包→押金和退款流水，同事务写逐轮 RELEASE、previous 版本及结案，随后逐段清单/会员按该版本回读。第 N 轮后如有真实后续协商终止，结案事务会调用 0286 目标失效入口。

本轮进一步接入 N 轮前已有真实已付款加购：按各付款的退款、接替和历次主单逐份额扣减回放本人剩余收益，确认方案固化相关资金及实际待确认接替；本次协商终止实际命中的待交目标后，同一退款和结案事务写 0286、失效原方案，其他未受影响的方案不应失效。最终清单按实际付款、各段责任和已发生退款归集，独立会员权益仍以真实实销为准。

0288 为 N 轮后的真实加购接替版本增加前一轮关联：0286 失效后，仍有当前履约陪玩时可重新提出并由各方重新确认；该次 HANDOVER 按最近真实退款/接替/转单版本及现有分配计算 RELEASE，不修改先前版本。N 轮结束后没有当前履约人时，责任保留，不能伪造接替。

本轮继续接入第四轮及之后的真实加购 PAYMENT / REFUND：每次 0284 记录最近已结案 round 与实际付款、退款、接替和转单前版；按原 lot 退回，按各人逐付款/履约段承担、钱包和押金计算真实资金与 RELEASE。后续同类事件按实际先后继续连接，最终清单按真实付款及逐笔退款归集。仍须经过真实订单、同店资金及到账锁和原方案确认。
