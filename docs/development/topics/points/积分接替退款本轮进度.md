# 积分订单加购接替与退款进度

本轮接入同单双陪积分订单中，首次加购接替后对同一加购发生多笔退款，且期间发生主单协商退款的后端流程。首次主单退款后，另一位陪玩未提前结算时的第二次主单退款、第二次主单退款后对同一加购的追加退款也已接入。其他加购退款已补充本人其他加购及主单未结收益、钱包和押金的实际承担记录；其他已接替付款、已结算或转单等组合仍在开发。系统按已保存的付款、接替、主单退款与各笔加购退款顺序重建个人份额、补资释放和结算依据。

多项加购分别完成首次同单接替后，第二次主单退款之后逐项退款已有受限路径。上述多项接替路径要求各接替均发生在首次主单退款前且无人提前结算；首次主单退款前以及两次主单退款之间针对已接替付款发生的退款，已纳入实际资金事件。目标加购先部分退款或收益先被其他退款占用、再首次同单接替的剩余份额也已接入，包括此前没有其他同单接替的情况。

首次主单退款后，已终止主单履约的陪玩将其未完成加购转交本单当前履约陪玩的路径已扩展至多项，逐项三方确认并记录资金 RELEASE；已接替项目退款可与其他项目接替交错。目标付款在主单退款后、首次接替前自身部分退款的受限路径也已接入，接替只使用退款后的剩余基数和收益；其他未闭环顺序仍受限。

无转单双陪订单首次主单退款后，仍在履约且未结算的陪玩可负责新加购；付款、后续售后及资金 RELEASE 按该付款实际时点和负责人处理。两次主单退款后没有合法继续履约人员时，仍不允许新购买。

首次主单退款后的已接替加购退款，已按本人该加购、同单其他加购、主单的未结收益，再到钱包和押金的顺序重建承担。此前加购退款已扣过的主单收益不重复计算；相关来源和 RELEASE 仍待最终联调。

本轮还补充了主单退款后转单场景中的待接替责任绑定：接替需对应实际加购、转出段和转入段，方案被拒绝或替代后可针对同一待接替责任重新发起。加购已经部分退款后再转单接替时，已接入按退款后的剩余责任构建待接替份额，以及接替后再次退款的资金版本和个人结算。该流程已扩展到多项加购逐项接替；第二次接替已纳入服务前改派记录并按席位累计两次更换上限，更多事件组合仍在开发。

两席位分别转单时，已补充按事件时点关联对应资金版本、旧接替完成后再生成新版本及结算读取最新资金事实。首席加购在第二席后续转单后退款时，入口已按该加购最近一次实际责任版本识别；多版本后的第二次主单退款已接入到账用途及逐段结算代码。第二次主单退款后，已完成接替的加购退款已扩展为逐笔记录 RELEASE 和到账用途；新增付款或接替等组合仍受限。

首次主单退款与多版转单完成后，一名陪玩已经结算、另一名未结算陪玩再协商退款时，已接入已付主单及加购流水快照和剩余责任的补资计算；此前已支付的份额不得改写或重复支付。多版转单后、首次主单退款前已有陪玩结算且存在加购时，也已接入受限的已付流水快照与未结算人员退款路径；其他尚未完成的时序仍受限。

普通单陪及双陪订单经一次服务前改派后，已接入多笔加购付款、补资和逐人结算；每笔按实际负责人及其接入时抽成快照计算，当前每笔最多一次加购退款。RELEASE 使用新增的普通改派历史快照、摘要和到账用途分录。主单退款、加购交接、多次改派和服务中转单等组合仍受限。新增 orders `0241`，尚未执行迁移。

转单订单的第二次协商已接入服务中受限路径：受影响当前段按双方确认时间终止，其他席位仍履约时保持订单进行中；无剩余席位时结束整单并关联房间异议。首次服务中退款后，仅一名陪玩继续、无人已结算且补资足额的零退款终止已接入，不创建退款流水；其他零退款组合仍受限。

转单零退款终止现已扩展到已有加购的受控范围，冻结付款、退款、加购接替与资金事实；终止后的加购退款仍受限。已有人员结算时新增独立终止结算版本，核对原清单及实际收益、押金和加购流水，并保留已付事实以防重付；限首次退款后唯一当前席位、加购事件已完成且补资足额。新增 `orders/0242` 尚未执行迁移，所有分支均待最终联调。

终止后加购退款已接入事务内结算版本写入，历史核验按事件截止点读取付款、接替、退款和资金 RELEASE，并保护已付款人的收益流水。已有人员结算时，支持同单多笔未接替加购各退款一次：已有一次主单退款及零退款结算版本，各项退款责任须完全归属零退款终止时实际履约且未结算的人。多笔加购中同一付款再次退款、加购接替及多笔加购退款后转单等未接通顺序继续受限。

零退款终止后，同单多笔未接替加购中的同一付款可多次退款：每次重新确认，按剩余原付款来源、真实承担、到账 RELEASE 和连续结算版本记账，并纳入其他加购退款对该付款收益的实际占用。加购接替或主单退款后新增转单仍受限；已结算人不得承担。

多笔未接替加购已接入首次主单退款前已有退款、零退款终止后继续退款的受控时序；此前各笔退款须发生在首次履约转单之后，并有真实到账见证和零退款结算版本。系统按每次退款时已付款的加购、原付款来源及实际收益扣减核对 RELEASE。首次主单退款至零退款终止之间的未接替加购退款也已按实际事件顺序接入；同刻无法区分的事件、多项加购接替或零退款后新转单仍受限。

单笔加购的一次既有接替也已接入零退款后的受控售后：接替须在首次主单退款前完成且此前该付款未退款，零退款时未结算履约人须保有正额责任份额。系统核对老板和双方接替凭证、接替 RELEASE、已结算版本及实际退款责任；多项接替、接替前已退款和多付款叠加接替仍受限。

接替前已有部分退款的上游受控链已接入：单笔积分加购在履约转单前或转单后部分退款，再进行首次三方接替时，按真实到账、逐笔退款和 RELEASE 计算剩余责任与收益；接替快照、主单退款、后续转单／售后及分段结算传递同一到账见证。退款早于转单时须在转单前已有同一真实到账分配。范围限首次接替且接替前无主单退款；退款与转单同刻、接替确认期间退款及重复接替仍受限。

多笔积分加购部分退款、实际转单后逐项完成首次三方接替的受控链已接入：某项接替完成后可先退款其他付款，再按其实际剩余责任发起接替，历史资金按事件时点核验。每笔付款仍须在首次接替前已有退款，且任何接替等待三方确认期间不得退款；后续可进入限定首次主单售后、零退款及加购退款和逐段结算。重复接替、主单退款后新增转单及服务前改派叠加等仍受限。

无转单双陪积分订单首次部分退款后，最后一名陪玩仍在服务时可发起第二次零退款协商：老板与受影响陪玩确认后由客服结案，订单按实际终止完成并处理房间异议，不产生退款流水；两人的售后和报单时钟分别计算。

无转单双陪首次退款后，订单自然完成并仍在售后期内时，也可为剩余陪玩发起零退款协商；已结算人员及已有加购须通过真实凭证核验。另接入限定范围的后续正额退款：加购接替和付款均在首次主单退款前，首次主单退款后没有加购退款，且仅首次退款受影响人已结算；到账用途与本人已支付流水按分段事实核对。其他交错顺序仍受限。

上述已结算人员后的第二次主单正额退款进一步支持接替之后、首次主单退款之前已有加购退款的场景，按实际事件及 RELEASE 重算各履约段净收益。退款后新增付款和未接通的事件顺序继续受限。

首次主单退款后已有人员结算、同单存在已接替加购时，仍履约且未结算的陪玩可对自己未接替的加购提出退款；已付款人的实际分段收益继续按原流水核对。新增付款及其他未接通顺序仍受限。

已接替付款本身在部分人员结算后也接入限定退款：首次主单退款后，仅仍履约且未结算的陪玩对其本人剩余接替份额申请并承担，核对确认、既有结算流水及到账释放；已结算人不得作为该次退款承担人。新增付款和其他未闭合顺序继续受限。

接替加购的历史退款回放进一步核对退款发生时是否已有人员结算，并修正首次主单退款前购买但实际属于另一位未结算陪玩的加购身份；多笔退款仍依真实事件及资金释放计算，实际接口和最终结算待联调。

无转单双陪首次主单退款前发生的其他加购退款，已接入既有接替付款和后续退款的事件核验；主单退款后的其他加购按事件时本人的结算状态及真实履约段识别，已付款人的收益及各笔 RELEASE 保留原事实。

首次主单退款后、已付人员实际结算前完成的多项同单加购接替，已纳入后续退款的受控资金版本及分段收益核验；各付款仍须早于首次主单退款，且每笔只接替一次，后续退款由未结算责任人承担。新增付款及其他未闭合顺序仍受限。

首次主单退款后、某陪玩实际结算前，该陪玩本人承担的已确认加购退款也纳入历史；已付主单收入回读扣除结算前实际加购占用，结算后的退款不允许选择已结算人。同刻无法可靠排序的事件及其他未接通顺序仍受限。

普通无转单订单已补充多笔加购的付款、席位和先前退款 RELEASE 事件快照；多笔加购后主单退款的到账用途回读仍须完成跨订单安全锁序，因此该生产门禁尚未放开。普通主单退款专属 RELEASE 在到账本地回读时明确阻断，避免倒序取得其他订单资金锁；正常退款写入及其他到账用途不在该新增阻断范围内。

普通协商退款现已准备无锁重建：核对老板及陪玩确认、付款来源、加购历史、逐人承担、钱包和押金流水，并与原补资快照比对。共享到账分配、之前的 RELEASE 和到账本地用途仍须完整证明后才能接入回读并开放上述门禁。

无锁来源覆盖实际分配、平台补资凭证、先前加购 RELEASE 与本地用途事件，并重算本次释放额；已接入本次 RELEASE 的事务事件写入和正式回读，并扩展到上述限定范围内的多个到账。先前加购释放按事件发生时的履约人员回放，后续退出须有可核验的协商终止证据。其他尚未覆盖的历史释放类型、资金与结算组合仍受限。

普通订单协商终止后，结算入口按终止前席位快照、双方确认和终止凭证识别受影响陪玩的主单与加购收益，不再要求其仍处于当前履约人员集合；其他未接通范围的门禁不变。

普通订单主单退款前的加购退款到账回读已补充直接押金扣减来源，核对陪玩账号及业务周期、经办人、门店押金流水和原始退款；逐人结算拒绝重复的付款与履约段组合。多笔加购付款、主单退款和结算仍未完整贯通，生产门禁保持关闭。

普通加购退款重试可在主单退款前后重新核验原 RELEASE 快照及已启用的到账用途账本，不重复追加；两笔加购的其他事件组合仍在开发。

普通主单退款后的加购售后已接入限定路径：此前没有加购退款、无人已结算时，可对一笔加购进行一次后续退款；按目标加购、本人其他加购及本人主单的未结收益、本人钱包、押金依次承担。实际押金不足时整笔不执行；钱包扣款为零而需要扣押金时，在持有钱包锁的退款事务内保存余额、冻结金额、启用状态与业务周期证据，资金版本和到账回读据此核验，不生成零金额钱包流水。无锁来源核对确认、逐付款／履约段扣减、钱包押金流水及业务周期，同事务记录 RELEASE 用途并处理零释放及重试，后续沿已有逐人结算。其他情形继续受限；新增迁移尚未执行，均待最终联调。

普通无转单单陪和双陪的多笔加购已接入限定资金路径：本店到账均已启用用途账本，全部意向已付款且此前无加购退款或至多一笔加购已退款时可进入首次主单协商，终止后按原席位、真实退款和到账凭证逐笔结算。双陪时各笔可由同一或不同原陪玩负责，主单协商影响一人或两人均按实际责任确认；先退款加购负责人可不受主单退款影响。支持多个本店到账，按到账编号顺序记录释放并在各自锁内核验本地用途。后续加购退款只支持下述限定范围；未接通的历史释放类型、转单、多次主单退款及其他事件顺序仍受限。代码尚未运行测试或迁移，必须在最终联调核对接口、资金守恒、重试、双店和并发。

共享到账用途账本和本地来源核验已改为每批 256 条遍历完整记录，不再因账本超过 5000 条直接拒绝；仍在到账锁内核对序号、摘要、金额及各来源请求编号。订单补资分配、释放及预约取消的资金回读也改为分批读取，按到账编号顺序锁定并核对全部来源。逐分配余额、匹配编号及部分返回结果仍需随记录数量增长的内存，来源核验也可能有逐条查询；其他独立业务路径是否存在数量上限仍需处理。上述修改未联调，须在最终联调覆盖超过 5000 条、共享到账、并发、回滚与资金守恒。

转单退款资金回读和相关转单版本重建也已改为按编号分批读取全部分配及事件，不再因该路径超过 1000 笔分配直接拒绝；结果及历史快照的内存占用仍随记录量增长，其他业务路径的独立限制不因此自动移除。

平台及单店通行证退款补款对账的到账、操作、分配和退款事实改为按原稳定顺序分批读取，不再因该接口超过 5000 条直接拒绝；该接口仍返回完整数组，内存和响应体随记录数增长。跨库读取不是单一原子快照，门店不可读或事实异常仍按原规则标注，须最终联调双店隔离与大数据量。

积分订单报单候选移除原 1000 笔硬上限，按订单时间与编号分批核验全部候选后计算有效总数和页面；准确总数仍需遍历全部候选，不同请求之间的并发变化可能影响分页。最终联调须覆盖大数据量、订单状态变化及双店隔离。

积分转单零退款后的加购售后已扩展到多付款二次接替：各付款先有真实首次接替，首次主单退款后由实际转单冻结责任并逐项确认后续接替；零退款时核验全部接替、真实 RELEASE、每席更换次数及已付款份额，后续限定加购退款按当前本人责任和结算版本处理。当前仅支持各付款首次接替均在首次主单退款前、每付款最多两次接替、后续接替均在零退款前完成且相关资金版本和到账见证完整；未接替付款混入、更多接替、后续新增付款或其他未闭合时序仍受限。本次扩展未运行检查、测试或迁移。
