# 消费积分授权核对结案与来源

主单实销时会员成长及消费积分均为 UNKNOWN 时，平台超级管理员可按现有积分核对接口依据真实证据独立给积分决定 `DENY`，不再要求先把会员成长恢复。若积分决定为 `ALLOW`，原会员授权必须已核对为允许；会员未恢复仅在账号业务周期已经关闭或本金已全部退回时允许零额结案，不能产生积分。

任何积分补发前重新核对已完成的本店实销、老板钱包实际支付流水、付款来源归属及其总额、累计退款记录和退回钱包流水，按付款时积分倍率和当前未退本金计算；会员资料锁内写入既有幂等流水。原请求重试沿用原结果，后续退款沿用既有冲回流程。来源或退款不一致时保持待核对，不据当前 License 推断历史事实；已发生的订单、资金与权益不修改。

参考 [Formance Ledger 的幂等请求核对](https://github.com/formancehq/ledger/blob/main/docs/technical/architecture/subsystems/admission/idempotency.md) 对原请求和重放结果的约束；本项目付款、退款及平台权限按现有业务实现执行。

按开发期要求未执行测试或迁移，仅完成 Python 语法解析。积分抵扣、逐段转单、多次退款、礼物以及缺失交易来源的实际可达性和兼容性仍需隔离环境联调；无法由现有本店付款来源及钱包流水证明的组合保持待核对，不扩大退款或结算能力。
