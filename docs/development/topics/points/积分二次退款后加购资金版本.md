# 积分第二次主单退款后加购：开发中

非转单订单第二次主单退款后的加购付款或独立退款，需要在既有订单、门店资金互斥及到账锁内，先核实前一资金版本，再按实际事件记录新的主单及各笔加购净资金版本和 RELEASE。不能用第二次退款时的旧加购快照冒充事件后的结算事实。

已编写 `orders/0238` 的版本快照字段，及两次退款后事件的资金重建、同事务释放写入、到账来源核验和按事件顺序读取的初步代码。旧版本的加购读取按第二次退款前的付款、退款事实重建，不将之后的事件回填到旧快照。

已在受控代码中接入已付款加购的独立退款：事件前在同一订单与到账锁内预核旧版本，事件和新版本、RELEASE 在同一门店事务写入；后续资金核验、人员结算及展示读取按事件顺序核验的最新版本。当前限定两次主单退款后、没有任何陪玩已结算且没有第二次退款结算预留的非转单订单；已付款陪玩及其他未接组合继续拒绝。新代码尚未经过联调，已有业务开关默认值不变。

双陪 A 终止后 B 继续服务的后续协商已接入受控代码：在 `IN_SERVICE` 核对首次协商结案、唯一继续履约人和受影响段；第二次方案确认退款并终止最后一位陪玩时，按真实确认时间结束本人履约段，通过状态机完成订单，收益仍须等后续结算条件。当前限定未出现任何陪玩结算的非转单范围，资金、退款与结案仍在同一事务；代码尚未联调，不能视为验收通过。

进行中再次协商与加购仍须完整联调。首次退款后 B 继续履约期间的新加购付款已接受控代码：付款事务核对首次协商和继续履约、现有资金版本及当前负责人；付款、真实支付来源、整单资金版本与到账用途释放同事务保存。第二次退款后新加购付款仍未开放：最后一位陪玩确认终止后订单已真实完成，不能为开放加购伪造状态或使用旧快照。

已有已付款加购时，后续协商预览按独立加购付款及退款事实重建收益和补资，第二次退款保存当时的加购快照；完成后的独立加购退款使用 0238 事件版本。主单首次全退但 B 仍在服务时，加购发现和申请依据已记录的首次终止、主单全退及唯一继续履约人判断；真正付款仍在资金事务中完整核验，不修改订单履约状态。主单全退后没有剩余主单款项可再次退款；B 对独立付款加购的售后使用加购自身付款和退款来源。

已编写积分主单全退后 B 零退款协商的独立凭证（0239）、方案预览、老板与 B 分别确认、客服执行及状态机接线。客服执行在同事务核对原全退与整单资金，记录零额凭证、结束 B 履约段、真实完成订单并结案；不产生新退款或修改原退款。后续收益和加购仍使用首次退款及后续加购资金版本，等待实际结束后的结算条件。此路径限定非转单、首次全退、唯一继续履约人且无人结算；代码尚未测试，不能视为已验收。最终联调须覆盖无加购及多笔加购付款/退款、确认或拒绝、零额执行重试、房间订单、双方履约段与报单、未到期收益、同到账释放及失败回滚，验证服务期间不得提前结算，以及真实结束后的独立结算和 MySQL 并发。

零额结案后的报单及结算资金能力须核对该零额凭证与状态日志；主单退款实销与每笔加购实销分别核对实际净额和各自授权时点。带加购的正式结算上下文也使用退款主单实销确认，主单全退不产生主单消费积分，加购仍按自己的净本金独立处理。用户明确 A 与 B 均须在整单结束后才能结算：已补受控代码处理整单实际完成、A 已先结算而 B 尚未结算时，B 在售后期内发起零额协商；核对 A 的报单、收益流水、加购与资金预留，保留原完成时间与 A 结算，不生成新退款。B 仍在服务时 A 不可结算。上述新增路径及权益读取均未测试或迁移，最终联调须覆盖 A 先结算、B 售后、零额重试、随后 B 结算和独立加购实销，及凭证缺失、锁竞争与失败回滚。

零额协商允许在既有积分资金门禁范围内读取多项已付款加购及其独立退款；结案凭证绑定当时最后一个加购资金版本，重放时核验首次退款、此前各加购事件及该版本的整单资金，A 的既有收入和加购结算继续核验原流水。另已编写受控的加购退款入口：整单真实完成、首次主单全退、A 已结算而 B 未结算时，仅允许 B 独自负责且未发生接替的加购在售后期内由老板和 B 确认退款；实际写入前重核 A 报单、收益和加购结算及当前资金版本，退款按 B 的待结收益、钱包和押金承担，并同事务记录真实来源和补资释放。服务中 A 提前结算、已接替加购及 B 已结算等组合仍关闭。最终联调须覆盖多项加购先后付款/退款、A 先结算后 B 加购退款与零额协商的不同顺序、A 流水保持不变、实销及授权快照、重试和失败回滚。以上均未运行测试或迁移。

针对 A 已结算后 B 连续多次加购退款，受控写入在每次退款和 RELEASE 后、同一门店事务内重新核验 A 的主单及各加购原收益流水，再以最新逐事件资金版本更新尚未终结的结算汇总和补资占用；下一笔须重新核对该版本。既有 A 的个人结算、原完成时间和支付流水不改写；整单补资不足或 A 收益被波及则整笔退款回滚。各笔来源及 RELEASE 仍以实际持久事件核验，新增路径尚未联调。
