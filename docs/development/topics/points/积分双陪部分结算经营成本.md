# 积分双陪部分结算的经营成本

本次补充普通双陪之外的积分订单报表路径：同一门店、原双陪席位无主单转单，已发生两笔正金额协商退款且整单补资足额。部分结算包括两类：一位陪玩在第二笔退款前已结算；或第二笔退款前两人均未结算，后续一人结算、另一人等待。允许有已付款加购和加购退款，各笔加购最多一次已生效的同单双陪换人。

读取报表时，系统复用两笔积分退款和售后凭证、原付款来源、门店补资版本、首位陪玩的报单与钱包入账流水、加购已结算流水及另一位的应结份额。核对两人的主单和加购收益与整单资金版本守恒；无法核对时保留待核对。收入仍按付款日期、退回店币按退款日期计算，积分返还单独列示；陪玩应计成本分别按付款及退款发生日期确认。门店赠送及赔付来源按原付款与原路退还分别核算，推荐佣金仅按主单实付口径计算。

已核实订单通过经营报表 `operating.partly_settled_provider_evidence` 列出。`income_posted_in_period_fen` 是查询期间已发生的陪玩钱包收益入账，不能当成提现打款；`pending_main_fen` 和 `pending_addon_fen` 是 `observed_at` 查询时点尚待结算的主单及加购收益，不是所查询期间末的历史余额。该列表只包含本次查询中符合凭证范围的订单，并非全店全部在途负债。

换人通过实际付款、同单三方确认、客服审计、换人资金版本和逐段收益核对；换人前的加购退款及收益扣减以现有已核实凭证为准。换人确认时的总收益与换人前尚存收益之差，按确认发生期作为陪玩应计成本调整一次，后续退款继续按实际退款期冲减，避免重复计算。整单已结算的订单也须完成最终结算与资金版本核对；未全员结算时仅在上述一人已结算路径提供入账与待结算详情。

首次主单退款后发生换人时，必须由该笔主单退款后的资金版本证明原陪玩已终止、接替人为本单继续履约的陪玩，并核对换人前后实际加购退款、三方确认及资金释放。第二笔主单退款后的加购付款或退款，须按每笔事件串联并核对后续资金版本；若该版本建立时双方均未结算，在完整核对最新资金版本后可继续核算，并可在随后一人结算时显示入账和待结算事实。现有资金凭证对该组合要求换人发生在第一笔主单退款前；第一笔主单退款后换人再发生此类后续事件，尚须由资金版本证明，无法证明时仍待核对。

换人时间与首笔退款同一时刻、或者不早于第二笔主单退款时，保持待核对。每笔加购多次换人、第二笔主单退款后的资金版本建立前已有个人收益结算、主单转单、补资不足或缺少确认与资金凭证的场景也保持待核对。

本次核查第二笔主单退款后再换人，现有业务尚不能形成可验证的正式资金链：`orders/addon_funding_release.py` 的 `_record_after_main_refund` 在主单已有两笔退款且事件是换人时直接拒绝；`orders/points_followup_addon_version.py` 的后续事件链只登记加购付款和退款，没有换人事件及对应资金版本。现有换人入口还要求主单处于服务中，而双陪后续协商可使整单完成。即使存在三方确认或个人收益快照，也不足以证明该时序下补资释放和各方收益守恒，因此报表不自行推算或开放该场景。后续须先由业务端明确可换人的履约状态，并建立换人确认、逐人收益、退款与整单补资的可校验连续版本；其中已有陪玩结算与未结算两种情况均需分别核实后再接入报表。

按要求本次未运行测试、检查或迁移，也尚未联调。最终联调需覆盖：首位陪玩及其加购先入账、另一位等待、两次主单退款后再加购或退款并逐人结算、主单退款后换人及其前后加购退款、换人前后不同抽成及跨月收益差、跨加购扣减、主单和加购跨月退款、赠送及赔付原路退款、补资不足、零收益、已入账流水被冲正、积分返还、双店隔离，以及成本查询与收益结算并发。若退款记录与客户钱包退款流水落在查询期间的不同侧，期间结果保持待核对。
