# KOOK 授权待决在线队列

engagement/0048 增加按本店 KOOK 绑定及业务周期隔离的处理游标、区间处理状态和独立处理事实。真实监听在某个有效区间授权未知后，保留此后的实际区间、当时授权结果及实际读取的积分开关，但暂停该周期继续发放。平台超级管理员依原入口和原请求编号裁决最早待核对区间；结案后在同一门店事务依时间顺序处理已有明确授权的后续区间，遇下一未知区间继续等待。拒绝的区间不计时、不补发；已发流水不改写。账号重入使用独立周期游标。自动监听停用后的人工在线登记如发现本周期仍有待决区间，提示联系平台先按时间处理，不能绕过队列。

此切片仍使用原规则版本 0：每 7200 秒 1 积分；未开放按店修改语音规则。尚须实现规则生效时点分段、各规则余量结转以及人工真实在线来源的同一队列，再完成 UNKNOWN 跨规则审核，不能把待决队列视为完整倍率功能。未运行测试或迁移；最终须联调多次未知、允许／拒绝顺序、断连、原请求重试、退店重入、跨库审计失败、锁顺序及两店隔离。

0048 的周期游标同时持久化原规则版本、已确认在线余量和已累计但尚未发放积分；正常计时、UNKNOWN 审核及后续排队重放时同步核对或更新。此状态当前只使用规则版本 0；规则切换、不同规则区间分段和人工来源共用游标尚未接通。

人工在线来源使用本店账号+业务周期游标，无需伪造 KOOK 绑定。`POST /api/admin/external-points/` 的 KOOK_ONLINE 请求填写 `observed_start`、`observed_end`、`online_seconds` 和真实 `source_id`；有序来源按现行规则累计完整组与余量，原请求重试复用结果。已处理时段之前的补录、或此前有未知授权时，保存 PENDING_REVIEW 并返回 202、无发分；`GET` 同一路径由 `engagement:points` 查看本店待核对记录。

独立平台超管可通过 `GET /api/admin/platform/store-management/<store_id>/kook-manual-review` 查询，`POST .../kook-manual-review/<id>/resolve` 以 `request_id`、`outcome`、`reason` 和整数 `points` 记录人工核对结论。允许结案时校验原账号周期、已保存真实时段、重叠、较早未决事件、积分开关及原固定规则；明确填写差额不得超过该时段及现存余量可产生的整数积分，形成独立幂等积分流水、保留平台审计和原发放事实。拒绝时差额必须为零；证据不足继续待核对。未绑定账号的真实人工累计保存在账号周期游标，后续真实绑定时结转，不虚构 KOOK 身份。

平台裁决明确代表人工核验的结论，不代表自动验证外部 KOOK 来源或跨库原子提交；平台审计失败按原请求重试核对。金额、历史授权和原事件真实性仍须由平台人员核实。上述管理接口、并发锁序与原请求恢复均未执行测试或迁移；语音规则变更及跨版本分段仍未实现。
