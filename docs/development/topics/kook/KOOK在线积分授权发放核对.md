# KOOK 在线积分发放时授权核对

KOOK 在线监听按既有真实在线事件和 30 秒心跳累计，仍按每两小时一积分及原流水键幂等记账。本次在达到发放门槛且锁定会员资料后，再核对当前门店 License；批次期间到期、降档或控制库故障，不再仅依赖批次开始时的旧结果。有效及宽限期按既有政策判断，已发积分和已有权益不受影响。

最终判断为拒绝或无法核验时不发放该次完整积分，将对应整段累计从后续可发放基数中排除，保留不足两小时的余量；因此恢复授权不会自动把这次未发部分当成新积分补发。对应账号、业务周期、累计时长、待发数量、判断和时点写入本店 `kook-license-points` 审计记录；开始核验即未知时，对符合监听规则且实际跳过的在线区间也保留事实。确认不创建积分流水，审计失败会随本店事务回滚，事件可按既有监听机制恢复处理。核对记录不自动认定历史授权或自行补发；人工处理入口尚未实现。

参考 [NestJS 幂等事件处理](https://github.com/nestarc/idempotency) 中对无法确定结果保留处理事实的做法；本项目账户、在线累计和授权规则仍以现有代码及 PRD 为准。

本次仅完成 Python 语法解析，按开发期要求未运行测试或迁移。仍需在隔离环境验证授权边界、可信缓存故障、连续心跳和事件交错、重试、双店隔离及审计查询；不代表真实 KOOK 连接或积分完整链路已验收。
