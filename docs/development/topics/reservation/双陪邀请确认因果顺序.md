# 双陪抢单邀请与确认的因果顺序

双陪首轮排序核验完整队伍时，邀请和队友确认的数据库提交观察区间可能因快速操作而重叠。正式 MySQL 写入路径中，确认事务先持同一订单锁，读取已持久化且属于该队伍的邀请与成员凭证，之后才创建确认收件；因此在同轮、成员及原始凭证均核实且数据库生成的收件顺序一致时，可据此证明邀请先于确认，不再仅因两个观察区间重叠阻断这支完整队伍。

重叠区间需要核对正式写入保存的阶段截止、两位成员的周期保护和邀请时保存的受邀人周期。凭证缺失或有矛盾时，仍按各原观察区间核对。确定反序的收件进入待核对。

此因果判断只用于同一队伍的邀请／确认。不同队伍和单陪候选的完成时间继续按原区间比较。通行证可见时间、各人资格和完全同分重开继续按原规则核验。隔离 MySQL 已用真实观察验证快速确认及缺证反例，无新增迁移，正式抢单开关保持默认值。正式双店物理切换待联调。[回归记录](../../16-开发进度.md#2026-11-23-抢单库存与重开回归恢复)
