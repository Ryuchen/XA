# 退押金与全退加购的零收益结清

本人负责、未发生加购接替的加购全部退款后，若真实逐人结算在原履约段留下零收益凭证，退押金资格会核对原付款、已确认退款、本人报单、结算父记录及整单结算时间，并将该零收益结算时点纳入七天起算依据。退款各方的实际承担和流水仍由既有核验处理；没有收入不虚造入账。

其他未结订单、售后、收益和冻结仍会阻断退押金；无法核对、涉及其他接替或不符合现有零收益结算形态的记录仍待核对。未运行测试或迁移；最终须在隔离环境联调全额退款后结算、七天边界、后续新业务、并发退押金及不同门店隔离。

已接替的加购全退后，结算计划可能没有剩余加购行。对 STANDARD 和有完整资金事件的 VOLUNTARY 接替，资格读取真实付款和各笔退款、逐次三方决定及客服审计，并核对本人对应履约段、实际逐人收益和已完成的整单结算；无收益不补造加购流水。曾经承担但未保留份额的接替人也按真实接替段查找。VOLUNTARY 在只读路径核验接替前责任、已确认分段、主单实际退款及到账分配和释放来源，不在已持陪玩钱包锁后反向获取订单或到账写锁。七天起点仍取相关结清事件中最晚者。

本次覆盖当前全退后无剩余加购结算行且该人的主单逐段结算和整单最终结算均可核实的情况；此前已支付的加购收益行、无法证明的交错版本和其他结算形态仍需继续接入，不是产品规则限制。未运行测试或迁移，最终须在隔离 MySQL 联调跨付款退款、多次接替及拒绝重提、共享到账、押金退还和结算竞争。

已付款的本加购收益段若仍有正剩余原价份额，全额退款必然包含该陪玩；当前 VOLUNTARY 积分退款入口会拒绝已结算人员承担退款，并且执行时不会扣已付收益。因此该已付段之后再将同一加购全退并非当前可达链路，不能在退押金核验中构造退款或清除原收益。已付其他陪玩但其不持有本加购剩余份额时，仍按实际可证明的本人结算与退款事实判断。
