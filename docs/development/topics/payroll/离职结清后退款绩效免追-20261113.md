# 离职结清后的退款绩效免追（2026-11-13）

已确认工资涉及的实际退款，其客户退款流水发生在员工线下工资结清之后时，不再从该员工后来工资扣绩效；工资确认期间同步捕获免追事实，员工重新安排工资也不会重复扣。此前发生的退款仍按现有绩效与提成规则处理，已确认工资快照不改。

逐店任务在工资事件屏障与工资锁下扫描已结清员工的已确认工资和真实退款，保存逐笔绩效调整、原退款、结清记录、金额和免追原因，不依赖员工重新入职。失败记录日志并留待下次扫描；写入使用唯一调整关联保证幂等。已授权 `salary:view` 的本店后台可通过 `GET /api/admin/payroll/separation-settlements/?settlement_id=<id>&after_id=<id>` 分页查看已捕获记录；未捕获不代表没有符合条件的退款。

需各店应用 console/0036 及依赖，启用现有工资退款核算和事件屏障，并运行逐店 worker/beat；依赖真实退款流水与原工资快照，无法核实的来源等待重试。未运行测试或迁移；最终联调须覆盖结清前后退款、同月提前确认、重新入职、主单和加购退款、工资确认并发、重复任务及双店隔离。

补充：同一员工存在多次离职结清时，以退款实际入账前、覆盖原工资月份的最近一次结清作为唯一免追归属；不同结清的恢复扫描共享相同选择，不重复或错误改挂已保存记录。员工账号重新启用不自动代表入职：授权人员须在账号及本店后台身份均启用后，通过结清接口提交 `action=reemploy`、`account_id`、最近一次 `settlement_id` 和 `reason`，留存登记人及原因。登记后可安排原结清月份之后的工资，再次离职时可使用新的最终工资期结清。若重入当月工资已确认，原快照不改，迟核业绩使用既有下一期补发入口；同月薪资安排仍遵守每人一份约束。

新增登记不替代人员人事资料或自动核验线下入职时间；实际入职与账号启停的并发、同月迟核业绩采用的方案快照、再次离职及多次退款交错仍须最终联调。本次未运行测试或迁移。

边界修正：现有已确认月的迟核工资代码按原月工资方案及基数计算；如果业绩发生在该月重新入职之后，现有四类人工业绩迟核入口现明确返回待核对，不能误用旧周期方案。重入后同月的新方案生效时点、派单／充值及门店绩效跨期分组、退款重放尚未接通，不能把重入登记当作该组合已完成。后续须按真实新方案及生效时间接通，不能更改既有确认工资。

重入后的同月薪资方案采用 `set_reemployment_plan` 动作明确登记 `reemployment_id`、`plan_id` 和方案 `revision`，服务端记录方案快照及登记生效时间，不倒推此前业绩。该时间后的同月派单与充值迟核以新快照及独立基数计算，迟核派单后续退款关联新方案分组；配置前发生的业绩仍待核对。同次重入可追加方案快照；多版本绩效封顶、加购及门店绩效分组尚未接通，是待开发限制，不覆盖原版本。新周期实际入职时间、晚登记及跨期退款仍须最终联调。

补充更正：同次重入现在允许追加不同薪资方案版本；每版保留实际登记时间和快照，同版重复提交返回原记录，迟核派单及充值按业绩发生时最后生效的版本分组，派单退款提成沿原版本回放。重入当月存在多个版本且涉及绩效，或该月派单退款影响绩效时，自动核算仍明确待核对；加购与门店绩效仍未按新周期接通，不能视为完整工资闭环。

同月重入后的加购迟核已接入明确版本：加购原真实付款时点选取已生效重入方案，以真实原派单记录确定人员，扣除已核验的加购退款后计算提成；工资确认后的后续退款按该笔已确认新版本来源回放。不同版本和旧周期分别累计，不覆盖旧工资。仅不含绩效的方案暂可通过该路径，涉及绩效等待用户口径；缺新方案、原派单或无法证明夜班时段时待核对。重入方案登记同时保存当时日夜班配置版本；配置随后变化而缺少完整历史时保守待核对，不能假称变化时点已证实。未运行测试或迁移。
