# VIP 停用期间的等级停用

本店 VIP 已关闭时，等级停用在完成既有权限、预览和券保护核验后，只保存等级停用与当前延期周期，不在关闭期间变更老板等级或发放升级权益。该行为不再依赖 `VIP_THRESHOLD_RECALC_ENABLED` 的当前值；停用前已经保存的规则基线不会被覆盖。

`GET /api/admin/club-config/` 无论重算开关是否开启，均返回 `vip_deferred`：存在停用周期时显示 `pending`、`baseline_known`、`epoch`，否则为 null；该读取不会执行重算。重新启用仍须经过已有钱包与配置锁、预览及权益核对流程，重算能力未就绪时保持延期，不能视为已完成。未运行测试或迁移；需在隔离库联调关闭 VIP、停用等级、开启重算、恢复及已发券保护。


补充：VIP 关闭且重算开关当前关闭时，本店后台可以新增启用等级、变更等级消费门槛或重新启用等级；配置与延期周期、原基线是否可信及审计在同一事务保存。此时不改变老板等级、不补发权益；等级顺序变更及停用仍沿用各自原流程。后台 `vip_deferred` 如实显示待处理状态，恢复 VIP 时仍必须通过原重算和保护条件，不代表开关已开放。未执行测试或迁移。


## 恢复入口

本店 `GET /api/admin/club-config/vip-resume-preview/` 按停用基线和当前净消费生成有时效的核对令牌；有 `engagement:edit` 权限的员工通过 `PUT /api/admin/club-config/` 提交 `vip_enabled: true` 和 `vip_resume_token`。事务依次锁老板配额、各老板钱包、本店配置和权益，重新核对预览，按停用前基线与当前有效等级重算；新达等级按现有发放、License 和幂等规则补发，已发券及权益条款保留。基线无法证明时继续生成待核对记录。响应的 `vip_resume` 给出处理数量和人工核对数量；GET 的 `vip_resume_recalculation_available` 表明恢复实现是否可用，与单项等级修改的重算开关分别显示。

平台独立超级管理员的首次开业配置入口也在既有授权和本店配置事务中复用该恢复流程。普通未发生月券切换的门店不需要开启全局门槛重算开关；已发生月券切换但对应规则不可用时仍明确阻断。停用期间新增等级和修改门槛的配置已保存，但 VIP 开启时的其他等级增删改仍受其原开关约束。消费来源复用实时会员净消费计算，包括已核准 UNKNOWN 的原付款及退款校验；来源不完整时不推断金额。

本轮未执行测试或迁移；还须在隔离环境联调两店、恢复期间开户和退店、门槛/券并发、License 状态变化及已发权益与人工核对结果。
