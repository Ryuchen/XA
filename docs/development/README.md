## 实施原则

1. 保留一店一独立业务库与现有三端页面，优先打通真实功能，避免视觉重设计；兴安继续 `xinan` 和原独立库，不迁回 `south`。老板与陪玩分别使用门店域名，后台统一入口。
2. 沿用 Django、MySQL、Redis、Celery、Channels 与现有 React 页面及服务；优先扩展已存在的模型、路由、幂等和审计，不另起三套业务服务或迁移数据库体系。
3. 所有金额明确单位：当前钱包与订单内部 10 个记账单位为 1 店币，人民币 1 元为 10 店币；薪资使用人民币分。新增支付须为整数店币，历史内部单位不可凭空舍入并改写。
4. 门店业务写入在对应门店库内成一个事务，平台目录写入是另一事务；跨数据库及线下付款不假设存在原子提交。以持久状态、幂等、可重试和逐店对账完成衔接。
5. 原价、折后成交、积分抵扣、实付、已退店币、已退积分及门店补贴分别保存；禁止让一个 `amount` 同时承担以上语义。
6. 以已付款快照和真实历史流水为依据，配置修改不追改已发生交易；历史未结订单按 [切换方案](08-房间加购与历史切换.md) 与 PRD 接管，已开始的计时和原有抽成快照保留。
7. 应用的登录规则以用户最新确认的三端统一密码加短信／OTP 和绑定微信后快捷登录为准；这覆盖仓库较早协作记录中老板只用微信的规定。真实微信头像和外部渠道能力须验证，不制造成功状态。
8. 独立研发复核发现的设计风险、现有实现位置和取舍见[研发评审](12-研发评审与待核实事项.md)。

## 交付边界

本文是可供拆任务和验收的设计，不等于数据库字段已新增、接口已上线、真实微信或线下打款已联调。参考薪资表原图本轮未取得，薪资部分依已有文字记录设计，具体岗位数值由配置提供；积分汇率等未提供的数值不能硬编码。原有 [`产品开发文档_兴安电竞陪玩平台.md`](../产品开发文档_兴安电竞陪玩平台.md) 保留为历史参考，不作为本轮三端路线依据。
