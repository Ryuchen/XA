# 试音报名直接提交录音

老板招募试音新增 multipart 接口：`POST /api/orders/orders/<order_id>/applications/recording/` 接收 `audio`、`client_request_id`、可选 `title`、`team_size` 和 `partner_id`；`POST /api/orders/orders/<order_id>/applications/<application_id>/recording/` 接收同一录音字段及 `action=CONFIRM_TEAM` 或 `SUBMIT_VOICE`。旧录音仍通过原有 `recording_id` 接口选择。

上传复用本人录音库的格式、大小、音频内容、门店身份和请求编号校验；同编号相同内容重试复用录音，不同内容冲突。录音入库提交后调用现有正式报名或本人确认事务，双陪各自提交和确认；报名失败时响应包含 `recording_saved` 和 `recording`，录音保留供选择或同编号重试。异常断连可用已有录音查询接口按原编号恢复；存储成功而数据库结果不明时沿用录音文件审计清理，不能直接删除可能已提交文件。

未执行测试或迁移。最终联调需覆盖双陪分别确认、同编号并发、上传成功后报名失败、断连恢复、账号周期和跨店隔离及文件审计；本切片未改前端。

录音库读取、上传、查询及移除在账号行锁内始终复核请求所属门店和原业务周期；注销或重入与请求竞争时，旧请求不会写入新周期，既有已提交报名的录音文件仍按原规则保留。该校验不依赖正式注销功能开关。
