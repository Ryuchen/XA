# 抢单超时取消通知恢复

单双陪抢单池在真实轮次仲裁后超时未分配而取消时，在原取消及退款事务中保存老板通知意图；既有待接单超时任务也使用相同入口。开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `ORDER_TIMEOUT_NOTICE_RECOVERY_ENABLED` 后，提交后独立投递，失败由逐店任务重试；每个订单最多创建一条超时通知。待发送消息按原订单老板周期核验，账号退店重入或来源不可证明时记录跳过。

消息金额方向来自实际退款事实：有店币退款时提示退回余额，有积分退回凭据时才提示积分退回，不把仅积分退款描述成余额退款。投递再核对超时自动取消状态日志、订单与退款关联；积分退款须有最终退款及相应流水凭据。提交后消息故障不回滚取消、退款或权益；站内消息创建不代表客户端已收到。开关关闭沿用原周期保护的即时通知。老板主动取消、客服核对取消、售后退款和微信直付退款预留不在此恢复范围。

须在各店应用 `site_messages/0028_ordertimeoutnotice` 及依赖并运行逐店 worker/beat。最终联调覆盖单双陪抢单池的窗口、留池和总期限、老板取消并发、未付款与纯积分/混合支付退款、退款与通知回滚、消息失败重试、两店同号和老板退店重入；正式注销保持关闭。本轮未运行检查、测试或迁移。
