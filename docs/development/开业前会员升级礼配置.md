# 开业前会员升级礼配置

初始化中的门店，首位本店超级管理员可通过原 `GET/POST /api/admin/club-rewards/` 和对应明细接口查看、新建与维护奖励配置，使 VIP 等级可以引用本店不在积分商城上架的服务、冠名或标签升级礼。继续执行原有 `engagement:view`／`engagement:edit` 权限、奖品字段和引用校验。

未获商城授权时可以配置不上架的升级礼，启用并上架商城仍须通过原 `POINTS_SHOP` License 校验；该初始化白名单不开放积分兑换、抽奖、领取或权益发放，也不新增开业前置。门店数据库隔离与平台/本店权限不变。

## 删除引用保护

奖励删除在本店事务中先锁会员配置、等级和目标奖励；启用或停用的 VIP 等级仍在 `upgrade_rewards` 引用该奖励时，须先移除引用才能删除。原有停用操作仍可使用，不改变已发权益。门店与平台等级写入共用配置锁，并对待保存奖励执行锁定当前读，防止 MySQL 旧快照下与删除并发形成悬空引用；影响预览仍为只读。

该保护现同时覆盖 VIP 升级礼及生日礼物引用；其他 JSON 引用仍不在本次范围。未运行测试或迁移，需最终联调新增/修改和删除竞争、停用等级引用、双店隔离、角色权限及重算路径锁顺序。

## 生日礼及并发竞争

等级的 `benefits.issuance.birthday_reward_id` 在奖励删除时与升级礼一样受到保护；等级实际保存时在本店配置锁后锁定当前奖励，重新确认生日类型、商城状态和启用状态。被升级礼或生日礼引用的奖励不能通过修改类型、生日用途或商城状态破坏对应规则；单独停用仍沿用原操作及授权，已发权益不变。

现有抽奖按活动→奖励→钱包→会员配置取锁，VIP 配置及奖励结构编辑按会员配置→等级→奖励取锁，存在 MySQL 锁环。本次没有改变抽奖与钱包的业务锁序；抽奖、奖励编辑/删除及本店等级写 API 在自身事务退出后将 1213/1205 明确返回 503，提示使用原请求编号重试；若部署存在更外层门店事务则标记其整体回滚，不在嵌套事务内自动重试。平台初始化仍按既有跨库不确定结果处理。其他资金或异步调用也可能成为锁冲突受害者，本次未覆盖，锁环尚未根除。

## 抽奖与积分兑换锁序调整

抽奖、积分兑换的新请求在核对本店身份、原业务周期和授权后，先锁本人钱包与会员配置，再锁抽奖活动（仅抽奖）、奖励及积分资料；实际扣积分及发奖前仍重新校验授权、配置、库存和账号周期。已完成请求按原凭证返回，锁后幂等核验采用当前读，避免 MySQL 可重复读中的旧快照；失败事务回滚钱包行、积分、库存及奖励写入。余额奖仍按原钱包状态和金额判断。

该顺序消除了这两条新交易中原先持奖励等待会员配置、与 VIP/奖励配置持配置等待奖励形成的直接锁环。权益交付/取消、其他资金与异步业务尚未全面梳理，不宣称全局无锁环；原 503 冲突提示保留。未运行测试或迁移，须最终以隔离 MySQL 验证抽奖/兑换与 VIP 及奖励配置竞争、同凭证重试、积分和库存守恒、跨店、退店周期、授权变更及外层事务回滚。
