# 默认本金转单的会员授权核对

默认本金付款且 `funding_terms` 为空的主单，若真实发生转单、已有最终逐段结算清单，并通过现有逐段结算核验，可在既有实销入口记录 VIP_GROWTH 的原时点授权决定。控制库不可核验时按原付款会员及积分开关保存 UNKNOWN；主单消费积分与会员成长分别待平台核对，原付款、陪玩结算及加购分别保留。明确 DENY 不因续期自动补发。此接线不开放新的转单或退款功能，底层结算门禁仍然有效。

平台超级管理员沿用 `license-vip-review` 和 `license-points-review` 入口，先核对会员授权、再核对积分。会员裁定重新核验唯一最终分段清单及真实逐人结算、原老板钱包付款、本金批次、实销时及当前退款记录和退款钱包流水；部分退款按当前净本金、全退不恢复成长，后续退款继续按原来源核对。原业务周期改变时不能给新周期恢复权益。平台核对及积分补发保持原请求幂等与跨库审计规则。

只处理主单无来源单及无衍生服务单、无未结售后、付款来源可证明均为本金、没有积分抵扣的情况。逐段清单、底层能力、退款或支付流水无法验证时仍返回待核对；不同资金模型、无分段证明及真实断库场景未冒称完成。参考 [Databricks 支付与退款数据模型](https://github.com/databricks-industry-solutions/lakehouse-industry-data-models/blob/main/data-models/payments_fintech/v1/ecm/schemas/payments_fintech_transaction_schema_v1_ecm.sql) 将退款与原支付事实关联；本项目的实销及授权仍以自身账本和 PRD 为准。

本次未执行测试或迁移，仅完成 Python 语法解析。最终须在隔离环境验证默认本金真实转单入口、逐段和多轮退款、控制库故障、可信缓存、授权 DENY/UNKNOWN、跨店和跨周期、重复核对及后续退款。相关底层功能开关和真实可达性须单独核验。
