# 积分双陪已付后加购退款

接入范围为无服务中转单、无加购接替的积分双陪：第一次主单退款后 A 已按本人报单与等待期结算，第二次主单退款由未结算的 B 承担；B 对本人已有加购发起独立退款。售后仍受原期限约束，老板及 B 需按原方案确认，已结算 A 不能承担新退款。

退款预核保留 A 的实际主单及逐笔加购流水，后续资金快照重新核对 A 的付款归属、已入账金额及未被后续退款占用；B 的实际加购退款按原事务写回并计算门店补资 RELEASE 和到账用途。最终结算读取最后一个已核验加购资金版本，以 B 扣除后续加购退款对主单收益的实际占用后的剩余金额放款，不重发或改写 A 收益。老板退币、积分及推荐佣金沿原主单退款与加购退款各自的资金规则。

仍限制 A 被新退款占用、A 的已付凭证不完整，以及原售后、到账或资金版本无法核验的组合。本轮未执行测试或迁移；最终须在隔离环境联调 A 已付/零收益、B 原路退款与钱包押金承担、有无共享到账及 RELEASE、本人报单时钟、重试回滚、会员实销和最终账目守恒。

入口追踪补充：到账预锁已识别两次主单退款、A 已付且无接替的真实版本；会员实销沿原最终结算验证读取最新资金版本。B 的加购全额退款时，结算会为其原履约段保存零收益凭证；加购实销现在核对该凭证及原路全额退款后允许零净额确认，非零加购仍按现有逐段结算规则。

此前同单双陪加购接替扩展：仅接已确认接替及资金事件发生在 A 已付之前、后续退款只由未结算 B 承担的范围。到账和资金回放按接替后的实际逐段责任重新核对 A 已付款项，不能按原加购负责人推断；若 A 的主单或加购已付金额发生变化，则事务回滚。售后、退款记账、补资 RELEASE 与 B 最终结算继续使用原业务事务和最新资金版本。其他接替时序和未证明的已付组合保持原限制；该范围尚未联调。

接替后的全额退款若只留下已付 A 的零收益记录，加购实销以真实已确认接替、该段零收益及其结算父记录核验后继续，不视为新增入账。非零记录及未结算份额仍遵循原校验。

继续扩展：同单加购已接替，首次主单退款后仍履约的 B 新购加购，随后 A 已付、B 再次主单退款及本人加购退款。能力域不再仅因首次退款后存在付款而拒绝；每笔付款仍须核对 B 的真实在履约时点和原付款。第二次退款的共享到账回放逐事件核对付款资金版本、接替及此前退款，仍逐项核验 A 原有已付加购和主单流水，后续 RELEASE、结算与会员实销沿原真实资金版本。接替或付款与关键事件同一时点、付款属于已付 A、缺少资金事件及其他不能核验组合仍受限。本轮未运行测试或迁移，须最终隔离联调。

若历史接替或 B 的付款发生时本单尚无到账分配，后来才登记本单到账，回放允许用该本店到账作为后来的见证，并以事件自身保存的空分配和真实资金版本核验，不把新到账回填进旧事件。此前已经存在的分配仍须出现在对应事件快照中。

第二次主单退款当时也没有任何本单分配时，其后新增到账同样仅作为零金额历史核验的见证；真实 RELEASE 仍只能引用实际分配及当时用途事件。

同单接替拒绝后重提：正式能力域现允许在未转单的积分双陪中保留真实拒绝方案后重提；逐次核验原负责人、份额、三方决定和客服审计，拒绝不生成资金事件。首次主单退款前后的已接受接替分别沿原资金版本及共享到账释放回读，第二次退款后的加购预核也读取这些拒绝事实。仍限定每笔付款最多一次已接受接替、拒绝方案不依赖既有已接受版本；退款使方案失效和已接受后的再次接替不在本次开放范围。上述接线尚未执行最终联调，不能据此认定整个退款链已验收。

时间边界：真实逐人收益结算要求整单完成，加购接替入口要求订单服务中；故 A 已到账之后新发生的接替不属于现有合法时序，本轮不放宽完成条件或改写 A 流水。最终须在隔离环境串联拒绝、重提、三方确认、首次及后续退款、共享到账释放、报单等待、逐人结算及实销，核验重复请求、回滚和金额守恒。

第二次主单退款的到账回放同时允许首次退款后实际完成的同单接替：须存在该时点的真实主单退款资金快照，继续逐事件回放付款、退款及共享到账用途，不能将后来的分配回填历史。未付情况下的接替与首次退款同一时刻仍不可区分而保留限制。该代码接线与上述拒绝重提均待统一联调。

退款承担回放按付款、陪玩和履约段合并真实份额收益，再对该段的历史退款扣减一次，与实际退款执行的分组口径保持一致；逐份额原始分配仍由真实退款凭证回放。该调整本身不开放同一加购多次已接受接替：当前同单接替资金版本、到账用途和退款来源验证仍以单次接受为前提，须完成逐事件资金回放后才能开放。未执行测试或迁移。

补充实际入口：接替提交时已拒绝的旧方案不再占用新方案位置；待确认方案仍按全单唯一处理，已接受方案不会因本次改动被绕开。多次已接受接替尚未开放，需按两位陪玩当时均实际履约的 A→B→A 时序完成各次确认、版本、退款和到账回放。

多次同单接替的资金事实准备：在主单及加购尚无退款的时序中，可按真实前次资金事件重建后一次已确认份额、三方决定与客服审计；历史接替事件按实际顺序回放，不再在该资金事实层把付款视为仅有一次接替。当前正式接替入口、后续退款和结算门禁仍未开放，故尚不能从 API 发起该多次接替，也不代表完成资金闭环。待接入确认事务和到账写入，并统一逐份额退款及最终结算后联调。

跨加购承担回放已按最新实际接替及其前版链取份额，同一付款、同一陪玩、同一履约段多份额先合计再减历史承担；第二次主单退款到账回放也按付款各自前版关系识别多次事件。上述为资金回放准备，正式再次确认和退款、结算门禁仍在，不表示多次接替 API 可用。

后续接线位置：`addon_handover.py` 创建及确认必须在订单、资金锁和到账锁的现有事务内允许经过核验的已接受前版，并由 `points_team_addon_handover_release.record_locked` 对本次确认写入独立资金事件和实际 RELEASE；`points_business_access.py` 需以每付款实际前版链替代单次接受限制。退款须让 `points_addon_handover_refund_facts.py` 按最后有效份额、逐份额退款凭证和各到账事件重建，结算须在 `points_refunded_settlement.py` 保持已付流水及本人等待规则并回读同一版本。完成这些环节之前，当前门禁保留；尤其不能先允许第二次接替而使后续售后不可办理。

最终结算事实对账已改按付款、陪玩和履约段汇总实际份额后比较，不再以字典覆盖同段早前份额；已到账人员仍沿原结算流水及等待校验。多次已接受接替的真实入口仍有门禁，修改尚未经过联调。

补充已付人员的共享到账回放：同一付款有多次同单接替时读取最后一个真实资金版本，先合并本人同段份额再扣该版本之后的历史退款，并继续核验原报单、到账流水和已付金额。二次接替创建、最终确认和业务能力域的实际开放尚未完成；本轮未执行测试或迁移。

本轮继续接通有界实际入口：未转单积分双陪、两人均在履约且再次接替前没有主单或加购退款时，同一付款可按实际前版链发起后续接替。每次三方确认在原事务调用同单资金版本及共享到账 RELEASE；首次主单退款的到账回放现逐事件核验各次接替，退款及逐人结算读取最新份额并聚合同人同段。首次或独立退款之后再发起接替等组合仍受限制。以上是代码接线范围，不代表业务验收完成；未执行测试或迁移，必须最终在隔离环境完整联调资金来源、逐次释放、退款、零收益、报单等待和会员实销。

继续接入独立加购退款后再次接替：主单尚未退款、两席仍在履约时，以此前逐份额退款和收益占用回放出的剩余责任发起；确认期间若该付款发生退款或被其他退款占用则不生效。新确认仍在原事务写资金版本、共享到账用途和实际 RELEASE。主单已退款后再次接替及确认期间变化后的自动重提仍需后续接通；该范围未执行测试或迁移，须最终隔离联调。

主单部分退款后的继续接替代码已接入有界前版链：此前同单接替均已真实确认并写入资金事件，主单退款终止当前加购负责人后，由仍在履约且未结算的另一席接替；按创建时逐份额净余额保存新方案，确认期间发生退款或占用则不生效，确认事务沿既有 post-main 版本记录共享到账 RELEASE。当前仍限制为一次已确认主单退款、无转单和无已付款人员，退款前接替事件必须早于该主单退款；其他时序不视为已完成。未测试或迁移，最终须以真实账户、逐事件到账、后续退款、逐人结算和会员实销联调。

主单退款后的新接替资金事实同时固定前一次接替 ID、前次资金事件 ID 与摘要；重新回放时逐笔核验这些前版，不从当前负责人推断历史。上述能力仍待最终隔离联调。

转单双陪两次主单退款后的自愿接替：第二次退款只终止历史履约段而整单仍在服务时，按付款最新责任及真实前版资金版本核对，要求原负责人和目标均为当前实际履约且未结算的不同席位；老板和双方确认后，在原事务使用第二次退款后的整单资金版本记接替及逐到账 RELEASE。实际 RELEASE 必须有到账用途账本；零释放只保存真实资金事件，不虚构用途。后续加购退款沿同一 followup 资金事件回放，最终逐段结算和会员实销继续使用最新版本。此切片未开放已有已付结算清单或整单完成后的新接替，未执行测试或迁移；须在隔离环境联调多笔退款、当前席位、逐份额扣减、共享到账、多次确认与重试回滚、最终结算及实销。

转单两次退款及后续自愿接替的空释放见证：回放可选本订单实际 redemption 或 service_order 分配；service_order 仅在对应历史资金快照为空、核验金额为零且该分配晚于该历史事件时作为见证。退款后转单回放从主单退款凭证取得真实 redemption，并按本订单两类实际分配重建历史；不把后到账计入旧事件、不跨店或跨订单取资。实际 RELEASE 继续核对原分配及用途流水。本轮未执行测试或迁移，须最终隔离联调空分配、后新增共享到账、多次接替及退款、并发与回滚。

两次退款后自愿接替的真实重试：同一已确认方案在整单完成但尚未结算时，可核验原三方决定及资金版本后回读确认；发起请求重试也重新核对前版链和实际资金事件，不生成第二笔 RELEASE。新建或变更仍须服务中，已产生结算清单或人员入账后的回读仍受原门禁限制。本轮未测试或迁移，最终须联调真实确认、完成后的重试、分配共享与回滚。

补充已结算后的幂等回读：原自愿接替确认请求和原发起请求在对应业务主体、原内容及真实接替资金版本核验后，可在已结算订单上进入 settlement 核验最终清单和实际逐人流水，再返回原结果；回读不创建方案、不变更决定或生成 RELEASE。新建和修改仍须合法服务中。代码尚未执行测试或迁移，必须在隔离环境联调已结算流水、相同及冲突重试和共享到账锁序。

两次主单退款后的混合付款补充：既有加购和第二次退款后新增加购并存时，自愿接替方案被拒绝或被实际退款失效后，可继续进入原重提事务。形态识别允许 VOLUNTARY，但仍逐条核验旧拒绝决定或失效退款及其 RELEASE；旧方案不算已接替、不生成接替资金事件，重提以当时实际剩余份额和双方仍在履约的席位重新确认。后续退款、到账及结算仍沿各自真实版本；未执行测试或迁移，须最终隔离联调多付款、拒绝/失效、重试与退款时序。

多付款入口补充：转单订单两次主单退款后，既有加购与后购加购均有真实付款，另有未付款意向时，该意向不再阻断已付款加购的接替或退款，也不计入收益和资金历史；本次付款仍在订单锁内验证所选意向属于本单且尚未支付。已有付款、各次接替/退款及共享到账 RELEASE 仍由 followup 资金版本逐事件核验，最终结算和实销只使用实际付款。尚未执行测试或迁移，须最终联调多意向并发支付、接替、退款、到账和结算。

首次主单退款前的同单双陪跨付款失效：已有真实已接受接替、原负责人和目标均仍履约时，另一笔已付款加购可发起协商退款；仅当该退款实际扣用了待确认接替付款的当前负责人收益，原方案才在退款事务内失效并保存逐份额扣减、原前版与三方决定。售后/方案/执行入口按目标付款建立能力范围；重提先核验真实退款及 RELEASE，再以当时剩余责任重新三方确认并写新资金版本。未影响待确认付款的退款不产生失效事件。此切片限定无主单退款、无服务转单、目标退款付款与待接替付款不同；确认期间同付款退款、已结算人员和其他时序仍受限。未执行测试或迁移，须最终隔离联调申请、跨付款扣减、押金、到账用途、重提、逐人结算及会员实销。

同付款部分退款使待确认接替失效：无服务转单双陪、此前已有真实确认的同单接替且两席仍履约时，售后和退款方案可针对同一付款继续。真实退款事务先按老板与实际承担人的确认写入原路退款、逐份额退回及收益扣减，再将待确认接替标为失效并绑定前版资金事件和实际退款；原事务继续写共享到账 RELEASE。重提需核验旧失效事实及 RELEASE，并按退款后的实际剩余份额重新取得三方确认。后续主单退款和结算仍核对失效发生在主单退款之前的真实历史。该范围不包含服务转单、已有主单退款时发生失效、没有前次已确认接替或已结算人员；未执行测试或迁移，须最终隔离联调同付款部分退款、份额、钱包/押金、共享到账、并发确认及重试回滚和会员实销。

主单退款后同付款使方案失效：无服务转单、已有一次主单协商退款时，仅允许该次实际终止的源段向仍履约且未结算的目标交接；同付款部分退款以真实逐份额退回及逐人扣减保存旧方案失效，原事务继续写退款资金版本与共享到账 RELEASE，重提回读前版和失效事实后重新确认。另对已开放的积分服务转单后自愿接替/第二次退款后接替，放通同付款由多个实际履约段共同承担的部分退款：逐份额凭证校验各段及责任人，跨付款仍须实际占用待接替当前份额才失效。两次主单退款后的无转单双陪已完成整单，不新建接替；未核验的转单、已结算及跨时序组合继续限制。未测试或迁移，最终须联调真实各方确认、退款来源、共享到账、押金、重提和逐人结算/实销。

后续退款入口补充：一次主单退款后，同付款多人部分退款使接替失效并重提；若后来 A 在整单完成后按本人报单及等待期真实结算，再由未结算 B 发生第二次主单退款及后续加购退款，能力域可识别 A 入账前已完成的多人退款、失效记录及真实 RELEASE，不把历史多人承担误判为 A 入账后的新承担。后续退款若发生在 A 入账后，参与人不得包含 A；预核还要求失效事实、实际退款和 RELEASE 事件均早于 A 入账，并继续核验原收入流水。未测试或迁移，须最终在隔离环境联调历史多人退款、真实到账、先后结算、重试回滚和会员实销。
