# 抢单留池失格通知恢复

单陪或双陪留池候选在实际分配时被判定资格失效，且同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和 `GRAB_RESULT_NOTICE_RECOVERY_ENABLED`，失格事实与逐人通知意图在同一业务事务内保存。即便订单继续留池，没有产生最终结果，也可在提交后投递或由逐店任务恢复。单陪核对本人 SINGLE 回执，双陪分别核对队长 INVITE 和队友 CONFIRM 回执、所属队伍及原业务周期；账号离店、重入或来源不可证明时记录跳过。每个失格事实的每个收件位置最多创建一条消息，消息失败不影响已提交的失格或分配结果。开关关闭时使用原有提交后发送路径；双陪失格现也会通知两个队员。

上线前须应用各店依赖结构迁移 `orders/0255_grab_disqualification_notice_intents`、`site_messages/0018_grabdisqualificationnotices`，启用上述开关并运行逐店 Celery worker/beat。最终须联调单双陪失格后留池、重新参加、后续分配、事务回滚、部分投递失败、重复扫描、双店同号和账号重入；消息创建不代表客户端实际收到。客服新单仍走抢单池，正式注销保持关闭。未运行检查、测试或迁移。
