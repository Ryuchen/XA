# 咨询刷新通知周期与恢复

咨询已读和接待状态变更在锁定的会话行内追加独立通知意图，与业务状态同次提交。每条意图保存独立编号、原收件账号及业务周期；多次变更逐条保留，不将旧周期事件合并到新周期。提交后生成已有会话 outbox，写入失败时原意图保留，由逐店 `chat.tasks.drain_chat_notifications` 补建；outbox 与意图移除在同一事务内完成，并以意图编号去重。

生命周期集成开启时，账号目标投递及 WebSocket 消费均校验原周期；账号已离店、周期变化或来源不可核验时记录跳过原因，不标为已发送。客服工作组按原领取和主管权限处理；频道接受不代表客户端实际收到。`CHAT_NOTIFICATION_OUTBOX_ENABLED` 关闭时保留原刷新路径，不写恢复意图。既有咨询会话和聊天历史读取规则不变。

首版空库新增 `chat/0013_session_refresh_intents`，依赖 `chat/0012_notification_recipient_cycle`；启用前需应用结构迁移并运行逐店 Celery worker 和 beat。最终联调须覆盖连续变更、outbox 写失败及恢复、并发扫描、双店同号、退店重入、客服领取与权限、业务回滚，以及频道接受与客户端实际送达的区别。其他通用通知仍未全部覆盖；正式注销保持关闭。本轮未运行检查、测试或迁移。
