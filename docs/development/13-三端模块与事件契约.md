# 13 三端模块与事件契约

此页用于把既有页面清单落到研发任务；更细的页面和按钮见 [PRD 页面追踪](../prd/08-页面接口追踪.md)，路由见 [PRD 接口清单](../prd/09-后端接口清单.md)。旧清单个别行保留过时动作（如门店切换、陪玩续买通行证、旧手机号规则）；实现以本页及最新产品决策为准。`R` 表示读取，`W` 表示写入，均须通过服务器校验权限与状态。

## 1. 三端模块的实际串联

| 模块／现有主要代码 | 老板端 | 陪玩端 | 后台 | 关键数据和完成条件 |
| --- | --- | --- | --- | --- |
| 门店与认证：`stores`、`club_accounts`、`users` | 固定本店域名，密码+短信／OTP 或已绑定微信登录 | 同上；首次正式接单另验微信与头像 | 统一入口、独立平台身份与店内身份 | 店上下文、认证方式、会话撤销、跨店拒绝；不在老板／陪玩 UI 提供门店切换 |
| 入驻／档案：`users`、`provider-registration` | 列表、详情、`SL-`／`XA-`、头像、评分、语音 | 实名材料、押金方式、技能、音视频、跨日档期及接单开关 | 审核、退回、资格、封禁、押金凭证 | 本店本人和授权后台可查私密资料；不因后续换头像抹除首次真实取得记录 |
| 内容与服务目录：`announcements`、`banners`、`orders`、`promotions` | 首页、公告、游戏／玩法／服务、价格、评价、收藏 | 查看本人技能和适用服务 | 上下架、游戏、服务、玩法、活动与展示内容 | 保留既有搜索／分页／图片／富文本；实体下架不改历史订单快照 |
| 服务报价与下单：`orders/pricing.py`、`orders/views.py` | 单／双陪、指定／抢单／试音、资料、优惠、积分、钱包来源 | 查看真实资格、候选与本人份额 | 按老板明确选择代单、记录负责人；新单客服安排仍入池 | 三种金额与支付来源清楚显示；用户可重新选择合法组合；非本人／跨店拒绝 |
| 招募试音：`orders/applications.py`、`audition`、`users` | 看本人已付款订单的录音、选人 | 本人录音库、新上传、报名、双人确认 | 可按授权查询和协调；旧入驻试音链接仍独立 | 报名音频版本不可变，试听不改变报名事实；本人、老板、授权后台才可取媒体 |
| 抢单与预约：`orders/reservation_*`、`orders/tasks.py` | 预约、付费转单；查看池／安排与候选结果 | 按可见性抢单／组队，预约本人确认或拒绝 | 协调、转单、处理超时；不能代陪玩确认预约 | 订单／轮次／候选／人员占档独立；计时及状态规则见 [04](04-抢单预约与履约.md) |
| 履约、报单、评价：`orders`、`wallet` | 看进度、确认结束、四项评价及回复 | 本人入队／结单／战绩凭证、分段报单及评价回复 | 审核报单、核对状态、授权作废评价 | 提交／审核／结算三个事实分离；匿名评价与私密图片权限正确 |
| 服务中售后／退款：`orders/aftersale.py`、`refunds.py` | 联系客服、确认协商方案、查看自己的退款构成 | 仅查看本人受影响事项，确认涉及本人的方案 | 售后人员核实，预览并执行授权退款 | 期内建立、逐人逐段责任、原支付来源返还、分摊与取整及幂等完整对账 |
| 余额、充值、礼物：`wallet`、`engagement` | 线下收款充值、查本金／赠送／赔付、送礼、查流水 | 查本人收入、礼物、调账，不提供普通充值 | 客服登记收款、赠送调整 OA、调账及审计 | 实际收款与钱包奖励分开；礼物只用本金；重复和不明结果可查询 |
| 押金、收益、通行证、提现：`wallet`、`users` | 仅查看与本人订单有关结果 | 押金补差、收益及冻结、买通行证、申请／取消提现 | 店客服初审；平台财务跨店终审及登记线下打款 | `pending`／冻结／支付成功分开，历史通行证按原规则退，实际打款凭据可对账 |
| VIP／券／预存：`engagement`、`coupons` | 等级、权益、成长、优惠券、充值组合 | 按适用权益和分成规则履约 | 每店配置、发券、OA、查看权益交付 | 退款降级、券条款、开关、启用时点及个人数据跨店隔离 |
| 积分／商城／抽奖／签到：`engagement` | 积分流水、签到、补签、商品、多个抽奖和保底 | 本人积分及允许的商城兑换／通行证抵扣 | 配置活动、奖品、领用／交付 | 只删除积分直兑余额能力，真实中奖余额及历史兑换保留；领取与发奖不重复 |
| 榜单、成就、标签、冠名：`engagement`、`orders` | 本店消费榜、非礼物成就、标签和赠礼权益 | 实际履约单数榜、公开评价和本人权益 | 规则维护、异常审计、必要时人工交付 | 各榜单使用对应原价、实销、实付或实际履约口径，退款处理不能统一套用 |
| 咨询、站内消息：`chat`、`site_messages`、`support` | 联系客服、订单卡片、历史消息与已读 | 同上，并只收到本人允许的业务通知 | 列表共享、领取、转交、主管分配与回复 | 列表元数据与正文、推送、私图独立授权；主管直接回复不改变接待人 |
| 员工、薪资、经营：`console/payroll_*`、`console/dictionaries` | 不显示职能员工私密工资 | 陪玩收入和后台员工薪资独立 | 超管／平台财务配置、核算，店内人员按授权查本店工作事项 | 已确认工资、跨月调整、财务公共成本、投流与 ROI 按来源可回算 |
| 特殊加购与通用房间：拟增领域模块 | 主单进行中选加购、进房、提出异议、确认 | 负责加购及房间履约，转入接替 | 配置项目、审核异议和原单售后 | 逐项价格与退款，房间保留进度；九种旧玩法未在本期重做 |
| 退店、停用与历史：`engagement/retirement.py` | 按授权查看本人历史及结清结果 | 已接订单按规则继续、限制新接单 | 独立权限确认退店，处理迁移和员工停用 | 预览清空权益与负积分、保留历史流水；历史未结订单按切换方案接管 |

老板退店接口：门店后台角色须具备独立 `user:retire` 权限，本店超级管理员自动拥有；普通 `user:edit` 不包含该权限。`GET /api/admin/users/{id}/retire-preview/` 返回本店钱包余额和冻结额、积分（内部单位为百分之一积分，可为负）、会员、待清空券和权益、标签、冠名及阻断原因，以及绑定本店和操作人的短期确认令牌。`POST /api/admin/users/{id}/retire/` 提交 `reason`、`confirmation_token` 与 `confirm: true`；服务端重新核对内容，结清后在同一门店保存清空事实及审计。历史订单和资金流水保留；该老板释放本店授权名额，重新登录入店须重新检查本店 License 名额。开发中功能尚未最终联调，并发资金、权益与门店隔离须在最终联调验证。

平台门店初始化中，`GET /api/admin/platform/store-management/{id}/setup` 的 `membership` 返回预存档位、VIP 等级与配置版本。`PUT /api/admin/platform/store-management/{id}/setup/membership/{kind}` 的 `kind` 为 `recharge-package` 或 `vip-tier`，请求提供 `version`、目标 `id`（新建为 `null`）和 `configuration`；平台仅在门店待开业且尚无老板账号时使用该入口，营业后的等级及权益变化继续走门店现有重算流程。保存写入原门店配置并留平台和门店审计；启用 VIP 时开业核对须有至少一个有效等级。该接口和并发行为尚待最终联调。

## 2. 关键请求与响应应具备的字段

下列字段为研发契约建议；API 路径与序列化名称实施前对照现有前端适配，不能把建议误当现有接口。

| 业务动作 | 请求关键字段 | 成功回读 | 错误与竞争 |
| --- | --- | --- | --- |
| 录音上传／报名 | 音频文件／上传凭证、本人录音版本、`order_id`、`client_request_id`；双陪各自确认 | 录音 ID、文件状态、报名 ID／版本、队友确认状态 | 格式或时长不合规则拒绝；文件归属错误、订单关闭或资格变化不生成有效报名 |
| 抢单与队伍确认 | `order_id`、`round_version`、本人或邀请队员的动作、请求号 | `candidate_id`、本人的提交时卡级、完整队伍状态、窗口截止；不提前显示抢中 | 未到个人可见时间、资格失效、截止、重复／版本过期分别可恢复；同刻取消按 [04](04-抢单预约与履约.md) |
| 预约／转单 | 服务、所选起止、单／双陪各 ID、游戏资料；转单带 `reservation_version`、`quote_id` 与请求号 | 每人确认状态及各时段占用、确认／付款截止、订单 ID 与支付结果 | 时段冲突、距开始过近、候选拒绝和报价变化；确认不等于付款 |
| 售后／退款 | 事项 ID、受影响段、方案版本、店币／积分构成、双方确认标识、退款计划摘要、请求号 | 售后状态、本人受影响范围、退款实际构成、财务流水引用；后台还可查差额 | 期限失效、方案变更、余额／押金不足、重复请求、权限不足；不足时不部分退款 |
| 报单／结算 | `segment_id`、报单版本、三类证据引用、有效提交与审核动作 | 审核状态、个人冻结截止、售后截止、是否待资金及实际到账状态 | 驳回重提、证据失效、权限／旧版本错误；不能把审核通过显示为资金已到账 |
| 提现审核／登记 | 提现申请 ID、状态版本、原始收款快照；财务登记真实付款证据、请求号 | 门店初审、平台终审、付款待核对／成功、冻结／账务状态 | 等于门槛、零实付、重复凭证、状态冲突、未授权店；付款不明停止自动操作 |
| 会话领取／转交 | `session_id`、状态版本、操作、目标员工（转交时） | 领取人、状态、原员工撤权、新员工取得权限；消息列表不暴露正文 | 并发领取一人成功；转交与新消息同时发生时按权限重新过滤；无权图片拒绝 |
| 房间确认／异议／加购 | 房间或订单 ID、事件版本、本人确认或异议、所选项目数量／单位、请求号 | 房间状态、剩余确认时间、当次加购支付及人员归属 | 非参与人、服务未开始、规则条件不符、版本冲突或余额不足；重复请求不重复结算 |
| 平台建店／工资 | 平台主体、获授权门店范围、配置版本、建店步骤／工资月结版本 | 分步骤状态或工资预览／确认快照，包含失败项及真实操作人 | 新库不属于本次申请、重复别名、步骤失败、已确认工资及权限撤销均拒绝非法覆盖 |

## 3. 领域事件与受众

| 事件族 | 同店持久事件的最小事实 | 接收端与验收重点 |
| --- | --- | --- |
| `order.paid`、`order.cancelled`、`refund.completed` | 店、订单、事件版本、支付／退款来源 ID、实际发生时间 | 老板、相应陪玩和授权后台按各自权限读取；不得重复扣退或把消息当支付证据 |
| `dispatch.round_opened`、`candidate.submitted`、`dispatch.assigned` | 店、轮次／订单、版本、可见截止或分配对象；敏感排序数据不下发无权用户 | 本人先见已提交，最终分配后才见结果；外部群按延迟发送原价与要求 |
| `report.submitted`、`report.reviewed`、`earning.released` | 段、版本、有效提交时间／审核结果／实际入账流水 | 只发本人及授权后台，审核通过与收益到账不同；重试不复发钱 |
| `aftersale.changed` | 事项、受影响人员／段、权限版本、状态 | 双陪仅 A 受影响时不向 B 泄露 A 的售后及附件；主管和参与人按授权查询 |
| `withdraw.status_changed` | 店内申请 ID、状态版本及授权受众；实际付款须有凭据与流水 | 本人、本店初审客服和平台财务各看允许字段；付款结果未知单独展示 |
| `chat.claim_changed`、`chat.message` | 会话、接待权限版本、消息 ID 和接收人 | 未领取客服不得收到正文、预览和附件；转交后撤销旧接收权限 |
| `room.state_changed`、`room.objection` | 房间、版本、状态、计时快照及授权成员 | 订单老板、负责陪玩与获权后台；异议暂停、恢复不重复创建订单事件 |
| `payroll.confirmed`、`store.provision_changed` | 月结或建店任务、版本、平台主体和目标店 | 仅相应财务／超管；不能跨店推送工资、连接密钥或私人数据 |

事件 ID、门店和业务版本唯一；同一业务写入与事件写入在店库同事务，投递可至少一次但消费必须幂等。接口列表和本事件表不是新 HTTP/WebSocket 功能已经存在的证明。

正式积分订单在开工后首次协商退款，提交成功后通过 `order_status_update` 刷新本单陪玩页面，适用于符合执行门禁的转单和未转单主单。陪玩收到本单 `id` 和 `status`，再经本人接口读取履约、报单和售后状态。消息按本店、订单受众、账号当前状态及原业务周期核验。老板和具备订单查看权限的后台收到完整订单状态。退款结果以原请求回执为准。
