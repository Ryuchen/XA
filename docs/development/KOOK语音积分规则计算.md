# KOOK 语音积分规则计算

实时在线累计、授权 UNKNOWN 原始事实核验和人工在线登记共用整数整组计算，读取首版不可变规则版本 0（7200 秒 1 积分）。实时发放仍使用原业务周期和幂等流水，授权拒绝／未知继续按现有原事件留痕；已有累计和积分不因代码切换重算。规则缺失或异常不猜测积分。

该变更只是把实际入口的现行计算统一，并未开放按店变更倍率。下一步仍须实现规则版本生效时切分真实在线区间、逐绑定周期余量结转、UNKNOWN 迟决与后续区间的有序重放及人工登记真实时段，然后才能开放配置。未运行测试或迁移；最终须联调边界秒数、跨周期、授权故障、并发和真实监听。


### 规则余额事务（0049）

新增按本店账号业务周期游标与规则版本唯一的余量和待发积分记录。实时在线区间及授权待决队列回放在同一事务内锁定规则余额，并以其计算结果核对实际累计；人工登记和平台人工差额裁决同步维护绑定和无绑定账号的规则余额。原积分流水不改写。锁顺序沿用账号、绑定、游标、规则余额、积分资料；不一致或缺少余额时回滚并待核对。0049 为首版空库结构，不回填历史数据。

目前实际仍只运行规则 0（两小时一积分）。规则配置保存、生效时点跨区间切分、多版本余量结转及按原版本复核仍未接入，不应开放可变倍率或宣称完整支持。以上变更尚未执行迁移或联调；最终需核对实时/人工并发、UNKNOWN 后顺序回放、未绑定后绑定、事务回滚和同请求重试。


### 在线规则草稿与区间切分（0050）

本店 KOOK 配置接口 PUT 可同时提交 `online_draft_window_ms` 和 `online_draft_points`，通过已有门店角色权限与配置 revision 保存操作者、配置版本和时间；GET 返回最近草稿与当前规则，草稿 `active=false`。该草稿不触发监听重连或变更正在发放的规则。监听对真实不超过 90 秒的在线区间按已持久化规则生效点切段；在实际计数前检查所有片段，目前任何非 0 已生效版本均拒绝，避免未经完成的账本回放造成错误发放。

尚无发布入口：跨版本时间余量及旧规则待发积分的原子结转、人工来源跨生效点处理、UNKNOWN 原版本审核和顺序队列回放仍须完成。故草稿不是可生效配置；不能将切分器称作多倍率已接通。未运行测试或执行迁移。


### 人工来源规则片段（0051）

正常人工登记和等待平台裁决的人工来源，在积分登记或待审核记录的同一事务中，按实际起止时刻写入规则片段，记录规则版本、窗口和积分。平台裁决前按原来源逐片核对；缺片段、条款不一致或非已接通版本 0 时不补发。自动监听继续使用既有在线区间及其授权来源记录。首版空库不回填旧记录。

新版本的发布、跨版本余额结转及自动/人工/UNKNOWN 统一回放仍未完成，草稿继续不生效，未执行测试或迁移。


### 逐规则结转基础（0052）

新增账号业务周期的规则结转事实和事务内结转函数，保存真实生效时刻、原规则未发积分与转出的未满组时间、新规则余量及形成的整组；旧待发积分留在原规则余额。现有待决队列已使用该函数核对当前规则；非 0 规则仍被上游门禁拒绝，所以跨版本结转尚未实际开放。后续必须先让实时计分、人工与 UNKNOWN 审核使用逐规则余额，完成旧规则待发的实际发放及幂等凭证，再开放发布。未执行测试或迁移。


### 分规则真实发放（0053）

实时监听、有序待决回放、正常人工登记与人工差额裁决，已在真实事务内更新规则余额；对应实际积分流水写入原规则分配，流水失败连同余额变更回滚。待决回放可锁定并汇总各规则待发记录，但目前仍受原规则校验约束。版本 0 的 UNKNOWN 审核也将实际流水按原规则留存分配；跨规则实时处理、人工处理与版本发布仍未开放，不视为倍率配置已完成。未执行迁移或测试。


### 非零版本片段的受控执行

有序队列现按片段时间核对规则版本和条款，按顺序结转多个规则的余量，汇总原规则待发并为真实流水逐规则留分配。监听在明确授权 ALLOW 且连接、周期可核验时，可将非 0 规则片段写入该队列；已有待核对区间时保持顺序等待。非 0 片段的 UNKNOWN/DENY 已保存原授权事实；平台可按原规则核对 UNKNOWN 并继续顺序回放。人工跨规则来源及发布入口尚未贯通，当前没有发布入口产生该规则，不能认为倍率配置已完成。以上尚未测试或执行迁移。


### 发布与实际版本结算（0054–0055，覆盖以上旧的未发布状态）

`GET /api/admin/config/kook-points/` 返回本店监听配置、最新草稿和当前生效规则；原有权限分别为 `engagement:view` 和 `engagement:edit`。`PUT` 延用 `revision`、`enabled`、`guild_id`、`checkin_channel_id`，保存草稿时同时填写整数 `online_draft_window_ms` 与 `online_draft_points`；下一次 PUT 使用新的配置 `revision` 和 `publish_online_draft_revision` 发布该草稿。发布保存发布人、原草稿和实际生效时间；同草稿重复发布返回原版本，配置发生其他变化时须刷新。启用监听仍须本店 License 允许；保存或发布配置不代表 KOOK 已连接，连接以实际心跳为准。

实时监听按生效时点切片并保存当时条款和授权决定；确定 ALLOW 的片段与授权待核对后的后续区间按各自版本顺序结算。原规则未发整组保留原规则，原未满组时长原样结转；新规则整组在下一实际 ALLOW 时段计算，DENY 和 UNKNOWN 时段不凭空计时或发放。流水按规则留分配，不改既发流水。平台超管可裁决 UNKNOWN，保持原业务周期和幂等审计。

人工按实际起止登记且顺序可证明时，按原时点逐规则计分；跨规则来源等待审核时，平台可按原来源顺序核对。早于已处理流水的跨规则差额，平台人工核对接口额外接受 `allocations` 数组，每项为 `rule_revision`、正整数 `points`、`reason`，与总 `points` 相符，逐项限制在原片段理论上限；理由和分配与独立流水及平台审计关联，不重放旧流水。零额使用空数组。人工判断依据须可核实，上限不代表平台自动证明该差额。

0054 为逐规则人工核对依据，0055 为发布版本与草稿唯一关联；尚未执行迁移及联调。最终需以隔离库覆盖跨生效点、规则窗口缩短、跨版未发、UNKNOWN 多事件顺序、迟登记差额、变更时并发和失败回滚。
