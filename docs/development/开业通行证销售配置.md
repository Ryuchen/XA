# 开业通行证配置与销售开关

本店通行证销售开关使用现有业务库配置存储。尚未明确选择时沿用原行为：允许新购仍须通过 License 和其他原有校验。首位本店管理员或获 `escort:edit` 的本店人员可通过 `GET/PUT /api/admin/config/provider-pass/availability` 读取或设置 `{"enabled":true|false}`；有查看权限的人员可读取。停用只阻止新购与新积分报价，不改变已购通行证、其有效期、抢单可见时延或既有退款。切换与购买共享本店通行证配置锁，修改及操作人留在本店审计。

档位价格与可见延迟沿用 `/api/admin/config/provider-pass` 保存，并使用 `/api/admin/dictionaries/setup-confirmation/provider_pass` 或平台已有确认接口核对当前快照；恢复销售前须有完整且已确认的价格及延迟。首次开业时，销售开启或尚未明确选择时须核对这组配置；明确停用则不因通行证缺项阻断。平台超级管理员读取门店初始化快照时可看到本店开关和配置核对证据。门店仍须持有相应 License 才能实际新购。

参考 [Microsoft 订阅生命周期说明](https://github.com/MicrosoftDocs/microsoft-365-docs/blob/public/microsoft-365/commerce/subscriptions/resolve-detached-subscriptions.md) 关注既有订阅可用性；本项目停售后保留既得 24 小时权益、价格和权限边界依据用户决定与项目 PRD，不套用其停用规则。

按开发期约束未执行测试或迁移，仅作 Python 语法解析。隔离环境仍须验证配置与确认、停用／恢复与并发购买、跨店权限、已有通行证抢单与退款，及真实资金快照；本记录不代表实际验收完成。
