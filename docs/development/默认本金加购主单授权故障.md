# 默认本金加购主单的会员授权故障

本项覆盖默认纯本金付款、已结算且有已付款加购的普通主单：不含原单退款、转单和来源单。原有加购结算、主单结算和加购自身的会员及积分授权决定不变；主单在实销确认时额外记录自己的 VIP_GROWTH 决定。控制库不可用且无可信缓存时，主单决定为 UNKNOWN，不创建未经确认的会员成长；符合条件的消费积分另记录待核对决定，付款和结算继续。授权明确拒绝不在续期后自动补发。

沿用平台超级管理员现有会员授权和积分授权核对接口，两个决定各自幂等；先核对主单会员授权，再核对对应消费积分。核对时检查真实主单支付流水、付款来源、退款记录和老板钱包退款流水；部分退款后按当前净本金计成长，后续退款按既有来源记录继续冲减，全额退款不恢复成长。核对积分时仍按付款时倍率和已退款本金计算；不重做主单或加购付款，不修改已发权益。未通过证据核验的复杂来源会保留待核对，不用当前授权推定历史。

参考 [Microsoft 事务性 Outbox](https://github.com/MicrosoftDocs/power-platform/blob/main/power-platform/architecture/reference-architectures/transactional-outbox-pattern.md) 分离业务提交和后续处理的思路；本项目使用本店订单事务及既有平台审核，而非引入其平台或消息服务。

本次只做 Python 语法解析，按开发期要求未运行测试或迁移。带转单、来源单、已有主单退款或其他不属于本范围的路径仍需分别核实；控制库真实故障、可信缓存、主单与加购并发实销、部分及全额退款、双店隔离和平台审计恢复均待隔离环境联调。
