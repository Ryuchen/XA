# 服务履约人数与计费人数

服务新增 `fulfillment_provider_count`（1 或 2），后台商品和平台首次配置均通过既有商品接口保存；`billing_provider_count` 只作为整单价格倍率。单陪服务计费倍率必须为 1；双陪可选倍率 1（标价为双人整单价）或 2（标价按人计价）。老板端商品和后台服务选项同时返回两项。

普通下单、客服安排、指定陪玩、自动抢单及预约的单／双陪选择按履约人数校验；预约分别记录并确认两人。付款和预约报价按计费倍率计算，实付分配、抽成及房间按实际履约人数处理。商品确认信息和玩法快照增加履约人数，付款重验配置变化；订单仍保留既有 `required_provider_count` 快照。体验和 VIP 资格券继续只适用于单陪。

老板未指定陪玩且未明确选择试音时默认走自动抢单池；指定陪玩但未传模式时按指定流程处理，明确选择 `BOSS_SELECT` 且未指定陪玩仍走招募试音。客服安排新单归一为自动抢单，报价与付款使用同一序列化规则；双陪在未分配时也记录正确的双陪模式。

订单接口的 `audition_recordings_required` 按实际订单来源区分：抢单开池事实和老板直接指定日志不会被双陪履约共用标记误判为试音；已选择的试音单以真实报名记录确认，待选择的新试音单沿用付款时保存的选人标记。此修正不改变双陪入队与结单凭证要求，也不改变报名或抢单分配。

首次空库部署需应用 `orders/0278_service_fulfillment_provider_count`，依赖 `0277`；配置双陪商品时须明确填写 `fulfillment_provider_count: 2`，默认值为 1。本轮不接管旧线上商品数据，不修改前端。积分专属链由并行工作处理，不能据本记录视为已联调；需最终验证两种双陪计价、预约、老板及客服下单、抢单分配、抽成、售后退款及门店隔离。本轮未运行测试或迁移。

本地参考价目导入在首次创建商品时，为原价目明确写明按人计费的七款双陪服务设置履约人数 2、计费倍率 2；钓鱼双陪以原价目的两人整单价设置履约人数 2、计费倍率 1。重复导入不会覆盖门店修改过的这两项配置。该命令仍只允许专用本地测试库，并不是生产初始化入口；此次未执行导入或测试。
