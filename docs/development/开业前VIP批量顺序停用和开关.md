# 开业前 VIP 批量顺序、停用和开关

平台超级管理员在门店 `CONFIGURING` 状态，使用已有会员初始化入口及当前版本，可操作已有老板的 VIP 配置：

- `vip-reorder`：`id` 为 null，`configuration` 为 `{"mapping":[{"id":等级ID,"level":顺序}]}`，须提供全部等级。复用现有批量重排、会员重算与已发券保护。
- `vip-tier`：对已有等级单独提交 `{"active":false}`，复用已有停用流程，保留已发权益及券的事实并重新计算受影响会员。
- `vip-switch`：提交 `{"vip_enabled":false}` 时固化已发券并保存停用前规则；重新启用时按既有净消费口径重算、处理符合条件的升级权益。VIP 停用期间的消费是否计入成长继续由真实消费确认事实决定。

操作在本店事务中沿用老板钱包、会员配置与权益锁，关联平台目录操作号，并在每项门店审计中记录真实平台主体，不冒充店内员工；配置版本不匹配时须重新读取。实际重算和权益保护仍要求相关开关及 License 条件，不能把未知权益当作已发。

已有老板时直接修改其他等级权益与老板分级仍需各自门店配置流程。本次不执行测试或迁移；最终隔离联调须覆盖多等级换序、停用及重启、VIP 停用期间消费、券保留、升级权益、两店隔离、并发支付与失败回滚。
