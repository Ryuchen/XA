# 积分抵扣订单协商售后退款通知恢复

积分抵扣服务订单的售后协商实际退款并完成结案时，若同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `POINTS_AFTERSALE_NOTICE_RECOVERY_ENABLED`，从本次售后周期唯一对应的已处理 `PointsNegotiationPosting` 及其退款凭据，在结案事务中保存老板通知意图和实际退回的余额、积分构成。老板收到这条结果通知，相关陪玩仍按既有结案通知范围处理，避免给老板重复发送通用结案消息。

逐店任务恢复发送失败的意图；每个实际退款 posting 最多创建一条消息。投递核验售后历史、双方确认方案与本次退款关联、原支付凭据、余额退款流水及积分返还流水、原订单账号周期和所记录的退款构成；账号重入、售后重开或凭据无法证明时记录跳过，不声称资金已退回。若找不到唯一对应的 posting，保留原通用结案通知路径，不推测退款构成。消息故障不回滚已提交的退款，站内消息创建不代表客户端收到实时刷新。

此链仅覆盖已有门禁允许执行并实际调用售后结案通知的积分协商退款；未开放场景不会因此开放。加购退款、零退款协商、非协商的积分取消/退款和其他通知不在本范围；它们沿用原路径。启用前须在各店应用 `site_messages/0031_pointsaftersalerefundnotice` 及依赖，运行逐店 worker/beat。最终联调须覆盖全额/部分、余额与积分组合、双陪转单、售后重开及多个方案、流水缺失/冲正、重复扫描与失败恢复、双店同号、账号退店重入、事务回滚和资金守恒。正式注销保持关闭，本轮未运行检查、测试或迁移。
