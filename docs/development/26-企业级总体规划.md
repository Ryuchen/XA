## 2. 企业级目标与范围

1. **首版交付**：按 PRD 完整实现三端业务闭环（订单、资金、履约、售后、薪资、经营核算、会员积分权益），通过统一最终联调与 T/G/D 验收追踪。
2. **SaaS 多店运营**：一店一独立业务库＋平台控制库；域名即门店边界；License 三档（Basic/Pro/Ultra）授权、配额、宽限期、线下合同收款与提醒全链路可用，含控制库故障降级。
3. **生产就绪**：云端部署、真实微信/短信渠道、备份容灾、监控告警、安全加固达到可上线门禁，按逐店灰度发布。
4. **企业级治理**：单一事实来源的文档体系、可复核的验收证据链、明确的发布与回滚（补偿）规则、技术债清偿计划。

**本期不做**：旧数据迁移与兼容；微信支付线上收款（一期人工收付）；三端视觉重设计（沿用现有界面，仅修必要交互）；移动 App 交付；管理后台手机端适配。

## 3. 阶段路线图

主链依赖顺序沿用 [PRD 07 §3](../prd/07-差距待决与验收.md)；License、真实渠道、前端对接、生产就绪与治理作为并行工作流穿插。每阶段有进入/退出门禁，退出只声称已有证据的范围。

### M0 规划确认与复工基线（前置）

- 用户确认恢复业务开发；确认本文阶段顺序与 §7 开放决策的处理方式。
- 盘点工作树未提交变更与他人工作边界，冻结文件分工，避免并行互相覆盖。
- 修复前端共享测试 2 项失败与 4 个接口 500 所需迁移列（`room_required_snapshot`、`room_enabled`），恢复三端可联调基线。
- **退出门禁**：`pnpm run typecheck`、`test:frontend`、`build:all`、后端 `manage.py check` 与 `deploy/dev.ps1 Verify` 全绿；阻塞性 500 消除。

### M1 身份与门店边界收尾

- 在登记隔离库验证后，按窗口对开发/目标环境执行 `stores.0006–0008` 及后续平台迁移；完成 `bootstrap_platform_admin` 初始账号与真实渠道配置后才启用 `PLATFORM_IDENTITY_ENABLED`，不得只开开关。
- 平台账号管理、OTP 首次绑定、微信快捷登录、跨店聚合（经营金额、财务、薪资）补齐。
- 落实 §6 调整项 A1（门店上下文 fail-fast）与 A2（建店七态状态机）。
- **退出门禁**：T01–T03 场景在隔离 MySQL 通过；平台/门店令牌互斥、授权撤销、同名消歧有并发行锁证据。

### M2 建店初始化与基础配置

- 网页动态建库、失败恢复、店员初始化在独立测试资源全流程验证；新店域名、微信能力、积分汇率/上限未配置时的状态明确。
- 按 [PRD 18 配置详表](../prd/18-门店初始化配置项详表.md) 完成"开业前/新店初始化"系列专题的逐项收口。
- **退出门禁**：T04 通过（成功、同名、无权限、迁移失败、重试五路径）；空库初始化可重复执行且不清已有库。

### M3 订单、资金与售后组合闭环

- 按 [18-后端剩余任务盘点](18-后端剩余任务盘点.md) 清偿积分×退款×转单×加购组合的未测试/未迁移项；逐项打开默认关闭开关前先补隔离 MySQL 证据。
- 贯通抢单/预约正式持久化时钟，恢复自动抢单类新单。
- 资金不变量（守恒、锁序、幂等、outbox）按 [10-测试发布与回滚](10-测试发布与回滚.md) 必测清单执行。
- **退出门禁**：T05–T18 及 [24-退款后加购实销联调](24-退款后加购实销联调.md)、[25-积分转单加购ROI联调](25-积分转单加购ROI联调.md) 范围在隔离环境通过；未知金额与统计不显示为 0。

### M4 履约、提现与薪资经营

- 微信绑定接单资格、头像、试音、押金、低星售后、续单奖励收口；提现门店初审＋平台财务终审＋线下打款登记全链路。
- 工资屏障、退款工资核算开关按证据逐项启用；平台公共薪资、投流与经营 ROI 单店/平台聚合复核。
- **退出门禁**：T19–T22 通过；离职结清、跨月退款扣回、迟核补发有 MySQL 并发与故障恢复证据。

### M5 License 可信缓存与业务拦截（并行，M3 起）

- 完成各增值功能发放入口的业务拦截、其余功能入口拦截与离线授权；降档超额、宽限期、到期权益保留规则按 PRD 33 验证。
- 执行控制库故障微信登录连续性方案的测试与迁移；真实物理断库演练＋隔离模式 MySQL 全流程；Celery 周期派发真实联调。
- **退出门禁**：控制库不可用时按缓存到期/宽限推进状态、恢复后重验有演练记录；无有效快照时新账号/新权益暂停且已有核心业务保留。

### M6 真实渠道与前端对接（并行，M1 起）

- 微信：正式 AppID 域名白名单、手机号能力、隐私指引、类目/认证/备案核验，上传提审；真实扫码、头像 CDN、授权手机号联调。资质未获批前保留真实链路，不伪造成功。
- 短信：真实服务商接入与送达验收；错误次数与重放限制回归。
- 前端交接：按 [PRD 34](../prd/34-SaaS产品模块与三端前端闭环.md) 与 [09-接口契约与工作包](09-接口契约与工作包.md) 向后端排期 SaaS 模块、平台订单、派单、H5 品牌接口；修复后台 13 个入口读取异常；预存倍率字段移除与 chat 事件接入。接口契约变更须同步前端开发并留验证记录。
- **退出门禁**：T10、T25 真实渠道部分单独记录通过；前端 R/W 层在隔离双店有写入证据（UI-R 通过不等于写入通过）。

### M7 统一最终联调与验收

- 按用户确认的"统一最终联调"执行：MySQL 并发、失败恢复、空库初始化、资金隔离、双店全量 T01–T228 场景；G01–G120 差距逐项关闭或明确豁免；205 决策中 160 条待核验批量核验。
- 每场景记录门店、角色、对象、前后金额、状态、请求编号、实际结果与证据；展示、接口、数据库、外部依赖分别记录。
- **退出门禁**：T/G/D 追踪表（[11-需求与验收追踪](11-需求与验收追踪.md)，`generate_trace.py` 校验）无未解释缺号；资金对账平；未覆盖真实链路明确标注。

### M8 生产就绪与灰度上线

- 云资源采购（主机规格按 160 人容量与 50RPS/30min 压测结果定，历史 2核2GB 不作为容量依据）；托管 MySQL 方案定型（非 root＋TLS CA）；备案核实。
- 落实 §6 调整项 B1–B4（异地备份、监控告警、容灾演练、媒体对象存储）。
- 发布按 [10-测试发布与回滚](10-测试发布与回滚.md) 逐店灰度五步：备份盘点→隔离迁移双读→配置切换水位→测试账号纵向→放量对账。资金事实禁止回滚消除，只能补偿/前向修复。
- 清除旧线上数据后全新部署（须用户单独授权执行）；执行结构迁移、`check_mysql_readiness`、平台与门店初始化、License 配置。
- **退出门禁**：[RELEASE_READINESS](../ops/deployment/RELEASE_READINESS.md) 清单逐项有据；压测达标；RPO≤5min/RTO≤2h 演练通过；发布仅手动触发且绑定完整 SHA。

### M9 上线后运营与迭代（首版验收后）

- 按真实经营数据复核薪资/ROI 口径与 License 档位配额；收集门店反馈进入二期需求池。
- 二期候选（不在首版承诺）：微信支付线上收款、视觉升级（老板/陪玩双风格 H5 App 形态）、监控深化与高可用架构、移动 App。

## 5. 验收门禁与证据规则

1. **构建成功≠业务验收**；隔离替身通过≠真实渠道通过；UI-R 通过≠写入/资金隔离通过。每轮只声称已有证据的范围（CONTRIBUTING、10 文档）。
2. 资金类改动必须有隔离 MySQL 并发/行锁证据与前后金额对账；SQLite 跳过行锁的用例须在 MySQL 层补验。
3. 默认关闭的功能开关，启用前逐项补测试与迁移证据，启用记录写入 16/18 文档。
4. 测试不得触及生产资金、真实客户或真实消息接收人；有状态资源与生产隔离，`xa_test_` 前缀库强制。
5. 发布门禁：M7 退出＋M8 清单全绿＋用户明确授权，三者缺一不可；本仓库配置检查不构成上线许可。
6. 视觉演示数据不能作业务验收证据；示例数据须明确标识。
