# 房间异议通知恢复

老板提出房间异议时，开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `ROOM_OBJECTION_NOTICE_RECOVERY_ENABLED` 后，在异议及暂停确认时钟的原事务中固定当时具有订单查看和客服处理权限的本店工作人员及其账号周期。提交后独立发送通用待处理消息，失败由逐店任务重试；异议已处理、账号离店或重入、工作人员停用或权限不再符合时记录跳过，避免发送过时或越权提醒。

客服正常处理或整单协商终止同步处理异议时，以原订单老板周期保存结果通知意图，投递前核验原异议和真实处理事实；每个异议、收件账号和事件种类最多创建一条消息。说明文本仍由原异议记录提供，通知不复制私密内容。发送失败不回滚异议、协商或资金事实；站内消息创建不代表客户端已收到。关闭开关沿用原周期保护的即时路径。

异议暂停、零剩余时间、处理后恢复原剩余时间或确认失效的规则没有改变；未新增其他收件人。启用前须在各店应用 `site_messages/0026_roomobjectionnotice` 及依赖，并运行逐店 worker/beat。最终联调覆盖提出与超时竞争、暂停及恢复原剩余时长、条件失效、普通处理与整单协商终止、部分终止保留异议、重复请求、授权撤销和账号重入、双店同号、通知失败和并发恢复及业务事务回滚。其他实时事件仍有缺口，正式注销保持关闭。本轮未运行检查、测试或迁移。
