# 老板主动取消退款通知恢复

老板主动取消未分配且已付款的订单时，普通取消入口及单双陪抢单池取消回执均在原取消与退款事务内保存老板通知意图；只在同时开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `CUSTOMER_CANCEL_NOTICE_RECOVERY_ENABLED` 时启用。未产生实际退款记录的订单不创建此退款通知。提交后独立发送，失败由逐店任务恢复，每个订单最多创建一条。

消息按实际退款构成分别描述余额及抵扣积分。投递核对老板取消状态日志、原订单和账号周期、退款记录及对应流水；抢单池额外核对本人取消回执。积分退款须匹配最终退款凭据和原订单积分流水；普通余额退款仅在本单只有一笔退款、且能唯一核对成功退款流水时发送。无法证明退款、账号退店或重入时记录跳过，不推测到账；消息创建不代表客户端已收到。关闭开关维持原取消入口通知行为。

须在各店应用 `site_messages/0029_customercancellationnotice` 及依赖，并运行逐店 worker/beat。最终联调覆盖普通与单双陪抢单池取消、积分和余额混合退款、退款凭据缺失或歧义、老板取消与分配竞争、消息失败恢复、重复扫描、退店重入、双店同号、资金和业务事务回滚。客服核对取消、售后退款、直付退款和未付款取消不在此通知恢复范围；既有取消业务和资金逻辑不变，正式注销保持关闭。本轮未运行检查、测试或迁移。
