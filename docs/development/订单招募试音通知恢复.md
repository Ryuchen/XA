# 订单招募试音报名通知恢复

订单招募试音的真实报名在 `OrderApplication` 新建时保存发起人及受邀队友的本店业务周期。开启陪玩生命周期集成后，组队确认、提交录音、撤回及老板选人会复核原报名周期，不能让重入后的账号沿用旧报名。停用后允许处理已有撤回的既定行为仍保留；选人和确认继续按原资格规则验证。

生命周期集成开启时，队友邀请、确认、撤回及老板选中／未选中结果的逐人意图随实际报名或选人事务保存，提交后独立创建站内消息。意图保存原收件周期；任务按本店账号、订单、报名和通知的锁序核对来源，重复处理不会重复创建消息。邀请只在订单和邀请仍有效时发送；已经撤回、选人、过期或账号重入的过时意图记录跳过。消息发送失败不回滚已提交的报名或分配；消息创建不代表客户端已收到。

`ORDER_APPLICATION_NOTICE_RECOVERY_ENABLED` 默认关闭，只控制逐店定时恢复；生命周期集成开启时新意图始终持久化并尝试即时发送。空库须执行 `orders/0256_application_business_cycles`、`site_messages/0019_orderapplicationnotice` 及依赖，并运行逐店 Celery worker/beat。最终联调须覆盖单双陪录音报名、邀请确认撤回、同人重复报名、赢家与未中选人、账号停用和重入、并发选人、事务回滚、部分通知失败和恢复、两店同号及实时刷新。订单取消通知与其他订单实时事件未纳入此链路；客服安排新单仍走抢单池，正式注销保持关闭。本轮未运行检查、测试或迁移。
