# 积分无转单部分退款后的加购

当前代码中，双陪订单首次主单协商部分退款后，若真实终止凭证确认另一名陪玩继续履约，老板可在原订单的加购报价和申请入口选择该陪玩；付款由 `service_order` 资金上下文核验主单退款、钱包来源和实际履约席位，付款、补资重算和 RELEASE 在原事务内记录。加购退款沿既有售后方案、双方确认及执行入口，按付款来源退款，并核验本人未结加购收益、主单收益、钱包与押金。财务补资及订单完成后的逐人结算复用退款后资金和结算路径。

本次修正无转单积分单的逐段扣减：主单退款影响某陪玩时，使用已确认的本人保留收益，并从扣减历史中排除该保留收益已包含的主单退款前加购扣减；未影响的陪玩仍使用本人原收益及实际扣减。原退款、已付流水和已发生权益不重写。

本切片依赖现有正式功能开关、真实退款与继续履约凭证，未放开单陪已终止、订单已完结、新的转单、无凭证或其他未接入组合。未运行测试或迁移；需在隔离 MySQL 联调首次部分退款后的新加购、原构成部分与全额退款、补资不足及补足、逐人结算、重试、并发锁顺序和失败回滚，不能据代码接线视为已验收。
