# 退款押金补差收益释放（2026-11-13）

退款押金缺口存在时，部分结算产生的服务收益可能因整单尚未完成而暂存冻结。收益扫描现在排除这些未完成的服务订单，锁定订单及钱包后再次核对完成状态；因此它们不会排在已满足条件的其他订单或礼物收益之前，也不会提前关闭该单补差接单机会。礼物仍按自身售后及冻结时钟判断。服务收益进入冻结前仍由原报单审核与结算入口负责校验，释放时继续检查适用的开放售后、冻结流水和跨来源排序凭证。

全额追回的现有通用退款路径会把对应冻结标记为取消，不会产生零额释放流水；首版服务报单结算要求完成并通过售后、冻结时钟，逐段结算还拒绝旧式追回。故不能仅凭已取消冻结推断该服务补差单在实际结算条件下已完成，不在此创建虚假收益或关闭机会。若其他可达售后分支出现全额追回，须基于其真实退款及逐人结算凭证继续接入。

退款押金缺口、保护和补差接单开关默认关闭；跨来源到期及售后结案先后无法从既有凭证证明时仍留待核对。本次未执行测试或迁移，最终须在隔离 MySQL 联调服务与礼物交错到期、售后结案、机会关闭和并发锁序。

复查状态机：首版正常协商终止和追加协商终止将履约订单转换为 `COMPLETED`，以双方同意时点记完成，逐人结算仍校验本人报单及等待条件；没有发现可达的 `CANCELLED` 协商终止后收益结算入口。旧 `negotiated_refunds.py` 虽有转 `CANCELLED` 并立即入账的代码，其方案固定不可执行，且不具备双方同意证据，不据此放宽本次释放判断。最终联调须覆盖协商终止的真实状态转换、本人报单和售后等待、补差收益释放及机会关闭，不以旧入口或构造状态替代。
