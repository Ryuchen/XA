# 礼物退款后的授权核对来源

平台核对礼物的会员成长或消费积分 UNKNOWN 时，两项现共用同一付款与退款证明：唯一老板礼物扣款与订单金额、钱包变动和原交易状态一致；每笔正额退款按金额和实际操作人对应本店退款钱包流水，且每笔余额变化、累计退款和原付款来源一致。充值混合来源须有明确的本次赠送部分为零的快照，来源缺失不能推断为本金。部分退款按现有真实净本金处理，全退或账号业务周期已变化时不恢复成长或积分。

该核对只针对平台人工恢复 UNKNOWN 权益，不修改赠礼付款、退款、已发券或现有成长；付款或退款凭证不完整时维持待核对，原请求的幂等和平台审计不变。来源缺失导致的待核对不能仅靠当前余额或当前 License 推断补发。参考 [Reconcile 交易与账本对账](https://github.com/opensyndicate/reconcile) 对支付事件和流水分别核对的思路，具体账务证据以本项目规则为准。

按开发期要求未执行测试或迁移，仅完成 Python 语法解析。真实多次退款、同额退款、原本金和赠送批次、退店重入、跨店及并发审核仍需隔离环境联调；其他凭证结构不兼容的组合继续待核对。
