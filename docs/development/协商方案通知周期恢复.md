# 协商方案通知的原周期与恢复

站内消息列表和详情继续返回 `cycle_relation`：原周期为 `PREVIOUS`，当前周期为 `CURRENT`，来源无法确认时为 `UNKNOWN`。旧消息不删除；详情、未读和全部已读受本店账号周期锁保护。

协商方案创建、参与人全部同意或有人拒绝时，从真实方案、受影响人员及订单席位记录保存每人的原业务周期，同事务建立发送意图；不读取发送时的当前周期冒充来源。提交后尝试发送，失败由本店任务恢复；按方案、收件人、事件状态幂等。恢复时重新核验方案是否仍为最新、状态、本人参与及当前账号周期；已经处理或方案变化的过时提醒跳过。原订单周期缺失或冲突时意图保留为 `REVIEW` 供核对，不向新周期发送。方案确认消息明确退款以实际流水为准。

`NEGOTIATION_PROPOSAL_NOTICE_RECOVERY_ENABLED` 默认关闭，依赖 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED`。关闭恢复开关但开启生命周期集成时，即时路径也使用原订单周期核验；来源缺失会记录告警，不能自动恢复。生命周期集成关闭时沿用原即时行为；启用前必须执行 `site_messages/0040_negotiationproposalnotice` 及依赖结构迁移并配置逐店任务。未具备原周期或持久意图的其他旧发送路径仍需逐项接入；`REVIEW` 目前保留数据库记录，尚无专门的后台核对页面。当前未运行测试或迁移，需隔离联调旧消息展示、退出重入、方案更新、失败恢复及双店隔离。
