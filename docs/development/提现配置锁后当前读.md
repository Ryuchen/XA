# 提现配置与并发申请

平台初始化和门店配置共用本店提现配置互斥锁，提现申请也先取该锁。但原实现锁后仍以普通查询读取规则：在 MySQL 可重复读事务已建立较早快照时，等待配置更新后仍可能看到旧的最低额、余额门槛或手续费。

提现申请在互斥锁后改用配置行当前锁定读；配置保存时比较旧规则、版本及指纹也使用当前锁定读。单笔最低额仍单独判断，可用余额须严格大于门槛，提现手续费及冻结金额按申请事务锁后规则确定。只读预览继续返回本店快照，已有申请继续保留申请时的费率和金额。

未运行测试或迁移。最终隔离 MySQL 联调须覆盖平台及门店修改与申请并发、旧试算版本、严格大于门槛、最低额、手续费和两店隔离；不以本次修改代替提现审核及线下付款验证。
