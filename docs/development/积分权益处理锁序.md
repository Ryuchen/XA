# 积分权益处理锁序

后台权益交付、取消入口沿用原角色权限和已有权益，不因 License 到期或暂不可核验要求重新授权。处理真实领取记录前，按陪玩生命周期锁（适用时）、本人钱包、门店会员配置、账号、奖励、领取记录、积分资料的顺序获取锁，并在锁后核验原领取记录的归属和来源。

积分兑换取消必须确认原 `REDEMPTION` 扣积分流水、金额及账号业务周期，才返还原积分并恢复库存；同一已完成取消继续返回原结果。退店后原周期不得向新周期返积分，退店已取消的权益不能重新交付。所有积分、库存和领取状态写入在原事务中提交。

该改动消除原领取取消持领取记录等待积分资料、与老板退店持积分资料等待领取记录的直接锁环，并与当前抽奖、兑换及 VIP 配置使用兼容的前置钱包/配置锁。后台处理入口沿用 MySQL 并发冲突的明确重试提示，不自动重试。

未运行测试或迁移；其他资料编辑、标签审核、钱包资金及异步任务尚未全部统一，不能认定全局无锁环。最终需隔离 MySQL 联调取消与退店、VIP 配置、抽奖/兑换竞争，原周期和 License 到期、重复取消、库存/积分守恒及回滚。
