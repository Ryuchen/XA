# 预约优惠活动锁后核对

老板普通下单、客服代单和预约转单不使用组合令牌时，付款事务在锁定选中活动后核对活动身份、折扣、抽成及活动规则版本；如果同金额报价对应的活动或其抽成发生变化，要求重新报价，不以金额相同视为规则相同。已选择的券仍按现有锁内复价、消费和原路退款处理；积分订单同样使用核对后的成交数据。网页直付意向代码也传入该活动核对，但微信直付仍是后续能力，不能据此认为已开放或验证成功。

组合令牌的付款复核直接比较已锁定的服务、会员配置、活动和券行与签名时的依据；返回实际锁定的活动和券供付款使用。会员档位与私有券条款变化也要求重新报价。优惠类型互斥、一张券和已选金额券叠加规则不变。

付款的最终组合计算使用锁定后的当前读，不再用 MySQL 可重复读中较早的普通查询重算；VIP 私券还锁后读取月券发放事实、会员档位与安全箱规则，并按同一结果保存生效条款。无令牌付款也按活动、券的顺序锁定并重算；不把推荐券当作用户已选择的券。最终须核对不同优惠同时付款、会员变更和活动/券修改的锁顺序与失败回滚。

参考 [Saleor 订单模型](https://github.com/saleor/saleor/blob/main/saleor/order/models.py) 将优惠前金额和券关联分别保存的做法；本项目继续使用本店原价、优惠券、活动身份、整数店币及抽成快照，不采用 Saleor 的优惠或税务规则。

本次未运行测试或迁移。最终须在隔离数据库联调预约付款与活动修改并发、相同折扣不同抽成、积分及券组合、原路退款与双店隔离。
