# 积分转单后加购退款的追加协商

受控积分订单先完成服务转单和一笔加购，首次主单退款后再退款该加购、期间没有新的服务转单时，追加主单协商现可复用首次退款冻结的逐段履约事实及真实加购资金事件，不再要求虚构一条退款后的转单版本。原有每席最多两次转单规则不变。

追加协商在实际订单资金事务中核对原付款、首次退款、加购退款和对应 RELEASE；第二次退款及后续补资、逐段报单和结算按第二次退款时点回放相同事件。共享到账在到账锁及当前读下逐笔核验实际 RELEASE，零释放也须有真实事件凭证；已发生的第二次退款不会改变此前加购退款的时间依据。涉及同一陪玩时，须明确选择首次退款未关闭的真实履约段。

进一步支持多笔已付款加购，以及首次主单退款前完成真实三方确认的加购接替；首次主单退款后发生的独立加购退款按每笔付款与 RELEASE（包括真实空释放）逐项回放。须在第二次退款前核验每笔付款、本人责任、已确认接替、退款及整单资金历史；接替尚在确认、来源缺失或事件时序无法证明时不放行。原先支持的退款后新转单与其接替版本链继续独立核验。

本次扩展限定付款和已确认接替发生在首次主单退款前、至少一笔加购退款发生在首次主单退款后、追加退款前无新转单版本的组合；每笔加购接替仍受既有责任版本支持范围约束。其他加购接替、付款时序、已付人员及后续转单仍受各自现有凭证与门禁约束，无法证明时继续待核对。原退款权限、双方确认、原构成退款、到账及逐段结算规则不变。

未运行测试或迁移，正式开关保持原值。最终须在隔离 MySQL 联调每席一至两次转单、多笔加购和已确认接替、双方确认与原路退款、加购部分及全退、真实或空 RELEASE、共享到账与后续补资、逐段报单和等待期、同人不同履约段、并发与回滚。
