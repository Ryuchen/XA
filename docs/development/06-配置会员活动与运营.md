# 06 配置、会员、活动与运营

## 1. 系统字典与开店初始化

保留 [BusinessDictionaryItem](../../services/backend/console/dictionary_models.py#L7)、[SystemConfig](../../services/backend/wallet/models.py#L277) 及游戏、会员、薪资等现有专用表，新增统一配置目录、表单和版本服务，不要求把所有配置塞进单一 JSON 表。每项登记 `code / 名称 / 类型与单位 / 合法范围 / 是否核心 / 所属权限 / 生效方式 / 校验 / 来源表 / 版本 / 更新时间和操作者`；系统安全字段和商户业务项分级管理，敏感接入凭据不在普通字典页面回显。

| 组别 | 主要项 | 开业／生效 |
| --- | --- | --- |
| 身份与门店 | 名称、`shenglang/SL/浪花`、`xinan/XA/星辉`、域名、店头像与客服名片 | 唯一性、域名归属、展示前缀显式配置；不因变更昵称重写历史编号 |

| 资金 | 钱包单位、押金模式／目标、提现最低额／余额门槛／手续费、售后与冻结期限、预存档位和审批 | 资金核心项必填并校验；人民币、店币及内部记账单位不得混用 |

字段逐项定义与默认参考以 [PRD 配置详表](../prd/18-门店初始化配置项详表.md) 为准。所有配置在服务端校验并版本化，读配置以当前门店上下文；需要交易快照的字段随支付、入池、预约、人员转入等业务时点存储，不能仅保存当前值。后台修改采用版本检查和审计，避免管理员并发覆盖。

新店在准备资料、完成迁移、配置核心项、校验和显式营业这几阶段均有状态、可恢复错误与逐项检查；没有配置的非核心功能要明确关闭，不能默默使用别店值。两店历史业务数据和现有配置逐项核实后作为各自初始值，不能复制钱包或客户。

## 2. 陪玩资格与抽成配置

集中化资格判定并在所有入池、试音、指定、转单、预约与开工路径调用；兼容历史人员的头像资格。现金押金／单抵目标及每店并发规则按配置。新购通行证支付成功立即生效 24 小时；已有生效通行证时不得提前购买或升级，历史未生效队列可在生效前本人自动全额退并按购买顺序提前后续权益。通行证可见配置和提交排序快照遵循 [04](04-抢单预约与履约.md)。

三角洲根据游戏／玩法／端／难度／档位配置抽成；瓦罗兰特和英雄联盟仅配置陪玩、代肝两类，上分按代肝。转入人员使用其接入当时的费率快照，已参与人员和历史未结订单保留原快照；不允许客服单笔更改比例。统一检查现有 [ServiceItem](../../services/backend/orders/models.py#L119) 的固定比例、覆盖和政策字段，移除与新规则冲突的单笔入口，而非直接删除历史值。

## 3. VIP、券、积分与预存

- VIP 等级数量、门槛、折扣、月券、安全箱与积分倍率均由每店配置。按净有效消费升降级；同月升级不补发月券，已发券原条款保留，下月使用新等级。退款降级、取消等级时保留已发未用券与未交付权益的适用原条款；取消等级需按新门槛重新计算。
- 仍有效等级的规则调整通常使未使用券按新规则更新；月券数量调低不回收本月已发券，下次发券使用新数；已用券不改；全退恢复的有效券使用其原下单时条款。等级停用时已发券有效但停止等级折扣；VIP 停用期间不产生消费积分，其间消费不计入重启后成长。
- 支付和实销时均须满足 VIP 相关启用约束；付款时快照 VIP 与生日倍率。只有本金消费产生积分，赠送／赔付不产生；实际退本金冲回，使用前核查积分余额。礼物仅本金支付且支付成功即计 VIP 成长。
- 积分发放、抵扣、商城或抽奖任一项关闭时暂停所有积分**使用**；如果积分发放开关仍开启、VIP 等发放条件满足，消费仍可获得积分。四项恢复后使用自动恢复。保留商品兑换及抽奖余额奖品，禁止积分商城直接兑换余额。
- 允许同店多个积分抽奖同时开放，各自独立计数；修改保底次数重新计数，仅变目标奖品且次数不变则保留计数。保留已发奖品／权益及审计。
- 充值档位按从高到低贪心可重复组合，不比较全局最大赠送；若 6000 赠 250、3000 赠 100，则 7000／9000／12000 分别赠 250／350／500。充值赠送变更需 OA；各账务保留收款人和来源。

## 4. 其他小功能的口径

签到、补签门槛看当日实付净额，按实际付款日期归属，包含服务、礼物及服务加购，扣除已退款的店币；积分抵扣不计入，已领的奖励和补签卡不因事后退款追回。签到统计代码已接入付款及加购流水，跨日预约、退款和积分组合仍待最终联调。非礼物成就及会员标签统一按本店已确认实销的非礼物服务订单；老板消费榜包含礼物且对外按原价净额。赠礼获得的已发权益、标签和冠名期限不因退款撤销。老板退店须独立权限，确认页完整显示清空内容（含负积分），结清钱包后执行并留审计，保留历史订单与资金流水。

以上计算不可复用同一个笼统“消费额”字段；按订单类型、时间点和快照生成可追溯事实。积分商城、抽奖、签到、广播、消息、客服名片、内容等既有入口逐项按 [页面接口追踪](../prd/08-页面接口追踪.md) 和 [接口清单](../prd/09-后端接口清单.md) 验证，不能因未改变视觉而忽略权限和隔离。

老板消费榜补充：真实已完成的服务或礼物若主单全额退款后状态转为 CANCELLED，仍按原完成时间归入本店榜单；该主单优惠前原价全额冲零，已付款加购按各自真实付款及退款净额单独保留。未开始即取消且没有完成时间的订单不计入；身份沿本店账号和现有映射处理，榜单不等于实付。未运行测试或迁移，最终需联调全退、保留加购、礼物及双店场景。
