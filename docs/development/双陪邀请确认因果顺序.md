# 双陪抢单邀请与确认的因果顺序

双陪首轮排序核验完整队伍时，邀请和队友确认的数据库提交观察区间可能因快速操作而重叠。正式 MySQL 写入路径中，确认事务先持同一订单锁，读取已持久化且属于该队伍的邀请与成员凭证，之后才创建确认收件；因此在同轮、成员及原始凭证均核实且数据库生成的收件顺序一致时，可据此证明邀请先于确认，不再仅因两个观察区间重叠阻断这支完整队伍。

此因果判断只用于同一队伍的邀请／确认，不用于比较不同队伍或单陪候选的完成时间，也不改变完全同分重开与时间无法核实时的处理。通行证可见时间及各人资格仍按原规则核验，非 MySQL 或证据不足仍待核对。无新增迁移，正式抢单开关保持默认值；未运行测试或迁移，须最终隔离 MySQL 联调快速确认、同分、跨店及提交失败回滚。
