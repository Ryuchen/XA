# 报价推荐与预约显式用券

普通下单报价、预约转单报价及客服代单报价新增 `recommended_discount`，展示按当前门店规则计算的最低价合法比例优惠及最多一张适用券，包括券编号、折扣和抵扣积分前的金额；体验、礼物及加购不使用该普通服务推荐。原 `amount`、`user_coupon_id` 等字段继续表示本次实际选择，不把推荐当成已选择，更不在未提交选择时静默核销券。积分试算仍根据实际选择进行，按既有完整兑换组规则计算。

预约报价 GET 和转单 POST 可提交 `user_coupon_id` 显式选择原老板本店本周期的券；未传或空值表示该参数不选券。优惠组合凭据与 `user_coupon_id` 不能同时提交。组合选择功能开启时，报价可按明确的券编号生成对应选择凭据，转单仍须提交该凭据；显式空券报价选择无券组合。普通订单的组合凭据若包含券，与显式 `user_coupon_id=null` 矛盾时拒绝。客服选择券时须记录老板明确确认；转单时沿用原券归属、适用范围、有效期、钱包及券锁、折扣复价和请求幂等校验。

本次没有默认启用优惠组合付款或积分资金功能；不开启组合付款时，不能通过券编号指定非最优的另一比例折扣，须等既有组合凭据能力启用。推荐是价格试算，不代表特殊零实付、积分或其他受限资金路径已经可付款。未运行测试或迁移；最终须隔离联调普通、预约和代单的选择、空券、优惠变更、券并发核销、积分组合与真实付款回滚。
