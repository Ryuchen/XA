# 双陪预约席位超时通知恢复

双陪预约的待确认席位实际超时并释放时，开启 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 和默认关闭的 `RESERVATION_EXPIRY_NOTICE_RECOVERY_ENABLED` 后，在同一事务保存该席位原陪玩账号、原周期和实际 TIMEOUT 事件的通知意图。提交后独立投递，失败由逐店任务恢复；同一席位超时事件最多创建一条陪玩消息。投递核验对应原邀请、超时事件及原账号周期，席位后续已重选、账号离店重入或来源不明时记录跳过。

预约仍存续时，老板通过既有席位事件恢复链收到超时提醒：既覆盖另一席位已确认，也覆盖另一席位仍待确认；席位已重选或预约已结束时延迟的旧提醒跳过。整单过期仍走既有预约过期通知，不额外发送误导性的重选提醒。发送失败不回滚席位释放或预约事实，创建站内消息不代表客户端已收到；关闭开关保留原即时发送路径。

启用前须在各店应用 `site_messages/0036_reservationseattimeoutnotice` 及依赖，并运行逐店 worker/beat。最终联调覆盖一席超时而另一席确认/待确认、双方均超时、整单过期、同人再次受邀及换人、老板和陪玩各自的延迟投递、并发扫描、账号停用或重入、双店同号及事务回滚。服务前改派不在本轮范围；正式注销保持关闭。本轮未运行检查、测试或迁移。
