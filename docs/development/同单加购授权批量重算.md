# 同单加购授权批量重算

同一老板原业务周期内，如果待重算审核全部来自同一服务订单的多笔加购，后台任务会锁定该订单，按加购实销顺序逐笔重进原审核验证。每笔均须核对原授权审核、真实付款、逐笔退款来源、已退本金和实销快照；锁定原钱包与账号后再次核对周期、待处理审核集合，以及是否混入礼物或服务退款待处理审核。全部一致才调用一次既有会员重算；任何一笔无法证明或批次发生变化，事务回滚，全部保留待处理。任务沿用原平台审核操作者及请求，不创建新的平台审核。

本次支持同单多笔加购，单笔处理沿用既有入口。跨订单、跨类型及不能被原验证器证明的退款仍不自动重算，不能视为完整批量恢复。旧周期依旧依靠原退店审计处理，不向新周期发放。

跨单批次后续接入须先统一资金锁契约：目前积分服务的 `orders.points_business_access.service_order`、`case_refund_scope` 和 `orders.points_transfer_refund_access.after_transfer` 会在各自范围内获取订单、资金互斥及关联凭证锁，某些范围还先后持有账号和多个钱包；现有单笔审核也在不同阶段取得订单、审核、资金来源、钱包与账号锁。不能在持有第一笔钱包或账号后继续进入第二笔订单范围。需要由资金层提供能按全局稳定次序一次锁定所有订单、资金互斥、退款/分段凭证及钱包账号的批量范围，并重新核验批次快照，再让各审核验证器复用已持有的范围；混合类型也须纳入同一事务及完整集合检查。该契约尚未实现。

本次未运行测试或迁移。最终需在隔离环境验证同单多加购、多笔部分退款及退款并发、新审核插入、授权恢复、退店重入、任务重试和锁等待；还需覆盖跨库审计与真实资金来源。
