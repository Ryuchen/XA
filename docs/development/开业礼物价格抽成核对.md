# 开业礼物价格及抽成核对

礼物商品使用现有门店商品目录保存和读取；直接赠礼和订单后赠礼共用现有服务端礼物价格与抽成规则。本次增加 `gift_pricing` 核对快照，列出当前及未来上架礼物的价格、商品实际抽成、现有统一门槛和默认比例。未设置单品比例时展示业务实际采用的默认比例；不生成新比例，也不改变历史礼物、钱包或已获权益。

本店有 `dictionary:edit` 和 `service:edit` 的人员可通过 `GET/POST /api/admin/dictionaries/setup-confirmation/gift_pricing` 读取并确认快照；平台超级管理员从初始化配置读取快照并通过已有 `/api/admin/platform/store-management/{id}/setup/confirm/gift_pricing` 核对。确认与商品修改使用同一本店目录锁；价格、抽成、商品上下架或期限变化会使快照失效。平台和门店继续使用原商品接口保存，开业判断与礼物读取使用同一商品数据。

首次开业只在当前授权允许新赠礼且有当前或未来上架礼物时要求确认；无授权或无上架礼物不强制启用或创建商品。若部署关闭 License 权益拦截，则按真实业务开放情况核对。过期礼物不计入待售清单。此项没有将营业后新发布商品与开业确认绑定，也不代表完成全部礼物资金验收。

参考 [VTEX Marketplace 订单模型](https://github.com/vtex/openapi-schemas/blob/master/VTEX%20-%20Marketplace%20Protocol%20-%20External%20Seller%20Fulfillment.json) 将交易商品及其价格作为核对对象；本项目抽成、门槛和资格遵循现有源码和 PRD，不照搬其交易流程。

按开发期约束未运行测试或迁移；仅完成 Python 语法解析。后续在隔离环境验证商品启停和期限、授权变化、门店权限、目录修改与确认并发，以及实际赠礼和退款快照。
