# 07 薪资、客服与通知

## 1. 员工、工资与经营

现有 [SalaryPlan / SalaryAssignment / SalaryActivity / PayrollRun](../../services/backend/console/payroll_models.py#L20) 和 [payroll_calculation.py](../../services/backend/console/payroll_calculation.py#L143) 已有方案、来源与月结，可扩展，不需另起薪酬系统。按门店配置岗位底薪、目标、绩效、白天／夜班派单、充值、售后、考试等，工资方案及岗位独立于后台授权。夜班按北京时间固定时段和店内配置判定；声浪考官每次 50 元为扣抽成前，抽 30% 实得 35 元。参考表截图原件本轮未复核，其他具体数值必须由门店确认配置。

平台超级管理员与平台财务可配置、核算各店，动作同时记录平台主体、目标店、本店工资对象和授权版本；不把平台主体对象写进目标店的员工外键。平台财务本人薪资属于平台公共成本，仅平台总账计一次、不分摊门店。已有本店工资记录原有外键保留，新增可表示平台操作人的审计字段。

工资来源表按实际工作归属：老板选择绑定员工的客服名片只设置订单负责人；咨询仍需领取，绩效依真实派单、售后等工作记录。订单实付与退款按发生月形成净业绩，派单提成使用店币实付而非原价；对账应能追溯原订单、充值、退款和操作者。原消费按付款月、退款按发生月；负净业绩当月绩效为零且负业绩不结转。

已确认工资不改写：晚核实业绩于下一期补发并关联原来源；退款导致应扣的原单提成在退款当期或已确认后的下一期扣除，应发不低于零，剩余欠扣继续结转；离职或停用结清未结工资后，剩余欠扣不再追扣并留痕。原月绩效不追扣，退款计入发生月绩效；若该月工资已确认，则下一期按此退款对发生月绩效的影响调整，避免重复扣。月结快照、来源版本、调整原因、上期余额与本期余额需要可重算及去重。

经营报表同时提供 `净订单消费 / 投流` 和扣业务成本、薪资、投流、其他已录成本的经营 ROI。订单净消费为实付减实退店币，赠送／赔付实际消费计净消费但利润须扣相应成本一次；按付款月份计收入、退款月份冲减。已经以积分抵扣后的实付为收入时，同一笔积分抵扣不得再作为成本重复扣一次：成交 100、积分抵 40、店币实付 60、陪玩应得 80，不计其他费用利润为 -20，而非 -60；仍单列抵扣、应承担和实际待补足供对账。补贴、取整差额、佣金以及平台公共成本分别显示，不能把不可用数据默认为零。

## 2. 客服共享池

当前 [ChatSession](../../services/backend/chat/models.py#L5) 与 [ChatSendView](../../services/backend/chat/views.py#L71) 实现账号会话与消息，但尚须增加接待责任。每店共享会话列表，普通客服只能看会话列表和接待状态；领取后才可读取该会话正文并回复。领取动作行锁／版本冲突，确保同时只有一名接待人；可交还、转交，主管可重新分配，不自动回收。

主管按权限可查看全部会话并直接回复，回复不改变原领取人。对象级授权统一用于 HTTP 历史消息、发送、已读、未读摘要、WebSocket 订阅／重连、图片和私有文件；领取前列表不得把正文预览、附件链接或推送内容泄给其他客服。跨店一律拒绝，不因猜中会话 ID 得到任何信息。转交／撤销后立即失去正文和后续推送权限，既有已签文件链接也要能重新授权或短期失效。

从订单发起咨询时保存正式订单关联及卡片快照，客服和主管可按权限跳至原店订单与售后进度；不能只靠聊天文字里的订单号。订单信息读取需要再次检查订单及售后对象权限，双陪人员不能从卡片读取另一人的售后详情。名片员工绑定与实际会话领取不是同一责任。

## 3. 消息与外部通知

保留站内消息、Channels、群发及短信接入；事件在原店事务提交后持久投递，消息携带门店、业务对象和事件版本，每个接收人去重。重试、撤单、转交、权限变化后再次检查有效性；外部群避免泄露钱包、私人聊天和提前可见的订单详情。消息发送失败单独重试与报警，不回滚已成功的订单资金操作。实际微信／短信／群通知以可用测试接入验证；无法安全触达真实接收人时使用明确标识的隔离替代。

咨询接待重分配：依据《咨询消息与通知》2 节主管重分配规则，主管转交其他客服正在接待的会话，或将该会话交还共享池时，必须填写调整原因；成功后沿现有事务保存原／新接待人、操作人、原因和时间。普通客服处理自己的会话仍沿用原规则。未运行测试或迁移，最终需联调并发领取、主管重分配和权限变化。
