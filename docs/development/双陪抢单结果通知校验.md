# 双陪抢单结果通知校验

双陪抢单既有结果意图在实际仲裁事务内保存老板及每位队员的原周期，提交后由本店任务重试。发送获胜者和老板的结果前，复核原 GRAB 状态日志、获胜队伍、双方当前席位及席位周期；订单取消、改派、状态变化或来源不一致时记录跳过，不再补发过期接单提醒。未抢到队伍仍按原真实仲裁结果通知。重开提示仅在后续最新双陪轮次仍为 OPEN 或 PARKED、订单仍待接单时发送；不能仅因首轮窗口已截止认定留池邀请失效。

双陪 INVITE／CONFIRM 在生命周期开关关闭时也先持两人的生命周期共享锁，核对已认证请求身份及队友在店周期，再随真实回执保存本人周期和受邀人周期；因此新回执的即时结果可使用可信原周期，不从当前账号推测。该入口依赖 MySQL、本店初始化的 `club_accounts/0010_provider_lifecycle_lock` 和已有抢单回执结构，缺来源时即时投递记录失败。可靠恢复仍需 `GRAB_RESULT_NOTICE_RECOVERY_ENABLED` 与 `PROVIDER_LIFECYCLE_INTEGRATION_ENABLED` 均开启，以及既有订单/消息结构和逐店 worker/beat；两开关默认关闭，即时回调失败没有持久重试。本轮未新增迁移、未运行测试或迁移；最终需联调双陪首轮、留池首个完整队伍、重开、改派取消、收件人重入及失败恢复。

组队邀请投递不再依赖生命周期总开关决定是否检查周期：始终读取邀请回执中受邀人的原周期，并在订单锁后核对当前账号；来源缺失保存待核对记录，账号重入或邀请结束记录跳过。有效期仍按实际轮次状态和总等待期限判断，留池阶段不因首轮截止而失效。
