# 咨询订单卡片及接待联调范围

聊天消息的 `order_card` 在现有订单卡片中增加 `after_sale`：

- `{"available": false}` 表示当前账号没有售后查看权限，不代表不存在售后。
- `{"available": true, "case": null}` 对老板和后台表示该订单没有售后；对陪玩表示没有可向本人展示的售后，不表明其他陪玩是否有售后。有权看到的 `case` 包含 `id`、`status`、`status_display`，每次读取均查询当前状态。
- 老板须仍拥有该订单；后台须有会话正文读取权和 `order:view`（现有售后列表查看权限）。陪玩须本人属于订单，抢单池可见本身不授予售后查看权；只返回本人在受影响陪玩和指定履约段范围内的售后，整单售后对本单参与人可见。范围字段异常时不展示该售后。订单自身不可见时继续返回原有的订单卡片不可用结果。
- 实际开始履约后已转出的陪玩可在本人会话关联该订单并读取卡片；仅有未开始的接替记录不授权。普通订单详情无权打开时 `can_open` 为 false，`participation_detail_url` 指向只读 `GET /api/chat/messages/{message_id}/participation/`，仅本人会话且有本人已开始履约事实可读，返回卡片与本人履约时间，不开放普通订单正文或操作。正式履约段作为本人开始事实的后备，缺本人完成时间时返回 null；前端尚未接入此入口。

共享池的领取、交还、转交、主管查看及回复继续使用原接口和版本控制。接待状态广播失败时记录错误，已提交操作以接口回读为准；该状态广播目前没有独立持久重试队列。聊天消息的 outbox 能力仍由现有配置控制，广播被通道接受不代表客户端收到。

本轮未运行测试或迁移。最终联调须覆盖双店同号隔离、并发领取及转交、撤权后正文和私图、主管回复、老板／陪玩订单关联、双陪仅 A 受影响时 B 不获知 A 的售后详情、整单与履约段范围、多个订单的售后状态变化、权限撤销、断网后状态回读以及消息 outbox 重试。前端卡片展示和跳转尚需接入；外部消息渠道实际送达未验证。
