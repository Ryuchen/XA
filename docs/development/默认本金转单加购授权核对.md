# 默认本金转单含加购的授权核对

默认本金转单主单与加购在实销时各自记录会员及积分授权决定；UNKNOWN 使用既有平台超级管理员核对入口，DENY 不因续期自动补发。主单核对继续按主单原本金及实际退款计算，不把加购金额重复计入主单；加购以自己的付款、实销和授权决定独立核对。

含加购时，主单裁定除原有逐段结算、主单付款及退款证明外，还须逐笔核对：真实加购扣款与付款凭证一一对应；逐段最终清单中的加购 payment_id 与全部付款凭证一致；每笔付款和退款流水及资金来源通过现有校验；独立加购实销记录属于同一老板及业务周期，付款、退款、本金和实销时间相符。清单未记录加购、存在孤立扣款、独立实销缺失或不一致时，主单继续待核对；不以主单核对代替加购授权决定，不修改已付款、已退款或已有权益。

此项仅加强会员授权人工核对的证据门槛，不开放默认本金转单、加购支付或退款的底层入口。参考 [Payment Ledger Service 的支付与退款对账](https://github.com/tikhonov12/payment-ledger-service) 将交易与退款流水分别核对；具体分段、授权和账户周期按本项目既有规则执行。

按开发期要求未运行测试或迁移，仅完成 Python 语法解析。底层默认本金转单含加购是否可达、实际逐段清单结构、加购退款、跨店及跨周期、并发与平台审计恢复均须在隔离环境联调；未有完整证明的组合不能裁定。
