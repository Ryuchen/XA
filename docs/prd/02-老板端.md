# 老板端：从选服务到售后

本端面向在单一门店消费的老板。目标是让老板知道为谁、按什么价格下单，订单由谁履约，以及实际支付、退款、积分和钱包发生了什么变化。桌面与手机使用同一套真实业务；不以演示数据替代业务结果。

## 1. 进入、身份与服务发现

1. 声浪和兴安通过各自域名进入，页面展示所属门店名称、店币名称和实际配置；老板无法在页面中切换门店。未知、停用或未初始化门店不能进入其他店。
2. 老板可使用账号密码登录：未绑定 OTP 时使用已验证手机号接收短信验证码，已绑定 OTP 时默认使用手机验证器动态口令，并可切换短信验证码；新老板可自行填写手机号并通过短信验证。微信已绑定时可扫码或快捷登录，授权确认后直接进入。微信、短信和 OTP 的注册、绑定、登录、找回与身份合并按本店本人真实账户核验，不得把手填号码冒称微信授权取得。验证码错误、身份冲突或渠道不可用时给出下一步。
3. 未登录可查看允许公开的首页、服务、陪玩和客服信息；订单、钱包、积分、评价、聊天等个人数据须验证本人身份。登录后返回原有效页面，但不携带其他门店或旧账号的业务状态。
4. 服务按游戏、玩法、套餐、价格、可用资格和真实上下架状态展示。陪玩列表支持现有搜索、服务资格、时价、语音和排序能力；参考时价与实际套餐成交价分开标示。
5. 陪玩在老板端显示所属店大写英文艺术字前缀，如 `SL-昵称`、`XA-昵称`，头像展示本人当前头像：新入驻者先取得微信头像后可自行更换，已绑定的存量陪玩可保留历史头像。列表、详情、选人、报名、订单和评价等同一身份展示保持一致，不改写原昵称或历史用户名。

## 2. 下单与积分抵扣

1. 选择服务套餐、份数、游戏资料、服务要求和适用优惠，选择已指定陪玩、未指定自动抢单、招募试音或客服安排；实际可用方式按服务和人数展示。老板未指定的普通新单和客服安排的新单进入自动抢单池，试音仍由老板试听选人；历史普通报名选人记录保留。游戏资料按本店服务级优先、未设置时继承游戏级校验。
2. 报价由服务端计算并给出项目原价、所选比例折扣、优惠券、积分抵扣、应付店币及余额。**会员折扣、门店活动折扣、折扣券及其他按比例打折的优惠互斥，只能选一个**；系统默认推荐符合条件的**最终实付最低的合法组合**，老板可切换。每单最多一张券：符合资格的金额券可叠加会员或门店活动折扣，但不能与折扣券同单使用；符合条件时再用积分抵扣。积分只按门店配置的完整兑换组使用，不能约分拆组，未使用积分保留。折扣后的金额出现小数店币时向上取整，付款为整数店币；积分不足、规则变化或余额不足时给出可执行反馈。现有代码允许会员折扣与活动折扣连乘，并禁止活动折扣与金额券同用，均须按新目标调整。
3. 老板购买符合条件的陪玩服务时可以选择使用本店积分直接抵扣本店店币；实际抵扣和剩余应付不能由前端自行决定。礼物订单和体验套餐暂不支持积分抵扣；体验套餐继续按原有专价和资格规则执行。原有积分直接兑换钱包余额的商品入口和服务端兑换能力需关闭；其他原有商品兑换和积分抽奖保留，历史兑换及余额不改写。
4. 提交前重新核对服务、陪玩资格、价格、券、门店积分汇率及可用余额。确认后按服务器结果创建订单、扣除实际应付店币和使用的积分，保存实际成交及积分规则快照。重复提交只能生成一笔有效订单及对应流水。
5. 支付结果不明时，保留原请求编号并引导查看该订单及余额；不能因为网络超时直接告知失败或重新扣款。更换账号／门店时隔离草稿与待核对记录。
6. 老板钱包本金合并显示，赠送和赔付各自显示可用数；服务订单付款时两者默认均不使用，老板可分别输入愿意使用的数量，剩余应付从本金支付。**礼物订单只能使用本金支付，不可使用赠送、赔付或积分抵扣。**系统校验选择金额、各余额和应付总额，并在订单详情保存实际支付构成；本金消费积分按付款时老板 VIP／普通会员倍率计算，赠送和赔付消费不赠分。

**招募试音**：老板选择该方式并完成支付后，同店具备正式接单资格的陪玩按要求报名并提交录音；老板在订单详情试听每位报名者的本次录音，再选择符合人数和资格的陪玩。试听失败不等于报名失败；报名关闭、人员已被选择或资格变化时重读状态。[详见陪玩试音](03-陪玩端.md#3-公开订单与招募试音)。

## 3. 查看订单与预约

| 环节 | 老板看到和能够做什么 | 三端关联 |
| --- | --- | --- |
| 待接单 | 查看支付、安排方式、抢单收集与分配状态；在服务端允许时选择试音陪玩或取消本人订单。 | 老板未指定的普通新单和客服安排的新单进入抢单池；试音保留老板试听选人。系统实际派单后显示结果，不能把提交抢单视作已安排。 |
| 已接单／服务中 | 查看已安排陪玩、履约进度、联系入口和允许的售后动作；特殊玩法满足条件时可从进行中的原单选择并支付加购。 | 客服派单、陪玩开始或完成服务后，老板以服务端状态刷新。加购不使用折扣、优惠券或积分，金额及付款记录与原单关联；具体见[特殊玩法加购](31-特殊玩法订单加购.md)。 |
| 已完成 | 查看服务、评价对象、报单或结算相关状态及允许的售后、赠礼。 | 完成履约不等于报单审核完成、收益已到账或售后已结束。 |
| 已取消／退款 | 查看取消原因、退款状态、实际退回店币和积分；优惠券依券类型及原规则判断是否返还，返还不延长原有效期，资格券并非一律返还。 | 后台与钱包流水必须对应同一次处理，不能重复退回。 |
| 预约 | 查看时段、每位陪玩确认状态及截止时间；可按权限取消、重新预约或核对新报价转单。 | 支持双陪分别确认；一人拒绝或超时后保留已确认者的档期，老板重选另一人。全部确认后按门店时限付款；转单后原时段继续防重叠，陪玩可提前开始服务。 |

服务端提供的当前允许动作、时限及版本优先；旧页面、并发选人、失效报名或价格变化均应重新读取。本期老板通过客服线下收款充值后使用店币钱包支付，网页直接微信支付留待后续；不能把钱包退款说成微信原路退款。历史微信直付决策保留追溯，不代表本期重新开放。

## 4. 评价、售后与退款

- 老板可对符合现有规则的本人已完成订单评价；双陪分别选择评价对象。综合、技术、态度、沟通任一项为 1–2 星时，售后期限内按规则创建或关联售后；售后期过后仍可提交评价并记录低星提醒，但不能新建售后或退款。低星不等于退款通过。
- 老板主动发起售后与低星触发售后保留各自规则。处理中工单追加评价，已结案工单不因新低星重新开启；历史低星不批量追溯建单。
- 老板在订单详情看到售后处理中、处理结果及真实退款状态。退款先按原支付构成分别计算返还的实际店币和积分；店币按该单本金额、赠送额、赔付额的顺序退回各自余额，部分退款的店币与积分按原支付比例计算，优惠和分账冲正遵循对应订单快照。
- 老板须对综合、技术、态度、沟通四项分别主动选择 1–5 星后才能提交，未选择的项目就近提示；服务端也须校验完整，不以默认评分或自动回填冒充老板选择。旧客户端无法提交四项时提示更新，历史评价按当时真实记录保留。[低星专项](../ops/records/low-rating-aftersale-prd-20261103.md)是设计草稿，不代表已上线。
- 老板可选择匿名评价：对陪玩和公开评价页面隐藏老板昵称、头像，订单号仍可展示；获授权的本店后台可查看真实订单与身份关联。评价被有权限人员填写原因后作废，保留历史和审计，该老板不能对同单同一陪玩重新评价；已建立的售后继续按原规则处理。

## 5. 钱包、权益、消息与客服

- 钱包按本人和门店展示可用／冻结余额及本金、赠送和赔付，列出充值、消费、退款和收益等真实记录；充值赠送需要 OA 时，应区分本金已到账与赠送待审批，审批驳回则显示按系统原赠送额发放的真实结果。余额不足联系本店客服，不把未验收的自助支付当成成功充值。
- 会员、优惠券、签到、成就、积分、积分商城、权益交付、抽奖、收藏、排行、公告和消息按本店配置及本套 PRD 的最新决定执行；未被新决定覆盖的行为继续核对原规则。[活动与会员](13-活动会员与优惠.md)、[签到抽奖与其他功能](16-签到抽奖权益与其他功能.md)列出本轮口径和现状差异。积分仅在本店使用；积分退款、赠币及会员成长不能与现金充值本金混同。
- 客服会话保留对应门店、本人和订单上下文；私图、已读和发送结果按实际权限与记录展示，发送结果不明时先核对，不能重复发送。
- 有限库存、券过期、奖品条款变化、兑换或抽奖重复请求、积分不足和外部通知失败均需给出明确状态；不以弹窗或动画结果代替后台实际交易。
