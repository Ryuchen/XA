# 历史未结订单切换新规则


> **2026-11-11 范围变更：** 用户确认线上旧数据全部清除并全新部署，本文历史订单接管方案退出本期交付和验收，仅保留作为历史记录。现有开发／隔离测试数据不因这一决定自动清除；实际线上部署与数据清除尚未执行。

状态：**历史迁移尚未完成；旧游乐场人工核实结单的部分后端能力已开发，尚未执行真实订单切换**。本页衔接[跨端订单与资金](05-跨端订单资金售后.md)、[配置初始化](12-系统字典与门店初始化.md)、[差距与验收](07-差距待决与验收.md)和[特殊玩法房间](32-特殊玩法订单房间.md)。实际切换日期、演练环境和实施操作仍须按店安排，不触碰生产资金或真实客户进行文档验证。

## 1. 切换对象与总原则

用户确认：上线时**已付款但业务尚未结束的历史订单也切换到新业务规则**；已经发生的付款和资金流水保留。范围包括仍待安排、履约中，以及服务已经完成但售后、报单或收益尚未处理完的订单；不能只按一个订单状态字面过滤掉仍有未结业务的记录。已经真实完成的付款、退款、结算、提现及其流水不能删改或伪造成新发生的事实。

迁移的例外已经明确：原陪玩已形成的份额继续用原抽成快照；已开始的售后期和已实际开始的收益冻结保留原截止；切换时仍待抢的订单另开始新一轮完整抢单窗口和总等待。这些例外与用户后来确认的**新接入陪玩按接入时配置建快照**并行，不是让整张历史单永久停留在旧流程。切换后产生的新付款、加购、转单、退款和报单各自按适用的新规则记录。

每家店独立确定切换时间和授权操作人；以所属门店及原订单身份逐项核对。兴安沿用既有 `xinan` 标识与原独立业务库，不能通过复制另一家店的客户、钱包或历史订单来制造迁移数据。店内配置、原事实、迁移结果和异常均保留来源及审计，平台汇总可按授权查看各店进度及未完成项。

## 2. 订单状态及资金怎么接管

| 切换时的事实 | 接管规则 | 结果与异常 |
| --- | --- | --- |
| 已付款和已发生流水 | 保留原订单、付款、钱包、积分、退款、结算及提现事实，不能因为切换而重新收费或虚构一笔反向流水。 | 记录业务事实及切换前后规则版本；结果不明先核对真实原记录。 |
| 原陪玩已有份额 | 即使还未结算，仍按该份额原抽成快照；已经结算的钱和流水不重算。 | 如果原应得无法从可靠记录还原，标为待核对，不直接套当前费率。 |
| 切换后陪玩转入／转回 | 新接入者按其接入订单时本店适用配置建立本人新份额快照；旧参与份额保留。 | 同一人多次接入各次独立；客服不得借迁移或转单临时改单笔抽成。 |
| 原付款来源可可靠区分 | 老板退款时按已确认的本金→赠送→赔付顺序和原支付构成处理。 | 已退部分与各来源分别核对，累计不得超过原支付。 |
| 原付款来源无法区分 | **无法区分的已付款部分退回老板本金余额，并记录迁移依据**；原历史钱包余额无法准确归类的部分同样按已确认规则归本金。 | 可区分的部分不抹成未知；历史记录保留，无法区分不应伪造为已核实的真实本金来源。 |
| 切换时待抢订单 | 以切换时为新一轮入池时间，重新开始完整抢单窗口及本店总等待时间。原本未正式分配且仍符合其他资格的旧报名自动转为新一轮候选，排序使用原提交时通行证等级；无法核实时要求相关陪玩重新抢单。 | 原入池、报名及付款作为历史留痕；试音老板选人等非抢单模式按其对应流程处理。仅已完成组队确认的双陪才是完整候选，不能把半个队伍派出；已经有效提交后通行证到期不单独淘汰候选。 |
| 已在旧游乐场履约 | 旧 `play.xaesports.club` 房间继续使用至该订单结束；不建立旧房间与订单的系统关联，由新系统按本店规则处理账务。 | 旧站老板确认结单后，客服人工核实旧站结单和对应订单，再在新系统完成原订单并留痕；老板无需二次确认。不能清空旧房间、抹掉进度，或声称两边已自动同步。 |

例：A 原服务份额成交 200 元等值、原门店抽成 20%，尚未结算时切换，门店新配置为 30%。A 的该份额仍按原快照应得 160 元等值；切换后 B 接入的本人新份额才按 B 接入时配置建快照，不能按新比例把 A 原份额改为 140。

## 3. 售后与收益时钟

| 切换时状态 | 保留或采用的时钟 | 例子与限制 |
| --- | --- | --- |
| 售后等待已经开始 | 保留原售后截止时间。 | 原单完成 40 小时、原售后期 72 小时，新店配置 48 小时，仍剩 32 小时；不能改成剩 8 小时或从切换时再等完整 48 小时。 |
| 售后等待尚未开始 | 切换时保存本店新售后时限；订单按适用规则完成或协商终止时开始计时，随后门店再改配置不影响本单。 | 切换时 48 小时、以后改 36 小时，该单仍按切换时的 48 小时。已在期限内建立的售后按用户确认继续处理。 |
| 旧系统收益冻结已实际开始 | 保留该冻结原截止，不因为迁移再串联同一冻结期。 | 原冻结事实、起点和应解冻金额需可追溯；若记录不足以确定原截止则人工核对，不伪造。 |
| 旧系统收益冻结尚未开始，但已有最后有效报单 | 从本人最后一次有效报单提交时刻按新规则计算；切换前已经过去的时间计入。切换时保存本店适用的新冻结时限。 | 切换前 50 小时已提交、切换时冻结 48 小时，则冻结时限已经到期，但仍须满足本人审核、售后、资金和其他结算条件才释放。 |
| 尚无有效报单或此后被驳回重提 | 按本人最后一次有效提交开始或重算冻结；双陪分别核算。 | 没有有效提交不能伪造冻结起点；旧已发生的审核和重提记录保留。 |

售后等待与收益冻结是两段独立且可重叠的时钟。切换只改变用户确认的新接管规则，不等于服务已经完成、售后已结束、报单审核通过、门店资金充足或陪玩已可提现。礼物等特殊订单按各自已确认的原始起点和既有状态分别核对，不擅自伪造普通服务报单。

历史收益已进入冻结且原截止已到时，仍需检查本店该订单是否有影响本人、尚未结案的售后；有则继续冻结至售后处理完毕，不重置原截止、不重复冻结。同一订单中未受影响的陪玩可以按本人的条件释放。售后范围不明时须先核对，不能据此提前释放。

对于已完成的历史普通服务单，收益冻结提前到期也不意味着售后期已经结束；须等原售后截止和原收益冻结截止均到达，且本人没有未结售后，再释放该笔已冻结收益。历史完成时间缺失、无法计算售后截止时，应先核对，不得推断已到期。该限制不修改原冻结截止，也不串联重新计算冻结时长。

历史订单如果没有保存付款时的单抵押金比例，按切换时本店配置的比例保存快照；已有可核实的原快照保留，不随以后配置修改。该补充规则不改变已形成的陪玩抽成或既有押金、钱包流水。

## 4. 切换实施与三端反馈

1. 按店列出待切换订单、原付款和退款、未结售后、原参与者及各段快照、报单、售后与冻结时钟及待抢候选。使用旧游乐场履约的情况由客服人工核实，不建立系统关联。只读预览展示缺失资料和潜在影响，不发生付款、退款、清库或给用户发真实消息。
2. 核验切换时的门店配置版本、旧截止、原价及钱包支付来源。无法确认的抽成、参与人、旧冻结起点或旧房间归属进入待核对状态；已明确允许按本金处理的来源不明部分记录迁移依据，不以猜测补造原始付款。
3. 以门店和订单为单位原子登记切换及相关新状态；重复执行必须识别同一切换事实。旧超时任务、报单审核、退款及新派单与切换并发时只能形成一个合法结果；已经取消或已退款的订单不能被重新激活或再次扣／退钱。
4. 老板、陪玩和授权本店后台可查看切换后的实际订单状态、待处理事项及本人可见的钱包事实；平台财务只在授权的财务工作范围查看。旧游乐场不建立系统关联；客服人工核实应按订单、人员、结单事实及授权留痕，不得仅凭昵称冒领或跨店代操作。
5. 在隔离的真实业务代码与数据库上演练普通服务、双陪、转单、未开始／已开始的售后与冻结、待抢、原支付来源不明及旧游乐场继续履约。记录原始事实、配置版本、操作人、结果及核对差异；第三方真实支付或消息不以演练结果冒充成功。

## 5. 实施前核对

- 旧报名迁入使用原提交时的通行证等级；无法可靠核实时通知该陪玩重新抢单。原提交等级可以核实但完成时间不能可靠还原时，如果窗口结束排序同分需要比较先后，该候选本轮直接落选，继续比较下一位；以后有机会重抢时以新提交完成时间为准。双陪须有完整合资格队伍，历史提交事实与重试分开记录。
- 旧游乐场不与新订单建立系统关联。客服人工核实旧站老板已确认结单和对应订单后，在新系统完成原订单并记录核验人、时间及依据；老板不用二次确认，也不能假装旧站已自动同步。权限及证据不得跨店泄露。
- 各门店实际切换日期、旧记录的数据质量与运营处理安排须在实施前真实盘点，PRD 不推断生产数据现状。
