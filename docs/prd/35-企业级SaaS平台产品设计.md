# 企业级 SaaS 平台产品设计

版本：2026-11-17；状态：**产品设计基线（规划），不是已实现或已验收的声明**。

本文以专业企业级平台产品视角，把现有"电竞陪玩三端运营系统"定义为**企业级 SaaS 化电竞派单管理平台**，给出产品架构、租户模型、能力打包、租户生命周期、平台运营与商业化设计。业务规则以用户最新明确决定和 [PRD 总纲](README.md) 为准；本文不新增或改写已确认业务规则。每项设计标注状态：

- **【已确认】**：用户已明确决定，直接执行（来源见标注）。
- **【自主设计】**：用户已授权按专业 SaaS 实践自主决策的范围（2026-11-11 License 产品与技术细节授权，见根目录 AGENTS.md）。
- **【设计提案】**：超出已确认范围的新能力，须用户确认后才进入开发排期。

配套文档：[目标系统架构](../architecture/SAAS_TARGET_ARCHITECTURE.md)、[重构实施计划](../architecture/REFACTORING_PLAN.md)、[企业级总体规划](../development/26-企业级总体规划.md)。

## 1. 产品定位与产品原则

**定位**：面向电竞陪玩门店的多租户 SaaS 派单经营管理平台。平台方（青岛声浪传媒有限公司）统一部署运营；**第三方门店入驻**并按域名接入，获得订单派发、履约管理、资金账务、会员运营与经营核算的完整闭环；平台方通过 License 档位与增值模块实现商业化。平台与任何特定门店不绑定：声浪/兴安仅为开发期的门店隔离与业务验证实例（用户 2026-11-17 确认）。

**产品原则**（企业级平台视角，约束全部后续设计）：

1. **租户即边界**：域名确定门店；数据、身份、资金、消息、文件、任务全链路携带并校验租户上下文。跨店能力只属于平台授权角色，且只读聚合，不合并账户与资金。【已确认】
2. **资金事实不可篡改**：所有金额整数内部单位、同事务流水、幂等与锁序；配置变更不追改已发生交易；错误只能补偿，不能回滚消除。【已确认】
3. **权益集中裁决**：一个功能能不能用，由 License 档位、平台增值配置、门店开关三层统一裁决，任何入口不得各自判断。【自主设计，规则来源 PRD 33】
4. **降级保核心**：控制面故障时门店核心订单、履约、资金闭环继续可用；暂停的是新增账号与增值发放，不是营业本身。【已确认】
5. **未知不装已知**：金额、统计、授权状态未知时明确标注缺失，不显示为 0 或成功。【已确认】
6. **B 端固定、C 端可购**：管理后台与陪玩端是固定 B 端模块不拆卖；老板端 H5 是独立可购模块，私人定制严格限定可购范围（品牌白名单仅作用 `.boss-app`，禁自定义 JS/CSS）。【已确认，PRD 34】
7. **证据先于声称**：构建成功≠业务验收，隔离替身≠真实渠道；每轮只声称有证据的范围。【已确认】

## 2. 租户与角色模型

### 2.1 四层主体

| 层 | 主体 | 身份体系 | 数据边界 |
| --- | --- | --- | --- |
| 平台 | 平台超级管理员、平台财务 | 独立平台账号（控制库），授权独立于任何门店员工 | 控制库＋按授权范围的跨店只读聚合 |
| 租户（门店） | 店内超级管理员、客服、售后、运营 | 店内 `ClubAccount`，ID 仅本店有效，审计用 `(store_slug, local_id)` | 本店独立业务库 |
| 门店客户 | 老板 | 店内账号，密码＋短信/OTP，微信绑定后快捷登录 | 本人数据 |
| 门店供给 | 陪玩 | 店内账号，正式接单前须绑定微信并真实取得头像 | 本人数据 |

【已确认，PRD 01/24；三端登录规则见 AGENTS.md 2026-11-11】

### 2.2 租户标识与入口

- 每租户唯一 slug、独立业务库、独立店币品牌、独立二级域名入口（`/boss`、`/player`）。后台统一 `admin.esports.club`，按已验证凭据识别身份，同名同密码跨店冲突须显式消歧。【已确认】
- 租户模型对任意第三方入驻门店通用；声浪（`shenglang`/浪花）与兴安（`xinan`/星辉）是**开发验证实例**，用于门店隔离与业务验证，不与平台绑定，平台逻辑与配置不得硬编码这两家门店。【用户 2026-11-17 确认】
- 新租户域名由平台分配并写入签名路由快照；未知域名不回落默认门店。【已确认＋自主设计（快照机制已实现）】

### 2.3 平台角色权限模型

- 平台超级管理员：全门店授权，管理门店、License、合同收款、增值配置、平台账号。
- 平台财务：全部门店或指定门店授权，处理提现终审、公共薪资、跨店财务汇总；不能管理平台账号。
- 店内超级管理员不自动获得任何平台权限；更换店内身份须重新登录。【已确认，PRD 01】
- 【自主设计】平台操作全量审计（授权前后变化、操作者、时间、对象），审计不可由被审计角色删改；现有 `stores` 平台审计模型沿用扩展。

### 3.3 权益裁决模型【自主设计】

功能可用性 = `License 状态（有效/宽限/过期/未授权）` × `档位配额` × `平台增值配置` × `门店开关` × `角色权限`。

- 裁决顺序：先角色权限（能不能做），再 License/增值（租户买没买），再门店开关（店开没开）。
- 过期/未授权：保留已有用户订单、履约、售后、资金闭环与已获权益；停止新增账号与增值发放；消费积分以实销确认时 License 状态判断。【已确认】
- 降档超额：保留存量账号，禁止新增同类；升级/降档在管理员指定时间生效，未来生效前维持原档。【已确认】
- 技术要求（详见架构文档 §5）：统一 entitlement 服务＋签名快照缓存，全部发放/新增入口接入同一裁决，禁止散落 if 判断。

## 4. 租户生命周期

### 4.1 全生命周期状态【已确认规则＋自主设计编排】

```
商机/签约 → 授权签发 → 建店(七态) → 初始化配置 → 开业核验 → 营业
营业 → 临期提醒(30/7/1天) → 续期(无缝) / 到期 → 宽限期(默认7天) → 过期
过期 → 续费恢复 / 终止 → 退出流程(提案)
任意阶段：控制库故障 → 缓存降级营业 → 恢复重验
```

- 建店七态：REQUESTED→RESOURCE_READY→SCHEMA_READY→ADMIN_READY→CONFIGURING→READY→ACTIVE，任一步可 FAILED、分步持久化可恢复；允许无授权先建店配置，有有效 License 才可首次正式营业，宽限期不得首次开业。【已确认】
- 授权码一次性展示、摘要入库；同店重复激活返回原结果，跨店拒绝；丢失重发沿用原合同与收款记录；授权结束时刻及之后不得首次激活，迟激活不延长授权期。【已确认】
- 未来安排最多一项；提前续期默认从当前到期时开始；未来授权已激活未生效时平台可取消并通知门店。【已确认】

### 4.2 开通交付流程（Onboarding）【自主设计】

1. 合同登记（档位、起止、应收、线下收款计划）→ 签发授权码（仅展示一次）。
2. 平台建店：动态建库、迁移、初始管理员、域名与路由快照。
3. 门店初始化：按 [PRD 18 配置详表](18-门店初始化配置项详表.md) 完成下单与资金核心配置（必须），其他功能可先不启用；开业前系列核验（KOOK、VIP、抽成、押金、支付费率估算等）逐项留痕。
4. 门店超管激活授权码 → 开业核验通过 → ACTIVE。
5. 交付物：门店管理员操作手册、初始化核对清单、平台支持通道。【设计提案：手册与培训材料】

### 4.3 退出与数据处置【设计提案，须确认】

- 终止后门店进入只读保留期（建议 90 天），期间平台可导出对账与审计数据；老板/陪玩入口关闭并提示。
- 数据导出范围、保留期时长、销毁审批流程须用户确认后实现；首版不开发自动销毁。
- 陪玩显式注销释放名额的接入为已确认未完成项（PRD 33），随 M5 落地。

## 5. 平台运营控制台（产品设计）

现有平台能力（账号/授权/门店目录/数量汇总/License/合同收款/提现终审/公共薪资）之上，按企业级 SaaS 运营补全：

| 模块 | 内容 | 状态 |
| --- | --- | --- |
| 租户台账 | 门店档案、域名、档位、有效期、宽限、配额用量、健康状态 | 部分已实现，用量/健康为自主设计 |
| 授权与合同 | 签发/重发/作废/续期/调档、合同应收与分次收款、审计 | 已实现，拦截与离线授权未完成 |
| 跨店经营聚合 | 订单、资金、薪资、ROI 按授权范围聚合；缺失逐店标注，不显示完整零值 | 数量汇总已有，金额聚合待开发（M1） |
| 财务运营 | 提现终审、线下打款登记、跨店提现汇总、欠款汇总、对账 | 大部分已实现，故障边界待演练 |
| 提醒中心 | 到期/宽限/取消提醒队列，晚到节点立即补发当前临期提醒 | 队列已实现，真实派发待联调 |
| 租户健康度 | 配额使用率、活跃度、License 临期、故障降级次数，支持续约与增购决策 | 【设计提案】 |
| 平台公告与版本 | 维护窗口通知、版本说明下发门店后台 | 【设计提案】 |

## 6. 计量、配额与用量分析

- **配额口径**【已确认】：老板/陪玩按各店未注销账号计数，停用、封禁仍计入；老板退店释放名额、重入重新检查；陪玩停接或退押金不自动释放。并发计数已有专项（[License账号名额并发计数](../development/topics/license/License账号名额并发计数.md)）。
- **计量设计**【自主设计】：控制库按日快照各店配额用量与订单量（订单不限档，仅运营分析用）；快照来自逐店只读采集任务，失败标注缺失不补零；不复制客户明细到控制库。
- **用量呈现**【设计提案】：门店后台展示本店配额余量与临期提示；平台台账展示趋势，支持续约提醒与升档建议。

## 7. 商业化与账务（线下收款闭环）

【已确认，PRD 33】一期收款全部线下：

- 合同应收默认档位年费，平台超管可改实际金额并留审计；允许 0 元合同直接结清。
- 收款分多次登记（未收款/部分收款/已收款、人民币金额、日期、备注），不作为激活前提；累计实收不得超过应收。
- 登记错误由平台超管填写原因作废重登，保留审计；重发授权码不重复计费。
- 【自主设计】应收账龄视图（合同维度应收-实收-账龄）纳入平台财务工作台；催收提醒复用提醒中心队列。
- 【设计提案，二期】线上支付续费、自动开票、自助升降档；一期不做，见 §9。

## 9. 现状差距与演进路线

### 9.1 首版必须补齐（进入 M0–M8，见 26 规划）

1. 权益裁决统一化：增值发放入口业务拦截、其余功能入口、离线授权（PRD 33 未完成项）。
2. 平台身份启用：迁移上库、初始账号、真实渠道、`PLATFORM_IDENTITY_ENABLED` 按序开启。
3. 跨店金额聚合、动态建店全流程、开业核验闭环。
4. 控制库故障降级真实演练（物理断库＋隔离 MySQL 全流程）。
5. 真实微信/短信渠道、生产部署与备份监控容灾。

### 9.2 二期候选（设计提案，须逐项确认）

- 租户自助门户（自助续期、线上支付、发票、自助升降档）。
- 租户健康度与用量分析、平台公告/版本通知。
- 退出流程自动化（只读保留期、导出、销毁审批）。
- 老板端 H5 商业化定价与定制交付流程（依赖 Q-BOSS_H5 决策）。
- 高可用架构（多可用区、读写分离）、开放 API/Webhook 供门店自有系统集成。

### 9.3 开放决策（沿用 PRD 07 编号）

Q02 积分汇率/上限默认值、Q03 特殊服务积分资格、Q05 微信真实授权能力、Q06 提现文案权限、Q07 历史押金口径（空库部署下是否适用）、Q08 各店启用时间、Q12 切换演练、Q26 评价映射、Q-BOSS_H5 售价/定制费/周期；另加本文新增提案项（§4.3 退出处置、§5 健康度/公告、§7 账龄视图、§8 SLA 时限）。
