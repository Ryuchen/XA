# 管理后台：门店业务与平台职能

后台使用统一入口，按经过验证的身份与细分权限展示功能。本文从客服、售后、运营、平台财务及超级管理员围绕同一笔订单和资金的实际操作描述要求；有菜单不等于有写权限。

账号密码登录时，未绑定 OTP 使用短信验证码，已绑定 OTP 默认通过手机验证器动态口令验证，也可切换短信；未绑定微信时可先进入后台，之后本人完成绑定才可使用微信快捷登录。已绑定微信可扫码或快捷登录，授权确认后直接进入。所有路径都必须识别唯一真实账号与门店、重新核对角色和平台授权；微信接入及普通浏览器可用性以真实渠道验证为准。

## 1. 平台与门店分工

| 使用者 | 本人应完成的工作 | 不应越过的边界 |
| --- | --- | --- |
| 门店客服 | 在本店共享咨询池领取后接待，处理订单安排、报单及已授权的老板充值；初审本店陪玩提现；人工核实续单。 | 充值赠送例外须经本店管理员 OA 审批；陪玩无充值，只能按授权调账。初审提现不代表打款，不能代平台财务确认付款或查看其他店的提现。 |
| 门店售后 | 处理本店订单争议、低星工单、转单和已授权退款，查看处理进度及资金结果。 | 售后或差评不自动退款；不能访问其他店订单或绕开分账、退款和钱包校验。 |
| 门店运营／管理员 | 管理本店服务、价格、陪玩资料、活动、积分与店币换算比例、内容及获授权人员。 | 不因店内管理员身份取得平台账号、跨店资金或其他门店权限。 |
| 平台财务 | 查看各店提交的提现，终审并线下打款、登记支付凭证；配置和核算各店薪资及平台公共薪资。 | 提现处理不自动授予所有门店订单、充值、调账、人员管理或建库权限。 |
| 平台超级管理员 | 管理门店、平台和店内授权；默认查看多店聚合，管理薪资和经营数据，审视待办与审计。 | 平台权限独立授予；对具体单店数据的操作须明确目标店和业务对象。 |

取消店内财务角色不等于删除充值、押金、退款、钱包和流水。门店客服或售后继续按照实际授权完成相应业务。历史人员角色、薪资安排及流水由迁移方案保留，不在此文档工作中修改。

## 2. 订单工作台

1. 按门店、订单号、老板、陪玩、服务、支付／履约／售后状态、时间等筛选；店内人员只能筛本店，平台超级管理员可查看授权范围的多店结果及单店明细。
2. 客服根据订单允许动作受理、代录和协调；客服安排的新单进入抢单池，由系统在本店配置窗口结束后按已确认顺序分发，而不是旧路径直接指派。客服仍可按授权处理已接订单的协调改派或售后；查看候选、人数、时限、资格及日志，不能重复分配或超名额。
3. 具有授权者查看履约凭证、报单和成员收益，审核通过或驳回写明原因。多成员、转单及售后时按实际份额和既有结算条件处理，不把订单完成或任一报单通过当作全部结算完成。
4. 售后人员按订单查看老板申请、低星来源、处理记录和可执行动作；转单、协商处理、部分或全额退款须显示对象、金额、资金去向和服务端约束。
5. 客服根据实际业务事实人工确认当场续单，记录原单、本次续单及确认人；奖励由系统按[续单规则](06-积分薪资经营.md#5-续单奖励)核对，不靠礼物来源字段推断续单。
6. 服务、等级、档期、抽成、时限、积分比例等配置更改只作用于适用的新交易；历史订单报价、支付、分账与人员快照保留。
7. 老板下单时选择的客服名片须绑定同店员工，并将该员记为订单负责人；负责人、实际派单者、实际获客者和会话领取人分别记录，业绩按实际工作归属。咨询仍须共享池领取，负责人若未领取且非授权主管，不能仅凭负责订单查看聊天正文。
8. 客服代老板下单时，可按老板明确告知的选择代填积分、赠送和赔付使用量，并保留确认信息；仍由服务端核对门店、本人、余额、权益、报价和相同的支付规则。不能默认替老板消耗其积分或赠送／赔付余额。

## 3. 两级提现工作台

| 阶段 | 门店客服 | 平台财务 | 陪玩端反馈 |
| --- | --- | --- | --- |
| 待客服初审 | 本店领取并核对身份、申请额、收款方式和必要信息，按权限通过或驳回。 | 不应将未经初审的申请当作可打款任务。 | 申请成功、金额冻结，显示待客服审核。 |
| 待平台处理 | 初审通过后可查看本店处理进度；不能代财务登记付款。 | 查看所属店、陪玩、收款资料快照、金额和客服意见，终审；实际线下打款后登记凭证。 | 显示待平台财务处理，冻结持续。 |
| 已打款 | 查看本店结果及获准的审计信息。 | 记录实际人民币金额、渠道、时间和凭证，确认后触发本店钱包最终记账。 | 真实状态显示已打款及对应钱包支出流水。 |
| 已驳回 | 按权限记录本店初审驳回原因。 | 按权限记录平台终审驳回原因。 | 申请冻结释放，显示退回可用余额及原因。 |
| 待核对 | 客服可查看本店结果，不重复提交。 | 打款或记账结果不明时先核对凭证、银行／渠道结果和原申请；禁止重新打款或擅自解冻。 | 显示处理中／待核对，不宣称到账或失败。 |

申请、客服初审、平台处理和实际付款分别留存人员、时间、状态、原因和版本；同一申请的领取、审核、付款登记必须防止并发重复处理。用户已经决定线下打款，当前不把自动转账或真实外部支付能力当成已提供功能。[详细账务规则](05-跨端订单资金售后.md#6-提现两级审核与账务)为准。

当前代码的 `withdraw:audit` 同时关联领取、通过／驳回和提现规则修改；不能把这个旧权限整体授给门店初审客服。新流程须在服务端拆分本店初审、平台终审／付款登记和规则配置等权限，避免仅隐藏按钮而保留越权接口。

## 4. 资金、运营与人员功能清单

| 功能域 | 主要对象／动作 | 与订单或资金的关系 |
| --- | --- | --- |
| 钱包、充值、流水 | 老板／陪玩钱包、老板充值记录和凭证、赠送、奖惩、调账、冻结、流水查询。 | 只有老板可充值；陪玩仅按授权调账。充值赠送修改走门店管理员 OA，本金、赠送、赔付、订单消费、退款和提现分开，凭证防重复。 |
| 陪玩档案与入驻 | 入驻审核、认证、等级、技能、档期、押金模式、封禁、退押金。 | 影响可见、接单、分成和押金，不更改已经产生的订单及金额快照。 |
| 老板档案 | 老板资料、会员等级、推荐关系、封禁与退店。 | 身份和优惠需关联本店真实记录；不得因同手机号自动合并其他门店资产。 |
| 游戏与服务 | 游戏类目、玩法、套餐、价格、人数、资格、履约要求、抽成、特殊玩法加购和上下架。 | 三角洲适用档位抽成；瓦罗兰特及英雄联盟按陪玩／代肝配置且上分归代肝。加购按店维护适用玩法、条件和价格；已成交订单快照保留，详见[抽成](14-陪玩资格与抽成.md)及[特殊玩法加购](31-特殊玩法订单加购.md)。 |
| 评价与售后 | 评价、回复、独立授权的评价作废、工单、证据、退款、处理记录。 | 作废须填写原因并保留审计，不计好评率且同单同一陪玩不可重评；已建立售后继续处理。匿名评价的真实关联仅供获授权后台查看；退款按原支付、分账和账户回滚。 |
| 积分与营销 | 积分汇率、积分商品、优惠券、活动、VIP、签到、成就、抽奖、冠名和权益交付。 | 抵扣成本由本店承担，不能与原消费发积分、充值本金或退款重复计算。 |
| 预约与派单配置 | 预约确认、转单、超时、公开池、通行证、KOOK 群派单配置。 | 不把预约当已付订单，不把群消息发送成功当作派单结果。 |
| 客服与内容 | 本店聊天接待、客服名片、消息、公告、轮播及运营内容。 | 订单上下文和私图按店及角色授权；外部消息必须区分是否真正送达。 |
| 薪资与经营 | 岗位方案、人员安排、业绩归属、工资核算、每日投流、其他成本、ROI。 | 平台财务和超级管理员配置各店薪资；工资与订单钱包分开，平台公共成本只在平台总账计一次。 |
| 人员、权限、审计 | 成员、角色、细分权限、平台授权、操作日志。 | 店内权限不可取得平台权限；历史操作和资金证据可追溯。 |

具体页面及现有路由对应见[页面接口追踪](08-页面接口追踪.md)。后台权限以服务端核验为准；敏感凭证和未授权个人资料不能因汇总而向所有平台角色开放。

## 5. 数据和配置例外

- 新店的积分抵扣比例未配置或配置停用时，不能默认为其他门店的比例；该店相关消费仍可按没有积分抵扣的正常路径进行。
- 工资、积分、订单和提现等配置有状态及历史版本。配置被并发修改时，不覆盖他人已保存结果；用户须重新读取并核对。
- 出现库连接失败、其他店不可用或汇总不完整时，明确受影响范围；不得在默认店补写或把缺失门店当作零。
- 店内客服和售后已获授权的业务动作保留；具体岗位权限模板由超级管理员按真实工作分配，不能用角色名称推断所有历史权限已经迁移。
