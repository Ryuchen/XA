## 已确认

- 平台统一部署并运营 SaaS，各门店通过域名访问；每个门店分别持有 License，独立设置档位与有效期；门店继续使用独立业务数据库、域名和身份边界。
- Basic：老板 500、陪玩 500，订单数不限，人民币 2,880 元／年；Pro：老板 1,500、陪玩 2,000，订单数不限，人民币 3,880 元／年；Ultra：老板、陪玩及订单数不限，人民币 5,880 元／年。

薪资分档首版：PAYROLL 的 BASIC、FULL 均可新增及修改门店薪资方案和夜班设置；OFF、到期只读或授权无法核验时暂停这些配置变更。现有工资义务不受此限制，人员安排、真实业绩核实、预览、确认和离职结清继续按权限及既有规则办理；已创建的平台操作可使用原凭证重试。平台公共人员工资不受门店授权影响。未来区分 BASIC 与 FULL 的功能须另行明确，不能据此追改已确认工资。

初始化阶段，尚未正式营业的门店由首位本店超级管理员按权限预先配置薪资方案与夜班时段，无须先激活 License；正式开业及开业后的新配置仍按授权规则执行，初始化不会产生工资核算或发放。
- 老板及陪玩配额按本店未注销账号计数，停用和封禁仍计入。老板完成退店后释放名额，重新入店时重新检查；陪玩停接或退押金不自动释放名额，明确注销本店账号后才释放。降档时允许存量超过上限，保留已有账号，超额期间不能新增同类账号。
- 初始增值功能矩阵参照设计文档 2.5.3，仅平台超级管理员可配置各档增值功能并留审计，保存后立即生效；已发权益和在途交易按既定规则保留，核心订单和资金闭环不能通过配置关闭。
- License 由平台超级管理员发放、续期和调档并留审计；费用线下收取。
- 平台生成绑定指定门店的授权码，由该店超级管理员输入激活；平台可另行授权其他本店管理员激活。授权码仅显示一次，丢失后平台作废并重新签发；未激活的码可作废并留痕。一个码只能成功激活一次，同店重复提交返回原结果，其他门店拒绝。
- 授权结束时刻之前可激活，不另设激活截止时间；到达或超过授权结束时刻拒绝首次激活并提示联系平台重新签发。迟于生效时间激活不会延长既定到期时间；未来生效的授权激活后进入待生效，原授权在切换前继续有效。
- 一个门店已有未来授权安排时，平台须先修改或取消原安排再创建新安排并留痕。调档不改变当前到期时间，续期单独设置；允许设置过去生效时间，但必须填写原因并留痕。
- 提前续期默认从当前授权到期时开始，平台可调整。未来生效的授权码即使已被门店激活，平台仍可取消该待生效安排；原授权继续有效并通知门店。
- 宽限期默认 7 天，允许平台超级管理员单店调整。License 记录线下收款状态（未收款、部分收款、已收款）、人民币金额、收款日期和备注；是否收款不影响平台确认后的授权激活。
- 一份 License 的每次线下收款分别登记，系统按合同应收和累计实收计算收款状态；合同应收默认使用档位年费，平台超级管理员可根据短期续费、调档补差或优惠填写实际金额并留审计。
- 允许 0 元合同，直接标记已结清；累计实收不得超过合同应收，超出时提示核对合同金额。
- 已签合同的授权码丢失时，新码沿用原合同及全部收款记录，不重复计费。收款登记有误时仅平台超级管理员可填写原因作废原笔，再重新登记；保留原记录与审计。
- 平台管理员填写授权开始和结束时间，默认一年，按北京时间计算；到达配置的到期时刻立即进入宽限期，无宽限期则立即到期。允许先建库及初始化，但必须在 License 有效期内才能首次正式营业；已到期进入宽限期的未开业门店不得首次开业。
- 宽限期由平台设置默认值，仅平台超级管理员可为各店单独调整并留审计，调整后立即按新宽限期重算当前授权状态，并保留已获权益和在途交易；宽限期内维持原档功能；降档或授权到期后保留已发放的优惠券、积分及其他已获得权益。到期超过宽限期后，已有老板的新订单仍可使用已有优惠券和积分，但不再新增发放。
- 按授权到期时间提前 30、7、1 天提醒门店管理员和平台管理员，宽限期结束再单独提醒。消费积分以实销确认时的 License 状态判断：超过宽限期时不再发放，即使付款发生在有效期。
- 到期及取消提醒发送给本店超级管理员和平台授权的激活管理员；到期提醒同时发送平台超级管理员。若激活较晚或系统故障错过提醒，立即补发一条当前临期提醒，后续仍执行剩余节点。已有已激活且在到期时无缝生效的续期时，不再发送原授权的到期和宽限期提醒。
- 平台控制库暂不可用时使用该门店最近一次成功校验的授权信息继续运行，并按缓存的到期和宽限时间自动推进状态；控制库恢复后重新校验。已营业门店如无可验证的授权缓存，仍允许已有用户订单、履约和资金业务，暂停新增账号及增值功能并提示联系平台。
- License 过期或未授权时，限制新增账号及增值功能；已有老板和陪玩的订单、派单、履约、报单、售后、退款、钱包及提现继续可用。授权不改变或代替平台与门店角色权限，也不得导致资金和履约中断。
- 档位升级与降档均在管理员指定的生效时间启用新配额和功能；设为未来生效时，切换前继续使用原档，到时自动切换。降档仍保留超额存量账号。
- 平台超级管理员的跨门店聚合、平台财务及独立授权仍按既有 PRD；`docs/history/design-20261117/apple-ui-20261109/UI-DESIGN-SPEC.md` 中与之冲突的“平台不聚合”仅为设计假设，不能覆盖用户要求。

## 服务异常与在途权益处理

- 门店业务库不可用时，本店需要该库的操作明确返回服务暂不可用；不得切换到其他门店数据库、伪造成功或在不确定结果时重复资金操作。已持久化的通知等异步任务保留并按幂等规则重试；恢复后重新核对结果。平台可展示该店不可用状态，其他门店不受影响。
- 授权到期、降档或功能停用时，保留已发放且仍有效的券、积分和其他权益，并按已确认规则允许使用；已开始的订单、履约、售后与资金处理继续完成，不新增被限制的权益。服务端执行权限判断，前端开关不能代替授权校验。
- License 到期的权益保留不改变门店独立业务开关：例如门店停用任一积分功能时，仍按既定规则暂停积分使用，重新启用后恢复。
- 内容运营授权不可用或无法核验时，门店仍可按角色权限下架现有轮播、运营内容和播报规则；恢复展示、修改内容及新增内容仍须满足对应授权。下架不撤销已有权益或订单。

## 实现与验收要求

平台控制域需保存各店授权、档位与有效期，并记录签发、变更和续期的真实平台操作人；权限及功能判定必须服务端执行，且令牌、API、文件、WebSocket 和异步任务保留门店边界。账号配额的最终判定必须在并发新增时防止超额；订阅状态变化不复制或合并门店资金。验收覆盖三档、两个门店、有效／到期／未授权、并发开户、降级和续期，以及已有用户完整订单与资金闭环。具体控制面及异常处理待上述规则明确后设计。

授权码不得写入数据库明文、请求审计、应用日志、错误记录或消息；接口必须在接入通用后台审计前完成脱敏。展示一次的响应应禁止缓存，传输与授权校验须适配真实生产 HTTPS 配置。

## 已实现的接口约定

以下路径均以 `/api/admin/` 开头，平台接口必须使用独立平台超级管理员身份；门店接口根据已验证后台登录身份确定门店。授权码只能从签发和重发成功响应的 `license_code` 读取一次，列表与审计不返回摘要或明文。下列接口不代表业务准入已接通。

| 接口 | 用途 |
| --- | --- |
| `GET/POST platform/store-management/{store_id}/licenses` | 倒序查询授权记录及其追溯原因和操作者，使用 `next_cursor` 读取后续记录且不返回授权码明文；签发提交 `tier`、`kind`，可提交带时区的 `starts_at`、`ends_at`、`backdate_reason` 和合同 `amount_due_fen`。时间与合同金额可由服务端按规则默认。 |
| `POST platform/licenses/{code_id}/void` | 提交 `reason` 作废未激活码或尚未生效的已激活安排。 |
| `POST platform/licenses/{code_id}/reissue` | 对已作废且未结束的码重发，沿用相同条款、合同和收款流水。 |
| `PUT/DELETE platform/store-management/{store_id}/license-activators/{account_id}` | 授权／撤销可激活的本店后台账号。 |
| `GET platform/store-management/{store_id}/license-activators` | 平台查看该店授权记录与本店身份核验状态；门店库不可用时身份状态未知。 |
| `GET/POST license/activate` | 查看当前门店在线授权状态；提交 `license_code` 激活，同店重试返回原结果。 |
| `GET/PUT platform/license-settings` | 读取或设置平台默认 `default_grace_days`。 |
| `GET/PUT platform/store-management/{store_id}/license-status` | 读取状态；通过 `grace_days_override` 设置单店天数，`null` 恢复平台默认。 |
| `GET platform/license-tiers/{tier}/features` | 读取档位配额、年费和增值功能默认值、覆盖值。 |
| `GET/PUT platform/license-tiers/{tier}/features/{feature}` | 读取该项当前模式及真实变更审计；用 `mode` 设置增值功能，`null` 恢复默认；核心订单、履约与资金功能不可配置关闭。 |
| `GET/PATCH platform/license-contracts/{contract_id}` | 查询合同、收款流水及对应金额调整／收款审计；用 `amount_due_fen` 和 `reason` 调整应收。 |
| `POST platform/license-contracts/{contract_id}/receipts` | 提交唯一 UUID `request_id`、`amount_fen`、`received_on`（`YYYY-MM-DD`）及 `note`；同内容重试不会重复登记。 |
| `POST platform/license-receipts/{receipt_id}/void` | 提交 `reason` 作废错误收款，原流水保留。 |
| `GET platform/license-notices` | 平台超级管理员查看本人的到期提醒和未读数量。 |
| `POST platform/license-notices/{id}/read` | 将本人的平台到期提醒标记已读。 |
| `GET platform/store-management/{store_id}/license-points-review` | 平台超级管理员按门店分页查看授权未能核实、积分发放待核对的订单。 |

新增赠礼按 `GIFTS` 档位能力判断：该能力未开放或授权超过宽限期时，礼物列表接口返回不可赠礼状态，赠礼请求在扣款前拒绝。授权变化前已经进入处理的赠礼按原交易完成；既有礼物订单的结果恢复、退款和已取得权益不因功能关闭而撤销。已有积分保留并可按门店规则抵扣符合条件的订单；商城新增兑换和新抽奖分别按下文的对应授权判断，已有兑换或中奖权益继续履约。

合同与收款金额均为**人民币分**，不是店币；当前只登记线下已收情况，不接第三方支付。需执行 `stores` 迁移至 `0025`，各门店 `site_messages` 迁移至 `0006`、`club_accounts` 迁移至 `0009`、`engagement` 迁移至 `0031`，并运行 Celery worker 与 beat 才能投递提醒。故障恢复完整链路和其余增值权益业务拦截仍需完成。


## 当前架构差距（2026-11-11 源码核对）

新增 `XA_ISOLATED_CONTROL_PLANE` 独立模式：`default` 专供平台目录，门店须分别使用独立数据库别名，路由阻止未绑定门店的业务模型落入控制库；平台登记锁不依赖任何门店，平台首位超级管理员可在没有门店时初始化，非周期任务缺少门店上下文时拒绝执行。生产默认启用，受控本机预览仍使用原两库布局，不自动搬迁或清空。新模式从空库部署：先配置不同的控制库及 `XA_STORE_DATABASES` 门店别名并执行 `migrate_stores`，使用 `bootstrap_platform_admin` 创建独立平台身份，再由平台登记、初始化和授权门店；声浪和兴安都不能使用 `default`。三个隔离 SQLite 数据库已验证控制／门店表分离、平台初始化、登记、域名令牌和任务上下文；实际新环境 MySQL 全流程仍待验证。

独立控制库模式新增本店路由签名快照，绑定门店标识、数据库别名及数据库身份，并使用控制库递增版本防止旧缓存覆盖新状态。已绑定域名的老板／陪玩请求、已绑定门店的后台身份与后台 `门店标识/账号` 登录，以及门店业务任务，在控制库查询失败时可从本店业务库恢复经验证的路由；定时任务可向已验证的可用门店快照分发，结果标明使用了缓存。未知域名、跨店令牌、签名错误及不匹配的数据库不会进入其他门店。首次缓存需要控制库和本店业务库均可用；没有可信路由快照时 HTTP 返回 503，WebSocket 关闭，不能伪称已经恢复。后台未带门店标识的新登录仍依赖控制库进行全平台账号消歧。

停用门店时，系统先在本店业务库写入较新版本的停用快照，再提交平台状态；快照无法写入则停用事务回滚。若本店快照已提交而平台事务回滚，后续更新先读取较新快照版本再递增，避免陈旧启用状态覆盖停用记录。隔离 SQLite 已模拟控制连接全部 SQL 失败，验证实际下单与实销积分、后台短信登录、WebSocket 和任务路由；MySQL 临时表测试覆盖版本并发与回滚恢复，控制与业务别名使用同一隔离测试 schema 的不同连接，故障为模拟。尚未验证物理独立 MySQL 服务断连、平台财务在控制库故障时的最终打款和全部资金／外部接口；数据库逻辑分离也不等于同一服务器整体故障时各门店仍可用。

`stores/license_policy.py` 是独立规则层：核对三档、有效期与宽限边界、账号数及核心动作和已获权益例外。平台签发、作废与重发、门店激活、平台指定激活管理员、在线状态与宽限期、按档位增值功能配置及 License 合同线下收款登记已实现；明文仅签发响应返回一次，数据库保存摘要和审计，重发保留合同及收款。取消及到期提醒通过控制库通知队列与门店站内消息幂等投递；需要迁移并运行定时任务。

在线授权可用时，老板和陪玩开户由本店账号类别锁与开户事务共同保障并发配额；老板退店释放名额，重新认证后入店须再次检查，本次退店前的令牌不会因重新入店而恢复有效。现已验证两门店隔离、到期时已有会话、退店及 MySQL 并发争抢最后一个名额。陪玩显式注销流程仍待接入；控制库故障时的门店路由和各增值功能发放入口的拦截仍未完成，不能将 License 整体标记为已交付。各门店本机开发库尚未执行新增结构迁移。

已增加门店业务库内的签名授权快照，用于**已经可信解析出门店上下文**的开户配额、已接入的权益判断及后台任务：控制库查询失败时验证签名与门店，再根据缓存的到期、宽限期、未来调档和档位功能，按当前时间计算状态；没有有效快照或签名无效时暂停新增账号及新增权益。正常查询恢复后使用最新在线状态并刷新快照；缓存不设额外有效期。快照仅在控制库与本店业务事务均提交后写入，失败不会回滚已提交业务；进程崩溃可能使最近一次成功查询未能写入，仍以已持久化的最近快照为准。签名使用应用密钥，轮换时必须保留必要的 `SECRET_KEY_FALLBACKS`，否则旧快照无法验证。隔离双库测试覆盖状态边界、回滚、签名及业务积分，隔离 MySQL 测试覆盖行锁和模拟控制库故障；尚未进行真实断库演练。

老板签到在读取和提交时检查 `CHECKIN` 授权：不允许发放新权益时不产生新的签到和补签卡，但已获得的补签卡仍可使用并领取该卡对应的签到奖励；全勤奖励尚未获得时不能借补签新增发放。签到店币奖励计入赠送余额，消费不产生本金消费积分。

积分商城新兑换和新抽奖分别检查 `POINTS_SHOP`、`LOTTERY` 授权；到期或降档后若对应增值功能不可用，停止创建新的兑换或抽奖。已存在的兑换、中奖记录仍可查询、幂等重试和履约；兑换取消按原流程退还积分。原有积分仍可按门店积分使用开关和订单规则抵扣，授权限制不会清空已有积分。

订单消费积分已在实际发放点检查授权：宽限期内照常发放；超过宽限期的决定与订单一起留存，续期不会将该订单的积分自动补发。已获优惠券继续可用于下单；直接领取新券检查 `PROMOTIONS` 档位能力，自动月券、消费触发的 VIP 升级及门槛重算发放检查 `VIP_GROWTH` 档位能力，平台调整这两项后上述入口在线立即生效。已创建的 VIP 专属券与权益可幂等重试，不能借重试新增权益；发放期间授权失效时，VIP 发放局部回滚，不回滚已满足条件的订单结算。控制库查询暂不可用且无有效快照时，在尚可访问门店业务库的前提下不阻断结算，将积分决定记录为 `UNKNOWN` 供平台查询，不应将该状态当成已拒绝或已发积分。对于积分订单退款及转单退款，结算凭证也会记录本次授权未能发放的事实。会员权益的其他入口、其他档位功能开关和真实控制库故障下的门店路由仍需继续接入与验证。

平台超级管理员可通过 `POST platform/store-management/{store_id}/license-points-review/{decision_id}/resolve` 根据原时点证据对主订单或礼物的 `UNKNOWN` 决定人工结案，提交 UUID 请求编号、`ALLOW`／`DENY` 和核对依据。系统保留原始决定，补发按付款倍率和当前已退本金计算，后续退款继续按本金冲回；老板已退店进入新业务周期时不恢复已清空的权益。结果、操作者及依据分别留在本店核对记录与平台审计。平台审计提交失败时可用原请求重试，`kind=ORDER_REVIEWED` 列表显示审计待恢复记录，其他超级管理员可恢复且保留原操作人。

加购通过 `POST platform/store-management/{store_id}/license-points-review/addons/{consumption_id}/resolve` 分别核对未知的 VIP 和积分授权；已确定的部分不重新判断。确认应计入的净加购消费加入原业务周期的会员成长，遗漏的消费积分按原倍率和实际退款补发；后续退款冲回补发积分及会员成长。当当前授权或门店 VIP 状态暂不允许重算时，记录待重算状态，门店任务在条件恢复后自动重试，也可使用原请求重试；`kind=ADDON_REVIEWED` 显示核对及审计恢复状态。此流程依赖平台管理员核实原时点资料，不能用当前授权冒充历史事实；加购无自动历史重核。需在每家门店执行 `engagement.0033` 并运行 Celery worker 与 beat。

普通服务的新订单报价按 `PROMOTIONS` 授权控制门店活动：有效及宽限且档位允许时可以选活动，过期或档位关闭时不提供活动折扣或活动抽成；失效前的报价不能继续用于新付款。已经付款的订单保留原价格和抽成快照，已领取的券仍按原资格使用；核心订单仍可下单。控制库暂不可用时使用已校验的本店授权缓存，按缓存时间推进状态；无可信缓存时暂停新活动优惠。老板下单、客服代单及预约报价共用相关计价路径，后台新单抽成建议同步按授权处理。此项不代表所有 License 功能入口已接通。

审计日志读取按 `AUDIT_LOG_VIEW` 授权分档：`RECENT` 查看最近 30 天（含截止时刻），`FULL` 查看完整历史，`OFF` 不开放；授权到期后的 `READ_ONLY` 保留最近 30 天的查看能力。角色仍须具备审计读取权限，所有档位的审计记录照常写入并保留；无法核验授权且无可信缓存时返回服务不可用。30 天为首版对“近期”的平台默认定义。

经营成本与 ROI 按 `OPERATING_COST_ROI` 授权：`BASIC` 允许登记与查询成本，`FULL` 另允许计算 ROI，`OFF` 不开放；到期或平台设置为 `READ_ONLY` 时保留已有成本记录的查询，不开放新增或修改。ROI 当前是即时计算而非已保存报告，因此只在 `FULL` 可用。既有岗位权限与门店隔离仍须同时满足，授权异常且无可信缓存时返回服务不可用；不影响订单、售后与资金核心业务。

## 陪玩通行证授权

`PROVIDER_PASS` 是平台可配置的增值功能，Basic、Pro、Ultra 默认 `FULL`。有效期与宽限期内按本店档位及平台覆盖规则判定；超过宽限期、未授权或档位关闭时不接受新购。授权无法核验时返回 HTTP 503（`LICENSE_UNAVAILABLE`），明确不允许购买返回 HTTP 403（`PROVIDER_PASS_LICENSE_DENIED`）。

陪玩通行证查询返回 `license_status`（`ALLOW`／`DENY`／`UNKNOWN`）、`license_purchase_allowed` 和对应 `purchase_block_reason`；积分报价和购买在实际办理时分别重新校验授权。已成功购买的请求按原资金幂等凭证重放，已生效通行证、既有退款及订单履约不因本开关失效。授权状态按现有控制库／签名快照规则获取；本店业务库与控制库不是单一事务，授权调整与支付并发的实际边界须在最终联调核对。

首版空库部署须使用包含此功能项的新版本生成授权快照；本轮未运行测试或迁移。
