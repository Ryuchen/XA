# 活动、预存、会员与优惠券

本文从老板使用、本店运营配置及陪玩收益三方面整理现有业务和本轮新决定。门店配置统一纳入[系统字典与初始化](12-系统字典与门店初始化.md)；静态源码中的数值只是现有实现或历史模板，不等于当前两店生产配置。

## 1. 角色和作用范围

| 功能 | 老板 | 陪玩 | 本店后台 |
| --- | --- | --- | --- |
| 预存 | 联系本店客服，核对实收、组合档位、赠送及钱包到账；付款时可分别输入赠送和赔付使用数量。 | 没有充值业务；钱包调整按权限和调账流水办理。 | 授权客服核实收款；管理员配置充值档位及赠送。修改自动赠送金额须经本店管理员 OA 审批。 |
| VIP | 查看本人等级、已确认及待确认消费、下一级门槛、折扣、券和权益。 | 按服务、实际抽成和订单快照获得报酬；VIP 优惠或平台补贴不可随意改为陪玩承担。 | 在本店系统字典设置等级门槛、折扣、月券、安全箱和升级权益；查询资格及发放结果。 |
| 活动／优惠券 | 查看当前有效的活动、可领取／已领取券、适用服务及报价变化。 | 查看与本单关联的应得收益和实际结算。 | 配置作用范围、开始／结束时间、优先级、数量、限制及折扣／抽成；不能修改已支付订单事实。 |
| 权益交付 | 查看获赠权益、提交必要资料、查看进度。 | 如权益与陪玩有关，按本人授权查看相应工作信息。 | 客服或获授权人员核对交付状态、原因和完成结果。 |

同一自然人在不同门店的充值、余额、积分、等级、券和权益分别计算；平台聚合只展示授权范围及门店归属，不把门店币和权益合并。

## 2. 预存及积分来源

- 本店按人民币配置各预存档位及赠送；按一次实收金额从高到低组合，同一档可重复，未匹配本金不赠送。[组合示例及记账](12-系统字典与门店初始化.md#4-预存档位组合与记账)是本轮最新规则。
- 本金全额计入本店店币并汇总；赠送和赔付单独列示，老板支付服务订单时可分别输入使用数量，礼物订单仅能用本金。只有**本金被实际消费**才按付款时老板 VIP 等级对应的门店倍率计算消费积分；尚未达到 VIP 的老板按本店普通会员基础倍率计算。赠送、赔付和积分抵扣部分不产生消费积分；生日倍率等已适用的叠加规则继续核对。
- 老板取得的推荐佣金也归入本金余额并参与本金消费赠分；抽奖获得的店币奖品及客服赠送归入赠送余额，消费不赠分。各自真实流水来源保留，不能把推荐佣金统计为实收充值。
- 实收本金、赠送和充值组合明细形成快照；消费及退款记录各类支付构成。充值档位记录是历史凭据，本金余额不按档拆成供老板消费的批次；预存本金并非营业收入，也不能仅因充值就当作会员已确认消费。
- 客服修改自动算出的赠送需本店管理员 OA 审批，本金先到账，赠送审批通过后按批准额到账；驳回按系统原赠送额发放。现有代码允许人工输入赠送并且本金和赠送混入同一批次，上述新流程及积分计算均属待开发。

## 3. VIP 成长与权益

### 3.1 资格、升级及展示

1. 每家店可自行增减等级数量，并配置等级名称、顺序、人民币等值累计有效消费门槛、消费积分倍率、普通会员基础倍率、老板订单折扣和各类权益。初始化时可参考现有六级模板，但不得把 VIP1–VIP6 硬编码成门店的等级数量上限；实际值须由有权限的人确认。
2. 老板查看本人当前等级、已确认消费、待确认消费、下一等级差额、折扣及可用权益。充值、下单、完成服务、报单、陪玩结算与会员消费确认不是同一个事件；已有报单和售后时钟必须按真实业务结果处理。
3. 符合条件的服务订单按**积分抵扣后实际支付店币**换算人民币等值计入本店会员成长；用户另确认礼物只用本金支付，该礼物本金在支付成功后立即计入 VIP 成长，退款后按实际退回的本金冲回。礼物触发升级时，该礼物本身的消费积分仍使用付款时原 VIP 倍率快照，不倒用新等级倍率。服务订单仍遵循适用的实销确认及退款条件，部分退款只冲减退回店币；付款或会员确认时 VIP 停用的消费不计日后成长。实际支付可能包含赠送或赔付店币，不能称为现金实收；消费获得积分另按本次实付中的本金余额及付款时老板 VIP 倍率计算。成就排除礼物、消费榜包含礼物，不能把会员成长范围直接套用到成就。
4. 跨越多个等级时，按该店配置和实际达标事实核对各级升级权益；同一客户、门店、周期和权益来源防止重复发券或重复交付。历史消费和已经使用的券不因配置修改被重写。
5. 退款导致累计有效消费低于当前等级门槛时，按净消费重新计算并降级；**已发未使用的月券、升级券、安全箱券及未交付权益全部保留，后续新发权益按新等级执行**。本月已发未使用月券保留降级前原条款，已用券和已交付事实保留；降级本身不撤券、不改套新等级条款或取消交付。现有代码会撤销超出等级的部分未使用券及未交付权益，与新规则不同。
6. 门店取消已有老板持有的等级时，按调整后的等级和有效消费门槛重新计算受影响老板的等级。**被取消等级已经发出但未使用的券，保留该等级取消前的使用条款；调整后新发的券按新等级规则执行。**例如取消 VIP6、老板调整为 VIP5 后，已发未用的 VIP6 券保留原 VIP6 条款，新发券按 VIP5 条款。本月已发券数量保留，已使用券与订单历史保留。
7. 门店修改消费门槛、新增等级或重新启用等级后，按调整后的全部等级和已确认净消费立即重算所有老板；因此升级时补发新达等级的升级权益，已发月券保留原条款。VIP 停用期间发生此类配置调整时，等 VIP 重新启用后统一重算并补发升级权益；停用期间的消费不追溯计入成长。
8. 新规则上线时门店 VIP 已停用且无法还原停用前等级和门槛，重新启用后仍按当前净消费重算等级；无法核实是否已发的升级权益进入人工核对，不自动补发。

### 3.3 券与权益变更

- 用户已确认：门店修改仍在使用的 VIP 等级的月券、折扣或安全箱规则后，**该等级已发放但未使用的券跟随新规则更新**；已使用券保留原使用记录及对应订单快照。更新应显示影响范围并记录版本，不能修改别店券或历史支付金额。
- **取消等级是上述规则的明确例外**：被取消等级的已发未用券保留取消前条款，不因老板调整为其他等级而套用新等级条款；之后新发的券使用新等级规则。取消等级前须固化旧条款、展示受影响等级、老板和券的范围并保留操作记录。
- **退款导致降级的权益保留**：本月已发未用月券保留降级前原条款；已发未用升级券、安全箱券和未交付权益也全部保留，降级本身不套用新等级条款或取消交付，后续新发权益按新等级。若原所属等级后续另有配置调整，仍须区分前述“仍在使用等级的条款修改”和“取消等级”两种已确认规则，不能混同为降级自动撤销权益。
- 用户已确认：**月券数量调整从下次发券时生效**，本月已经发出的券全部保留，包括尚未使用的多余券；已使用券不能悄然抹除。例如本月已发 4 张、已用 1 张，数量改为 2 张后，本月仍保留其余 3 张未用券，下次发券再使用新数量。已过期券不能因为更新被误标成已使用或伪装成未发过。
- **老板月中升级**时，本月不按新等级补发月券，原已发券的条款不因升级改变；下月按新等级规则发券。该规则不取消独立配置的升级礼包，礼包仍按其适用配置及真实发放事实处理。
- **门店停用 VIP 功能**时，已发且未过期的 VIP 专属券继续有效，停止使用 VIP 等级折扣，也不再发放消费积分；不得将停用直接等同于撤销历史券和权益。付款时或实销确认时 VIP 停用的消费，不发消费积分，也不计入日后 VIP 成长；即使之后重新启用也不补计。例如 VIP 启用时付款但停用后才实销，不发积分且不计成长；停用时付款、重新启用后才实销也不计。此前合格消费发生退款时仍须关联原事实核对。
- 老板可维护生日及允许展示的标签；当前生日登记后本人不能自行改成另一天，需要联系客服核对。生日公开开关关闭时不应继续公开生日播报。
- VIP 专属陪玩券、安全箱券须绑定本店允许的具体服务，校验服务状态、单陪／主套餐范围和数量；已停用或不满足资格的服务不能因旧页面而核销。

### 3.4 VIP6 免费安全箱与真实资金

现有 [VIP6 安全箱专项](../ops/vip6-safebox-subsidy.md)记录：符合规则的免费券使老板该笔店币实付为零；陪玩报酬由平台补贴按对应原价和分成规则承担。VIP6 是历史示例，新目标中各店可增减等级并为相应等级配置此类权益，不应将免费安全箱固定绑定在 VIP6。此场景不是积分抵扣导致零实付，不改变“使用积分时须支付一部分店币”的要求。实际使用受门店配置、补贴开关、余额及订单状态影响，不把历史专项文档当作每个门店已启用的证据。

免费券在服务后的协商终止、陪玩协商报酬、补贴不足待处理及下一张券发放，必须分别关联订单和补贴结果；未真正结算不能提示已付报酬。配置新店 VIP 权益时应明确是否启用此项及对应服务。

## 4. 活动与优惠券

### 4.1 运营配置与生效

- 本店活动可配置名称、启停、时间范围、全场／分类／指定商品、优先级，以及对老板价格、抽成的影响。**所有按比例打折的优惠互斥，只能使用一个**：包括会员折扣、门店活动折扣、折扣券及其他比例优惠；系统默认推荐符合条件、最终实付最低的合法组合，老板可以切换。
- 每单最多使用一张券：资格允许的金额券可叠加会员或门店活动折扣，但不能与折扣券同单使用；折扣券属于上述互斥的比例折扣之一，不能与会员或门店活动折扣再叠加。符合条件时可以继续使用积分抵扣；券的范围、门槛、数量、体验资格及特殊权益仍须分别核验。
- 当前 [`promotions/models.py`](../../services/backend/promotions/models.py) 与 [`orders/pricing.py`](../../services/backend/orders/pricing.py) 区分价格折扣活动与仅影响抽成的活动；当前价格代码会把会员与活动折扣连乘，又禁止价格活动与金额券同用，和新规则不同，须改造各个报价及付款入口。
- 服务端核对并试算实际可选优惠和券；老板确认后才付款。服务项目标价须为 10 店币整数倍，单一比例折扣后出现小数店币时向上取整为整数店币；老板付款不使用小数店币。价格、活动时间、服务资格、券库存、适用范围或本人余额变化时要求重算，不以活动页或本地展示价格扣款。
- 本轮已确认：允许使用积分的服务订单先确定适用价格优惠，再使用本店积分抵扣。体验套餐保留专价及资格规则、礼物订单也不支持积分抵扣。

### 4.2 券的领取、核销和退款

| 环节 | 规则 |
| --- | --- |
| 类别 | 当前有满减、无门槛、折扣／服务券、套餐资格券；按实际券种决定面额、适用范围与退款处理。 |
| 领取 | 验证本店本人、券是否公开启用、是否过期、总量、当前业务周期和个人领取条件；资格券还需对应套餐及资格范围。领取竞争不能超发。 |
| 使用 | 每单最多使用一张券，在服务端按券范围、有效期、数量、套餐、优惠互斥及本人身份校验；资格券不是金额券，不让其他店或其他用户使用。 |
| 折扣顺序 | 会员折扣、门店价格活动、折扣券等比例折扣选择一个；符合资格的金额券可叠加会员或门店活动折扣，但不能与折扣券同单使用；符合条件的积分在价格优惠后按门店配置完整组抵扣，不能约分拆组。默认推荐最终实付最低的合法组合，可由老板切换。体验资格券及特殊权益仍按其规则核验。 |
| 退款 | 是否返券按核销时的券类型和快照决定；当前资格券使用后不按普通券一律返还。已用 VIP 券在门店改规则后因全退而退回、且仍在有效期时，保留该券原先使用时的条款；不得借返券擅自延长原有效期。 |
| 信息同步 | 老板、客服和运营可在各自权限内看到领取／使用／过期及订单关联；消息刷新不是券真实核销或退款成功的替代证据。 |

## 5. 关键边界和源码

- [`coupons/claims.py`](../../services/backend/coupons/claims.py)：领取数量、每用户／周期与体验资格控制；[`orders/purchase_benefits.py`](../../services/backend/orders/purchase_benefits.py)：体验套餐、资格券、原优惠与支付时核验。
- [`engagement/confirmation.py`](../../services/backend/engagement/confirmation.py)、[`engagement/refunds.py`](../../services/backend/engagement/refunds.py)：会员消费成熟、退款后的等级和权益处理。已用或已交付的事实与当前有效权益应分别展示。
- [`orders/commission.py`](../../services/backend/orders/commission.py)、[`orders/pricing.py`](../../services/backend/orders/pricing.py)：活动与服务／资格／等级／手工抽成存在不同分支，不能概括成一条不分场景的优先级。详见[陪玩资格与抽成](14-陪玩资格与抽成.md)。
- 不以历史种子、历史测试报告或演示资料推断任何门店当前的真实余额、活动、会员或外部权益已生效。
