# 客服咨询、消息与通知

本页区分**在线咨询会话**、**站内业务通知**、**公开客服名片／公告**和**外部渠道消息**。它们可以互相跳转，但人员、权限、未读状态和业务事实不能混同。普通客服须领取后回复；仅领取人及获授权主管可查看内容，主管可以不领取直接回复已由其他客服领取的会话，原领取人不变。

## 1. 使用方和范围

| 使用者 | 主要操作 | 权限和关联 |
| --- | --- | --- |
| 老板 | 查看本店客服联系方式、打开在线咨询、发送文字或图片、从订单发起咨询、查看回复和通知。 | 只可访问本人本店会话和订单；未登录用户仅查看允许公开的客服联系方式。 |
| 陪玩 | 就接单、报单、收益、提现或订单联系本店客服，查看回复与站内消息。 | 只可访问本人本店会话及获准查看的业务；个人或支付资料不向其他陪玩公开。 |
| 本店客服 | 查看共享会话池中的会话列表与接待状态；领取后阅读并回复，必要时交还或转交。 | 未领取的普通客服不能读取聊天正文、图片或内容预览；只能处理本店获授权会话。 |
| 本店主管 | 按授权查看本店会话及内容、接待状态和转交记录，必要时重新分配或直接回复。 | 有相应回复权限的主管可不领取直接回复已分配会话；原接待客服不变，消息记录真实回复人。 |
| 平台角色 | 仅在拥有明确平台数据授权时处理授权范围内的管理事项。 | 不因平台财务、平台超管或聚合报表身份自动公开所有聊天正文；具体授权须明确。 |

同一个业务账号在同一门店对应自己的咨询会话；老板和陪玩即使属于同一自然人，也不能因为手机号相同而自动合并账号或跨店会话。现有 [`chat/models.py`](../../services/backend/chat/models.py) 保存每个用户／业务账号的共享会话及消息，尚无本轮新增的领取责任人和流转记录。

老板下单所选客服名片须绑定具体本店员工，该员工成为本单负责人；**订单负责人、咨询领取人、实际派单人与薪资业绩归属人是不同事实**。咨询仍进入共享池，只有领取人和获授权主管可读正文；订单负责人未领取且不是获授权主管时，不因负责人身份自动获得聊天内容权限。业绩依据实际工作核定，不按名片选择自动计提。

## 2. 本店共享池与领取

### 2.1 状态及动作

| 状态／动作 | 本店客服 | 主管 | 老板／陪玩 |
| --- | --- | --- | --- |
| 待领取 | 看到会话列表、接待状态及未读提示；点击领取。未领取之前不看聊天内容或包含正文的预览。 | 可按授权查看及分配。 | 正常发送消息，看到消息真实发送状态；不需要知道内部权限字段。 |
| 已领取 | 普通客服仅当前领取人可查看正文、图片并回复；其他普通客服只看会话列表和接待状态。 | 可按权限查看、重分配或不领取直接回复，原领取人不变。 | 正常收到本店客服或主管回复。 |
| 交还共享池 | 当前领取人主动交还，保留原会话和历史。 | 可查看记录和后续领取情况。 | 会话及已发送消息不丢失；后续回复由新领取人处理。 |
| 转交 | 当前领取人转交给同店具备接待权限的客服；从成功生效时起由新领取人接待。 | 可查看记录、按权限重新分配。 | 原聊天记录和关联订单保留，不重复发送消息。 |
| 主管重分配 | 原领取人按新结果失去该会话的内容读取和回复权限。 | 选择获授权的同店客服，记录操作、原因、时间及前后责任人。 | 以实际消息为准，不重复创建会话。 |

领取后不因下班、离线或空闲时间自动回收到公共池；需要交还、转交或主管重分配。若原领取人离职、停用或失去权限，其旧权限必须及时失效，主管可人工处理接待归属，不能让无人可处理的会话伪装成正常接待。

### 2.2 同步、并发与隐私

1. 同一会话同一时刻只有一个有效领取人。两个普通客服同时领取、领取与主管重分配、转交与回复竞争时，以服务端原子结果为准；失败的普通客服不能冒充领取人回复。获授权主管直接回复不改变领取人，仍记录主管本人及消息顺序。
2. 客服交还或被转出后，其聊天列表、详情、搜索、消息状态、已读、回复、图片读取及 WebSocket 必须重新核验当前归属；不能只隐藏回复按钮。其他普通客服的会话列表不可泄露正文、图片、敏感预览或聊天历史。
3. 主管仅能访问授权门店；会话 ID、客户 ID 或消息 ID 在不同数据库可能重复，不得凭数字 ID 跨店获取内容。订单权限、聊天权限和私有图片权限分别校验。
4. 当前 [`console/views.py`](../../services/backend/console/views.py) 的客服工作台以 `chat:view`、`chat:reply` 及共享会话实现；[`chat/notifier.py`](../../services/backend/chat/notifier.py) 向客服组发送聊天事件，[`orders/consumers.py`](../../services/backend/orders/consumers.py) 当前按 `chat:view` 判定客服消息。新领取和内容隔离需要同时调整列表、接口、实时推送和私有媒体；仅改界面不满足要求。

## 3. 从订单发起咨询

用户已确认：从订单详情进入咨询时，**保留正式的订单关联**，聊天中可查看订单卡片并跳转订单和售后进度。

1. 老板只能关联本人本店订单；陪玩只能关联本人被授权参与的本店订单。后台处理卡片时仍须校验本店会话归属，以及该员工的订单／售后查看权限。
2. 一位用户的同一会话可以先后咨询多个订单或普通问题；卡片应记录所属门店、原订单标识及发出时必要的展示快照，打开时读取最新允许查看的状态，不把老状态冒充当前结果。
3. 客户从订单页面发起时，先校验订单与身份；关联失败、订单不可见或已变化时显示原因，保留尚未发送的文字，不能悄悄改成另一笔订单。历史会话中的订单号文本保留，不据文字猜测并批量建立业务关系。
4. 当前 [`boss/content.tsx`](../../fronted/boss/src/business/content.tsx) 会在消息中加入订单号文字，后台可识别文字跳转；[`ChatMessage`](../../services/backend/chat/models.py) 尚无正式订单关联字段。新卡片及可验证的关系是待开发，不应把文本前缀当作可靠关联已完成。

## 4. 发消息、图片和已读

- 老板、陪玩、领取中的客服及有回复权限的主管可发送当前支持的文字和图片。现有用户端服务端限制文本不超过 1000 字；图片支持 JPEG／PNG／WebP，大小不超过 5 MB，并核验真实文件内容；后台仍须补齐对应校验，具体失败原因以服务端结果为准。
- 消息保存后更新会话最新状态与接收方未读数；请求超时使用原消息编号查询同一发送结果，不以再次点击创建重复消息，也不能用相同编号发送不同内容。
- 分页加载历史时保留顺序和当前位置；只把实际已加载／已查看的指定消息或范围标记已读，不能因为打开旧消息清掉刚收到的新消息。
- 图片采用本店私有访问授权；上传失败、票据过期、会话转交、账号撤权或门店停用时必须重新核验。缓存和长连接不能继续向非领取人发送聊天内容。
- 实时推送、提示音和页面刷新提供便利，不代替消息持久化；网络异常时显示可核对状态。提示音遵循用户此前要求：关键提醒清晰、可控，不重复打扰。

## 5. 站内消息、公开内容与外部联系

| 类型 | 内容与用户动作 | 后台与例外 |
| --- | --- | --- |
| 站内业务通知 | 订单、预约、报名、报单、提现、售后、权益及系统通知；列表、详情、未读、全部已读及获授权跳转。 | 只发送本店目标账户；点击消息只改变已读，不应重复执行原业务。跳转目标失效时可返回并查看真实状态。 |
| 客服聊天 | 用户与本店客服的对话历史。 | 与站内通知未读数分开；按本页领取人与主管权限处理。 |
| 公开客服名片 | 未登录也可查看本店允许公开的联系信息；已登录订单场景可获取相应客服信息。 | 运营维护启停与排序；原负责名片停用时现有接口回退本店当前默认名片，不跨店找客服。 |
| 公告、轮播、活动内容 | 按门店启用状态、展示时间和可见范围展示，进入实际对应内容。 | 公告与聊天、个人通知分离；修改内容不改历史订单或用户资金。 |
| KOOK／企微等外部渠道 | 仅在本店配置且实际启用时使用。单陪及双陪抢单均可按规则通知，双陪注明两人组队；内容展示服务原价和订单要求，不承诺个人实际收益。 | 含无卡陪玩的混合群等所有通行证等级及无卡均达到该单可见时间后再发完整订单；发送前重核订单，已分配、取消或到期不能再发送待抢消息。权限、凭据和接收目标隔离；真实外发失败应有状态和重试依据，不能把站内消息创建当作外部送达。 |

后台可按权限向本店用户发送站内通知；全员及按角色发送按本店有效业务账号选取接收人，不依赖旧用户映射。发送请求可持久去重，逐人保存创建状态并支持失败后重试；账号停用或业务周期改变时不继续向新身份发送。发送结果区分站内记录创建成功、待处理、失败和跳过，不能将站内记录创建当作实时推送或外部渠道送达。此路径代码尚须最终联调，覆盖无旧映射账号、退店、双店隔离及发送异常。

老板退店后重新入店、陪玩注销后重新入驻时，同一账号此前已经收到的站内消息继续保留并标明属于旧业务周期；待发送通知不得跨周期发送。消息所属周期应来自发送时保存的事实，不能用当前周期推断旧消息来源；尚无法确认的来源应明确标示未知。此规则不改变各项业务对象自身的访问授权。

## 6. 待验收场景

- 两店同数字会话 ID、客服并发领取、交还、转交、主管重分配、客服离线／撤权，以及旧领取人尝试读取正文、图片、推送和回复。
- 未领取客服只看到列表及接待状态；领取人和授权主管能看到内容；失权后旧图片票据和长连接不能继续读取。
- 老板／陪玩从本人订单发起、跨人或跨店订单被拒、同会话多个订单、订单退款或售后状态改变后卡片回读。
- 网络丢响应后按原消息编号恢复、图片失败、历史分页与新消息同时到达、只标记已读范围、声音开关及消息跳转。
- 按角色、指定用户和全员发送通知，覆盖新业务账号及旧账号映射；站内、外部及实际送达结果分别记录。
