# 陪玩端：入驻、履约、收益和提现

陪玩业务身份和资金按门店独立。入口为所属门店 `/player`，手机和桌面均可完成接单与必要的触控操作。个人账户资料、订单、报单、押金、积分和钱包不可在不同门店混用。

## 1. 入驻、微信与头像

1. 陪玩可按门店要求报名、试音、填写实名、游戏技能、联系方式和押金方式；待审核、需补充和已通过状态及原因清楚可见。证件及押金凭证仅本人和获授权的本店人员查看。
   陪玩可用账号密码登录：未绑定 OTP 时短信验证，已绑定 OTP 时默认使用手机验证器动态口令并可切换短信；已绑定微信可扫码或快捷登录。登录方式不等同接单资格，正式接单前仍须完成本人微信绑定。
2. 正式接单前必须绑定本人微信。规则生效后**新入驻陪玩**首次正式接单前还须真实取得该微信头像；微信头像暂时无法取得时，不能用自行上传头像绕过首次接单前置。绑定冲突、取消授权或无法证明身份也不取得接单资格；不能将手动填写的信息冒充微信授权结果。
3. 新入驻陪玩首次成功取得微信头像后，头像可按微信实际支持能力重新读取／选择，也可由本人上传更换；记录首次真实获取事实与当前头像来源，后续自行上传不取消已完成的首次获取事实。已有陪玩已绑定微信但历史头像来源不明时，可保留现有头像并继续按其他资格接单，不伪造历史头像来源。头像按本人和门店保存并同步到老板端展示，不能伪造微信不支持的静默读取。
4. 未完成微信绑定的陪玩、新入驻但未完成首次微信头像获取的陪玩限制新接单和老板端选用；已有陪玩的历史头像按上条兼容。现有已接订单继续履约，钱包、已提交报单和提现等本人既有能力保留。门店入驻试音与老板已付款订单的招募试音分开：后者按正式接单资格校验。
5. 可维护个人展示资料、语音卡、视频、技能、档期、接单开关与通知偏好；档期支持由本人自选开始和结束时间，包括跨午夜时段，例如 18:30 至次日 02:00。完全未设置档期时默认全天可接，但仍须满足上线、微信绑定、押金、技能等其他条件；认证、等级、押金及其他后台受控字段以服务端和授权为准。


## 2. 押金和接单资格

| 模式 | 最新标准 | 使用与历史 |
| --- | --- | --- |
| 现金押金 | 各门店配置人民币目标 | 不足额统一线下补款，客服核验后直接登记增加已缴押金并记录调账原因，不经过陪玩可用钱包余额，不记作普通充值。 |
| 单抵押金 | 各门店配置人民币目标 | 按收益抵扣与结款比例执行，直至达到本店目标；调整目标不改写实际流水。 |

须区分押金应缴、已缴、待缴、来自现金还是单抵；变更目标不改写实际流水。现金模式下不足额按资格规则处理；单抵模式仍沿用允许接单与分次抵扣条件。已接订单不因规则更新被悄然取消。

陪玩仍有进行中订单、未结束售后或尚未结清的订单收益时，暂不允许退还押金；收益已入钱包但仍在冻结期时，也必须等该笔冻结释放后再申请。页面和后台应显示未满足的具体条件，服务端重新校验并处理与新订单、售后及结算的并发；历史已退押金流水保留。

退款中本人应承担的分摊额，先冲减本人该单待结算收益，不足再扣本人可用钱包，仍不足则从本人已缴押金扣除并记录待补缺口；三者合计仍不足时退款暂不执行，待陪玩补足后再处理。对**退款造成的押金缺口**，已有服务订单继续履约，并在其他接单资格满足且未达到本店普通并发上限时额外放行一张新单；已满上限须等有名额再放行。该陪玩已有或新接订单中最先满足结算条件的收益优先补缺口，礼物收益到期释放时也优先补，不占服务接单名额。允许的新单尚未满足结算条件、缺口未补齐时，不能再放行另一张新单；若该单结算后仍不足，再放行下一单并继续由满足条件的收益补齐，直至缺口补足，剩余收益正常结算。其他原因导致押金不足仍按原资格规则处理；不得伪造已补齐押金或未发生的扣款。

补差单在服务开始前取消时，立即恢复一次补差接单机会；已经履约时须等待该单收益满足结算条件后，再根据剩余缺口决定能否放行下一单。

同时校验账号状态、认证、微信绑定、新入驻陪玩首次微信头像获取事实、押金方式、接单状态、技能、等级、时间、服务要求、容量和当前订单状态。抢单、报名、老板选择、客服指派及双陪确认均应在服务端复核，不依赖页面上一次展示；首次获取后自行更换头像不应被误判为未获取，已有陪玩按存量兼容规则处理。

每家门店配置一个统一的陪玩同时进行订单上限，适用于本店所有陪玩；普通订单沿用“已接单及服务中”计数，双陪各自占用本人容量，同一人同单不重复占用。**已付款的未来预约在服务实际开始前不占当前接单名额；开始后计入，即使开始时已达到上限也允许该预约开始，暂时超出。**达到或超过上限后，普通新单仍不得继续取得；降低上限不撤销已有订单。列表、抢单、选人、指派和转单均须读取本店配置及正确计数。当前代码固定为 3 单，仅供历史参考。

本人可查看预约及待确认截止时间，并由本人确认或拒绝，客服不能代操作。支持双陪预约，两人分别确认并占用各自档期；一人拒绝或超时后保留已确认者及其档期，老板重新选择另一人，即使距离开始不足常规确认时限也可重选，替代者最晚在预约开始前确认；到开始仍未完成时取消并释放。两人全部确认后老板才能付款转单；付款截止为全部确认后的本店时限与预约开始时间中较早者，未付款自动取消并释放档期。距预约开始时间不足门店确认时限时不得提交新预约。付款转正式单后原预约时段继续防重叠；陪玩可以提前开始服务，不能自行拒单。客服协调改派成功时释放原陪玩占档，核验并锁定新陪玩原约定时段；改派失败保留原占档和真实状态。

## 3. 公开订单与招募试音

1. 接单工作台展示本人符合可见规则的公开单，以及已接和历史订单。老板未指定的普通新单和客服安排的新单进入抢单池，先按提交抢单时的通行证等级、再按接单额和好评率依次排序；已接订单须本人开始履约后才计入接单额，按各次本人接入时间及其份额归属近 30 天。双陪可自行组队且每项分别取两人较高值。首轮窗口从入池立即计时，本单可见时间按入池时各人通行证状态及门店延迟配置确定；购卡、卡到期或改配置不改变该单可见时间，也不延长窗口。窗口内显示已提交、待分配，系统完成派单后才告知抢中与否。试音招募仍由老板试听选人。
2. 普通抢单的双陪由两位合资格陪玩组队并确认，系统按窗口和排序决定分配；A 可提前邀请尚未到本单可见时间的 B，但 B 必须等到本人可见时间后才能确认，提前邀请不等于完整候选。不能借邀请提前泄露仍受可见延迟约束的订单详情；确认前须重新核对订单、资格和时限。不能把报名成功直接显示为正式接单。试音报名则由老板试听并选择。首轮无人形成完整候选且仍未到总等待截止时，由后来已到本人通行证可见时间的首个合资格单陪或首个完整合资格双陪队伍直接取得；状态变化要及时回读。
   若首名候选分配前失去资格，尚未到订单总等待截止时重开完整窗口，所有当前合资格陪玩同时可见并重新抢；剩余时间不足则延长至新窗口结束。重开仍无人抢且尚未到期时继续留池，之后首个合资格单陪或完整合资格双陪队伍直接取得。若判断重开时已到期，直接取消退款。普通抢单成功分配后、服务尚未开始时陪玩不能自行拒单，由客服协调转单或取消退款。
3. **订单招募试音**与现有后台创建的招募邀请是不同场景。老板在下单并付款时选择试音招募，陪玩报名该订单时提交本人录音：从本人以前上传的多段录音中选择，或上传新的录音。报名时上传的新录音自动保存到本人录音库，并关联本次报名；现有单条语音卡不等于多录音库已经实现。
4. 双陪报名中每位陪玩分别提供本人的录音，队友未确认或缺少本人录音时，老板不能把该报名当作完整可选队伍。陪玩可查看自己提交的状态；不能替队友提交或读取无授权录音。
5. 系统保存本次实际提交的录音及归属快照；后续更换或删除个人录音不能使已提交报名的试听内容悄然改变。只能由申请人、订单所属老板和具备对应权限的本店后台人员读取；不得跨店访问。
6. 上传失败、格式无效、权限失效、报名截止、订单已被选择、本人已报名或队友拒绝时，保留清晰反馈并按实际状态恢复，不以试听界面或本地文件选择冒充已提交。

**现状**：[`users/models.py`](../../services/backend/users/models.py) 有单个 `voice_card`；[`orders/applications.py`](../../services/backend/orders/applications.py) 有订单报名及选人；[`audition/models.py`](../../services/backend/audition/models.py) 另有后台招募邀请和文字报名。当前 [`Auditions.tsx`](../../fronted/provider/src/pages/Auditions.tsx) 的公开试音及音频样本显示待开放。本人多录音库、订单报名录音及其三方权限为新增需求。

## 4. 履约、报单与收益

特殊玩法的老板在进行中原单成功加购后，陪玩可查看与本人相关的新增内容和预计收益；收益沿用主单对应人员的抽成比例及收益归属，跟随主单报单、售后等待和收益冻结条件结算。加购付款不表示收益立即到账；规则和可见范围见[特殊玩法加购](31-特殊玩法订单加购.md)。

- 接到订单后查看服务、老板需求、应负责人员、时间和收益口径。开始服务提交入队截图；完成服务提交结单截图；随后关联本人实际履约份额，补充至少一张战绩截图并提交报单。
- 后台可审核通过或驳回并写原因；陪玩按允许的状态补充材料、撤回或重新提交。双陪和转单中，各自只操作本人份额，不代替队友完成或报单。
- 订单完成、报单通过、售后窗口结束、收益结算、冻结释放和可提现是不同事实。订单、报单、钱包与流水必须分别回读；低星售后只暂缓受影响陪玩尚未结算的收益，其他条件仍然适用。
- 普通订单的售后等待从整单完成开始，服务中协商终止则从老板与受影响陪玩确认终止时开始；收益冻结从本人最后一次有效报单提交开始。转出的旧份额在整单完成前不能结算，整单完成后再按对应条件等待。双陪中 A 协商终止、B 继续履约时，即使 A 的等待时间和审核均已满足，也须等整单完成才能结算 A；整单完成不重置 A 已开始的售后等待。两段默认各 72 小时，各门店可分别配置，已付款订单保存付款时两项时限快照并重叠计算，后续配置变更只影响新订单。驳回修改并重新提交后按本人最后有效提交重新计算冻结时间。整单完成后双陪分别计时，售后等待到期、本人冻结到期且审核通过及其他结算条件满足时分别释放，不因另一人冻结尚未到期而一律等待；已在售后期内建立并仍处理中者按影响范围阻断对应收益释放。
- 收益、礼物、奖励、罚款、押金抵扣、平台补贴、退单冲正及冻结／解冻分别显示真实来源。对预计、已入账、已退回和待核对状态不混用。
- 礼物无需陪玩报单，但礼物收益从支付时起同时等待本店售后时限和收益冻结时限；两段均到期且无未结售后、其他条件满足后才释放为可提现余额。老板的礼物 VIP 成长在支付成功时立即处理，不等待收益释放。
- 双陪中老板只对 A 提起售后且 B 的服务与收益不受影响时，B 只查看自己的订单与收益状态，不查看 A 的售后详情；A 与获授权本店后台按权限查看。服务端、实时消息和相关附件须按受影响人校验，不能只在页面隐藏。
- 同一单笔续单符合[续单奖励规则](06-积分薪资经营.md#5-续单奖励)时，结算后每位符合条件陪玩入账人民币 5 元等值店币；有转单或发奖前退款不发奖励，发奖后退款不追回。

## 5. 钱包、积分和提现

1. 陪玩查看本人可用余额、冻结金额、押金、收益和流水；微信、支付宝、银行卡各可保存一个收款账户，申请提现时保存独立收款资料快照，后续改账户不改历史申请。
2. 购买陪玩通行证时，可按本店现行兑换比例自愿选择积分抵扣；服务端给出积分消耗、折算店币和剩余应付，并保存交易快照。[积分规则](06-积分薪资经营.md#1-积分抵扣店币)适用于获准的本店老板服务订单和陪玩通行证。
3. 提现前显示申请金额、扣除规则、预计实际打款人民币、收款账户和当前可用余额。本店分别配置单笔最低申请金额及可用余额门槛，申请须同时满足：**可用余额严格大于余额门槛，申请金额达到单笔最低额，扣除并取整后的预计实际打款大于零**。否则提示调整金额或核对费率。提交后先冻结申请金额，不得重复消费或提现；此时尚未记为实际提现支出。
4. 门店客服初审，平台财务终审并实际线下打款；财务登记打款成功后，系统才消耗冻结并将该笔钱包流水记为成功支出。客服初审前陪玩可本人取消并解冻；初审后由工作人员确认尚未打款后取消并解冻。付款结果不明时先核对，不能盲目取消；驳回时也按已确认的未付款规则解冻。
5. 陪玩端至少区分待客服审核、待平台财务处理、已打款和已驳回／退回；平台不能确认真实打款时显示待核对，不能提示已到账或重复打款。

用户确认新购通行证在支付成功后立即自动激活，每张自激活起生效 **24 小时**；生效期间不可升级，也不能购买任何等级的通行证，必须等当前通行证到期后再买，因此今后不能提前续费或形成新的待生效队列。购买成功会形成陪玩钱包支出、购买记录及所属门店业务库内的平台钱包收入，三者应可关联；价格变化或网络结果不明时重新核对，不能重复扣款。新增积分抵扣时须同时记录实际店币与积分，不能把原价全部记成实际店币收入。[代码入口](../../services/backend/users/views.py)。实施进度以[开发进度](../development/16-开发进度.md)为准。

**历史待生效通行证的退款与时段**：

> 以下为过往方案的追溯记录。按当前首版空库部署要求，不承接旧购买记录，也不以历史待生效退款和顺延作为首版交付或验收要求；首版通行证以本节上方“支付后立即激活”的规则为准。

1. 针对新规则生效前已经购买但**尚未生效**的历史通行证，陪玩可在本人购买记录中申请退款；系统以服务端时间和当前有效计划核验，满足条件后自动全额退款，无需客服审核。生效时间已到或已经生效的购买不退款；退款成功以实际账务结果为准。新规则下购买成功即激活，不再新建待生效购买。
2. 原购买使用积分时，按原支付构成全额退回实际支付的本店店币和全部使用积分；未使用积分则退回实际支付店币。门店对应通行证收入和退款流水须关联原购买及原支付，不能按退款时的新积分汇率重算，也不能重复退款。
3. 已退款购买不再提供权益。若其后还有未生效的通行证，按购买顺序依次提前，衔接前一笔仍有效的通行证，保持连续；不改变已生效时间、其他购买的支付金额或已使用积分。保存首次购买计划及每次时段调整记录，并同步当前到期时间及订单池可见延迟。
