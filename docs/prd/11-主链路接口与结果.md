# 订单与资金主链路：接口、角色及业务结果

本页对已经静态阅读的关键入口建立产品到源码的追踪。接口路径和当前处理器是现状；“本轮目标”是待实施需求。仅靠路由、页面或单元测试名称不能认定三端联调通过。

## 1. 登录与门店

| 使用场景 | 当前入口及代码 | 当前可证实行为 | 本轮目标／需核对 |
| --- | --- | --- | --- |
| 老板网页登录 | [`users/urls.py`](../../services/backend/users/urls.py) 的 `web-login/*`、`h5-login/*`；[`boss/login.tsx`](../../fronted/boss/src/business/login.tsx) | 有微信授权流程；当前老板页面有密码＋短信表单，扫码按钮待开发。 | 密码＋短信或已绑定 OTP 默认验证器并可切短信；已绑微信可扫码或快捷登录；新老板可自行填写手机号并短信验证，真实微信扫码另验。 |
| 陪玩登录与微信绑定 | `users/password-login/`、`h5-login/start/` 等；[`h5_login.py`](../../services/backend/users/h5_login.py) | 已有陪玩账号密码／短信和 H5 微信身份绑定；绑定授权使用 `snsapi_base`。 | 同样支持短信／OTP 与已绑微信登录；正式接单前须绑定本人微信，新入驻者首次接单前须真实取得微信头像，之后可上传更换。已绑定存量陪玩可保留历史头像，不伪造微信获取事实。 |
| 后台登录 | `admin/auth/password-login`、后台微信授权；[`admin_entry.py`](../../services/backend/stores/admin_entry.py) | 当前按有效账号识别门店，密码路径使用短信且首次强制绑定微信；同名身份需要消歧。 | 未绑定 OTP 用短信、已绑定默认验证器并可切短信；未绑定微信也可先登录，绑定后可微信快捷登录；核对平台和单店身份边界。 |
| 门店查询与管理 | `stores/current/`、`stores/manage/`；[`stores/views.py`](../../services/backend/stores/views.py) | 已有门店目录、当前店读取和平台授权管理入口；创建时携带首位管理员可触发预配置数据库的建库与初始化。 | 超管默认多库聚合、平台财务授权、完整开店配置及 `SL`／`XA` 展示仍须补齐或核验；不能把已存在的受限建库调用当作完整验收通过。 |

## 2. 老板购买到陪玩接单

| 步骤 | 现有接口／处理器 | 需要核对的输入、权限及结果 | 本轮影响 |
| --- | --- | --- | --- |
| 服务与陪玩 | `GET /api/orders/services/`、`GET /api/users/escorts/` 等。 | 当前店、上架状态、服务资格、可见资料；非本人私有信息不返回。 | 老板端统一门店前缀和微信／上传头像；未绑定微信或新入驻且首次未真实取得微信头像者不能新接单，已绑定存量陪玩按兼容规则保留历史头像。 |
| 试算 | `POST /api/orders/quote/` → `OrderQuoteView`。 | 服务、数量、券、陪玩、会员、活动和当前价格；后端返回报价。 | 增加本店积分比例、上限、可用积分、抵扣金额与实际支付，配置变化重新核对。 |
| 下单 | `POST /api/orders/create/` → `CreateOrderView`。 | 老板本人和本店、预期金额、服务状态、钱包、券、请求标识；提交后生成订单和资金事实。 | 积分余额及店币消费一起核对；保存折扣前后、积分和门店承担额，不允许积分造成店币实付为零。 |
| 赠送礼物 | `/api/orders/gifts/context/`、`gifts/send/`；[`gifts.py`](../../services/backend/orders/gifts.py)。 | 目标陪玩、本人及本店、礼物价格、来源订单和现有结算规则。 | 礼物只能用本金，不使用赠送、赔付或积分；前端和服务端一致校验，收入等待售后和冻结条件后释放。 |
| 体验套餐 | 共享报价和下单入口；[`purchase_benefits.py`](../../services/backend/orders/purchase_benefits.py)。 | 体验专价、资格类型、平台、单陪单份主套餐及资格券；普通优惠活动不适用。 | 体验套餐暂不支持积分抵扣；不以积分新功能改变原有资格及退款规则。 |
| 结果不明 | `/api/orders/create/resolve/` → `ResolveOrderRequestView`。 | 按原业务请求检查结果，避免超时后重复扣款。 | 需要同时核对订单、店币、积分、补贴和门店范围；原请求不能重复创建。 |
| 公开抢单／报名 | `POST /api/orders/orders/{id}/grab/` → `GrabOrderView`。 | 本店陪玩、公开路线、支付状态、资格、容量和并发；当前实现中老板选人模式从此入口转入 `ApplyOrderView`，普通直接抢单是先到先得。 | 普通新单和客服安排新单须改为门店窗口内收集候选、按用户确定指标排序后分配；提交时通行证等级留快照，开始履约后才把原价份额纳入近 30 天接单额。招募试音为每位报名成员保存并校验录音，微信绑定与头像条件贯穿抢单和报名。 |
| 组队／老板选人 | `applications/{application_id}/action/`、`select/` → [`applications.py`](../../services/backend/orders/applications.py)。 | 队友本人确认、申请未撤回、订单未超时；只有下单老板选择本单申请。 | 试音队伍每人提交本人音频；选择前再次验证资格、人数、录音及归属。 |
| 客服安排与转单 | `/api/admin/orders/` 对应旧 `assign`、`transfer` 等动作；[`console/views.py`](../../services/backend/console/views.py)。 | 本店获授权人员、服务及账号资格、容量、当前订单状态和份额；转单保留事实和分账。 | 客服安排的新单也进抢单池，旧 `assign` 不能绕过自动分配；已接单协调改派时，转入者按本人接入时配置生成本人份额快照，旧份额不重算。拒绝未绑定人员的新接单；本次续单发生转单时取消该续单奖励。 |

## 3. 履约、报单、退款与评价

| 步骤 | 现有接口／处理器 | 需要核对的结果 | 本轮影响 |
| --- | --- | --- | --- |
| 开始／完成服务 | `/api/orders/orders/{id}/start/`、`complete/`。 | 陪玩本人及对应份额、订单当前状态、入队／结单凭证；订单状态和审核分开。 | 允许已接订单继续完成，不因为后续绑定或押金规则变化删除事实。 |
| 特殊玩法订单房间 | `/api/orders/orders/{id}/room/`、`room/completion-requests/`、`room/objections/`；后台 `/api/admin/room-completion-requests/` 及核实接口。 | 订单、门店、已安排参与者、房间状态、异议和确认时限；本人及授权后台才能读取或操作。新单付款前须配置本店房间确认时限，房间结单流程关闭时不得发起新单。 | 付款且所需人员安排后自动开房；陪玩提交、客服核实、老板确认或无异议超时自动确认，按本店配置处理异议暂停／恢复及转单。具体九种旧玩法本期不接入，详情见[房间专项](32-特殊玩法订单房间.md)。 |
| 特殊玩法加购 | 当前附加项目由 [`gameplay.py`](../../services/backend/orders/gameplay.py) 阻止普通购买，服务详情链接客服；未发现完整的主单自助加购资金接口。 | 进行中的本店本人主单、玩法条件、所选小时／局或其他适用数量、服务端单价、本店钱包及唯一请求。 | 按加购价付款，不使用折扣、券或积分；瓦罗兰特四项加收及其他适用项目按各自规则配置。关联付款、实际负责陪玩快照、退款及统计，详情见[加购专项](31-特殊玩法订单加购.md)。 |
| 报单及审核 | `/api/wallet/reports/`、报告图片和 `submit/`；后台 `reports` 的 `approve`／`reject`。 | 订单、陪玩、三类凭证、报单版本、审核意见和实际结算。 | 积分抵扣前分成须与报单金额、补贴及约束兼容；双陪和转单逐份额核对。 |
| 售后 | `/api/orders/orders/{id}/aftersale/`；后台 `aftersales` 的 `resolve`／`refund`。 | 老板本人、本店订单、工单状态与允许动作；售后不自动代表已退款。 | 售后期内四项低星创建／关联；期后仅记录低星提醒，不新建售后或退款；期内已建立工单继续处理。双陪只暂缓受影响的未结算份额，保留历史。 |
| 退款预览及提交 | 后台 `orders` 的 `refund-preview`、`refund`、协商退款动作；[`refunds.py`](../../services/backend/orders/refunds.py)。 | 真实可退额、原支付、成功分账、可追回额、券／权益及原请求；不超额或重复。 | 店币按本金→赠送→赔付返还，已发消费积分按退回本金冲回；已发推荐佣金不追回、本店承担；向下取整、最终补齐，收入与经营指标相应对账。 |
| 评价与回复 | `POST /api/orders/evaluate/`、`evaluations/{id}/reply/`。 | 本人订单、评价对象和原状态；陪玩只能回复获准的本人评价。 | 老板四项评分分别主动选择并由服务端检查；低星和售后事实一致。 |
| 续单及奖励 | 现有 `Order.source_order` 在赠礼使用，未见可直接复用的续单事实。 | 目前没有可把礼物来源直接当续单的依据。 | 增加客服核实的原单／续单关系和奖励追踪；严格按成交额、转单、退款和结算判断。 |

## 4. 钱包、积分和提现

| 步骤 | 现有接口／处理器 | 需要核对的结果 | 本轮影响 |
| --- | --- | --- | --- |
| 钱包查询 | `GET /api/wallet/info/`、`transactions/` 等。 | 本人本店余额、冻结及来源，待处理和成功分开。 | 新积分抵扣、续单奖励、提现两级审核及财务付款状态须可追踪。 |
| 充值与调账 | 后台 `wallets` 的 `recharge`、`adjust` 等动作。 | 本店授权、真实收款凭证、赠送与本金、唯一请求、前后余额及审计。 | 老板才可充值；陪玩只有授权调账。赠送金额修改须本店管理员 OA，按批准／驳回结果入账；不将本金当订单收入。 |
| 积分商品兑换 | `/api/club/points/`、`redeem/`、`claims/`。 | 同店本人积分、商品、库存、条款、事件标识及结果。 | 禁止直接将积分兑换为钱包余额；其他原有商品和积分抽奖保留，旧记录不改。 |
| 同店多场抽奖 | `GET /api/club/lottery/campaigns/?page_size=20&before=<上页next>`，`GET /api/club/lottery/?campaign_id=<活动ID>`，`POST /api/club/lottery/`。 | 列表仅返回当前门店已启用、已开始且未结束的活动，分页的 `next` 为空表示末页；详情与抽奖使用所选活动的奖池、次数和保底。原不带活动编号的详情返回最新开放活动。 | 仅老板本人可访问；草稿、未开始或已结束活动不出现在可选列表，调用不跨门店。已获奖品和交易重试仍按原记录处理。 |
| 购买通行证 | `/api/users/provider-pass/` → `ProviderPassView`。 | 当前每次购买 1 天；有效期内仅续同档并顺延，陪玩支出、门店库平台钱包收入和购买记录对应。 | 新购支付成功即激活 24 小时，有效期内不得买任何等级；允许按本店规则积分抵扣，收入不能把抵扣当实付店币。历史已购未生效通行证本人申请自动全退，后续历史购买按顺序提前；生效后不退。 |
| 收款账户 | `/api/wallet/withdraw-accounts/`。 | 微信、支付宝、银行卡各一条；按本人和版本读写。 | 保留提现申请时快照；后续改账户不能改历史付款记录。 |
| 提现申请 | `/api/wallet/withdraw/` → `WithdrawView`。 | 余额、扣除规则、账户版本、请求标识；当前已冻结并生成待处理流水。 | 保留冻结但不记成功支出，进入本店客服初审。 |
| 后台提现 | 后台 `withdrawals` 的 `claim`、`approve`、`reject`、`release-claim`。 | 当前同一审核权限含领取、付款凭证与最终记账；驳回返还冻结。 | 拆分店内客服初审和平台财务终审／实际付款；跨店财务须保留店标识和付款待核对恢复。 |
| 薪资与成本 | `admin/payroll/config/`、`preview/`、`confirm/`、`salary-*`、`operating-roi/`。 | 方案、员工安排、真实业绩归属、月度快照与缺项；工资核算不自动打款。 | 平台超级管理员和平台财务按店核算，平台财务本人作为平台公共成本单列。 |

## 5. 读写联动与实际证据

- 下单、履约、售后、退款、积分、报单和提现更新后，相关端读取持久状态；[`orders/routing.py`](../../services/backend/orders/routing.py) 和通知模块提供实时通道，但消息不代替账务事务。
- 预存、会员、客服咨询与排行榜等新确认规则已分别展开在[门店配置](12-系统字典与门店初始化.md)、[活动会员](13-活动会员与优惠.md)、[咨询消息](15-咨询消息与通知.md)及[运营小功能](16-签到抽奖权益与其他功能.md)；需同步核对这些模块的真实接口及跨端结果。
- 订单、钱包、积分、报单、提现与通知的当前接口清单见[后端接口清单](09-后端接口清单.md)；逐页操作清单见[页面追踪](08-页面接口追踪.md)。
- 以上为本轮静态核对的关键主线，不表示每个历史页面、每种分支、真实微信／短信、实际打款或所有异常已完成本轮端到端验证；后续按[验收场景](07-差距待决与验收.md)逐项补证。
