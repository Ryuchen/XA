# 管理端功能核对

后续更新：2026-09-10 新增通行证管理，后台现为 30 个菜单；跨端闭环修复见 [BUSINESS_CLOSURE.md](BUSINESS_CLOSURE.md)，凭证见 [INTEGRATION_CREDENTIALS.md](INTEGRATION_CREDENTIALS.md)。下文保留 2026-09-09 的验收记录。

核对日期：2026-09-09。已核对当前路由中的全部 29 个菜单，结合页面检查、真实业务 JWT 接口回归、配置增改查删和资金联动修复发现的缺口。此结果是本地功能验收；真实群消息、企业微信接待和正式小程序发布仍需对应的生产配置与实机验收。

## 已复现并修复

- 平台概览缺少 `dashboard:view` 校验；成交额原先包含未付/退款订单，现按已支付订单汇总。
- 陪玩概览把双陪/转单全部归入主打手，现按成员的分账基数和收益快照汇总，保留转出但仍应得的份额；日期参数增加有效性及先后校验。
- 老板编号筛选引用不存在的字段并报错，现使用业务编号；更新昵称、手机号后同步旧业务关系，使钱包等列表能检索到新资料。
- 老板编辑页提供后端禁止修改的账户开关，并误称报单后才扣老板余额。现展示真实扣款规则，封禁/解封通过专用流程操作。
- 老板、陪玩列表新增封禁记录及带原因、期限的封禁/解封入口；陪玩在途订单拦截和强制处理权限沿用后端规则。
- 陪玩编辑页不再直接修改已缴押金，新增退回钱包入口，包含原因和请求防重，沿用已有押金流水流程。
- 跨菜单表单曾要求额外取得整套用户、商品、等级或角色管理权限。新增仅返回选项字段的接口，按实际使用场景授权，原管理接口权限不放宽。
- 字典选项改为逐页读取，避免服务端每页上限 100 导致后续选项消失；派单老板搜索支持编号、昵称、账号和手机号。
- 通用表格避免旧请求覆盖新筛选结果，加载失败提供重试；删除末页末条后恢复可用页码。
- 没有平台概览权限的客服，默认进入其第一个可访问菜单；按钮判断使用服务端实际权限集。
- 钱包和充值记录统一使用业务老板编号，修复新注册用户在资料页与钱包页编号不一致、跨菜单搜不到的问题；充值表单优先传业务账户 ID。
- 调账必须填写原因，并接入请求防重、金额范围与钱包状态校验；老板钱包入口不能通过替换 ID 操作其他类型钱包。派单扣款和后台退款流水补齐实际客服身份。
- 提现列表、详情和人工打款确认提示增加人民币应打款金额，保留税额、收款人、收款账号与凭证编号核对。
- 优惠券增加领取记录、领取人、核销订单及过期筛选；拒绝零面额与少于已领数的库存，已领取模板只能停用，不能删除领用记录。
- 客服会话增加分页加载，避免第一页以外的会话不可访问；处理切换会话时的异步响应串会话、只读账号标记已读权限错误，并校验回复长度和图片。
- 站内消息增加完整内容详情，指定接收人改为搜索业务账号；校验消息类型和全部收件人，避免部分目标无效却仍给其他人推送。
- 角色权限只接受已注册的权限标识；内置超级管理员角色不可停用、改标识、删权限或删除。客服资料在所有输入校验通过后再保存，避免无效角色导致部分资料已写入。
- 活动的分类/商品范围必须有对应目标；轮播要求有效尺寸图片和有效跳转目标，后台直接选择商品/公告，外链需 HTTPS。
- 消费成就的目标值按兴安币显示和输入，修复内部账务值直接显示造成的十倍差异。
- 已有试音报名的招募链接保留审核记录，通过停用停止报名。签到页区分站内全勤资格和客服在 KOOK 发放身份标签，避免把资格记录当作外部发放结果。
- 构建时停止改写开发服务正在维护的自动类型声明，解决 Windows 下开发预览和生产构建同时写文件导致的构建错误。
