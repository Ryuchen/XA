# 游戏类目与陪玩技能三端联动验收

日期：2026-09-24。范围为老板原生微信小程序、陪玩 H5、运营管理端及共用 Django API；在现有工作区改动基础上完成，未部署生产环境。

## 业务规则

- 游戏 → 服务项目 → 陪玩服务技能使用同一组关联。后台新增或编辑陪玩技能时自动补齐所属游戏；陪玩自行保存后，后台档案和老板选人使用相同数据。
- 游戏、服务分类、玩法或服务自身停用，均阻止相关新服务展示和报价。收藏、服务详情、规格、玩法价格及技能候选项采用统一可见性规则；历史订单保留。
- 礼物、附加收费项、无游戏归属的旧服务不作为新增技能。已关联的停用技能可留存在后台档案；陪玩端明确提示移除失效项后再保存，不静默丢失数据。
- 具体游戏服务的选人、指定下单、后台派单、抢单统一校验服务技能，同时保留认证、押金、档期、等级等既有准入要求。无游戏归属的历史服务继续使用原有准入规则。
- 服务调整所属游戏时，同步关联陪玩的游戏范围；旧游戏下仍有其他技能则保留关联。有服务或陪玩关联的游戏不能直接删除，可以停用。
- 带文件上传的陪玩编辑表单可以正确清空游戏与技能数组；无效技能提交不会部分修改档案。

## 展示调整

- 管理端游玩项目页增加游戏概览、可见服务数和陪玩数，点击类目可筛选服务；分类配置中说明停用效果。
- 陪玩管理将头像、昵称、等级和游戏/技能范围放到主要阅读区，提供游戏筛选。服务选择器按游戏分组，展示平台、难度、价格和单位，区分同名套餐；次要操作收进“更多”。
- 陪玩技能页增加游戏切换、名称搜索、平台/难度筛选、只看已选与分批展示。显示保存状态、失效项目和重试入口，拦截重复提交与误清空。
- 陪玩技能页复用既有主题令牌，桌面双列、手机单列；修正字体尺寸、按钮宽度和双重滚动。老板小程序陪玩列表补充可接游戏标签。

## 上线前事项与现有限制

- 对于以前只配置游戏、没有具体服务技能的陪玩，需要由运营补齐服务技能，否则无法接取对应游戏服务的新订单。不能根据游戏名称自动赋予全部套餐能力。
- 本轮未在微信真机上验证，也未执行生产发布；原生检查为编译器和逻辑回归。
- 仓库现有 `style:check` 仍报告 3 处非本次改动的金额展示规范问题：`apps/admin-web/src/views/engagement/index.vue:85`、`:86` 和 `apps/admin-web/src/views/wallet/index.vue:271`。

## 后续手工验收路径

1. 管理端“游玩项目”检查游戏启停、服务归属、排序和统计。
2. “陪玩管理”编辑一名验收陪玩，选择具体服务，保存后核对自动关联的游戏。
3. 陪玩端“我的技能”核对同一服务，修改并保存；后台刷新核对结果。
4. 老板小程序进入相应游戏服务，检查符合技能和等级的陪玩可被选择；停用游戏后确认新服务入口消失。
