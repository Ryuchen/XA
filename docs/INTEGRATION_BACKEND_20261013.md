## 已修复的接口缺陷

1. 后台报单仅返回比例，固定抽取报单会显示为 0%。两端报单增加 `commission_type` 与 `commission_fixed`，金额为内部账务整数；优先读取本人的订单分账快照。
2. 历史无关联订单报单的预计收益忽略报单已填写的非零抽成比例，而审核采用该比例。预计与审核现在共同读取 `wallet/reporting.py` 的原有优先级：报单填写 → 有效陪玩等级 → 全局配置。
3. 已通过报单的预计金额重新读取订单金额，可能与已保存审核事实不同。现在读取 `payout_amount` 审核快照，保留已审核的零抽成比例，不按后续配置重新计算。
4. 财务字段共用一次快照解析，复用预取的成员明细；新增零额外查询检查，避免每个字段重复查询。

新增回归为 `services/backend/console/test_report_financial_snapshot.py`，包含固定金额、历史填写优先级与实际审核一致、零比例已审核快照、关联订单历史实得及查询次数。报单快照修复未修改分账、收费、冻结期限或退款规则。

实际 Daphne 联调还发现：COMPLETED 通知中的售后截止时间为原生 datetime，直接传消息通道及 `json.dumps` 会使已打开的 WebSocket 出错。通知现先使用与 HTTP 相同的 DRF JSONRenderer 规范化数据。新增真实订单序列化到消费者的回归；22 项通知/实时授权专项通过，实际完整 COMPLETED 推送和后续 pong 复验通过。
