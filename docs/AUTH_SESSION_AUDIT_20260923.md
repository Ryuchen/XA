# H5 登录会话隔离验收

日期：2026-09-23。范围为陪玩 H5 与管理端的请求、刷新凭证、退出登录、重新登录和路由资料加载。沿用现有认证接口与业务权限，没有修改资金规则或数据库。

## 复现的问题

原实现仅合并并发刷新请求，没有校验请求属于哪次登录：

1. A 的刷新请求尚未返回时退出登录，迟到结果仍能把 A 的访问凭证写回。
2. 切换到 B 后，A 的请求返回 401，可触发 B 的刷新或清除 B 的登录；A 的成功响应也可能被页面采用。
3. 刷新遇到网络中断或 503 会被当成登录过期，强制退出。
4. 陪玩新登录未返回刷新凭证时，会残留前一次登录的刷新凭证；认证变化事件早于用户资料完整保存。
5. 管理端路由读取个人资料失败会无条件清除登录；登录与刷新接口还会携带旧访问凭证。

新增的首批 30 项确定性交错检查，在修改前 **2 项通过、28 项失败**，修改后全部通过。后续增加重试失败、登录请求头、路由与上传边界，专项共 40 项。

## 修复后的行为

- 登录或退出改变会话版本；请求发送、凭证写回、响应交付、资料保存和重试都验证该版本。旧会话的结果以 `SESSION_CHANGED` 拒绝，不清除或覆盖新会话。
- 同一次登录的并发 401 共用一次刷新；较晚到达的 401 复用已更新的访问凭证。不同登录各自刷新，旧 Promise 的清理不干扰新登录。
- 明确的刷新 401、没有刷新凭证或重试仍为 401 时结束登录；网络故障、限流及服务端临时错误保留登录，操作仍返回失败供用户重试。
- 新登录优先于更早开始但后返回的登录请求。陪玩登录先完整保存凭证及用户再发变化事件，未返回刷新凭证时删除旧值。
- 管理端登录和刷新不附带旧访问凭证，避免认证层在进入对应视图前拒绝请求。资料读取失败由请求层区分认证失效，路由不再无条件退出。
- 上传响应同样受会话版本约束；一次认证失败后的上传重试保留文件与表单参数。陪玩登录成功和过期跳转的延迟回调在执行前再次检查会话。

已发送到服务器的业务操作可能已经提交，本次修改不会撤销它；它只阻止旧结果影响新登录。资金请求的幂等与结果恢复仍由既有业务实现负责。
