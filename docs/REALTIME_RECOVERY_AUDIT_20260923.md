# 三端实时连接恢复验收

日期：2026-09-23。范围为老板原生小程序、陪玩 H5、管理端以及本机双 Web 网关；未向外部频道发消息。

## 修改与原因

- 管理端和陪玩端连接现在按当前登录凭证复用，避免页面切换、重复连接或迟到的异步 SocketTask 创建第二条连接。旧连接的关闭、错误和消息回调不能干扰新连接。
- 三端均增加连接建立期限和心跳应答期限。连接假在线或服务停止后会关闭失效连接，并退避重连；重连读取当前凭证，通过现有 HTTP 认证链路处理凭证刷新。
- 陪玩与管理端在连接恢复时重新读取订单、统计和客服消息。原生端保留并加固原有恢复后刷新。Redis 实时通知不会补发离线期间的全部历史事件，因此以 HTTP 持久数据重新校准页面。
- 管理端聊天恢复时保留未发送草稿，并隔离旧会话的迟到请求。退出登录关闭连接与计时器，原生应用隐藏后停止连接。
- 网关增加被动故障剔除与有限重试。已建立上游连接后发生传输故障时，仅 GET/HEAD 可以重试；尚未建立连接的失败可改连其他实例。没有添加付款、充值、提现等 POST 的自动重放，业务幂等仍由原有后端负责。

网关配置依据 [Caddy reverse_proxy 文档](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)，本机和发布模板保持一致。

## 回归和部署

新增 `scripts/test-realtime-clients.cjs`，15 项覆盖连接去重、旧回调隔离、错误/关闭合并、凭证变化、心跳超时与回复、退出登录、迟到任务、原生隐藏停止重连。首次对旧 H5 实现执行的 13 项中 11 项失败；修复后 15 项全部通过。

与推送合并、原生核心回归一起运行共 **49 项通过、0 失败**。管理端与陪玩端类型检查通过；原生结构及 JS 检查通过，官方编译器验证 **41 个 WXML 模板、42 个 WXSS 文件**。H5 镜像已在 WSL 重建部署。

实际 Redis → 网关 → 陪玩浏览器的推送合并复验：25 次公共通知触发 1 次列表读取、0 次个人统计读取；25 次个人通知触发 1 次列表读取、1 次统计读取。

## 实际停机恢复演练

在已校验 Compose 项目和服务标签的 `xa-local-validation-web-1/2` 上执行。浏览器分别打开管理端订单、管理端聊天、陪玩“已接单”；微信开发者工具打开原生订单页。

| 场景 | 最新完整演练结果 |
| --- | --- |
| 停止其中一个 Web 实例，持续经实际网关读接口 | 57 次请求，0 错误，最长 144 ms |
| 停止两个 Web，保持中断后重新启动 | 登录未被清除；三端连接恢复并完成 HTTP 数据同步 |
| 从启动命令发起至全部恢复条件满足 | 22,089 ms，包含容器启动与客户端退避等待 |
| 管理端聊天 | 已选会话重新读取，未发送草稿保持一致 |
| H5 连接数与异常 | 每个页面实例 1 条活跃连接，0 个未捕获脚本异常 |
| 管理端与陪玩端退出登录 | 连接关闭，继续观察 4 秒未新建连接 |

首次较小演练在 4,678 ms 内恢复；扩展到独立聊天页、草稿和退出检查后的最新完整结果为上表。退避重连和本机调度会影响时间，不把单次结果当作恢复 SLA。

两次扩展演练的早期失败来自测试定位（会话上下文及 Taro 标签被图标覆盖），修正为对应真实可点击容器后完整通过；没有绕过页面业务动作。演练的 `finally` 保证重新启动已校验的两个本地 Web 容器。
