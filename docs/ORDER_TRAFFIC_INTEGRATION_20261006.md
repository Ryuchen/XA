# 订单峰谷限流、自主下单与抢单网络监控验收

日期：2026-10-06。范围为当前工作区，本轮未部署线上、未产生真实支付或对外派单消息。

## 功能入口

- 老板原生端：首页 → 自主下单 → 老板选人 / 直接抢单 → 商品目录 → 报价与余额支付 → 订单详情。旧 selfOrder 分享链接转到新的 self-order 页面。直接进入商品结算也能选择接单方式。
- 陪玩端：订单 → 抢单池顶部查看平均往返耗时、P95、相邻请求耗时变化的平均值（抖动）、网络失败率、服务错误和限流倒计时。网络失败后可跳到已接单核对结果。
- 管理端：订单管理 → 峰谷限流与监控。查看需要 order:view；保存需要新增权限 order:traffic，角色权限页可分配。可修改峰谷时段、三套配额以及自主下单开关；配置版本冲突返回 409。

## 峰谷限流

北京时间默认波峰为 18:00–24:00，波谷为 00:00–08:00，其余为常规；支持跨午夜时段，禁止峰谷重叠。默认配额是起始配置，应结合真实流量调整。

| 时段 | 操作 | 每账号/分钟 | 全站/分钟 | 全站/秒 |
| --- | --- | ---: | ---: | ---: |
| 波谷 | 下单 / 抢单 / 刷新 / 报价 | 12 / 30 / 30 / 60 | 120 / 300 / 600 / 1200 | 12 / 30 / 60 / 120 |
| 常规 | 下单 / 抢单 / 刷新 / 报价 | 10 / 24 / 24 / 45 | 240 / 600 / 1200 / 2400 | 24 / 60 / 120 / 240 |
| 波峰 | 下单 / 抢单 / 刷新 / 报价 | 6 / 18 / 18 / 30 | 300 / 900 / 1800 / 3600 | 30 / 90 / 180 / 360 |

采用原子 add / INCR 固定窗口计数，账号配额先于全站计数；秒级全站配额限制瞬时突发。拒绝尝试也消耗所经过的窗口额度，配置或时段变更不会清空当前计数。限流返回 HTTP 429、errorCode、retry_after 和 Retry-After，客户端冷却时不继续发送同类请求。报价、刷新、下单和抢单各自使用配额；取消退款和履约继续使用原有准入规则。

原有写操作限流也改为按 ClubAccount 计数，匿名登录仍按 IP。缓存故障使新交易返回 503，并在资金扣减前停止。

生产默认共用 Redis DB 3，可通过 DJANGO_CACHE_URL 覆盖；Compose 的后端、Worker、Beat 和迁移容器使用同一地址。缓存连接与请求超时各 2 秒。开发单进程可用内存缓存。迁移文件为 orders/0045_ordertrafficconfig.py。

## 下单、履约和资金闭环

创建订单新增 dispatch_mode：BOSS_SELECT 为兼容默认值，陪玩申请后由老板选择；AUTO_GRAB 为单人直接抢单，保留资格、通行证可见延迟、名额锁和订单行锁。指定陪玩仍使用原流程，多人商品不能进入直接抢单模式。

报价和创建复用服务端计价，扣款保留资金请求幂等键；网络结果丢失可恢复原订单。原生与两套 Taro 资金请求在 429 后保留原交易编号。完成服务只形成报单，审核通过后才结算；取消退回余额，不重复扣款或退款。

## 监控口径

客户端保留最近一分钟、最多 60 个样本；只统计抢单及订单池请求。HTTP 429 和 5xx 与网络连接失败分开记录，401 刷新和其他业务请求不混入。账号切换清空样本及冷却，超过 30 秒无新样本显示等待采样。

监控是请求往返耗时，包含服务端处理时间；网络失败率并非底层网络丢包率。每分钟批量上报未确认的新样本，后台查看最近 15 分钟的放行、限流与上报汇总。上报数据校验范围、限制频率，不含游戏账号、令牌或订单详情，不参与接单资格和排序。
