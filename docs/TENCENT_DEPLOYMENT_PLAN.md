# 兴安电竞 · 腾讯云部署方案

2026-09-28 已按用户提供的现有主机完成实际部署；资源规格不同于本文采购建议。现状与验收以 [腾讯云部署记录](TENCENT_DEPLOYMENT_20260928.md) 为准，本文保留为架构和后续容量规划。

更新：2026-09-23。状态：部署设计与采购规格建议；尚未购买资源、修改 DNS 或执行远程部署。

## 1. 已确认条件与建议结论

用户已确认：腾讯云，主域名 `xaesports.club`；约 1000 名老板、200 名陪玩；高峰同时在线约 100 名老板及 50–60 名陪玩。月预算、主要用户地域、域名备案状态和云账号内资源尚未确认。

**建议首发采用一台 CVM 应用服务器 + 独立腾讯云 MySQL 双节点实例 + COS 私有备份。** 保留现有 Django、原生微信小程序、两端 H5、Docker Compose、Caddy、Celery 和 Redis。无需为三个入口各购买一台服务器。

这是根据现有业务结构作出的工程建议，在线人数不等于每秒请求数。下列规格是压测起点，不能据此宣称已承载 160 人或保证业务高可用。首发应用与 Redis 仍是单机，数据库双节点只保护数据库层。

## 2. 采购规格建议

| 资源 | 建议起步规格 | 作用及边界 |
| --- | --- | --- |
| CVM 应用服务器 | 1 台通用型非竞价实例，4 核 8 GB，x86_64；Ubuntu 24.04 LTS；50 GB 系统盘 + 100 GB SSD 数据盘 | 运行 API、WebSocket、两个 H5、Worker、唯一 Beat、Redis 与 Caddy；镜像在 CI 构建，不在运营高峰编译 |
| 云数据库 MySQL | 双节点，2 核 4 GB 起、50 GB 存储起；与 CVM 同地域、同 VPC，主备优先不同可用区 | 使用私网连接；仅应用服务器获准访问。具体规格及数据库大版本需在控制台确认支持后选购 |
| 公网网络 | 按流量计费、20 Mbps 峰值作为起测方案，并设置流量与余额告警 | 这是带宽上限建议，不是包月流量额度。图片和语音传输可能比 API 更早碰到带宽限制 |
| COS | 同地域私有存储桶，按量使用；先用于媒体和必要配置的异地备份 | 后续业务文件直存 COS 需要存储适配；当前代码不会因填写一个域名自动变为 COS |
| 云硬盘快照、云监控 | 系统/数据盘快照及 CPU、内存、磁盘、网络告警 | 快照配合数据库备份；不能把运行中的数据库目录打包当成一致性备份 |
| DNS 与 HTTPS | 复用 `xaesports.club`，按下表新增子域名 | 无需购买三个主域名；Caddy 在 DNS/80/443 条件满足后申请和续期证书 |

地域先列上海为候选，最终按主要老板与陪玩所在地的访问时延、价格和产品可用性确定；不根据俱乐部名称推断用户所在地。数据库和 COS 与应用同地域，减少跨地域链路。

Docker 官方支持 Ubuntu 24.04；安装使用官方软件源中的 Docker Engine 与 Compose 插件。[Docker 安装说明](https://docs.docker.com/engine/install/ubuntu/)

腾讯云双节点/多可用区 MySQL 提供备用副本和自动故障转移；应用仍需处理断线重连和资金请求结果恢复。[腾讯云数据库高可用说明](https://cloud.tencent.com/document/product/236/8459)

### 数据库版本不能直接照搬本地

仓库当前容器是 `mysql:8.0`，本地并发证据来自 MySQL 8.0.46。Oracle 已在 2026-04-21 将 MySQL 8.0 转入 Sustaining Support，建议使用 LTS 后续版本；因此不把社区 `mysql:8.0` 作为新购生产环境的长期默认。[Oracle 支持公告](https://www.mysql.com/support/eol-notice.html)

腾讯云公开内核动态已有 MySQL 8.4 条目，但生命周期页仍出现“内测”标记。**先向控制台/厂商确认目标地域的非内测、生产支持版本和支持期限，再购买。** 若 8.4 已正式支持，优先做 8.4 的完整迁移和并发验收；若仅供应商维护的 TXSQL 8.0 满足要求，需要确认其支持期限并记录后续升级路线。不能把 Oracle 社区生命周期与云厂商维护承诺混为一谈，也不能用旧测试证明新内核已兼容。[TXSQL 内核动态](https://intl.cloud.tencent.com/zh/document/product/236/35989)、[腾讯云版本生命周期](https://intl.cloud.tencent.com/zh/document/product/236/80804)

域名所有权由用户提供，备案状态尚未核实。使用中国大陆服务器对外提供服务前，先按实际主体核对备案及微信平台准入。腾讯云备案资源通常要求满足公网与购买时长条件；在腾讯云办理备案的 CVM 要求包年包月累计至少三个月、备案期间剩余至少一个月等，购买前逐项核对。已有其他接入商备案时另核对腾讯云接入备案。[备案资源条件](https://cloud.tencent.com/document/product/243/18908)、[接入备案](https://cloud.tencent.com/document/product/243/37403)

## 4. 应用与数据边界

应用服务器部署 Caddy、Daphne、Celery Worker、一个 Celery Beat、Redis、admin-web 和 provider-h5。业务库放在云 MySQL。Redis 持久化启用，资金与订单事实始终以 MySQL 为准；队列重启、延迟任务与 WebSocket 重连需单独验收。

本地短时负载发现单 Web 进程在推送高峰响应变慢，已将 local-validation 和 release 编排调整为同机两个 Web 实例，由 Caddy 动态 DNS 轮询，共用 MySQL、Redis 与媒体卷；不增加 Beat。最新实时权限策略下 100 老板 + 60 陪玩本地复验 2,936 请求零错误、p95 730 ms；此前 60 人同单争抢仅一人成功，详见 [本地容量验证](LOCAL_CAPACITY_VALIDATION.md)。这不改变下文云端持续时间、RPS 和延迟目标，也不构成跨主机高可用。

公网仅提供 80/443；SSH 限管理来源。MySQL 和 Redis 不开放公网端口。数据库应用账号不使用 root。正式配置保存在服务器环境文件及 CI Secrets；云访问密钥不进入前端、仓库或镜像。

首发文件可继续使用独立数据盘的媒体目录，按计划备份到私有 COS，避免马上更换全部上传链路。需要扩大图片/语音吞吐时，再将业务存储接入 COS：公开头像、封面、展示语音与报单/财务凭证分别管理。后者通过权限检查取得短期访问地址，不能把同一桶全部公开来解决图片显示问题。COS 支持预签名访问，但业务权限判断仍需项目实现。[COS 预签名访问说明](https://cloud.tencent.com/document/product/436/36121)

## 5. 备份、恢复和运行目标

以下是待部署演练验证的建议目标，不是已达到的承诺：

本机 WSL 已完成一次数据库与媒体隔离恢复：67 张表、1,361 条记录和 54 个文件一致，见 [本地部署记录](LOCAL_DEPLOYMENT_VALIDATION.md)。这证明本地备份可恢复；云数据库日志恢复、异地 COS 副本及下列云端 RPO/RTO 仍需单独实测。

| 对象 | 方案 | 建议验收目标 |
| --- | --- | --- |
| 资金与订单库 | 云数据库每日自动全量备份 + 日志/时间点恢复，保留至少 7 天，发布前追加备份 | 资金库 RPO 目标 ≤5 分钟，必须以实际备份/日志及恢复演练测量 |
| 媒体与凭证 | 每小时增量异机备份到私有 COS，每日核对清单和校验值；保留多版本 | 媒体 RPO 目标 ≤1 小时；备份失败告警，不静默覆盖或删除唯一副本 |
| 应用与配置 | 固定提交 SHA 的镜像、部署清单、加密的必要配置副本 | 应用单机故障后恢复服务 RTO 目标 ≤2 小时，需准备替代 CVM 的恢复步骤 |
| 整体恢复 | 在隔离环境恢复数据库和媒体，核对订单、余额、冻结额、分账、提现及凭证 | 上线前完成一次，之后定期演练；高可用副本不能替代误操作恢复 |

腾讯云支持自动备份，并可选跨地域备份；跨地域备份的适用实例、保留期和费用另核对。[数据库备份](https://cloud.tencent.com/document/product/236/35172)、[跨地域备份](https://cloud.tencent.com/document/product/236/73100)

若不能接受应用故障导致的恢复窗口，升级为两台应用服务器 + 负载均衡 + 共享业务文件存储，并重新规划 Redis/调度器；首发方案没有自动达到整站高可用。

## 7. 压测与发布顺序

1. 核对地域、预算、备案与资源规格，确认可购买的数据库正式版本；先准备测试资源和受限测试身份。
2. 配置已有托管数据库编排并完成云备份适配；按实际实例做迁移、恢复、权限和跨端联调。
3. 使用合成数据，禁止触发真实客服打款或外部频道群发；按 160 个同时在线会话测试浏览、服务选择、抢单池、订单及消息刷新。WebSocket 按实际每会话连接数统计，不能只开 160 个空闲连接算通过。
4. 建议压测基线：160 在线会话、混合 API 50 请求/秒持续 30 分钟；再以 300 会话、100 请求/秒持续 10 分钟检验余量。它们是测试目标，尚未执行；具体读写比例按真实流程固定记录。
5. 建议目标：常规 API p95 ≤500 ms、资金写入 p95 ≤1 s，非预期 5xx/超时低于 0.1%；同单 60 名陪玩并发抢单只出现允许数量的赢家；下单、退款、报单结算、提现重复/断网重试不多扣或多入账。业务拒绝与技术错误分开统计。
6. 核对 CPU、内存、数据库连接/锁等待、慢查询、带宽、任务积压；瓶颈先由证据定位，再决定升配、多个 Web 实例或媒体迁移。
7. 完成真实微信、企微客服和 KOOK 测试，再做少量真实运营灰度；保留回滚镜像与数据库变更说明。不要将压测数据和运营钱包混用。

## 8. 成本与采购决策

月成本组成：CVM 计算 + 系统/数据盘 + 公网出流量 + 云 MySQL 计算/存储/超额备份 + COS 存储/请求/流量 + 快照/可选监控。尚无月预算及登录控制台报价，本文不给出伪精确总价，也不把首年活动价当成续费价。

腾讯云按流量和固定带宽是不同计费方式。以公开价目中的上海常规 BGP 为例，5 Mbps 固定带宽为 2×20 + 3×25 = 115 元/月，仅为网络部分；10 Mbps 为 565 元/月。因此优先比较实际流量费用，再选择带宽方案，不机械购买大额固定带宽。购买时以当期订单和地域报价为准。[公网计费方式](https://cloud.tencent.com/document/product/213/10578)、[公网网络价格](https://cloud.tencent.com/document/product/213/113026)

预算优先级建议为数据库备份与可靠性 → 应用规格 → 媒体/网络优化。若总预算无法覆盖推荐组合，可退为一台 4 核 8 GB CVM、自建受支持 MySQL 和异地备份，作为成本方案另确认；这会增加自管升级、备份与故障恢复工作。无需起步就购买 Kubernetes、多台 Web 或大规格云 Redis。

先核对报价与续费成本，再采购；本方案未授权或执行任何购买。

平台凭据与入口仍按 [集成配置清单](INTEGRATION_CREDENTIALS.md)；实际源码交付状态见 [当前 PRD](PRD_CURRENT.md)。
