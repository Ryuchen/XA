# 玩法目录与转盘单

老板端主页和「服务」页提供一玩法一封面入口，路径为：**玩法 → 手游 / 端游 → 机密 / 绝密 → 商品详情 → 确认订单 → 钱包余额支付 → 履约 → 报单审核 → 结算 / 售后**。确认页默认平台派单，也可选择指定陪玩。

默认玩法：转盘单、体验单、陪玩单、趣味单、任务单、单局带出单、监狱单、定制单。它们是运营入口，具体服务内容、价格和结单条件由各商品配置；热销与上新不伪造销量或成交记录。

## 全玩法统一下单设计

参考站：https://djm.spansoda.cn/pages/tabbar/home 。普通单、任务单和转盘单均采用同一套商品详情结构：大封面、名称与价格、服务保障条、规格与数量、商品规则、真实评价、底部客服与立即下单。样式使用浅灰背景、白色圆角卡片、粉色主按钮和黑色客服按钮。

- 商品优先展示后台配置的商品图，其次继承玩法封面和主题，不再给所有普通玩法套用同一张封面。
- 更换规格保留当前手游 / 端游、机密 / 绝密选项；立即下单直接带入当前商品和数量。
- 指定陪玩通过选择页返回原确认页，保留游戏资料、备注、优惠券与数量。
- 确认页显示商品规格、客服、游戏资料、优惠明细与余额付款；客服充值返回后重新获取报价与余额，旧报价不可用于新规格或数量。
- 参考站的确认付款页需要登录，未取得其登录权限；本项目确认页沿用参考商品页的视觉，并连接本项目人工充值与余额付款业务。没有添加未经配置的库存、接单时效、满赠承诺或支付渠道。

## 后台配置

1. 在「玩法管理」维护名称、介绍、主题封面 / 自定义 HTTPS 封面、玩法规则、排序与启停状态。
2. 点「配置商品」进入已筛选的「游玩项目」，新增或编辑该玩法下的服务。
3. 每个商品选择一个平台（手游 / 端游）、一个难度（机密 / 绝密），再配置价格、等级要求、抽成、商品规则与上下架。
4. 四种规格可以独立设置价格和目标，也可以只上架实际能提供的规格；未上架的组合显示空状态和客服入口。
5. 转盘商品配置 2–8 个名称唯一的服务目标，每个目标填写履约说明与正整数权重。老板端公开概率 = 目标权重 / 总权重。普通玩法与礼物不能误配转盘奖池。

已有商品的玩法不允许更改普通 / 转盘类型，已有引用的玩法不能直接删除，可停用。停用玩法阻止新下单，历史订单继续按快照处理。权限复用 `service:view`、`service:edit`、`service:delete`。

## 转盘规则

- 商品详情的「模拟」完全在本地展示，不扣余额、不生成订单、不保存模拟结果。
- 正式购买每单只支持一个服务目标。余额扣款与订单创建在同一数据库事务中完成，使用后端随机数按权重确定目标，客户端不能提交或指定正式结果。
- 正式结果在支付成功时确定并立即进入派单要求；订单页的转盘动画用于查看已保存的结果，重复查看不会重新抽取或收费。
- 订单保存玩法名称、平台、难度、规则、当时的奖池与概率、正式结果。后续编辑商品、改变权重、调整价格或转单，不会改变已有订单的履约目标。
- 订单列表、打手接单卡片、打手报单、后台订单详情、报单审核及 KOOK / 企业微信群发单文案均可查看对应目标。群文案仅展示打手实得，不展示老板原价或实付。
- 沿用现有取消、退款和售后规则，退款保留历史结果与资金流水。活动价按实际成交金额重新抽成：例如原价 100 元、活动价 80 元、抽成 20%，打手 64 元、俱乐部 16 元。
- 各目标都是需要履约的服务约定，不增加现金奖品、实物发货或独立奖金提现流程。

## 发布与对接

执行数据库迁移 `0031`、`0032` 后会创建目录结构和 8 个默认玩法，**不会向正式数据库添加带价格的演示商品**。需在后台确认各平台 / 难度的服务内容、价格、概率、封面、完成条件与售后规则后上架。

本地预览库已添加 32 个带「本地测试方案」说明的规格，仅用于联调，不能直接视为正式运营定价或承诺。

不新增外部密钥或 Token。转盘与玩法由本项目后端实现；仍按 [对接凭据清单](INTEGRATION_CREDENTIALS.md) 配置小程序、KOOK 与企业微信。继续使用人工客服收款、后台充值和余额消费，不接微信支付。
