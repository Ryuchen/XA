## 视觉与交互规范

主色 `#0B6472`、按压主色 `#075260`、奶白页面 `#F8F7F1`、内容面板 `#FFFEFA`。浅海色表示选中，文字和边框同时变化；异常继续使用语义色与文案。数值由 `packages/design-system/src/_theme.scss` 维护，原生主题和图标用色由 `scripts/sync-native-theme.mjs` 生成。

短反馈 150ms、状态变化 250ms、展开 350ms。滚动保留浏览器和微信的系统惯性；横向选项使用轻量吸附，不接管鼠标滚轮。页面切换、按压和展开均提供减少动画设置的降级。

## 说明与反馈的使用场景

| 形式 | 场景 | 行为 |
| --- | --- | --- |
| Tooltip | 后台复制订单号的用途 | 悬停/键盘聚焦时解释只复制编号 |
| Toast | 复制成功、复制失败、既有轻量操作结果 | 简短结果反馈；需持续处理的错误另有页面提示 |
| Alert | 数据失败、待派核对、报价异常、余额不足 | 留在相关区域，并保留重试/客服等下一步入口 |
| Modal | 退款复核、派单配置、原生支付确认 | 需要专注或确认的任务；沿用现有资金校验 |
| Popconfirm | 资料编辑中移除接单资格 | 就近确认，取消可保留；仍以保存资料为生效点 |
| Drawer / 底部说明抽屉 | 后台订单详情、小程序费用与下单说明 | 保留列表/结算上下文，提供明确关闭入口 |
| 叠卡展开 | 陪玩网络详情、收益结算说明 | 核心金额、备注和接单动作持续可见，次要内容按需展开 |

## 微信小程序重点

- 目录筛选按实际内容高度展开；展开结束恢复自适应高度，连续切换时丢弃旧布局回调。
- 原生费用说明使用独立底部抽屉；遮罩、正文滚动、底部安全区和关闭状态独立处理。
- 陪玩选择沿用原有单陪替换、双陪上限、部分选择禁止提交、取消全部后平台安排机制；增加一致的视觉状态。
- 最新报价和原生支付确认保持；说明不代替费用明细或服务规则。
- 原生按钮和筛选触达高度提高至 44px，图标、原生 checkbox/switch/slider 和主题保持一致。
- 目录封面失败后显示现有功能图标；游戏图标失败时使用本地通用图标，不保留破图。

## 2026-10-29｜375px 结算补验与手续费检查修复

375×667 微信原生模拟器补验完成。为排除旧模拟器会话读取和点击不同步的问题，新建独立副本 `.tools/ocean-ui-20261029/wechat-checkout-375/`，通过开发者工具编译模式以 `service_id=992` 启动实际结算页；页面和组件使用当前产品源码，示例身份及 API 仍仅存在于本地测试环境。

发现并修复的布局问题：提交按钮原为 36px，输入框原为 40px，现均为 44px；页面底部留白按底部导航高度及安全区计算，为固定操作栏和状态提示保留空间。

实际操作通过项：

- 空白必填项阻止提交并显示“请填写游戏昵称与大区”；大区和昵称可填写，表单在 375px 内完整显示。
- 双陪 1/2 位时禁用确认，2/2 位时卡片、已选标签与按钮同步；返回结算后两名陪玩保留，套餐金额不变。
- 费用与余额明细可滚动查看，底部 44px 提交按钮和导航不遮挡末尾内容。
- 费用抽屉的三段说明和“我知道了”完整显示；遮罩区滚动不带动背景；底部确认、顶部关闭均可关闭，随后页面恢复滚动。
- 原生余额支付确认弹窗在小屏内完整显示金额和已指定陪玩信息；点击取消后弹窗消失，提交按钮恢复可用，填写内容保留。没有完成付款或创建订单。

手续费页面的两处裸金额换算改用共享包 `parseRmbFen` / `formatRmbFen`，明确以人民币分处理，不通过兴安币汇率换算；保留原表单的两位小数、正数及 2147483647 分上限。使用十进制文本转换避免分以下舍入，并覆盖一分、小数精度、非法输入和整数边界。本地固定示例中，12.34 元输入正确显示服务 12.34 元、手续费 0.07 元、合计 12.41 元；该示例只验证 UI 输入和展示，不代表真实商户扣费。
