## 当前产品与接口的修改范围

1. **老板小程序**：`apps/boss-miniapp/native/app.json` 导航标题；`pages/home`、`login`、`announcement-detail`、`service`、`companion-detail` 的品牌和分享文案；`checkout`、`wallet`、`coupons`、`gifts`、订单、成就及签到等页面的金额标签、弹窗、拼接文本和 `aria-label`。金额展示要同时核对旧有“币”简称，使余额、价格、优惠券、冻结、退款及流水的单位一致为“浪花”，不得误改“金币”等无关概念。
2. **打手 H5 / Web**：`apps/provider-vue/index.html`、`src/App.vue`、`components/AuthHeader.vue` 及钱包、接单、报单、押金、通行证、充值说明中的品牌和单位。`public/brand.svg` 的 title 及图形当前为 XA 标志，图形视觉是否包含旧品牌需实际检查并与声浪品牌方案衔接；不可只改标题就宣称视觉资产已完成。
3. **后台 Web**：`apps/admin-web/index.html`、登录、布局品牌及订单、定价、钱包、充值、提现、优惠、报表、抽成等页面的文字、字段提示、无障碍名称、确认和错误信息。根据用户最新要求以桌面 Web 验收，不增加适配目标。
4. **后端与消息**：`wallet/views.py`、`orders/views.py`、`console/views.py` 等接口返回的余额、充值、报单、退款、提现、押金和金额校验文字；`console/views.py` 也生成站内消息及备注；`engagement/services.py` 生日广播；`integrations/kook_config.py` 派单默认模板及字段说明；`config/admin_site.py`、`config/settings.py` 后台标题。更名后检查后端消息、请求失败及页面回显，避免仅替换前端静态文字。
5. **公共金额包与活跃文档**：`packages/money` 及相关 JS/TS 注释和公开说明的名称可更新，但保留内部账务整数与现有换算；`README.md`、`docs/API.md`、`docs/PRD_CURRENT.md` 及各端产品说明等活跃入口须更新当前口径，同时注明旧资料的历史语境。相关测试断言随新的输出更新，并继续核对换算、余额和退款数值。

## 需要分别处理的数据、资产和外部配置

- **运行时数据库内容**：代码中 `site_messages.Message`、`orders` 的派单内容、`console` 配置及充值/流水备注可能包含旧称；历史公告、商品描述、玩法规则、客服配置及上传图片也可能由用户维护并持久化。仅改源码不会改存量。先在专用隔离副本只读清点并分类：当前可编辑的运营文案、消息/交易历史、URL、附件及用户输入。新生成内容用新称；已有内容按确定的展示或迁移方案处理，保留金额、消息语义和历史可追溯性，不用全库盲目替换，更不应修改生产数据库或覆盖真实客户内容。当前尚未查询任何数据库，不能断言存量数目为零。
- **商品种子与图片**：`services/backend/orders/data/club_catalog_20260922.json` 同时包含可展示的旧品牌规则文字及带旧名称的图片相对路径。内容与路径是不同类型：更新文案不应机械改路径导致资源失效；海报、封面及其他位图中的品牌文字需查看原图与实际业务数据后按品牌替换并核对引用。静态文档和视觉示例不等于已部署内容。
- **可配置通知**：`services/backend/integrations/kook_config.py` 包含默认品牌和金额文案，但已保存的派单模板可能覆盖代码默认值；应识别并处理实际可配置模板。外部消息不使用真实接收人进行验收。
- **域名和小程序/第三方标识**：`apps/boss-miniapp/native/config.js` 的正式/体验接口及 `common/catalog_images.py` 的图片主机白名单使用 `xaesports.club`；后台 KOOK 配置也存在此域名。域名是实际连接、授权与资源标识，不可将旧域名作字符串替换成未经确认的新域名；确需更换时另行核对域名归属、DNS、证书、微信合法域名、回调及历史资源迁移。微信展示名称、应用 ID、KOOK 和企业微信的外部账号名称同样需在对应平台核对，代码改名不等于外部名称已变更。
- **内部标识与历史证据**：`@xa/*` 包名、`XA_` 环境变量、表字段、API 键、迁移标识、测试容器名及历史文件路径是技术标识，不等于界面文案；改动可能破坏兼容。历史审核记录、日志及历史 PRD 可能承担证据用途，不能伪造为过去即使用新名称；应在当前文档明确新旧名称关系，在产品可见位置满足统一新名称，并分别确定需要保留的原始证据和展示方式。

## 验收设计

在需求与设计明确后由开发按协调的文件范围完成；测试人员针对**本地 WSL 部署的打包容器**、隔离 MySQL/Redis 及合成数据验收，并记录镜像、小程序源码、环境和角色。微信开发者工具及浏览器为宿主交互端，访问隔离容器服务。

- 三端逐场景检查品牌、金额单位、空态、加载失败、确认弹窗、无障碍标签、分享标题及通知；包括后端返回的错误和站内消息。对单独的只显示“币”与图像内旧字进行人工复核。
- 用相同隔离账本数据对比更名前后充值、余额、报价、优惠、支付、退款、押金、收益及提现：用户可见数字、内部整数、人民币对应金额、四舍五入和历史余额均不变，仅显示名称变化；不得把文案测试当作资金流程通过。
- 分别核对只读历史数据、可编辑配置及最新生成的消息/规则、导入源及外部标识；记录旧称残留、无法访问的外部平台、图片及不适合改写的历史证据。外部发布、域名及真实消息依实际授权和安全测试条件单独记录，不能以模拟称为已改名或已送达。
- 使用带范围和排除项的源码扫描辅助定位，结合真实界面和数据库副本核查；扫描结果不应删除其他品牌、游戏专有名词、历史路径或篡改审计记录。测试失败与未覆盖项目在独立报告中列出。
