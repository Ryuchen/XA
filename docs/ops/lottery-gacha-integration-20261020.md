# 微信小程序单抽、十连与240抽保底 · 2026-10-20

> 本文记录第一版验收。用户随后确认增加十连非积分奖保底，最新规则与验收见[补充报告](lottery-ten-guarantee-integration-20261020.md)。

已实现单抽／十连、抽卡揭晓动画及68体验单240抽硬保底，并更新本地后端与微信开发者工具中的原生小程序。**现有活动仍保持关闭：13个奖项的基础概率原本全部为0，未擅自配置概率或开放活动。** 后台填入合计100%的基础概率后即可启用。

## 抽奖规则

- 单抽消耗原每次积分，十连消耗10倍；目前配置为100／1000积分。十连按顺序执行10次独立抽取，使用同一基础奖池和每日次数额度。
- 同一会员、同一活动、同一业务周期的单抽与十连共用保底。连续未获得68体验单时，最迟第240抽必得；提前抽中则立即从0重新累计，十连剩余抽数继续计入新一轮。
- 例如已有235抽未中，十连第5抽必出68体验单，后5抽继续累计；最终进度为5／240，而非把十连结束后再统一判断保底。
- SSR为68体验单、SR为其他非积分奖、R为积分奖。分级用于结果展示，不改变后台基础概率。本轮没有额外增加“十连必出SR”、概率递增或大小保底规则。
- 68体验单基础概率可以为0，仍受240抽保底保证；奖品必须启用、库存充足且作为专属服务权益交付。它产生待交付中奖记录，不生成抵扣海报体验单的通用优惠券。
- 调整奖池版本不清空当前保底。首次初始化时接续本周期、本活动最近一次68中奖后的旧抽奖记录；历史超过阈值者下一抽直接保底，不改写旧中奖记录。

## 扣费、发奖与重试

后端在事务内先校验十次全部入场积分，中奖积分不能反过来垫付本次入场费。逐抽记录扣分、奖品、库存、奖励积分、保底前后值和是否触发保底；任意一次库存不足、领取记录或广播写入失败，整批全部回滚。

同一批次重复请求返回原10条结果、积分和保底快照，不再扣费。相同凭证更改次数、活动或请求版本会拒绝。当前每日剩余次数单独更新。单抽兼容原有平铺字段，旧中奖记录仍可幂等重放。

原生页先持久保存本次请求编号，再发出一个十连请求。网络不确定、页面离开或凭证删除失败时，只允许确认同一笔结果，避免误发新抽奖。成功后采用服务端积分与保底结果；中奖记录可随时查看和领取。
