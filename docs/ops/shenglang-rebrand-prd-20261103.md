# 声浪电竞品牌与浪花单位更名 PRD

日期：2026-11-03。状态：**产品草稿，待七角色基于同一版本重新评审**。此前已有更名实现先于正式 PRD 评审，属于流程偏差；评审和验收均未因已有代码而通过。具体盘点及历史限制见[更名盘点](shenglang-rebrand-audit-20261103.md)。

## 用户确认与目标

- 全系统面向用户的品牌由“兴安电竞”改为“声浪电竞”，原“兴安币”改为“浪花”。三端和后台使用一致名称；用户可见的通用货币单位应标为“浪花”，不误改游戏或第三方自身的“金币”等专有名词。
- 本次为更名：现有金额、精度、历史余额、收入与支出、资金流水及规则不因名称变化改值。原换算比例保持：1 元人民币 = 10 浪花 = 100 内部账务单位；1 浪花 = 10 内部账务单位。折扣、退款、押金、冻结、提现及舍入保持原有规则。
- 老板端是下单老板使用的微信小程序；打手使用陪玩 Web，按用户最新要求陪玩端原型和布局只考虑桌面，不要求手机适配，现有 H5 业务能力仍需保留。后台 Web 主要供客服、售后、财务和管理员使用，岗位权限以实际授权为准。后台布局目标包括桌面及 12.9 英寸 iPad Pro 横屏（约 1366 × 1024 CSS 逻辑视口），保留平板触控操作空间，不要求手机端适配。
- 当前仅交付微信小程序；外部平台名称、域名和账号并不因为本地代码更名自动改变。未经核实不替换 `xaesports.club`、应用 ID、回调或技术标识。
- 用户可见的运行时内容和在用图片均是全系统更名需要完成的范围；不能将目标缩减为源码静态字符串替换。外部平台暂无法访问时作为依赖留待处理，不据此声称全系统已完成。
- 用户最新决定放弃 Figma，改用本地网页原型；原型数据可完全 mock，须醒目标注示例、不能写入真实业务或作为业务验收。此前 Figma 画板仅供历史追溯，不再是交付前置。
- 每个页面都提供加载中的骨架屏和有数据设计状态，并另行设计加载完成但真实无记录的空状态；失败、重试及权限等状态按业务需要呈现。原型数据明确标注为示例，不能作为真实业务验收证据。
- 用户明确：三端在 2026-11-03 已做视觉更新，原型应以当天现有的后台、打手和微信原生实际页面及源码为基准忠实迁移，保留现有布局、组件与业务信息，不另起一套替代视觉。逐一覆盖所有实际页面、页面内 Tab 和关键弹层，并与 PRD 的真实业务、字段、操作、授权、正常结果和异常反馈对应；兼容跳转应核对目的地但不冒充独立业务页面。需要新增的骨架或业务状态应在保留现有视觉基线的前提下补齐。

## 存量内容与历史证据的候选处理

以下是供七角色评审的具体方案，**不代表已改动数据库或已经完成存量内容处理**：

1. 应用负责生成的标题、金额单位和新消息由当前代码显示新名称。已有结构化历史交易/余额在当前产品页面以“浪花”单位展示，底层数值与原始记录保持不变；对账与审计仍能追溯原交易。
2. 用户已明确：历史聊天和评价原文照常显示，上传凭证保留原件；系统文案和运营内容改为新名称。公告、服务描述、系统历史消息和截图按来源区分，先在隔离场景库只读清点，列出当前对外内容和历史证据。原始历史凭证、审计记录和用户原文须保留，不做全库盲替、不伪称历史当时使用新名称；来源不明或可能改变原意的项目逐项核实，不静默跳过。尚未完成的项目保留为交付缺口。
3. 需持续展示的海报、图片与 SVG 逐项核查其中名称和标识；在用旧品牌图片须完成替换或可审计更新，并核对引用。缺少素材或访问条件时继续列为未完成，不能称全系统视觉更名完成。历史原始证据保留，当前展示采用经评审的新品牌呈现。
4. `@xa/*`、`XA_` 环境变量、API 字段、数据库/迁移标识、URL、文件路径和历史日志等技术或证据标识不因显示更名机械替换。活跃说明文档更新当前称谓并注明新旧名称关系；历史档案保留原语境。

### 可审计更名机制提案（待评审，未实施）

详见[存量内容可审计处理设计](shenglang-auditable-content-design-20261103.md)。七角色须评审以下完整契约及其实际模型、权限和兼容性；本段是具体设计候选，不能视为已确认规则或已上线功能：

1. **公告、服务和玩法运营文本**：授权人员逐对象、逐白名单字段预览及编辑，提交预期原文字段哈希；服务端锁定原对象，比较原文后在同一事务写入并追加不可覆盖的前后版本事件，记录操作者、时间、原因、请求 ID 和哈希。服务与玩法回退字段各自核实；富文本使用现有净化规则，金额、链接、路径、变量和游戏专名不变。
2. **KOOK 路由模板**：沿用现有查看/编辑权限、版本号及锁，逐路由预览并提交模板文字变化，同时保存不含密钥的版本事件；保持频道、开关、URL、变量与外部接收人。历史消息不重发，外部渠道无安全测试条件时标未覆盖。
3. **历史系统消息**：消息类型或关键词不足以证明来源。仅在有证据确认由系统生成后，授权人员按消息 ID 和允许字段逐条核对原文哈希，发布带来源依据的展示覆盖版本，原消息不变。多字段作为同一原子版本；先执行原消息访问过滤，再对授权对象应用哈希仍匹配的有效覆盖，不改变接收人、已读、排序、分页或推送。
4. **权限与审计提案**：公告、服务、玩法及模板沿用其现有细分权限；历史消息覆盖拟新增独立 `message:brand_override`，需同时具备 `message:view`，默认不自动授予既有角色。候选仅供定位，人员逐条核验来源与范围；未授权用户既不能操作，也不能通过错误或日志获取原文。新增模型、权限和界面是否必要、权限管理员如何配置，需在评审中明确，不以岗位名称推定授权。
5. **冲突、幂等与回退**：原文哈希不匹配、对象已删除或权限变化时不发布，提示刷新核对；并发仅一个有效版本，请求 ID 重试不重复追加事件。读取时原文已变则整组覆盖失效、回退原文并列待核查；撤销或恢复是追加审计事件，不删除历史。原文来源不明、用户聊天/评价、凭证和财务原始记录不自动覆盖。

隔离 WSL 容器验收须逐类验证实际权限、来源证据、前后版本、原消息不变、跨账号拒绝、并发/哈希冲突、失败无半条事件、撤销和重试；不能仅用字符串扫描判断通过。用户原话和凭证例外以用户已确认的展示口径为准。

### B4/B5 同一账本的前后对照

测试负责人和研发在变更前保留当前独立 Compose 项目的持久 MySQL 与媒体卷，完成一致性备份，记录镜像 ID、迁移、备份校验值；将备份恢复到**单独项目和卷**，核对可恢复后再升级。不得清库、重建场景库或覆盖已有场景。使用真实业务接口形成并保留合成充值、订单、优惠券、退款、押金、冻结、报单收益和提现，以及零值、小数单位和失败/重试样例；不构造虚假的核心业务成功结果。

停止对照数据写入并等待 worker 收敛，将同一快照恢复到两个互不相连的隔离副本，分别用可识别的更名前与更名后版本执行对应迁移、读取和只读对照；不让两个版本同时写同一库。更名前镜像或与快照匹配的源码不可得时，明确标记无法证明前后行为一致，不以新空库替代基线。导出仅限合成数据，排除凭证、令牌和收款账号。

按主键逐行或规范化哈希核对行数、身份与关联、状态及至少这些字段：钱包 `balance/frozen_amount/total_recharge/total_gift`；流水编号、类型、状态、金额及前后余额；充值与赠送金额；提现金额、税额、实付与状态；陪玩押金应缴/已缴；订单原价、成交、优惠、份额、状态和结算时间；成员结算份额、退款金额与追回分配；报单收益与冻结；优惠券门槛、面额及使用状态。具体字段以实际模型及迁移核对，缺失字段须显式失败或标不可比较，不能静默跳过；任何异常均需报告而非只比总额。`scripts/fingerprint-finances.py` 现有覆盖不足，不能单独证明上述范围。

额外核对小程序、打手 H5/Web 与后台同一服务端数据：例如 100 内部单位显示为 10 浪花且对应 1 元；充值、报价、退款、押金、冻结、收益和提现的数字、精度和既有行为不因更名变化。模型字段展示迁移、前置迁移、重复运行、旧种子兼容及权限由容器内实际验证；本地单元数据与持续场景数据分离。本方案的基线版本、夹具、对照工具、备份恢复演练及证据路径若尚未准备齐全，测试标阻塞，不推断通过。更详细字段及技术依赖见[后端对照底稿](shenglang-rebrand-backend-design-20261103.md)。
