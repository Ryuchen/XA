# 第一轮 WSL 容器隔离验收实施方案

日期：2026-11-03。本文为实施设计，不代表本轮正式业务验收已经执行。独立 WSL 场景环境已建立，具体环境与现有证据见[团队交接](team-waterfall-handoff-20261103.md)及实际运行状态；其运行本身不等于评审通过或功能验收通过。首轮业务范围以 [首轮候选 PRD](round-01-order-prd-draft-20261103.md) 及最终确认的验收标准为准；转单售后场景在后续纳入范围时使用下述扩展方案。

## 原则与环境边界

功能测试和开发运行验证均针对打包后部署在本地 WSL 容器内的应用。后端、后台、陪玩 H5、MySQL、Redis、ASGI、Celery worker 和 beat 均运行于本轮隔离容器；真实业务逻辑和接口不以 mock 替代。Windows 宿主的微信开发者工具、浏览器及其自动化程序只作为操作和观察客户端，访问本轮容器网关。微信模拟器本身在 Windows 宿主，不能表述为运行于容器内。外部身份、消息、实际支付及线下打款如未接入，只记录替代范围，不记为真实链路通过。

## 构建和可追溯性

1. 测试负责人先记录当前 Git HEAD、工作区变更清单及测试快照的内容哈希；当前工作区存在大量未提交内容，HEAD 单独不能标识被测代码。对实际构建上下文、后端镜像、后台镜像、陪玩 H5 镜像分别记录不可变摘要或镜像 ID，并记录小程序导入副本的源码哈希、微信工具版本及配置。不得覆盖或重置已有修改。
2. 在 WSL 构建本轮专用镜像标签；后台和陪玩端由各自 Dockerfile 打包静态资源并在容器中提供，后端镜像包含实际业务代码。记录构建命令、时间、结果、依赖版本和镜像 ID；不将 `latest` 标签本身当作证据。
3. 启动后记录实际运行容器对应的镜像 ID、迁移版本、服务健康状态与访问入口；验证界面加载的资源属于本轮构建。代码变动后需重建受影响镜像、重新部署，并重新执行受影响验收。
4. 小程序使用与本轮快照一致的独立项目副本和官方编译器，明确记录编译结果及源码哈希；模拟器连接本轮隔离网关，不能误连当前 Windows 热更新端口或试用/正式环境。小程序宿主测试与容器服务测试共同构成端到端证据。

## 隔离部署设计

- 使用独立 Compose 项目名、专用网络、独立 MySQL/Redis 及媒体和静态数据卷，端口只绑定本机回环且与现有服务错开；运行前核对实际容器、卷、端口与连接，禁止复用现有 `xa_verify`、预览数据库和生产资源。新建的测试数据库和账号仅有本轮测试所需权限。仅使用新建合成老板、客服、陪玩、订单、凭证和钱包数据，不复制真实客户或生产数据。
- 基于现有 `deploy/compose/docker-compose.remote.yml` 和 `deploy/compose.local-validation.yml` 的镜像部署思路使用独立隔离编排，保留真实迁移、MySQL、Redis、worker、beat 和网关，检查生成后的配置及实际容器；不要直接执行既有脚本的持久库 smoke。用户要求跨迭代持续保留本轮合成场景数据及媒体：不得清理、重建或覆盖场景数据库及其持久卷。只有已核实的临时一次性资源可清理；每轮升级前先备份并验证恢复，不删除现存环境或数据。
- 显式禁用 KOOK、企业微信和其他真实外部发送渠道，清空相关凭证；不加载 `.env.wechat` 或 `/etc/xa-local-validation/wechat.env`。现有 `deploy/local-validation.sh` 检测到后者时会自动叠加真实微信凭证，不能直接把该脚本视作本轮无外部凭证的保证。逐项检查最终运行配置，但不输出密钥。真实微信身份如不参与验收，以受控测试会话或测试身份进入，并在报告注明其边界。
- 运行前检查数据库名、主机、用户、容器镜像和网关地址与本轮记录一致；验证消息渠道关闭、支付外部调用不可触发、媒体目录独立、网络与端口符合配置。若不能确认实际连接或隔离，停止有状态测试并记录阻碍。
- MySQL 采用实际迁移及事务/行锁，Redis 使用独立实例；服务及 worker 使用相同隔离数据库和 Redis，并以真实 HTTP、WebSocket 及任务处理验证跨进程行为。现有 `config.container_test_settings` 将队列、缓存和 Channels 换为内存：其数据库回归可作为补充，不能作为 Redis、真实 worker 或跨进程推送通过的证据。

## 执行顺序

1. 依据已确认 PRD、原型和验收标准编制案例与角色矩阵，明确每步前置条件、动作、预期页面和数据库/资金结果；业务有歧义先交 team leader 汇总决断。
2. 检查构建依赖、编排和端口，建立独立环境，逐项验证隔离后部署打包产物；记录迁移、镜像和服务状态。
3. 通过真实业务接口准备合成数据：老板充值并下单，陪玩接单、履约及报单。测试负责人核对余额、流水、订单及相关角色状态；仅在转单售后被纳入范围时构造相应订单。
4. 按首轮 PRD 在微信开发者工具及容器提供的后台、陪玩 H5 逐项操作。后台分别核对桌面及 12.9 英寸 iPad Pro 横屏（约 1366 × 1024 CSS 逻辑视口）的表格、表单、弹窗和触控空间；仅改变浏览器视口不是实际平板触控验证，报告须区分两者。转单售后扩展场景包括老板提交、客服处理、陪玩查看限制和处理结果，并核查继续服务或协商退款的反馈。关键资金竞争和幂等以隔离 MySQL 独立连接测试，真实实时反馈以 Redis、ASGI 和 worker 场景另行验证。
5. 每次打开微信开发者工具模拟器验收或截图前，先最大化窗口，确认完整屏幕可见，并回读 iPhone 12/13 (Pro)、390 × 844；记录工具版本、连接目标与截图。不得把页面控制器宿主替身或示例数据视为 IDE 交互通过。
6. 测试人员完成所有约定案例，报告通过、失败、阻塞及未覆盖项；team leader 分析问题与功能调整，product leader 在下一轮重新设计并确认后再安排开发。

## 风险与待验证项

- 后台 `package.json` 依赖 `@xa/shadcn-vue`；先前静态检查发现 Dockerfile 缺少该 workspace 包的复制，当前工作区已补充清单和源码复制。该修改发生在正式评审前，须作为流程偏差在评审后重新核对；本轮最终快照的构建仍需实际验证，不能沿用旧镜像冒充新构建。
- 现有 `native/config.js` 的 develop 地址可能指向 Windows 预览，必须核对实际独立副本和运行时配置。现有 `native-aftersale-receipt-iphone12.cjs` 修改会话且未恢复，仅核对回执，不覆盖完整售后提交；须补齐隔离会话及页面操作测试，避免影响用户现有项目。
- 原有实时测试辅助函数启动 Windows 宿主 ASGI；需改造或另建容器化验收入口。容器内真实 Redis、worker 和任务的运行结果应分别留证，不能从客户端模拟推断。
- 实际微信授权、真实外部投递、生产资金和线下打款不在隔离测试结论中；如后续另行开展，应有对应安全测试环境与单独证据。

## 测试报告格式

每轮报告至少包含：需求与验收基线版本；构建快照、镜像 ID、小程序哈希和迁移版本；执行时间及责任人；容器、数据库、Redis、worker、宿主客户端与机型；合成数据及外部依赖替代范围；逐案例前置条件、三角色操作、期望与实际结果、订单/钱包/流水核对、日志或截图路径；通过/失败/阻塞/未执行状态与原因；缺陷复现步骤、影响和优先级；未覆盖场景及回归记录。历史测试结果与本轮结果分开，不将测试数量相加作为覆盖率或完成百分比。
