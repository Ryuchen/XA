# 抢单排序规则实现记录（开发中）

新增 `orders/grab_ranking.py`，以调用方提供的已核实候选事实比较单陪或完整双陪：按提交时通行证等级、本店最近 30 天个人原价净额、最近 30 天有效评价好评率、完成提交时间排序。双陪的前三项分别取两人较高值；好评率用有理数精确比较，无评价为零。前三项相同后，以完整提交时间较早者优先；时间也完全相同则返回需要重开，不按候选编号决胜。旧候选完成时间不可核实时，仅在同分必须比较时间时落选并继续比较其他候选。

同模块提供基于本店 `Evaluation` 的只读统计：以明确的统计时点截取最近 30 天，综合评分 4–5 星计好评；统计时已作废的评价不计，稍后才作废的评价不改变之前时点的结果。业务账号优先；历史评价未绑定业务账号时才按该陪玩历史用户关联。跨店查询由现有门店上下文及独立数据库路由约束。

新增 `orders/grab_window.py` 的轮次判定：首轮入池即开始完整窗口，必要时延长订单总等待；截止前已完成的候选先排序，同一截止时刻收到且有效的老板取消优先。首名复核失格时不递补，若未到总期限则开放完整新一轮，否则取消；完全同分即使总期限已到也重开，重开时同时可见且不继承上轮候选。无人参与且总期限未到时进入留池。该模块要求调用方先证明截止前的服务端命令均已处理，并在订单及人员锁内复核首名；它本身没有提供持久命令队列、水位或并发保障。

用户进一步确认：订单重开时沿用入池时保存的窗口长度；双陪原价等分后，各人向上取整至整数店币，超出部分单独展示，例如 101 店币各记 51、超出 1；履约中转单的原价份额由客服协商并留痕，单陪转出与转入的份额合计必须等于原价。`orders/original_share_rules.py` 实现了这两类计算与总额校验，统计取整差额不伪称资金收入；初始分配和服务中转单的原价记录已接入试验路径，退款尚未接入。

新增默认关闭的 `ORIGINAL_ATTRIBUTION_ENABLED` 试验记录与迁移 `orders.0099`、`orders.0100`。老板下单、预约转单和客服代单在付款事务内登记原价边界；分配时记录各人对应席位、原价份额和接单时间，另存双陪取整差额。单陪开始服务与双陪各自提交入队凭证分别记录开始事实；服务前改派保留旧段并为接替者新增段，不把未入队人员算作已履约。同一人服务前转回也保留独立记录。开启开关后仅为新付款订单采集，历史订单不由当前状态倒推；原价异常或退款目前标为待核对，不将不完整记录用于排序。

对拥有完整试验参与记录的服务中订单，授权客服转单时填写原陪玩及接替陪玩的原价份额和协商依据，系统在同一订单事务中校验两者合计、生成接替段并保存原始份额、操作人及依据；未开始的旧段不能保留原价份额。双陪只变更受影响席位，审计失败则订单和资金一并回滚。后台订单详情展示原价份额记录。接替段不会自动标为已开始：接替陪玩须在订单页上传本人本次入队截图，方能完成该段；双陪另一人可以单独完成自己的操作。每次转入保留独立的入队事实与截图，同一人转回不覆盖旧报单凭证。截图按本人或有报单查看权限的后台人员授权读取；重复提交使用请求编号避免重复操作。退款、加购、历史补录和自动排序尚未接通。开关关闭期间可能发生未记录的业务变化，因此以后使用这些事实前必须实现覆盖期和订单事件核对，不能仅凭 `ACTIVE` 状态认定历史完整。

在独立默认关闭的 `SEGMENT_ECONOMICS_CAPTURE_ENABLED` 试验路径下，对可核实的新钱包订单，转单根据每次原价份额记录成交基数分配和取整余数，并逐次校验全部履约段的成交额合计；数据缺口不会从旧聚合收益倒推。双陪另一席位不变，同人转回按新段保存。后台展示的是成交基数记录，接替时抽成与结算仍待核对；试验路径中存在未核对转单时，普通收益和平台补贴支付暂不执行，旧完成即结算订单须先完成规则迁移，历史已支付补贴保留且重试不会重复支付。

现有服务中转单的收益处理仍是旧实现，游戏抽成订单被阻断，接替陪玩按接入时门店抽成快照以及已发生履约段的完整结算模型尚未实现；上述记录不代表资金转单链路完成。`orders.0099` 至 `orders.0104` 均尚未应用到现有门店库；开关关闭时不查询新表，未重启后端。隔离 SQLite 验证不等同于真实 MySQL 并发验证。

本次只实现排序与可核验的评价统计，**尚未接入订单自动分配**。现有数据模型尚不能完整证明每次履约段的原价份额、接单时间、退款分摊和加购归属，不能以现有结算基数、陪玩收益或订单实付冒充用户要求的接单额；缺少可靠事实时不得调用排序并声称结果准确。首轮等待及时间快照、通行证入池和提交事实、候选持久化、多人并发、同刻取消优先的可靠命令顺序、最终资格复核、重开和退款、通知与群发、历史候选迁移、双陪抢单池及三端反馈仍须实现。不得将纯排序测试作为完整抢单流程验收。

隔离测试覆盖等级优先、双陪逐维取高、精确好评率、无评价、提交时间和完全同分、历史时间不可核实、评价窗口／作废及账号归属；轮次判定覆盖水位未完成等待、截止候选与取消、首名失格、窗口重开和总等待延长；原价规则覆盖双陪取整和转单份额守恒。两家完整迁移临时库使用同编号陪玩验证评价统计隔离；未验证真实 MySQL 锁与并发，也未修改现有门店数据库或重启后端。
