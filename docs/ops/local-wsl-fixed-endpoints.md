# 本机 WSL 项目服务入口

本机使用 WSL 镜像网络；Windows 与 WSL 本机调用统一使用 `127.0.0.1`，不要依赖网卡地址或 Docker 容器的临时 IP。以下端口只绑定本机回环地址。

| 服务 | 固定入口 | 用途 |
| --- | --- | --- |
| WSL 后端网关 | `127.0.0.1:18080` | 本地容器版 API 与媒体服务 |
| WSL 管理后台 | `127.0.0.1:18081` | 容器构建版本 |
| WSL 陪玩端 | `127.0.0.1:18082` | 容器构建版本 |
| WSL MySQL | `127.0.0.1:13306` | 隔离验证库 `xa_verify` |
| WSL Redis | `127.0.0.1:16380` | 隔离验证环境使用 |
| 热更新预览 Redis | `127.0.0.1:16379` | 独立预览环境使用 |

容器之间使用 Compose DNS：MySQL `db:3306`、Redis `redis:6379`、后端 `web:8000`；不固定容器 IP。数据库认证信息保存在 `.tools/local-validation.env`，不要将其提交或复制到文档。

当前 Windows 热更新预览另有 API `127.0.0.1:18101`、管理端 `127.0.0.1:13032` 和陪玩端 `127.0.0.1:13033`；它们是与 WSL 容器版分开的开发进程及隔离数据，不共享容器版数据库。热更新依赖这些进程继续运行。


WSL 容器版运行构建镜像，源码修改不会自动进入这些容器；需要更新容器版本时使用下方脚本的 `build` 和 `up`。不要把容器版入口当作当前 Windows 热更新预览。`127.0.0.1` 是本机固定入口，并不为局域网其他设备提供固定 IP。

启动或检查 WSL 容器服务：

```powershell
wsl.exe -d XA-Ubuntu-24.04 -u root -- bash -lc 'cd /mnt/g/Github/XA && bash deploy/local-validation.sh up'
wsl.exe -d XA-Ubuntu-24.04 -u root -- bash -lc 'cd /mnt/g/Github/XA && bash deploy/local-validation.sh check'
```

Docker 服务已在该发行版启用，容器采用 `unless-stopped` 重启策略。Windows 重启后，需先启动 WSL 发行版或执行上述命令；这不等同于已配置 Windows 开机自启。以上入口为本机访问，并非局域网固定地址。
