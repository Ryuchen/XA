## 用户确认的计算规则

参考附件 `822d655b-50ef-4ef4-82ca-ae87f46551fb/image-1.png`。表格中的全职客服底薪 3600、绩效 2400 为三人合计，按下方说明使用每人 1200、800；系统人数取实际员工薪资安排，不固定为图片人数。

| 薪资岗位 | 人均月底薪（元） | 人均月绩效（元） | 业绩目标及提成 |
| --- | ---: | ---: | --- |
| 店长 | 3000 | 1600 | 门店月目标 60 万；绩效按完成比例折算，封顶满额 |
| 客服（全职） | 1200 | 800 | 个人月目标 20 万；绩效按完成比例折算，派单日班 1%、夜班 1.5%，预存充值 1% |
| 客服（兼职） | 0 | 0 | 派单 1%，无底薪、绩效 |
| 打手管理 | 1500 | 0 | 固定底薪 |
| 售后管理 | 1500 | 0 | 核实完成的售后处理每次 50 元 |
| 财务 | 2500 | 0 | 固定底薪 |
| 运营 | 1000 | 0 | 固定底薪 |
| 考官（声浪） | 0 | 0 | 每次抽成前 50 元，扣 30% 后实得 35 元；用户已明确确认此解释 |
| 考官（兴安） | 0 | 0 | 每次 30 元，不抽成 |

以上作为可编辑薪资模板，不新增实际员工、不自动发工资。每人每月的薪资安排与后台权限角色独立；历史确认核算保留方案与业绩快照。

用户选择夜班按北京时间固定窗口自动判定，并要求在系统内部配置；未指定具体时段。因此初始不擅自写入夜班起止时间，缺配置影响核算时须明确提示。

用户明确要求同时展示：

1. 投产比：订单净消费折算人民币 ÷ 投流费。
2. 经营 ROI：（订单净消费折算人民币 − 陪玩及关联业务成本 − 员工薪资 − 投流费 − 其他已录成本）÷ 总成本。

订单余额消费可能含赠送浪花，净消费不等于现金实收。报告应显示日期归属、退款处理、来源、缺项和暂估/已确认状态，零分母不输出无穷大。薪资和外部支出用人民币分，不能误用浪花输入换算。

## 业务来源与边界

- 派单归属单独核实；真实创建/派单日志决定发生时间，不能由客户端任意选择日夜时段。
- 充值归属单独核实；只计实充，排除赠送。收款录入人不是默认销售归属人；充值本金不再次计入营业收入。
- 售后以真实完成周期计次，同一周期不能重复录佣；重开不覆盖已经核实的历史周期。
- 考试按明确的人工完成核实及理由计次；资格审核通过不能被冒充为完成考试。
- 订单、履约、退款、充值和私有凭证继续执行原有三端真实业务代码；不因成本核算改写成熟钱包结算规则。
- 图中陪玩等级、押金、赠礼和提现抽成继续使用原业务专用配置与规则；续单奖励说明不能通过赠礼专用的 `source_order` 字段伪造续单关系或重复发款。

## 字典抽象

新增真正被业务引用的薪资岗位、投流渠道、其他成本类别字典，采用稳定编码、显示名称、排序、备注及启停；已有引用保留，禁止修改编码和删除被引用项。

游戏类目、服务分类、老板分级、陪玩等级统一纳入配置入口，继续保留原模型、外键、金额/折扣/抽成校验。提现、押金、费率、限流、通行证等继续专用配置，不开放任意 `SystemConfig` 键值写入。订单/付款/提现/售后状态机和资金流水类型不能变成任意可新增的运营字典。

## 验收要求

- 岗位模板可编辑，员工按月安排，真实来源归属、计次、核算、确认快照和 ROI 完整联动。
- 每日投流支持日期、渠道、人民币金额及备注；其他成本支持分类；重复请求不重复记账。
- 覆盖退款、日夜窗口边界、绩效封顶、考官扣率、重复归属、配置变更、权限、零成本和缺项反馈。
- 在独立 MySQL 验收库执行真实接口和账务，不触及生产资金、真实消息或外部付款；浏览器验收不以示例图或路由存在代替实际保存与回读。
