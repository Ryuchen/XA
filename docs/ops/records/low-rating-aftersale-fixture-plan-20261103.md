# 低星售后测试数据与证据设计草案

状态：开发前测试设计，未创建数据、未执行验收。以[低星售后 PRD](low-rating-aftersale-prd-20261103.md)和最终七角色评审版本为准；测试用数据均为虚构合成数据。测试人员独立完善和执行，本文不替代他们的测试报告。

## 两套独立数据

| 数据集 | 用途及生命周期 | 约束 |
| --- | --- | --- |
| 本地单元数据 | 研发验证评分判断、身份映射、来源归类、结算条件和错误分支；每个用例独立构造及清理。 | 使用隔离测试库，不读取或清理 WSL 场景库；单元数据可以构造函数级边界，但不能据此认定真实资金事务、MySQL 行锁、任务或跨端通过。 |
| WSL 持续业务场景 | 正式功能测试使用打包容器、真实业务接口、MySQL/Redis 和 worker，持续保留合成订单、用户、流水和凭证供后续轮次查看。 | 独立 Compose、数据库与媒体卷；不使用生产客户、真实消息接收人或真实资金。后续迭代不重置或覆盖场景库；迁移前备份并在独立卷验证恢复。外部支付和消息隔离范围另记。 |

用户、订单和金额以下均为测试意图，不规定数据库主键，也不是运行中的实际记录。若现有业务接口不能合法生成某个状态，应记录原因和可复现前置，不通过直接改库伪造成功。特别是上线切换前后评价须按最终发布开关方案构造，不能修改历史时间戳冒充真实边界。

## 场景数据组

| 组 | 最小配置与准备方式 | 覆盖及核对 |
| --- | --- | --- |
| S1：单陪评分边界 | 同一合成老板、一个打手、多笔各自完成且可评价的订单；单项分数逐条变化，包含旧客户端仅传综合分和部分单项。 | L1、L2、L15、L16、L18、L19：每单每人仅评价一次；四维合法值和缺省回填、未触发、失败回滚、来源/工单数量以及可见结果。无效分值与跨账号请求使用独立订单。 |
| S2：双陪份额与结算 | 老板、甲乙两名打手、独立钱包；构造低星发生前未结算和其中一人已结算的不同订单。 | L3–L7、L11、L14：逐人记录实际份额、入账与冻结事实；核对低星只作用于受评价者的未结算部分，另一人的其他结算条件仍须满足；不把待结算份额视为钱包冻结。 |
| S3：主动售后与轮次 | 至少两笔双陪订单，分别按 L22 的“乙低星后主动再申请”和“主动再申请后乙低星”排列；另建一笔覆盖同时触发。 | L13、L22：每笔内只复用同一工单，记录评价、原申请理由、处理历史、轮次/来源和每位份额；历史低星不因主动申请被误当为本轮新来源，主动售后原有限制仍适用。若主动再申请在该订单不合资格，应另选真实合资格前置或标阻塞，不改写资格。 |
| S4：已结算与退款 | 用真实接口构造未入账、完整入账、部分份额入账及存在历史退款的独立订单；保留对应原支付、余额、收入、平台和退款流水。 | L6、L8、L11：分别核对退款预览与提交、余额不足、版本变化及并发。低星本身不自动追回已到账收益；退款是否允许及资金承担按现有规则与评审方案，不以 mock 代替账务事实。 |
| S5：身份、转单与历史兼容 | 新建普通双陪、转单或已释放参与者订单；另用真实可获得的旧单兼容数据和身份异常隔离样例。 | L17、L20、L23：对象由服务端实际资格决定，核对账号/旧用户身份和份额对应；没有可靠前置或数据来源时标未覆盖，不自行推断目标或重映射历史资金。 |
| S6：上线切换 | 一组切换前低星历史评价、一组切换附近并发请求及一组启用后评价，记录统一服务端切换事实与各实例版本。 | L21：切换前保留查询、不回填工单；切换后有效低星按规则处理，重试/回滚不漂移边界。具体切换机制未评审，不预先声明实现方式。 |
| S7：权限及展示 | 分别建立老板、两位打手、客服、售后、财务、管理员和只读/无权限隔离账号；具体动作由实际授权配置。 | L9、L10、L20：三端分别核对本人数据与跨账号拒绝、匿名及售后内容可见性、实际操作审计；后台桌面及 1366 × 1024 逻辑视口，微信工具按 iPhone 12/13 (Pro) 390 × 844 规范留证。实际平板触控单独记录，视口截图不能替代。 |

L12 使用更名专项的同一持久账本对照，不另造新旧金额；L18 的请求结果未知使用测试环境可控丢响应手段，先证明服务端实际结果再核对页面恢复；L19 使用受控失败注入证明评价及工单事实的事务一致性，不能仅看页面提示。以上分组可复用用户与账号，但**每条会改变评价资格或资金状态的案例使用独立订单**或明确记录顺序，不能悄然重置持续场景数据以便重复通过。

## 证据记录与并发

每次执行记录评审版本、源码快照和镜像 ID、迁移、日期、环境和合成数据标识；每次动作记录发起角色、请求及业务状态、评价和工单来源、每人份额、钱包余额/冻结/流水、订单状态和相关权益的前后值。金额按服务端内部最小单位与界面显示分别留证，并保留原换算比例；不导出密码、令牌、真实收款账号或真实客户资料。对通知额外记录事务提交、worker 消费和安全隔离范围，不将前端刷新等同外部送达。

MySQL 竞争案例使用独立连接、明确并发起点和提交顺序，覆盖双人评价、评价与主动售后、结案、结算和退款；记录结果、重试及最终持久事实。对每条路径写通过、失败、阻塞或未执行和原因；未准备的合成数据及未覆盖的真实外部依赖不能计为通过。研发的本地单元结果、原型 mock 检查与本轮容器业务验收分开报告。
