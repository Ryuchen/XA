# 岗位薪资、业绩归属与经营ROI

本功能沿用当前三端业务页面，只补充薪资、成本与经营核算入口。薪资是经营成本账，不会自动向员工或陪玩钱包打款，也不改变原订单分账、提现、押金和报单规则。

## 金额、岗位和人数

薪资、投流与其他经营成本均以人民币分存储，以人民币元输入及展示；费率以基点存储，100基点为1%。业务订单仍使用原内部账务单位，统一经过明确的换算边界进入人民币核算，不能将浪花展示数直接当人民币。

岗位使用`SALARY_POSITION`字典，薪资方案与后台权限角色相互独立。新增岗位不会授予后台权限，分配权限也不会自动产生工资。每月按实际员工安排计薪，同一员工每月一个明确方案；兼岗可配置包含其实际薪资构成的方案。

| 初始岗位方案 | 每人薪资标准 |
| --- | --- |
| 店长 | 月底薪3000元；最高绩效1600元；月门店业绩目标60万元 |
| 客服（全职） | 月底薪1200元；最高绩效800元；个人月业绩目标20万元；日班派单1%、夜班1.5%；预存充值1% |
| 客服（兼职） | 无底薪及绩效；派单1% |
| 打手管理 | 月底薪1500元 |
| 售后管理 | 月底薪1500元；核实完成售后50元/次 |
| 财务 | 月底薪2500元 |
| 运营 | 月底薪1000元 |
| 考官（声浪） | 每次考试抽成前50元，扣率30%，考官实得35元 |
| 考官（兴安） | 每次考试30元，不抽成 |

这些是可调整的初始方案，没有预先安排真实员工或生成实际工资。参考图中全职客服底薪3600元、绩效2400元是3人合计，不能作为单个人的薪资标准。

绩效按业绩÷目标线性折算并封顶；有绩效时必须配置正数业绩目标。人员安排会保留所选方案的完整快照。之后修改方案不会悄悄改变已有安排；同方案普通保存也保留快照，只有明确勾选“采纳当前方案”或更换方案时才更新。前端显示的模板版本可用`expected_plan_revision`核对，过期时拒绝覆盖。

陪玩仍按原等级、订单分账及押金配置执行。参考图中的续单奖励不由薪资页面推断或自动发放；现有赠礼来源不等同于续单。不得将人工薪资计次冒充已执行的钱包奖励。

## 业绩来源和夜班

- 派单：选择真实订单并明确归属员工。时间取客服创建或第一次实际派单日志，不能手填时间套用夜班费率。仅统计退款后的有效净消费，模拟直付订单及赠礼不作为此处派单业绩。
- 充值：选择真实成功充值记录并明确归属员工。财务录入收款的操作人不等于获客客服；赠送余额不计充值提成。
- 售后：选择真实已完成的售后周期并核实归属。历史记录与当前状态的相同周期只计一次；重新开启后的新处理周期有独立来源标识，不以页面刷新次数计次。
- 考试：由授权人员核实实际考试完成时间和原因，每条核实记录计一次。报名审批次数不直接转为考试次数。

夜班按北京时间固定窗口判断，起止时间均在系统内部配置，支持跨午夜且结束时间不包含在夜班内。初始窗口为空，不能凭空假定为22:00–08:00或静默套用日班；当某方案日夜费率不同且有待分类派单时，预览明确提示并禁止确认。日夜相同费率不依赖窗口。

同一订单、充值或已完成售后周期只允许一个有效归属。归属记录不支持修改来源的PUT/PATCH，未确认月份可以先撤销再重新核实；撤销保留原操作凭证，迟到重试不会恢复旧记录。人工考试与成本创建必须携带稳定的`client_request_id`；同凭证同意图回读原记录，不同意图或已撤销记录返回冲突。

## 月薪预览、确认和日期归集

每月预览列明每人的底薪、绩效、日夜业绩、充值业绩、售后和考试次数、考试抽成前金额、扣额及实得薪资。实际人数来自人员安排，没有安排的业绩会提示待核对。

确认必须提交当前预览指纹；人员安排、真实退款、归属或夜班配置变化会使旧指纹失效。确认在数据库事务及真实订单锁内复核，只保存一份月度快照，不改变钱包或资金流水。

确认后该月人员安排及业绩归属冻结，重复确认同快照不会多算成本。后续改模板或发生退款不会悄悄改写已确认的历史工资；后续实际调整须另行核实处理，不自动追回员工资金。确认当月工资也会冻结该月后续归属，日常经营可先看预览，待该月业务核对完整再确认。

快照保存每日成本：仅底薪按当月日历天数累计整数分摊，绩效按实际业绩发生日、提成按真实业绩日计入。因此月中查询不会再次把已经发生的提成乘以本月已过天数比例。整月每日成本相加精确等于月薪总额。

## 每日投流及其他成本

投流渠道使用`AD_CHANNEL`字典，成本类别使用`COST_CATEGORY`字典。`AD_SPEND`为投流，其他成本类别归入其他经营成本。每条成本记录日期、渠道、人民币金额和备注；同一天同一渠道允许多笔不同记录。

0元有效，表示该日明确未投放；没有记录的日期不能当作已核对的0成本。报表按全渠道当日合计核对是否已录，并列出缺失日期；并未由渠道字典自动推断收入归因或生成每渠道ROI。各渠道成本仍可在成本列表逐笔核查。

编辑与撤销成本必须提交当前`revision`，旧版本不能覆盖或删除他人刚修改的金额。撤销保留操作凭证防止旧请求重新生成成本。

## 两个ROI口径

1. **订单净消费 / 投流**：按订单创建日选择有效已付订单，原金额减累计退款，再除以同期已录投流成本。该值是倍数，净消费不等于现金实收，也不包含充值本金或押金。
2. **经营ROI**：同批已完成或已结算订单的净消费，减去陪玩成本、推荐分佣、独立平台补贴、员工薪资、投流费及其他已录成本，再除以这些成本的合计。订单按完成日归属，没有完成时间的已结算订单按结算日归属。

第二项的收入和业务成本必须来自同一批订单。已赚但尚未实际发放的陪玩分账、推荐分佣和平台补贴也属于成本，不能当0。部分退款使用原成功收益及真实冲正证明净成本，不能简单按新退款金额比例猜收益；无法证明的订单列为待核对且不给完整经营ROI。推荐人与陪玩为同一个钱包时仍分别识别服务收益和推荐分佣，防止遗漏或重复。

已确认月份使用工资快照；有明确安排且预览完整的未确认月份另外给出标注“暂估”的经营结果，随实际业务变化。没有人员安排、业绩归属缺口、未配置必要夜班或退款成本凭据不明时，不能以0成本做出虚假盈利。

成功`SHOP_INCOME`平台留存流水含退款冲正另外作为对照值，使用流水发生日。它可能与完成订单跨期，不替代同批订单的经营收入，也不能在已扣陪玩成本后再次扣除陪玩收入。模拟直付订单始终排除；充值本金、押金、提现本金不作为营业收入。成本分母为0时比值返回空值，不返回无穷大。

## API与权限

列表资源为`salary-plans`、`salary-assignments`、`salary-activities`和`operating-costs`，统一分页。夜班配置、员工选项、真实来源、预览、确认和历史快照位于`/api/admin/payroll/`下，ROI为`/api/admin/operating-roi/`。

权限分别为`salary:view/edit/confirm`、`cost:view/edit`和`roi:view`，沿用真实后台账号和OTP。字典维护权限单独配置，业务下拉只读所属类型的启用项；被历史业务引用的字典不能删除。

## 确认工资后的考试与售后补发（2026-11-11）

考试及售后事实在原月工资确认之后才被核实时，继续通过现有业绩核实接口登记。原确认快照中的该员工方案决定考试单次扣前金额、抽成和实得，或售后单次费用；业绩记录保留真实发生时间、原工资记录、原方案、核算金额和入薪月份。入薪月份为核实时从当前月份起的首个未确认工资期，且晚于原工资月份。原月快照不改变，入薪月薪资明细列出来源及补发；该期确认后不可撤销，重试使用同一业绩记录，不重复核算。后续期无该员工安排时仍需先完成人员安排。

当前只实现考试和售后两类已确认月份的补录补发；派单、充值的跨期补发、退款相关绩效及提成扣回结转、人员停用后的工资清算尚未随本项完成。工资仍是核算记录，不是钱包打款。`console.0024` 为新库结构迁移，未操作已有开发数据库。

## 退款提成、绩效与离职结清的内部联调（2026-11-11）

新增 `console.0025` 至 `console.0028`，将工资确认后的逐退款提成、已确认退款月的绩效差额、工资扣减与结转、离职结清后的旧提成免追分别留账。内部预览以真实店币支付和退款发生月计算绩效，净业绩为负时绩效为零，负业绩不结转；已确认工资不改写。已停用的原员工可在内部流程安排最后一期工资，授权人员确认全部工资线下结清后可登记结清，凭据和备注可留空，未扣完的旧退款提成免追。结清确认是工作人员的线下事实声明，不是系统转账。

上述工资预览、确认和结清 API 仅在 `PAYROLL_REFUND_ACCOUNTING_INTERNAL_TESTING=True` 的隔离测试下切换到新账务；默认仍关闭，不代表正式工资退款功能已交付。隔离测试覆盖真实协商退款、未确认月净负业绩、已确认月绩效顺延、工资扣至零与下月结转、停用人员结清、重复请求及来源留痕。真实 MySQL 并发与所有退款/业绩归属组合尚未验收；此前月份迟核派单、充值补发仍未接入。未修改已有开发库或重启预览后端。
