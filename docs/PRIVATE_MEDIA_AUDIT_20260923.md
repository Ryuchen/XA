# 凭证图片与客服消息访问验收

日期：2026-09-23。范围为本地文件存储、三个 Caddy 入口、业务账户权限和图片预览；不代表腾讯云 COS 或外部微信客服已接通。

## 修复内容

修复前，本地测试报单的 `/media/reports/...` 地址在未登录时返回 HTTP 200。充值凭证、报单截图、查外挂凭证和聊天图片与公开素材共用静态文件入口，知道地址即可绕过业务接口权限。

现在保留原有数据库和文件路径，通过以下入口隔离访问：

| 材料 | 可以签发和续签图片地址的账户 |
| --- | --- |
| 入队、结单、战绩和历史报单凭证 | 报单所属陪玩；具有 `report:view` 的有效后台员工（仍不开放草稿） |
| 充值凭证 | 具有 `recharge:view` 的有效后台员工；不因拥有钱包查看权限而放行 |
| 查外挂凭证 | 档案所属陪玩；具有 `escort:view` 的有效后台员工 |
| 站内聊天图片 | 会话所属老板/陪玩；具有 `chat:view` 的有效后台员工 |

提现记录当前保存收款资料快照、打款流水号与时间，没有独立图片上传字段，本次未新增打款凭证的业务规则。

- API 在序列化图片时检查归属和权限，签发有效期 **15 分钟**、只对应单一文件的地址。每次读取仍查询当前账户状态、后台角色、记录归属及文件名指纹；撤权、禁用账户、删除或替换文件会阻止原地址继续使用。
- 本地开发 Django 和部署 Caddy 均只公开明确列出的头像、视频、声卡、轮播、游戏图标及 `club-catalog` 封面目录。私有目录和未知目录直接返回 404，三个域名/端口使用同一规则；历史静态直链不再有效。
- 私有图片使用 API 域名，不使用 `DJANGO_MEDIA_BASE_URL` 指定的公开素材域名。响应禁止缓存，设置 `nosniff` 和 `no-referrer`，按图片内容确定类型；拒绝目录越界和指向媒体根目录以外的文件。
- `/api/media/renew/` 要求正常业务 JWT，重新检查原签发账户及资源权限；仅持有旧图片链接不能续签。管理端、陪玩报单和原生老板聊天在预览时续签；缩略图失败仅尝试一次自动更新，不刷新表单或清空草稿。
- 客服 WebSocket 在每条消息/会话更新发送前重新检查接收人的会话归属、有效后台成员资格及 `chat:view`。每个接收人获得独立图片凭据，无聊天权限员工不再收到正文和会话摘要。
- Daphne 启动入口调整为 `python -m config.serve`，保持原 CLI 参数，统一隐藏 HTTP 图片凭据及 WebSocket URL 中的 token。应用日志也进行相同脱敏；未清理以前已产生的日志。

## 使用与部署边界

限时图片地址本身是临时访问凭据：**他人取得完整链接后，在其有效期内也可以读取同一图片**。本实现限制签发、有效期和资源，不声称能阻止收件人转发、截图、保存图片，也不以普通退出登录替代所有已签发图片的立即撤销。

前后端与 Caddy 规则应一同部署；旧前端已缓存的 `/media/...` 凭证地址须刷新页面重新获取。发布流程中的 remote/release、managed、本地验证和开发编排均使用新的日志入口。新建公开素材目录时必须同步后端与网关白名单，不能重新开放全部 `/media/*`。

当前私有图片从本地 `MEDIA_ROOT` 读取。迁移 COS 时应使用私有存储及后端鉴权读取/限时签名，并处理原公开链接和 CDN 缓存；仅填写 `DJANGO_MEDIA_BASE_URL` 不能完成私有对象存储迁移。微信真机还需要配置 API 合法下载域名并验证图片预览。
