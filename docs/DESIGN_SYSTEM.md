# XA 系统设计标准

更新：2026-11-11。适用于管理后台、陪玩端、老板端 Web/H5，以及新增页面、组件和设计评审。根入口为 [DESIGN.md](../DESIGN.md)，具体实现尺寸见 [前端基线](../fronted/DESIGN.md)。

本标准整合用户已确认的设计与业务约定，并接入 [VoltAgent awesome-design-md 设计参考库](history/design-20261117/REFERENCE-LIBRARY.md)。文档描述规范要求；实施和验证状态以对应交付记录为准。

## 1. 决策顺序与适用边界

1. 用户最新明确决定、角色任务和业务 PRD 优先，尤其是门店隔离、权限、订单、资金、License 与模块购买边界。
2. 在上述约束内执行本标准、前端基线及已确认原型。规则冲突须记录具体来源与最终取舍。
3. 外部设计参考用于解决已识别的界面问题，选取具体模式后转成项目规则；版本与取舍记录在参考库。外部品牌分析不替代本项目规范。

当前正式前端为 `fronted/` 下的 React + TypeScript + Tailwind CSS 4 + shadcn 三端网页。旧 Vue、Element Plus、旧色卡及尺寸说明归档至 [2026-10-13 历史规范](history/DESIGN_SYSTEM-20261013.md)，仅供追溯。（微信小程序相关内容已按用户 2026-11-17 决定删除）

## 2. 任务、角色与模块

| 使用范围 | 设计目标 | 必须保留的边界 |
| --- | --- | --- |
| 后台管理端，固定模块 | 客服派单、审核、运营、财务与经营任务可扫描、可追踪 | 本店数据与平台独立授权分开；平台入口不由普通店内角色推断 |
| 陪玩端，固定模块 | 明确可接订单、本人履约动作及收益结果 | 与后台共享 B 端字体、语义色、控件和反馈；布局按手机与桌面任务适配 |
| 老板端，可独立购买的 Web/H5 | 选购服务、确认报价、下单及查看本人进度 | 私人定制仅在客户侧白名单；不能改固定模块、公共状态、权限或资金规则 |

先显示对象、当前事实与可执行动作，再显示次要规则。以角色任务组织导航，不按后端接口名称堆页面；不能把所有运营能力塞入会员管理。可见范围使用现有授权，前端隐藏不代替后端鉴权。

平台统一管理保留门店标识和缺失门店提示，不合并不同店币。老板与陪玩按域名绑定门店，不新增界面切店；后台身份由真实登录确定。

## 3. 视觉与 token

- 沿用已确认原型、Blue Planet 六色 `#020617 / #0F172A / #1E3A8A / #2563EB / #38BDF8 / #7DD3FC` 与奶白方向。具体颜色从共享语义 token 读取，不能在业务页硬编码另一套主题。
- 当前样式入口为 [theme.css](../fronted/shared/src/theme.css) 与 [product-ui.css](../fronted/shared/src/product-ui.css)，沿用已有 OKLCH 及语义映射。品牌蓝、表面、正文、辅助文字、边框、焦点及语义状态各有用途。
- 颜色与文字共同表达业务状态；成功、警告、错误不用于装饰。强调色优先服务当前操作；渐变限定已确认的重点表面，不扩展到每张卡片。
- 三端使用自托管 MiSans，字重 400/500/600/700。标题、金额、正文、标签、辅助说明遵循既有层级，不照搬官网营销大标题、专有字体或品牌素材。
- 以表面明度、细边框、字号和间距表达层级；遮罩、浮层才使用必要的层叠与阴影。深浅色分别检查可读性，品牌定制也必须保持文字与背景可读。
- 间距使用 4pt 整数倍。后台交互控件采用既有 40px 规格；按钮/输入 6–8px 圆角、标签 4px、普通卡片 8–12px。视觉紧凑不能压缩触控范围或裁切金额、单位与关键业务字段。

## 4. 导航、页头与信息层级

- 后台使用固定 80px 一级栏与 216px 二三级面板。图标 16px，同级使用同一风格与语义映射，不能用重复占位符表达不同业务。
- 二级分组与三级页面通过字号、缩进、间距及选中态区分。展开、收缩、浮层共用菜单源与稳定一级操作坐标，保留展开偏好；正文不因浮层打开移动。
- 搜索使用独立输入和分层结果，只搜索当前角色可访问功能。保留键盘选择、关闭和焦点返回；不能靠 placeholder 代替必要的字段名称。
- 主业务页面统一“标题 + 可选标签 + 简短用途 + 现有操作/真实指标”的页头。用途以一句话说明本页处理的事，不重复面包屑，不宣称待对接能力已可用。
- 跨页导航由侧边栏承接；页面内 Tab 只用于本页数据视图，避免重复薪资等跨页菜单。筛选、排序、分页与当前查询关联，切换条件时清楚反馈结果。
- 表格筛选直接融合在对应表格容器内，置于列表标题之后、表头之前；不另拆筛选卡，不把列表检索条件放进页头。常用字段常驻，低频条件只通过一次“更多筛选”展开，按业务优先级平铺；同一维度不同时提供 Tab、下拉和复选框入口。
- 后台所有表格操作列采用 24px 高、12px 字号的小按钮，间隔 4px、整体右对齐，空间不足时靠右换行；操作列表头居中。业务操作的颜色、权限与确认流程继续按各自用途呈现。
- 真正作用于子页面分析的日期或月份放在蓝色页头右侧，与标题共处一行区域，不追加页头下方筛选带。明确受影响的指标，账户/提现等全量快照不冒称按日期过滤。
- 表单只保留必要的业务分组；同一提交中的装饰性 Card 不重复套 Card。页面、Popover 与模态框中的下拉选择统一 40px 高、8px 小圆角；业务对象的空选择使用“请选择”，检索条件才使用“全部”。

## 5. 数据和交互状态

| 场景 | 原页面应如何呈现 | 不可出现的表达 |
| --- | --- | --- |
| 首次加载 | 保留页头、筛选、表头、区块；原数据位置显示骨架 | 切成另一套空白布局，先显示假 0 |
| 已确认空结果 | 保留相同结构；数据区说明暂无数据，提供适用的清除筛选或新增入口 | 把异常当空结果；为填满页面制造示例业务 |
| 首次读取失败 | 原区块显示未读取与重试；独立成功区块照常展示 | 整页替换为孤立警告框；未知资金或统计显示 0 |
| 刷新失败 | 同身份、同门店、同查询的旧快照保留并标明未更新 | 跨查询显示旧值；把旧快照称为最新 |
| 部分来源失败 | 按来源分别展示已读取、未读取及重试 | 一个接口失败遮掉整页，或用另一来源的状态冒充成功 |
| 配置未知 | 保留字段位置，用未知/未读取表示；必需来源未读取时禁用写入 | 把开关当关闭、配置当未设置或以默认值覆盖 |
| 提交中 | 明确进行中，防重复提交，保留用户输入 | 无反馈、重复扣款或提前显示成功 |
| 成功/明确失败 | 使用实际结果更新；错误靠近字段或动作并给出下一步 | 假成功、失败清空表单、仅用短暂 toast 承载关键错误 |
| 结果未知 | 保留原请求核对标记，提供查询结果和恢复路径 | 直接当失败重试，或刷新后解除待核对 |

金额、余额、数量和统计未读取使用“—”；已成功返回的真实零值显示 0。独立数据源分别判断；加载骨架和未知占位不能参与计算。配置缺失、确认为空和读取失败是不同事实。

后台状态统一使用 Status，标签同时提供文字、图标及语义色。

| 状态事实 | 标签与图形 | 显示依据 |
| --- | --- | --- |
| 未启用或已停用 | 灰色暂停图标，保留两者的实际业务名称 | 接口明确返回 false 或停用状态 |
| 未配置 | 灰色设置图标 | 接口明确返回未配置、空配置或缺少必需配置 |
| 未读取 | 灰色问号图标 | 尚未取得数据，或当前字段缺失 |
| 读取中 | 灰色加载图标，遵循减少动效偏好 | 当前来源正在加载 |
| 接口异常 | 红色警告图标，区块旁显示原因与重试 | 读取接口失败；旧快照单独注明未更新 |
| 已完成、已连接等确认结果 | 绿色勾选图标 | 已确认的业务或连接结果 |
| 待处理、待核对 | 琥珀色时钟图标 | 业务仍待处理或结果待核实 |
| 业务失败、驳回 | 红色叉号图标 | 接口确认的业务失败结果 |
| 进行中或普通业务信息 | 蓝色信息图标 | 对应业务状态，不用于填补未知状态 |

读取异常不能将启用开关呈现为关闭。历史上报的运行文字与当前连接状态分别显示，未知金额仍使用“—”，状态标签不参与资金和统计计算。

实现优先使用既有 `PageHeader`、`DataPageState`、`DataTable`、`SourceDirectoryCard`、`DataValue` 和 `DataRegion`，不另造独立异常页面骨架。当前覆盖与限制见 [后台读态逐页记录](../fronted/PAGE-STATE-AUDIT.md)。

## 6. 业务事实、文案与操作反馈

- 客服后台手动代单与老板自主下单共用订单、支付、派单、售后和结算口径；来源与分配路径分别显示。创建不等于付款，报名不等于接单，完成不等于结算，取消不等于退款。
- 状态与可用动作依据接口事实和已有权限；不凭前端计时、步骤条或套餐名推造状态。通知用于提示重读，不能代替业务事实。
- 金额明确人民币、当前门店店币或积分，不能混算；统计保留口径、时间范围和缺失数据说明。资金确认展示对象、金额及后果。
- 字段错误贴近字段，局部失败贴近区块；成功提示简短。需要持续处理的错误用稳定提示，确认、弹窗或抽屉按业务动作选择。
- 次要解释可放 tooltip，但必须可聚焦/点击查看；不可逆后果、失败处理步骤及关键金额不能只藏在悬停提示内。
- 待对接标记放在对应能力和操作处，说明未开放或下一步。演示数据明确标识，不进入真实余额与业务验收。

统一字段、状态及待后端契约见 [PRD 34](prd/34-SaaS产品模块与三端前端闭环.md)。本标准不新增业务规则或接口实现。

## 7. 适配、可访问性与性能

后台面向桌面和最小 1366×1024 CSS 视口横屏平板；老板与陪玩同时适配手机和桌面。复用既有断点与导航，不照搬外部官网断点。

手机交互目标保留至少 44px 触控空间，安全区、键盘和固定底栏不遮正文及操作。表格可以区块内横滚，页面不整体横向溢出。长名称可换行或展开，不能裁切业务数值。

保留可见标签、键盘顺序、焦点及返回位置，图标按钮有明确名称；状态不只依赖颜色。普通正文对比度以 4.5:1 为验收底线，大字及控件边界按适用标准检查。动效服务反馈并支持 reduced-motion，装饰不能阻塞业务操作。资源复用、按需加载，不为设计参考新增运行时请求。

## 8. SaaS 页面交互的十二项原则

采用用户根据《设计师从顶级SaaS产品中借鉴的12种 UI 模式》提供的十二项要点。下表是本项目的实施口径，适用于三端设计和评审；具体页面按角色任务选用。[参考来源与取舍](history/design-20261117/REFERENCE-LIBRARY.md)

| 原则 | 页面验收时检查什么 |
| --- | --- |
| 1. 新手先完成一件事 | 新店管理员进入配置页时看到一件当前可做的事，入口直达对应设置。任务的完成依据取自业务结果。 |
| 2. 空白给出下一步 | 首次无记录、筛选无匹配、未读取使用不同反馈。首次给有权限的新增或浏览入口；有筛选时就地清除条件；读取失败提供重试。 |
| 3. 提交前提示表单问题 | 在用户编辑或离开字段后检查已有必填、格式和取值范围。错误紧邻字段并可被读屏关联，纠正后消失，最终结果以服务端响应为准。 |
| 4. 熟练用户可用命令面板 | 后台通过搜索按钮或 Ctrl/⌘ K 打开同一面板，键盘可选择授权页面和高频操作。资金、派单等命令打开既有表单，保留确认步骤。 |
| 5. 帮助就在卡住的地方 | 折扣率旁说明输入单位，入队凭证旁说明提交内容；不可逆后果在确认前可见。在触屏上也能获得同一说明。 |
| 6. 决策旁有相关客户证据 | 服务详情从当前门店、当前套餐的公开订单评价提供依据，保留匿名处理。可见评价数为零时展示空态，失败时提供局部重试；推荐语、星级和成交量均须有来源。 |
| 7. 固定导航承接当前内容 | 详情页指明所属栏目。固定操作栏对应当前选择的服务、规格或订单；滚动到末尾仍能读到正文并操作，键盘焦点也能到达。 |
| 8. 等待时显示页面结构 | 保留原页头、字段、表头及操作位置，按独立数据源显示局部骨架。评价加载不阻塞看服务价格，未知金额与统计使用“—”。 |
| 9. 套餐推荐说明适用对象 | 用门店所需人数、功能、独立购买或定制需求解释适配理由。价格与能力取自已确认合同、价目或模块授权；询价入口保留询价语义。 |
| 10. 首次设置用清单 | 清单标出已完成、待处理、权限受限和待核实项。完成状态来自初始化证据或检查快照；点击进去、打开弹窗均不表示设置完成。 |
| 11. 操作后交代结果 | 对提交中、成功、明确失败及结果待核对给出具体对象与后续动作。区分首次读取失败与旧快照刷新失败。 |
| 12. 同类任务复用组件 | 后台列表、表单、空态复用已有组件；三端共用订单事实与同步提示。老板端的品牌 token 只作用于其可购模块。 |

## 9. 每次界面改动的验收要求

1. 记录页面、角色、共享组件、具体设计依据及采用/排除项；新模式先补齐共用规范，再在相关页面一致使用。
2. 核对加载、有数据、成功空、首次异常、刷新异常及独立来源状态。涉及动作时另验提交中、成功、失败、结果未知和权限不可用。
3. 后台检查 1366×1024 与桌面；老板/陪玩检查手机与桌面。验证深浅色、长文案、未知金额、键盘/触屏、滚动与底部操作。
4. 按变更范围执行类型检查、构建及必要验证，记录真实证据。后端待接部分单列，样例或 UI 测试不代替真实业务联调。
5. 开发沿用 `deploy/dev.ps1` 管理的 WSL + Docker 环境。前端修改通过 HMR 预览；不为设计标准重启后端、重建镜像或修改隔离资源。

2026-11-11 参考库最初接入仅更新标准与协作入口；随后后台前端实施与逐页验证见 [后台设计复核](../fronted/ADMIN-DESIGN-REVIEW.md)。记录明确已实施、已验证、接口异常及环境限制，不将规范本身当作完成证据。
