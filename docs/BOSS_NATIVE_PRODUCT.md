# 原生老板端产品规划与联动说明

## 目标与交付边界

将已有老板端能力重组为微信原生小程序，围绕「找到服务 → 确认价格与游戏资料 → 余额支付 → 接单履约 → 评价与售后」建立闭环。老板指购买游戏服务的客户，后台运营、陪玩和老板账号保持隔离。

`apps/boss-miniapp/project.config.json` 默认指向 `native/`。24 个业务页面全部使用原生 JS/WXML/WXSS；16 个历史路径仅负责将旧分享链接转到新页面。原有 Taro/H5 代码保留，方便既有环境继续运行。

用户提供的参考为 `#小程序://小樱电竞/0jDXiS5uxiMPHCm`。当前工具无法读取该微信分享入口，未将公开搜索的营销描述当作页面证据。现有实现依据仓库业务规划，尚未完成与该参考实机界面的比对。

## 视觉与交互

视觉方向：面向游戏服务买家的清晰移动交易界面，以微信原生控件为基础，柔和浅色背景、莓粉色强调、系统中文字体。以清楚表达金额、可执行动作与流程状态为主。

- 颜色、间距和常用组件定义在 `native/app.wxss`；24 个页面共享按钮、输入、面板、状态组件。
- 标准导航栏与底部五栏，原生安全区；固定支付栏留足内容和底部间距。
- 内容来自实际接口；缺图时保留语义占位，不编造服务销量、评分或账号余额。
- 每个请求页面提供加载、空状态、错误重试；钱包和消息支持分页。
- 账户切换清理个人页面数据；失效请求不会把旧账号数据覆盖到新账号。
- Tab 图标来源为 MIT 协议 Tabler Icons，许可证随包保留。
- 挑选陪玩支持昵称/段位/城市搜索、游戏或服务资格过滤、参考时价区间、参考时价排序和有语音筛选。时价来自后台陪玩档案，仅作选人参考；套餐报价负责实际结算。默认排序保留后端通行证优先及服务记录顺序；未配置时价放在价格排序末尾，筛选区间时排除。筛选隐藏正在试听的陪玩时停止声音。

## 微信快捷登录与绑定状态机

1. 用户主动同意隐私指引后点击微信快捷登录，客户端调用 `wx.login` 获取一次性 code。
2. `POST /api/users/wechat-login/ {code, checkOnly:true}`：已绑定老板返回登录令牌；未绑定仅返回 `requiresBinding:true`，不会创建账号或消耗手机号授权。
3. 未绑定时，用户可以授权手机号以识别唯一历史老板；授权回调后必须再次获取新的 `wx.login` code，再提交 `{code, phoneCode}`。
4. 手机号匹配多个老板、已关联另一微信、被禁用或非老板角色，返回明确错误，不覆盖或合并账号资产。
5. 新用户可以明确选择创建账号；创建前提示钱包和订单独立，避免误把历史资产变成新账户。
6. 已登录但尚未绑定微信的账号可通过 `POST /api/users/wechat-bind/ {code, phoneCode?}` 绑定；同微信重复确认安全，其他归属冲突被拒绝。
7. `GET /api/users/me/` 与登录结果提供 `isWechatBound`、`isPhoneVerified`、`bindingState`。界面根据后端字段显示，不能凭本地手机号字符串推定已验证。

状态：`UNBOUND`（未绑定微信）、`WECHAT_BOUND`（已绑定微信）、`PHONE_BOUND`（微信与手机号均验证）。后端保留 `bindStatus` 以兼容既有调用方。主要错误码包括 `WECHAT_CODE_INVALID`、`WECHAT_PHONE_CODE_INVALID`、`WECHAT_NOT_CONFIGURED`、`WECHAT_UNAVAILABLE`、`ACCOUNT_CONFLICT`、`ACCOUNT_DISABLED`、`ACCOUNT_ROLE_MISMATCH`。

老板手机号不再允许通过普通资料 PATCH 任意修改；在账号安全页使用微信手机号授权变更。手填手机号不会成为「已验证手机号」。既有后台维护的历史手机号仍用于首次归属识别，冲突需客服核实。

登录和已登录绑定共用 `WechatPhoneLock`：即使手机号尚未关联任何账号，也先锁定该手机号，再锁定账号、核对归属并写入。MySQL 双连接测试曾复现两个请求同时通过旧检查的问题；修复后只允许一方成功，另一方返回 `ACCOUNT_CONFLICT`。上线本轮后端前须执行 `python manage.py migrate`，包含 `users.0027_wechatphonelock`。

个人资料页保留原生 `chooseAvatar` 与昵称输入。头像通过已登录的 `POST /users/me/avatar/` 上传并同步历史账号展示；仅允许有效 JPG/PNG/WebP、最大 5MB，不接受客户端指定其他账号。选择头像不会丢失尚未保存的游戏资料草稿。

AppSecret 和微信 session_key 不下发客户端。登录态采用后端业务 JWT；`wx.login` 返回的 code 与手机号授权 code 分开处理，不复用。

## 交易与履约约束

- 金额以后台整数账务单位流转，10 账务单位 = 1 兴安币。仅 `core/ui.money` 负责展示换算，页面不自行按人民币分制转换。
- 优惠、会员折扣和余额由 `/orders/quote/` 计算。客户端不复制价格算法。
- 支付前重新读取报价，用户确认后提交 `expected_amount`。下单和礼物价格变化时返回 `PRICE_CHANGED`，不扣款。
- `/orders/create/` 与礼物 `/tip/` 携带持久化 `client_request_id`；相同账号、地址与载荷的并发请求合并，网络结果不明时保留编号。重复响应带有后端成功回执时恢复原订单并结束该请求；无回执则保留编号提示核对。另行确认的新购买使用新编号，见 [资金请求恢复专项](FUND_RECOVERY_AUDIT_20260923.md)。
- 后端仍负责钱包行锁、幂等占用、优惠券核销、派单、退款和结算。客户端从不写余额或决定抽签结果。
- 订单按钮严格由 `allowed_actions` 控制：老板没有接单/开始服务/完成结算权限。取消成功后从后端订单和账单读取退款结果。
- 新增 `GET /orders/orders/<id>/`：老板仅能查看本人订单；陪玩只看关联订单；其他订单返回 404。
- 当前充值业务为客服确认收款后入账。小程序不伪造微信支付成功，也没有绕过账务记录的本地充值。
- 客服订单上下文使用后端鉴权后的客户编号和订单号。匿名 `/support/public-contact/` 仅返回有效官方名片，不返回任何客户或订单字段。

## 运行与失效恢复

`core/api.js` 统一处理超时、非 2xx、业务错误、令牌刷新。并发 401 合并为一次刷新；网络暂不可用保留会话，确实失效才退出。账户修订号拒绝账号切换前发起的旧请求结果。

`core/realtime.js` 连接已有 `/ws/orders/`，处理订单更新和客服消息；进入前台连接、后台断开，25 秒心跳、指数退避重连。重连后通知页面重新获取权威数据；页面 `onShow` 和下拉刷新作为回退。

`core/legacy-route.js` 保留原 `productDetail`、`orderList`、`serviceCard`、`customer/*` 等 16 个分享入口；旧消息内部跳转也经过已知页面映射。横幅外部 HTTPS 活动链接由用户确认后复制，不把任意链接放进未配置业务域名的 web-view。

## 配置、构建与验收

1. 开发者工具导入 `apps/boss-miniapp`，基础库使用项目现有 3.15.2。
2. 配置 `native/config.js` 的开发/体验/正式环境地址。正式环境必须 HTTPS，禁止回退 localhost。需要独立 socket 域名时填写 `socketBase`。
3. 微信平台配置 request、socket、uploadFile、downloadFile 合法域名，隐私保护指引、手机号能力、客服和企业微信参数。
4. 后端 AppID 与小程序 AppID 一致，后端单独保存 AppSecret；生产关闭 `WECHAT_MOCK_LOGIN`，部署真实数据库、Redis、Celery。
5. 开发阶段执行根目录 `pnpm boss:build` 与 `node --test scripts/test-native-core.cjs`。发布前运行 `node scripts/check-release-config.mjs`（体验版加 `--target=trial`）及 `node scripts/check-native.mjs --require-compiler`；这两项不需工作区 npm 依赖。正式发布必须通过官方编译器，非默认路径使用 `WECHAT_COMPILER_DIR`。注意私有项目配置的 `urlCheck` 会覆盖公共设置，发布时须开启。
6. 后端验证：`python manage.py test users club_accounts orders chat support coupons --settings=config.test_settings --noinput`。
