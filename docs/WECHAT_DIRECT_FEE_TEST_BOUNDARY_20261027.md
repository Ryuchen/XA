# 微信直付手续费测试域边界

此实现只服务于受 `WECHAT_DIRECT_DOMAIN_TESTING` 保护的内部验证，没有小程序支付入口，也不调用真实商户。未配置手续费时以零手续费兼容旧测试合同；这不是生产默认费率，也不能据此开放支付。生产启用前必须完成有效商户费率配置与合规确认，并核对渠道账单实际扣费。

测试策略由服务端提供版本、分子分母、手续费计费基数和舍入方式。订单服务成交额与老板确认的渠道支付总额分别保存；配置变更后重新报价，已创建的意图继续使用原冻结快照。同一请求重试不按新费率重新计价。历史意图缺少可核对的兑换快照时，即使两边数字相等也不能猜测兑换来源：保留已收款证据并进入待核对，禁止新增派单。

金额单位不可混用：现有 `orders/pricing.py` 说明十个内部单位为一兴安币；客服充值现行规则为一元兑换十兴安币，因此新测试合同冻结一百内部单位兑换一元、一百分钱的版本、原始内部单位和精确换算规则。换算不能得到整分时拒绝报价。当前数值相等仅是这一规则的结果。正式接通前须验证该兑换口径、历史订单语义和各端人民币展示。

手续费大于零的订单暂不支持退款和结算：具体手续费退款及部分退款分摊规则尚待确认。未接单超时会保留支付和订单事实，将支付意图标为待核对，不会伪造余额流水或声称已退款。渠道优惠、权益和真实扣费对账仍需独立完成；出现缺失或未知资金来源时保持待核对。

测试配置只是单进程内的配置对象，不具备跨进程策略版本发布、持久化审计和并发切换保障。正式配置、报价展示和支付前确认还需要完整服务端接口、版本管理与生产级联调。

0062 历史数据隔离迁移要求在停写窗口执行，暂停付款回调、收件箱和派单工作进程并处理在途操作；其批量状态修改不是与运行中工作进程协同的在线迁移方案。旧合同尚需能核验来源的人工处理流程，不能直接恢复派单。
