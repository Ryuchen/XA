# 矢量排版与最终成图检查

适用于兴安电竞封面、完整价目和广告；2026-09-29 用户明确的版式要求优先于历史模板。首次填字前读取，最终渲染后逐张执行。只改旧图中的部分文案时，检查改动区及受影响的相邻区，并查看整图确认整体平衡。

## 1. 先确定展示内容与文字安全区

- 封面保留品牌、玩法名、核心卖点、平台/模式和活动主信息；不出现注意事项、下单须知、补偿例外或结算细则。“补偿另计，不参与上浮”留在完整价目对应规则区，不能变成封面小字、脚注或底栏。
- 对照 `content.json` 划分封面与详细页的展示字段；筛掉封面文字不等于删除原规则。图一/图三的反馈用于提炼版式要求，不把示例价格、优惠值或补偿额变成技能固定业务数据。
- 在底图实测每块容器的边界，标出插画实际轮廓及其周围安全间距；透明图片的整张外框不等于插画轮廓。以扣除内边距、图标及插画占位后连续可读的区域作为文字区，保存区域说明或辅助框预览。
- 装饰花纹可以退入背景；角色脸、手、鼠耳、主要道具和突出的轮廓属于插画主体，不允许文字或文字底板侵占。相邻组须有可见的呼吸空间，避免刚好贴边。

## 2. 先居中，再强调，再重新居中

1. 先用清晰的基础样式排出完整文案，按可见字形边界确定宽高；多行按整组实际边界计算。横向中心取所属可用文字区的中心，纵向中心取所属行或信息块的中心，不用字体基线或画布中线替代。
2. 封面全部文案在各自文字区横向居中；同一信息组共用中线。品牌图标与名称整体计算，艺术标题按所有字符的可见轮廓计算。副标题、版本、活动不能一部分居中、一部分挂在左侧。
3. 带插画的卡片按文图区分栏。例如“带出物资全部归板板”左侧有鼠与物资箱时，标题及正文组在右侧净文字区居中；标题自身居中，多行正文可在居中的文本组内部左对齐，便于连续阅读。若按整块面板中心放字造成视觉偏左，必须重排。
4. 居中成立后再突出玩法名、核心权益、关键数值。“工作日专享”应独立、显眼、横向居中，可与权益增益组成居中的上下两行，不做偏左的小标签。普通须知也要保持粗体与足够字号，不能靠削弱正文来制造重点。
5. 加粗、放大、换行、艺术字描边或阴影会改变可见边界；完成强调后重新测量，复查居中、边距与插画间隙。几何居中后，再按实际成图检查左右视觉重量，必要时微调文字组或分栏，并记录理由；不能靠目测随意移到插画上。

## 3. 须知可读性、补偿分组与尾部空间

- 下单须知的标题、分类和全部正文都用真实粗体；正文默认从 Bold / 700 开始，不只加粗小标题和金额，不以重描边代替字重。
- 先用约 390px 宽、无需捏合放大的手机预览检验正文；等效字号可从 14–16px 起排，再按实际字体、内容与使用场景调整。换算为 `布局字号 × 预览宽度 / 布局宽度`；不能把 3200px 导出的高清误当成正文变大。`maxWidth` 可能暗中缩字，应检查渲染后的 `effectiveSize`。
- 历史 809px 底图上的 13.4 字号缩到 390px 宽时约为 6.5px，不能继续作为须知默认值。扩大正文区、缩窄装饰/分类列、增加行高或延长画布；只允许不丢条件的等义精简，不能为了放大字体省略规则。
- 缺项补偿先按原因分组，每条将“物品 + 金额”紧邻放置，组内紧凑、组间清晰。可用短表或按行排列，同类金额及单位对齐；禁止把原因、物品与金额拉到整行两端，导致来回寻找对应关系。较长原因另起一行时，也要和其补偿项组成完整块。
- 补偿条目内部紧凑，不等于压缩整个须知区。多行正文留出足够行距，上下内边距均衡，完整规则组在行内垂直居中；不能贴分隔线或上下相碰。
- 同时查看须知和页尾：若正文拥挤而品牌周围有大块闲空，先回收多余尾部空白，增加须知高度、字号和组间距；必要时调整背景分区或页脚位置。底景保留适量收尾即可，品牌应与内容自然衔接，不能孤悬在大片空地里。空间仍不足时延长画布，不继续缩字，也不添加无关文案填空。

## 4. 检查文字与插画的空间及前后层级

- 对文字的最终可见边界（含强调后的描边/阴影）与插画主体、安全间距逐区检查，不只检查文字是否在画布内。
- 字与字、字与图主体发生相交、遮挡、贴边或视觉挤压均需处理。文字放在最上层仍可能挡住插画；把插画盖在文字上也不合格。
- 背景纹理、光效、线条的视觉强度低于正文；信息底板保障对比度，插画主体保留完整可辨轮廓。先移动文字组、调整分栏、装饰位置与容器大小；若底图已经烘焙了冲突，按原有美术授权流程调整底图，不盖住人物硬塞文字。
- 现有 `review/*-text-bounds.json` 只记录普通文本，未覆盖艺术标题、描边/阴影和插画轮廓；它能辅助查错，不能证明无图文碰撞或视觉居中。缺失边界须补测或用最终局部图核查。

## 5. 每次成图后的验收闭环

打开本次实际输出的 PNG，而非只看 SVG 源码、旧预览、模板截图或缓存成功信息。检查范围包括所有新图及所有受影响的成图：

| 视图 | 必查内容 | 不通过时的处理 |
| --- | --- | --- |
| 完整封面 | 没有注意事项；所有文案在所属文字区横向居中；活动醒目；左右文图平衡 | 精简封面展示字段、重排信息组及其中心 |
| 完整长图 | 阅读层级顺畅；须知与页尾分配均衡；品牌不孤立；插画保持完整 | 重新分配分区高度及尾部空白 |
| 约 390px 宽手机预览，可垂直滚动 | 须知正文粗体、无需放大可读；单位清楚；补偿关系一眼可对应 | 增加有效字号及正文空间，不能仅提升导出分辨率 |
| 原尺寸局部：活动/权益卡、缺项补偿、须知、图文交界 | 实际字形/多行组居中；无裁切、碰撞、贴边；字号变化后仍有安全间距 | 修正对应区块，重渲染再查 |
| 来源与最终展示对照 | 数值、单位、条件、且/或及规则完整；封面省略的条款仍在详细页正确呈现 | 修正数据或展示映射后复核 |

记录到项目 `review/visual-qa.md`：页面与版本、检查的实际文件/预览路径、各项通过或问题、修正方式及复查结论。发现问题后修改矢量布局或必要底图，重新渲染受影响页面；加粗、字号和位置任何变化后再次检查居中及图文关系。

打包若补渲染了页面，新增或变化的成图必须补查；包内文件须与最后检查的版本一致。渲染退出码、无文字溢出、`contentVerified=true`、`stage=delivered` 都不代表视觉验收已通过。未通过的版本保留为待修稿，不标成最终交付，也不把内部检查变成对用户的重复确认。
