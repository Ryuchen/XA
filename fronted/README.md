# 声浪电竞三端 React 前端

设计与界面评审统一从 [项目设计原则](../DESIGN.md) 开始，执行 [系统设计标准](../docs/DESIGN_SYSTEM.md) 和 [前端基线](DESIGN.md)。用户指定的 [awesome-design-md 参考库与选用边界](../docs/design/REFERENCE-LIBRARY.md) 已纳入三端开发流程。

2026-11-11 前端产品化交付见 [SAAS-DELIVERY.md](SAAS-DELIVERY.md)；模块、角色、状态和后端待对接契约见 [PRD 34](../docs/prd/34-SaaS产品模块与三端前端闭环.md)。日常开发统一使用 `../deploy/dev.ps1` 和登记的 WSL + Docker 环境，下表旧端口仅作历史脚手架记录。

按用户指定在 `XA/fronted` 重新建立源码，三端分别通过官方 `shadcn@4.23.0 init` 创建全新 React + TypeScript 脚手架，并用 `shadcn add` 安装组件。每端 `package.json` 的 `xaScaffold` 记录实际初始化信息；既有 `apps/` 是业务迁移依据，原型仅作视觉参考。

| 目录 | 适配范围 | 开发入口 |
| --- | --- | --- |
| `boss` | 桌面与手机 | http://127.0.0.1:13101 |
| `provider` | 桌面与手机 | http://127.0.0.1:13102 |
| `admin` | 桌面，最小1366×1024的iPad Pro 12.9横屏 | http://127.0.0.1:13103 |
| `shared` | 会话、请求、金额、实时连接、共享主题 | 不单独运行 |
| `wechat-bridge` | 只有微信身份、手机号授权与短信确认的一页原生桥接包 | 在微信开发者工具导入该目录 |

界面框架为 React，Tailwind CSS 固定4.0系列，组件由shadcn CLI生成；Vite仅承担React项目的开发服务和构建工具。此目录使用独立npm workspaces与锁文件，不安装或引用旧Vue、小程序UI运行时。

使用 Node.js 22.12+ 与 npm，在本目录执行：

```powershell
npm ci
npm run dev:boss
npm run dev:provider
npm run dev:admin
```

三个开发命令分别在终端运行。默认真实后端代理为 `http://127.0.0.1:18080`，同时代理API、WebSocket与媒体。通过进程变量 `XA_API_PROXY` 可切换隔离验收后端；外部微信/SMS替身只允许用于明确标识的隔离环境。

Windows可执行 `./dev.ps1` 启动三个后台开发进程；`-App boss|provider|admin` 只启动指定端。使用外部授权隔离的验收服务时执行 `./dev.ps1 -Backend http://127.0.0.1:18105 -Acceptance`，页面会明确显示验收边界。已有端口监听会保留，不会擅自停止其他服务；切换后端前应停止原开发进程再启动。

```powershell
npm run typecheck
npm test
npm run build
```

三端统一支持两种登录方式：普通浏览器使用账号密码和短信验证码，微信内通过公众号 H5 网页授权快捷登录。后台新账号首次密码登录后必须完成微信绑定初始化；老板可在账号安全中设置登录密码。微信开放平台扫码入口仅保留待开发组件。详见 `AUTHENTICATION.md`。

桥接包已独立放在 `wechat-bridge`，仅1页、约9KB，不包含旧小程序业务页面或业务JWT存储。执行 `node ../scripts/check-wechat-bridge.mjs --require-compiler` 可检查边界并调用微信官方编译器；正式扫码/短信仍需真实发布和服务配置。

迁移与验收分别记录在各端的 `MIGRATION.md`。构建通过、路由存在或页面可打开均不代表整条业务链路已经验收完成。

三端现在以页面根查询参数 `?store=门店标识` 进入对应门店，例如 `http://127.0.0.1:13101/?store=shenglang#/home`。未指定时沿用原门店 `shenglang`；服务器确认门店营业状态后才挂载业务页面，未知、停用或待初始化门店不会读取默认门店的数据。显示名称与网页标题来自当前门店真实配置。

登录、刷新、公开读取、上传和实时连接都携带当前门店。会话、未确认资金请求、聊天草稿、预约草稿和待核对操作按门店与角色隔离；原门店的历史待确认请求仅迁入原门店。通过登录页、个人中心或后台侧栏切换门店时整页重新载入，关闭旧实时订阅并离开原订单详情；各店使用各自已验证的登录会话。

平台账号获得独立门店管理授权后，后台出现“门店管理”，可登记新店、修改名称与入口、停用或启用门店，并复制老板端、陪玩端和管理入口。门店超级管理员权限不自动获得平台权限。新店登记后仍须由运维初始化独立业务库、配置和首位管理员，界面以“待初始化”明确显示此状态；初始化方式见[多门店部署说明](../docs/ops/multitenancy-20261104.md)。

本轮已执行链路与未覆盖范围见 `ACCEPTANCE.md`。原18080本地后端已同步新增微信登录接口及迁移，原18081/18082容器和28083原型预览仍可访问；新React源码的热更新入口使用上表13101–13103，当前明确接入独立验收库。

岗位薪资、每日投流、经营ROI与统一字典功能位于新React后台的“财务结算”和“系统管理”，继续使用13103热更新入口及18105隔离验收后端。本轮新增迁移`console.0018`至`0020`已在独立验收库应用；未将原18081/18082历史前端容器替换成新源码。功能口径、配置步骤及验证证据见[薪资与ROI说明](../docs/ops/payroll-roi-20261104.md)。
