# 后台筛选与页面层级修订

日期：2026-11-11。以用户本轮订单、陪玩业绩、报单审核、试音报名和外部积分登记的连续批注为准。本轮只修改后台前端与设计/PRD文档，沿用现有接口、权限与业务处理。

## 最终结构

- 列表：页头 → 必要提示/摘要 → **同一表格容器中的列表标题、筛选、表头、数据、状态**。筛选不另拆 Card，不放到页头。
- 分析：左侧页名/用途，**蓝色页头右侧放全局日期/月度条件**。不在页头底部追加浅色筛选条。
- 常用条件直接显示，低频条件使用一次“更多筛选”，条件按业务分组平铺；没有第二层 details 或筛选卡套筛选卡。
- 同一维度只保留一个入口。独立业务对象视图仍可用 Tab，例如签到规则、礼物与月度进度；编辑表单的基础资料/价格/内容视图也继续保留。

## 模块对应

| 页面/模块 | 常用条件与放置 | 更多条件/整理 |
| --- | --- | --- |
| 订单与派单 | 表内：关键词、订单状态、工作队列 | 原支付、路径、类型、售后、日期、精确查找和核对标记平铺；删除重复快捷队列栏及嵌套更多；客服待派/售后别名归并到单一对应字段 |
| 服务商品 | 表内：名称、游戏类目、玩法 | 编号、分类及资格在一次展开内；游戏类目从独立卡片列表合入；资格不再自行嵌套 details |
| 通用商品/营销/内容/Banner | 表内同一筛选行 | 使用既有支持字段，未开放条件仍明确禁用；不为统一展示新增接口参数 |
| 老板、陪玩、注册审核 | 各自表内关键词及状态 | 老板手机号、陪玩性别与资格归低频，一次展开；注册保持原搜索/审核条件 |
| 评价、消息、试音 | 各自表内条件 | 评价高级条件平铺；报名活动归更多；活动与报名为两个真实路由对象，不伪装同维度筛选 Tab |
| 报单、提现、流水/充值/奖惩 | 各自表内关键词/状态等原条件 | 原高级字段一次展开；不因有列表派生统计就上移页头 |
| 钱包 | 账户列表内关键词和账户类型 | 移除重复钱包分类栏，账户类型只保留首行选择；独立平台资金/台账不受其影响 |
| 成本登记 | 目录表内日期 | 保留原日期提交及统计来源，不增加另一日期入口 |
| 成员、角色、审计、通行证、签到月度 | 对应表格内 | 按现有检索方式保留实时/提交行为；审计/资格等低频条件一次展开 |
| 统一字典 | 表内业务字典类型、名称/编码、状态 | 类型选择合入主条件，移除外置类型 Tab；切换类型仍重置原条件 |
| 平台统一订单 | 订单追踪表内关键词、俱乐部、来源和订单状态 | 支付状态归更多；服务未开放时沿用原 capability 边界并禁用检索，不伪造平台数据 |
| 陪玩业绩 | 页头右侧日期 | 日期影响订单净额、占比及排行；账户和提现明确为全量快照 |
| 员工月度安排、业绩归属、薪资核算 | 页头右侧月份及相关类型 | 沿用原月份依赖；薪资预览/确认记录同范围，夜班配置独立 |
| 经营 ROI | 页头右侧日期 | 原投产比、经营核算和每日成本数据范围保持 |

订单实际请求仍由既有 `orderQuery` 映射。日期保留 `created_day/refund_day`；`queue=staff_dispatch` 仍转换为 `actionable_staff=1`，售后别名仍对应原 `aftersale_open`。已支付/未支付待接单队列原本固定订单与支付状态，界面同步展示该约束并禁用矛盾选择。没有改变派单、支付或资金处理。

## 表单与选择控件

外部积分登记保留一个提交外框，取消仅装饰的“配置内容”内层卡片；老板选择、来源与业务字段平铺。确认勾选、唯一来源编号、权限及提交保护保持。

所有后台搜索选择器使用8px圆角和40px高度，覆盖被 Radix `asChild` 改写为 `popover-trigger` 的按钮，以及 portal 中的模态框。筛选上下文空项显示“全部”；业务对象空项显示“请选择”，外部积分明确为“请选择老板账号”。空项依旧是原 null/空字符串语义，不改变绑定或提交规则。

## 验证与限制

- 在1366×1024逐页复核59个导航入口。31个具有共享表格筛选的入口全部位于对应表格内部；未发现独立筛选卡、嵌套更多或旧页头底部筛选带；无整页横向溢出。
- 陪玩业绩、员工安排、业绩归属、薪资核算、ROI共5个全局范围入口均位于同一蓝色页头右侧；报单等列表页不含全局筛选。
- 实际检查订单更多展开的15个低频字段、3个业务分组与10列表头；商品资格平铺。报单筛选确认属于表格内部。
- 页面外部积分选择器及试音绑定老板模态框选择器实测40px高、8px圆角；模态框选项列表可展开。只打开和关闭弹窗，没有提交绑定/登记/审批/资金动作。
- 保留上轮读取状态回归：加载、成功空、首次失败、成功和刷新失败仍使用原结构；金额未知与真实0区分。原13个接口异常仍由后端对接方排查。
- 后台类型检查/构建、8项导航与实时刷新测试、共用读取状态回归通过。完整部署Verify的既有后端监听归属限制未处理；没有为界面改动重启或接管后端。
